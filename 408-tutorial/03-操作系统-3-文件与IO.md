# 第一部分：文件管理

## 10.1 文件的基本概念

### 🧒 大白话
文件就是**有名字的一堆数据**，存在硬盘上。操作系统里的**文件系统**就是**图书管理员**：
- 给每本书（文件）建**档案卡**（记录书名、作者、放在哪个书架）
- 管理**目录**（分类索引）
- 管理书架上的**空位**
- 决定谁能借哪本书（权限）

### 📖 文件控制块 FCB 和索引结点（⭐）
**FCB**：文件的“**档案卡**”，包含文件名、类型、大小、**物理位置**、权限、创建时间……
**目录**就是 **FCB 的有序集合**，一个 FCB 就是一个**目录项**。

🧒 问题：查找文件时，只需要**文件名**来匹配，但要把整个 FCB（很大）从磁盘读进来，浪费！
**解决 → 索引结点（inode）**：
- 把 FCB 里**除文件名以外**的信息拿出来，单独放在“**索引结点**”里
- 目录项只剩：**文件名 + 索引结点号**（很短）→ 一个磁盘块能放更多目录项，查目录时读盘次数少
- **文件的所有属性（大小、权限、物理地址……）都在索引结点里**

**真题（2025 年第 29 题）**：用索引结点方式，新建文件 F 时，文件系统**不会**做的是 **C. 在目录文件中写入 F 的访问权限信息**（权限在**索引结点**里，目录项只有文件名和索引结点号）。

**真题（2020 年第 31 题）**：目录项 64 字节 = 文件名 60 字节 + 索引结点号 4 字节。能创建的文件数量上限？
→ 每个文件对应一个索引结点，索引结点号 4 字节 = 32 位 → 最多 **2³² 个**。（文件名的长度只影响命名，不限制文件数量。）

### 📖 文件的操作
- **创建**：分配外存空间，在目录中建立目录项
- **删除**：找到目录项，回收存储空间，删除目录项
- **打开 open()**（⭐）：
  1. 根据文件名**查目录**，找到 FCB（索引结点）
  2. 把 FCB 复制到内存的**系统打开文件表**（如果别人已经打开过，就不重复复制，只把**打开计数 +1**）
  3. 在进程自己的**用户打开文件表**中建立一项，指向系统表的那一项，并记录**读写指针**、访问权限
  4. 返回一个编号（**文件描述符 fd**），以后用 fd 操作文件，**不用再查目录**
- **关闭 close()**：删除用户打开文件表中的项；系统打开文件表中的打开计数 −1，**减到 0 才删除**该项
- **读/写**：用 fd 找到文件，按读写指针操作

**真题（2020 年第 23 题）**：多个进程共享同一个文件 F，正确的是 **B. 在系统打开文件表中仅有一个表项包含 F 的属性**。
- A ✗：可以用不同方式打开
- C ✗：各进程的用户打开文件表中，**读写指针、打开方式**可以不同
- D ✗：计数为 0 时才删除

### 📖 文件的逻辑结构（用户看到的样子）
- **无结构文件（流式文件）**：就是一串字节（源代码、文本文件）
- **有结构文件（记录式文件）**：
  - **顺序文件**：记录一个接一个（定长可以随机访问，变长只能顺序访问）
  - **索引文件**：给变长记录建一张索引表
  - **索引顺序文件**：分组，给每组建索引（像分块查找）
  - **散列文件**：用散列函数算位置

## 10.2 目录结构

- **单级目录**：整个系统一张目录表 → 不能重名
- **两级目录**：主目录（每个用户一项）+ 用户目录 → 不同用户可重名，但不能分类
- **树形目录**（⭐ 最常用）：像 Windows 的文件夹
  - **绝对路径**：从根目录开始，如 `/home/user/a.txt`
  - **相对路径**：从**当前目录**开始，如 `user/a.txt` → 查找时读盘次数更少
  - 缺点：不方便共享
- **无环图目录**：树形 + 允许多个目录项指向同一个文件 → **便于共享**

## 10.3 文件共享（⭐）

### 📖 硬链接（基于索引结点的共享）
🧒 两个目录项（两个名字）指向**同一个索引结点**。就像一个人有两个名字，本质是同一个人。
- 索引结点里有**链接计数 count**，记录有几个目录项指向它
- 删除一个名字：count − 1；**count 减到 0 才真正删除文件**
- 不能跨文件系统

### 📖 软链接（符号链接）
🧒 创建一个**新的小文件（LINK 类型）**，里面只写着**原文件的路径名**。就像 Windows 的“**快捷方式**”。
- 访问时要**按路径查找**原文件 → 多次读盘，慢
- 原文件删除后，软链接就**失效**了（“悬空”）
- 可以跨文件系统、跨网络

**真题（2021 年第 30 题）**：目录 dir 下有文件 file1，删除该文件时内核**不必**完成的是 **A. 删除 file1 的快捷方式**（快捷方式是软链接，是另一个独立文件，内核不管它，它自然失效）。释放 FCB、释放磁盘空间、删除目录项都要做。

**真题（2022 年第 45 题）** 里，文件 doc 和 course1 的**索引结点号都是 10** → 它们是**硬链接**，是同一个文件！所以 doc 占用的磁盘块号 x 就等于 course1 的块号 **30**。

## 10.4 文件保护
- **口令保护**、**加密保护**
- **访问控制**：访问控制列表（ACL），记录每个用户/用户组对文件的权限（读、写、执行……）

## 10.5 文件的物理结构（外存分配方式，⭐⭐⭐）

### 🧒 大白话
文件在磁盘上怎么放？磁盘被划分成一个个**盘块**（比如 4 KB 一块）。

### ① 连续分配
文件占用**连续的**若干盘块。目录项记录**起始块号 + 长度**。
- ✅ **顺序访问快**（磁头不用来回跳）；**支持随机访问**（第 i 块 = 起始 + i）
- ❌ 会产生**外部碎片**；**文件长度不好扩展**（后面的块可能被别人占了）

### ② 链接分配
文件的盘块可以**分散**在磁盘各处，用指针连起来。
- **隐式链接**：每个盘块的**末尾**存下一块的指针。目录项记录首块和末块
  - ✅ 无外部碎片，文件易扩展
  - ❌ **只能顺序访问**（找第 i 块要从头读 i 次盘）；一个指针坏了后面全丢
- **显式链接（FAT）**：把所有指针**集中**放在一张表里，叫**文件分配表（FAT）**。整个磁盘**一张** FAT，开机时读入内存
  - ✅ 查找在内存中进行，**支持随机访问**（查 FAT 很快），磁盘访问次数大大减少
  - FAT 里还标记了**哪些块空闲** → FAT 同时用于**空闲空间管理**
  - **真题（2025 年第 31 题）**：文件系统能够知道外存空闲空间使用情况的是 **C. 文件分配表（FAT）**

### ③ 索引分配（⭐ 大题最爱）
每个文件有一个**索引块**，里面按顺序列出这个文件所有数据块的块号（像**书的目录页**）。
- ✅ **支持随机访问**，**文件长度可变**，无外部碎片
- ❌ 索引块占用额外空间
**真题（2020 年第 24 题）**：支持文件长度可变、随机访问的磁盘分配方式是 **A. 索引分配**。

文件太大，一个索引块放不下怎么办？
- **链接方案**：多个索引块链起来
- **多层索引**：一级索引块指向二级索引块……
- **混合索引**（⭐⭐ UNIX 的 inode 用的就是这个）：

```
索引结点（inode）
┌───────────────┐
│ 直接地址 0     │──→ 数据块
│ 直接地址 1     │──→ 数据块
│ ...           │
│ 直接地址 9     │──→ 数据块
│ 一级间接地址   │──→ [索引块：放 N 个块号] ──→ N 个数据块
│ 二级间接地址   │──→ [索引块] ──→ N 个 [索引块] ──→ N² 个数据块
│ 三级间接地址   │──→ ... ──→ N³ 个数据块
└───────────────┘
```

### ✏️ 混合索引计算（⭐⭐）
> 盘块 4 KB，块号（地址项）4 字节，inode 含 10 个直接地址、1 个一级间接、1 个二级间接、1 个三级间接。

1. **一个索引块能放几个地址？** N = 4 KB / 4 B = **1024 个**
2. **各级能管多少数据？**
   - 直接地址：10 块 = **40 KB**
   - 一级间接：1024 块 = **4 MB**
   - 二级间接：1024² 块 = **4 GB**
   - 三级间接：1024³ 块 = **4 TB**
3. **最大文件大小** = (10 + 1024 + 1024² + 1024³) × 4 KB ≈ 4 TB
4. **访问某个字节要读几次盘？**（假设 inode 已在内存）
   - 在直接地址范围：1 次（读数据块）
   - 在一级间接范围：2 次（读索引块 + 读数据块）
   - 在二级间接范围：3 次
   - 在三级间接范围：4 次

**真题（2022 年第 45 题）**：盘块 4 KB，inode 256 字节，10 个直接 + 一级、二级、三级间接各 1 个，地址项 4 字节。
- 第 3 问：**目录文件 course 已在内存**，打开 course1 并读入内存需要读几个磁盘块？
  → 从 course 目录中得到 course1 的 inode 号 10 → **读 inode 所在的块（1 块）** → 从 inode 中得到数据块号 30 → **读数据块（1 块）** → 共 **2 块**
- 第 4 问：course1 增长到 6 MB，需要用哪几级间接地址？
  → 6 MB / 4 KB = **1536 块**。直接 10 块 + 一级间接 1024 块 = 1034 块 < 1536，还需要**二级间接**
  → 要用**一级和二级间接地址项**

### 📊 三种分配方式比较
| 方式 | 随机访问 | 外部碎片 | 文件扩展 | 额外空间 |
|---|---|---|---|---|
| 连续 | ✓ | 有 | 难 | 无 |
| 隐式链接 | ✗ | 无 | 易 | 每块一个指针 |
| 显式链接（FAT） | ✓（查内存中的 FAT） | 无 | 易 | FAT 表 |
| 索引 | ✓ | 无 | 易 | 索引块 |

## 10.6 文件存储空间管理（空闲空间管理）

### ① 空闲表法
像连续分配时的空闲分区表：记录每个空闲区的**起始块号 + 块数**。

### ② 空闲链表法
- 空闲**盘块**链：所有空闲块串成链
- 空闲**盘区**链：每个空闲区（连续多块）串成链

### ③ 位示图法（⭐ 计算）
🧒 用**一个二进制位**表示一个盘块：0 空闲，1 已分配（题目会说明是 0 还是 1 表示空闲）。所有位排成一个矩阵（每个字 n 位）。

**位置 ↔ 块号换算**（字号 i、位号 j、每字 n 位）：
- 从 **0** 开始编号：**块号 b = n × i + j**；反过来 i = b / n，j = b % n
- 从 **1** 开始编号：b = n × (i − 1) + j

**例**：每字 16 位，字号和位号都从 0 开始，第 3 个字的第 5 位对应的块号 = 16 × 3 + 5 = **53**。
**例**：磁盘 16 GB，块 4 KB，位示图要多大？→ 块数 = 2³⁴ / 2¹² = 2²² 个 → 位示图 2²² 位 = 2¹⁹ 字节 = **512 KB**

### ④ 成组链接法（UNIX）
把空闲块分组（比如 100 块一组），每组的第一块记录下一组的块号和数量，形成链。适合大文件系统。

## 10.7 文件系统的层次和虚拟文件系统

### 📖 文件系统层次（自上而下）
用户调用接口 → 文件目录系统 → 存取控制模块 → 逻辑文件系统与文件信息缓冲区 → 物理文件系统 → 设备管理

### 📖 虚拟文件系统（VFS）
🧒 电脑里可能同时有好几种文件系统：硬盘是 ext4，U 盘是 FAT32，还挂了网络文件系统 NFS。
**VFS 给上层提供一个统一的接口**（open、read、write……），用户程序不用关心下面是哪种文件系统。
**真题（2025 年第 28 题）**：正确的是 **C. VFS 定义了可访问不同文件系统的统一接口**。
- A ✗：VFS 不是“运行在虚拟内存的文件系统”
- B ✗：VFS 不能加快访问速度（多了一层，反而有一点开销）
- D ✗：VFS 也能访问网络文件系统

### 📖 文件系统挂载（mount）
把一个文件系统（比如 U 盘）“挂”到目录树的某个目录（**挂载点**）下，之后就能通过这个目录访问它。

## 10.8 磁盘

### 📖 磁盘结构和访问时间（复习）
见组成原理篇 5.6 节：**访问时间 = 寻道时间 + 旋转延迟（半圈）+ 传输时间**。

### 📖 磁盘的初始化
1. **低级格式化（物理格式化）**：把磁道**划分成扇区**（磁盘出厂时完成）
2. **分区**：把磁盘分成一个或多个分区，每个分区由若干柱面组成（分区表放在 MBR 里）
3. **逻辑格式化**：在分区上**创建文件系统**——建立根目录、空闲空间管理结构、**确定盘块大小**等

**真题（2025 年第 32 题）**：文件系统能为机械硬盘和固态硬盘都提供的功能是 **B. 确定盘块大小**。
- A 划分扇区：低级格式化做的，不是文件系统
- C 降低寻道时间：只对机械硬盘有意义，而且是磁盘调度做的
- D 实现均衡磨损：只对 SSD，由 SSD 内部的**闪存翻译层 FTL** 做的

### 📖 磁盘调度算法（⭐⭐ 必考计算）
目标：**减少寻道时间**（磁头移动的总距离）。
统一例子：磁头在 **100 号**磁道，向磁道号**增大**方向移动，请求队列 `55, 58, 39, 18, 90, 160, 150, 38, 184`。

**① 先来先服务 FCFS**：按请求顺序
100→55→58→39→18→90→160→150→38→184
移动距离 = 45+3+19+21+72+70+10+112+146 = **498**

**② 最短寻找时间优先 SSTF**：每次去**离当前最近**的
100→90→58→55→39→38→18→150→160→184
移动距离 = 10+32+3+16+1+20+132+10+24 = **248**
- 缺点：可能导致**饥饿**（远处的请求一直被近处的新请求插队）

**真题（2021 年第 26 题）**：磁头在 184，请求 184, 187, 176, 182, 199，SSTF 移动距离？
184(0) → 182(2) → 187(5) → 176(11) → 199(23)，总计 0+2+5+11+23 = **41**，选 C
（在 182 时，187 距离 5，176 距离 6，选 187；在 187 时，176 距离 11，199 距离 12，选 176。）

**③ 扫描 SCAN（电梯算法）**：像电梯一样，**沿一个方向一直走**，处理沿途的请求，走到头再掉头
- 严格的 SCAN 要走到**磁盘最边缘**（比如 199）才掉头
- **LOOK**：走到**最远的请求**就掉头（不走到边缘）
- 本例用 LOOK：100→150→160→184→90→58→55→39→38→18
  移动距离 = 84 + (184−18) = 84 + 166 = **250**
- 若用严格 SCAN（磁道 0~199）：100→…→184→**199**→90→…→18，距离 = 99 + (199−18) = **280**

**④ 循环扫描 C-SCAN**：**只在一个方向上**处理请求，到头后**直接返回起点**（返回途中不处理请求）
- 解决 SCAN 对两端磁道不公平的问题
- **C-LOOK**：走到最远的请求后，直接跳到**另一端最远的请求**
- 本例 C-LOOK：100→150→160→184→（跳到）18→38→39→55→58→90
  移动距离 = 84 + 166（返回）+ 72 = **322**（返回距离是否计入看题目说明）

> ⚠️ **做题前一定看清**：磁头当前在哪、往哪个方向走、是 SCAN 还是 LOOK、返回距离算不算。

### 📖 减少旋转延迟
- **交替编号**：逻辑上相邻的扇区在物理上**隔开**一些，给磁头处理数据的时间
- **错位命名**：相邻盘面的扇区编号错开

### 📖 固态硬盘 SSD
- 按**页**读写，按**块**擦除，写前要擦除
- **闪存翻译层（FTL）**：逻辑块号 → 物理页
- **磨损均衡**：动态磨损均衡（写新数据时选擦除次数少的块）；静态磨损均衡（把长期不变的“冷数据”搬到磨损多的块上）
- 随机访问快（没有寻道），适合随机读

# 第二部分：I/O 管理

## 10.9 I/O 设备和 I/O 软件层次

### 📖 设备分类
- **块设备**：以数据块为单位，可寻址（磁盘）→ 常用 DMA
- **字符设备**：以字符为单位，不可寻址（键盘、打印机）→ 常用中断
- **网络设备**

### 📖 I/O 软件层次结构（⭐⭐）
```
用户层 I/O 软件           ← 库函数（printf、scanf）、SPOOLing
     ↓（系统调用）
设备独立性软件（与设备无关）  ← 逻辑设备名映射、缓冲管理、设备分配、错误处理、权限检查
     ↓
设备驱动程序               ← 把抽象命令翻译成具体设备的命令；与设备硬件密切相关
     ↓
中断处理程序               ← 处理 I/O 完成的中断
     ↓
硬件（设备控制器、设备）
```
🧒 **判断某个功能在哪一层的技巧**：
- 和具体设备型号有关的（设置设备寄存器、检查设备状态）→ **驱动程序**
- 和具体设备无关的通用功能（缓冲、逻辑名到物理名的映射、分配设备）→ **设备独立性软件**

**真题（2022 年第 32 题）**：关于驱动程序，**不正确**的是 **A. 驱动程序与 I/O 控制方式无关**（驱动程序要根据设备用的是中断还是 DMA 来编写，**有关**）。
其他正确：设备初始化由驱动程序完成；进程执行驱动程序时可能阻塞（等设备）；读写设备的操作由驱动程序控制。

### 📖 设备独立性（⭐）
🧒 用户程序只说“我要打印”（**逻辑设备名**），不用管到底是哪台打印机（**物理设备名**）。系统通过**逻辑设备表（LUT）**把逻辑名映射到物理设备。
**好处**：换了打印机，程序不用改。

**真题（2020 年第 30 题）**：具备设备独立性的系统，**错误**的是 **D. 更换物理设备后必须修改访问该设备的应用程序**（正是因为有设备独立性，才**不用**改）。
其余正确：可以使用文件名访问物理设备（UNIX 把设备当文件）；用户程序用逻辑设备名；需要建立逻辑设备到物理设备的映射。

## 10.10 缓冲区管理（⭐ 计算）

### 🧒 大白话
CPU 很快，设备很慢。**缓冲区**就是中间的“**蓄水池**”：设备慢慢往池里灌水，CPU 一下子取走，大家都不用等对方。
- 缓解 CPU 和 I/O 设备**速度不匹配**
- 减少 CPU 的**中断频率**
- 提高 CPU 和 I/O 设备的**并行性**

### 📖 单缓冲 vs 双缓冲（⭐ 计算时间）
设：
- **T**：设备把一块数据输入到**缓冲区**的时间
- **M**：把数据从缓冲区**传送到用户区**的时间
- **C**：CPU **处理**一块数据的时间

**单缓冲**：每块数据的处理时间 = **max(C, T) + M**
🧒 缓冲区只有一个：必须等缓冲区的数据被搬走（M）后，设备才能往里写下一块；而 CPU 处理（C）和设备写缓冲区（T）可以同时进行。

**双缓冲**：每块数据的处理时间 = **max(C + M, T)**
🧒 有两个缓冲区，设备往一个里写的同时，另一个可以往用户区搬并处理。

**例**：T = 100，M = 50，C = 50
- 单缓冲：max(50, 100) + 50 = **150**
- 双缓冲：max(50 + 50, 100) = **100**

**其他**：循环缓冲（多个缓冲区连成环）、**缓冲池**（多个缓冲区公用，分成空缓冲队列、输入队列、输出队列）

## 10.11 设备分配与 SPOOLing

### 📖 设备分配的数据结构
- **系统设备表 SDT**（整个系统一张）
- **设备控制表 DCT**（每个设备一张）
- **控制器控制表 COCT**、**通道控制表 CHCT**
分配顺序：设备 → 控制器 → 通道

### 📖 独占设备、共享设备、虚拟设备
- **独占设备**：一次只能给一个进程用（打印机）
- **共享设备**：可以多个进程交替使用（磁盘）
- **虚拟设备**：用 SPOOLing 技术把独占设备变成“逻辑上的共享设备”

### 📖 SPOOLing 技术（假脱机，⭐）
🧒 **大白话**：全班只有一台打印机。每个同学都**先把要打印的文件交给班长**（存到磁盘上的“输出井”），班长再**按顺序一个个送去打印**。每个同学交完就能走，感觉像**自己独占了一台打印机**。

组成：
- **输入井和输出井**（在**磁盘**上）
- **输入缓冲区和输出缓冲区**（在**内存**中）
- **输入进程和输出进程**
- 井管理程序

特点：
- 把**独占设备**改造成**共享设备**（虚拟设备）
- 提高了 I/O 速度，实现**虚拟设备**功能
- 需要**磁盘**作为高速外存支持，需要**多道程序**支持
- 破坏了死锁的“互斥”条件

## 10.13 课后练习

1. 盘块 1 KB，地址项 4 B，inode 有 8 个直接地址、1 个一级间接、1 个二级间接，最大文件多大？
2. 位示图每字 32 位，从 0 编号，块号 100 对应第几个字、第几位？
3. 磁头在 50，向磁道号减小方向移动，请求 20, 44, 40, 4, 80, 12, 76，用 LOOK 算法，移动总距离？
4. 为什么目录项中只存文件名和索引结点号能加快目录检索？

<details>
<summary>答案</summary>

1. N = 1024 / 4 = 256；(8 + 256 + 256²) × 1 KB = (8 + 256 + 65536) KB = 65800 KB ≈ 64.26 MB
2. 100 / 32 = 3（第 3 个字），100 % 32 = 4（第 4 位）
3. 50→44→40→20→12→4 = 46；再掉头 4→76→80 = 76；共 **122**
4. 目录项变小，一个盘块能放下更多目录项，检索目录时读入的盘块数减少，I/O 次数少
</details>
