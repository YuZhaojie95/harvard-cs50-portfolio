# 第一部分：操作系统概述

## 8.1 操作系统是什么

### 🧒 大白话
电脑里同时有很多程序（微信、浏览器、音乐播放器）都想用 CPU、内存、硬盘。
如果没人管，它们会**打架**。**操作系统就是“大管家”**：
- 管**CPU**：安排谁先用、用多久（处理机管理）
- 管**内存**：给每个程序分地盘，不让它们互相踩（存储器管理）
- 管**文件**：帮你存东西、找东西（文件管理）
- 管**设备**：键盘、打印机、磁盘（设备管理）
- 给用户和程序提供**接口**（命令接口 + 程序接口 = 系统调用）

### 📖 四大特征（⭐）
1. **并发**：一段时间内多个程序**轮流**运行（宏观上同时，微观上交替）
   - ⚠️ 区分：**并行**是同一时刻真的同时运行（需要多个 CPU 核）
2. **共享**：资源给多个进程共同使用（**互斥共享**：打印机一次只能一个人用；**同时共享**：磁盘文件可以多人同时读）
3. **虚拟**：把一个物理实体变成多个逻辑实体（虚拟内存、分时让一个 CPU 像多个）
4. **异步**：进程走走停停，以不可预知的速度推进

**并发和共享是最基本的特征**，互为存在条件。

### 📖 发展历程
- **单道批处理**：一次只有一个程序在内存，CPU 等 I/O 时就闲着
- **多道批处理**：内存里放多个程序，一个等 I/O 时 CPU 切换到另一个 → 提高资源利用率，但**用户不能交互**
- **分时系统**：CPU 时间切成**时间片**，轮流给各用户 → 用户感觉独占电脑，**交互性好**
- **实时系统**：必须在规定时间内响应（导弹控制、工业控制）

**真题（2022 年第 23 题）**：关于多道程序系统，**不正确**的是 **D. 进程数越多 CPU 利用率越高**（进程太多，内存不够，会频繁换页“抖动”，利用率反而下降）。多道程序系统**不必**支持虚拟存储。

## 8.2 运行机制（⭐⭐）

### 📖 内核态和用户态
🧒 大白话：CPU 有两种“身份”：
- **内核态（管态、核心态）**：**管家身份**，什么指令都能执行
- **用户态（目态）**：**普通住户身份**，只能执行普通指令

**特权指令**（只能在内核态执行）：I/O 指令、**开/关中断**、修改页表基址寄存器、设置时钟、停机等
**非特权指令**：普通运算、访存等

**真题（2022 年第 27 题）**：正确的是 **C. CPU 处于用户态时只能执行非特权指令**。（内核态**既能**执行特权指令**也能**执行非特权指令。）
**真题（2021 年第 23 题）**：只能在内核态执行的是 **B. I/O 指令**。（trap 指令是用户态执行的——它正是用户态进入内核态的“门”！）

**用户态 → 内核态**：**唯一途径是中断/异常**（包括 trap 指令引起的系统调用）
**内核态 → 用户态**：执行一条**特权指令**修改 PSW（中断返回指令）

### 📖 系统调用（⭐）
🧒 用户程序想读文件、创建进程、申请内存……自己没权限，只能**请求管家帮忙**：这就是系统调用。
```
用户程序：准备参数（放寄存器）→ 执行 trap（陷入）指令
   ↓ 硬件：保存断点和 PSW，切换到内核态，按系统调用号找到入口
操作系统：保存通用寄存器 → 执行系统调用服务例程 → 恢复 → 返回
   ↓
用户程序：继续执行 trap 的下一条指令
```

**真题（2022 年第 31 题）**：执行系统调用时，由**操作系统**完成的是？
I. 保存断点和程序状态字（**硬件**）；II. 保存通用寄存器（**OS**）；III. 执行系统调用服务例程（**OS**）；IV. 将 CPU 模式改为内核态（**硬件**，trap 指令自动完成）→ 选 **B（II、III）**

**真题（2020 年第 25 题）**：与中断相关的操作中由 OS 完成的是？
I. 保存被中断程序的中断点（硬件）；II. 提供中断服务（OS）；III. 初始化中断向量表（OS）；IV. 保存中断屏蔽字（OS）→ 选 **D（II、III、IV）**

**真题（2021 年第 32 题）**：通过系统调用完成的是 **C. 创建新进程**。（页置换、进程调度是 OS 内部自己做的，不是用户请求的；生成随机数是普通库函数。）

**真题（2022 年第 24 题）**：需要在操作系统**初始化过程中**创建的是 **A. 中断向量表**。（根目录、硬盘分区表、索引结点表是在磁盘**格式化/分区**时就建好的。）

### 📖 操作系统结构
- **分层结构**：一层只调用下一层，易调试，但效率低
- **模块化**：功能分成模块，模块之间可以互相调用
- **宏内核（大内核）**：主要功能都在内核里 → **性能好**（Linux、Windows）
- **微内核**：内核只保留最基本的功能（进程/线程管理、低级存储管理、中断、IPC），其他功能放在用户态服务器进程里 → **可靠、易扩展**，但频繁切换**性能差**
- **外核**：内核只负责分配硬件资源，由应用自己管理

### 📖 操作系统引导（开机过程）
1. 按下电源 → CPU 执行 **ROM 中的 BIOS**（或 UEFI）程序
2. BIOS **自检**硬件
3. 读取磁盘第一个扇区 **MBR（主引导记录）**，含分区表和引导程序
4. 找到**活动分区**，执行它的**引导程序（bootloader）**
5. bootloader 把**操作系统内核**装进内存，内核开始初始化（建立中断向量表等）

### 📖 虚拟机（2025 年考过）
- **虚拟机管理程序（VMM / Hypervisor）**：把一台物理机虚拟成多台虚拟机，每台都能装自己的 OS
- **第一类 VMM**：直接运行在硬件上（裸机），**运行在最高特权级**
- **第二类 VMM**：运行在宿主 OS 之上（像 VMware Workstation、VirtualBox）

**真题（2025 年第 24 题）**：关于虚拟机技术，**错误**的是 **C. VMM 与操作系统特权级相同**（VMM 的特权级**高于**客户操作系统，客户 OS 以为自己在内核态，其实被 VMM 管着）。
其余正确：操作系统可以在虚拟机上运行；一台主机可支持多个虚拟机；可以在一台主机上模拟多种 ISA。

# 第二部分：进程与线程

## 8.3 进程（⭐⭐⭐）

### 🧒 大白话
- **程序** = 一本**菜谱**（静态的，放在硬盘上的文件）
- **进程** = **正在按菜谱做菜的过程**（动态的，有自己的锅碗瓢盆、做到了第几步）

同一本菜谱（程序），两个厨师同时照着做 → 两个进程。

### 📖 进程的组成
- **PCB（进程控制块）**：进程的“**身份证 + 档案**”，是**进程存在的唯一标志**
  - 进程 ID（PID）、状态、优先级
  - 各寄存器的值（PC、通用寄存器、PSW……）——切换时保存/恢复用
  - 内存管理信息（页表基址等）、打开的文件列表、资源清单
- **程序段**（代码）
- **数据段**（全局变量、堆、栈……）

**真题（2025 年第 46 题第 1 问）**：进程运行时 **PCB 位于内核区**（PCB 由操作系统管理，放在内核空间，用户程序不能直接访问）。

### 📖 进程的五种状态（⭐⭐）
```
          创建
           │
           ▼   ←─────── 时间片用完 / 被抢占 ──────┐
         就绪 ──────── 被调度（分到 CPU）────→ 运行 ──→ 终止
           ▲                                       │
           │                                       │ 请求 I/O / 等待事件
           └──────── 事件发生（I/O 完成）──── 阻塞 ←┘
```
🧒 比喻：去银行办业务
- **就绪**：拿了号，在大厅**等着叫号**（万事俱备，只差柜台）
- **运行**：**正在柜台办理**
- **阻塞（等待）**：柜员说“你缺一份材料，回去拿了再来”（等某件事，就算有空柜台也办不了）

**关键规则（⭐ 选择题）**：
- 就绪 → 运行：**只能由调度**引起
- 运行 → 阻塞：进程**自己**主动（请求 I/O、执行 wait 操作等）
- 阻塞 → 就绪：**被动**，由别人唤醒（I/O 完成中断、别人执行 signal）
- **阻塞 → 运行 不可能直接发生**；**就绪 → 阻塞 不可能**

**真题（2022 年第 28 题）**：可能使进程 P 由运行态变为阻塞态的是？
I. 读文件 ✓（要等磁盘）；II. 时间片用完 ✗（变为**就绪**）；III. 申请外设 ✓（可能要等）；IV. 执行 wait() ✓（信号量不够就阻塞）→ 选 **D（I、III、IV）**

**真题（2025 年第 46 题第 1 问）**：执行 scanf() 等待键盘输入时，进程处于**阻塞态**。

### 📖 进程控制
**创建进程**（2021 年第 24 题）：
1. 分配 PID，**申请空白 PCB** ✓
2. 分配资源（内存等）
3. **初始化 PCB** ✓
4. 把 PCB 插入**就绪队列**（状态设为**就绪**，而不是执行态！）
→ 必须完成的是 I、II，选 B

**fork()**：UNIX 创建子进程。子进程复制父进程的地址空间（现代系统用“写时复制”），**父子进程有各自独立的 PCB 和虚拟地址空间**，并发执行。

**真题（2020 年第 29 题）**：关于父子进程，**错误**的是 **B. 父进程与子进程共享虚拟地址空间**（它们各有各的地址空间，这正是它们和线程的区别）。
其余正确：父子可以并发执行；有不同的 PCB；不能同时使用同一临界资源（互斥）。

**进程切换（上下文切换）**：保存当前进程的上下文（PC、寄存器、PSW、**页表基址寄存器**……）到 PCB → 更新 PCB 状态、移到相应队列 → 选另一个进程 → 从它的 PCB 恢复上下文。
**真题（2025 年第 23 题）**：上下文切换时**不需要**更新的是 **D. 内核中断向量表基址寄存器**（中断向量表是全系统共用的，和哪个进程无关）。通用寄存器、页表基址寄存器、程序计数器都要换。

### 📖 进程通信（IPC）
- **共享存储**：划一块两个进程都能访问的内存（需要自己用 PV 做同步互斥）
- **消息传递**：发消息、收消息（send/receive）
  - 直接通信：直接发给对方
  - 间接通信：发到**信箱**里
- **管道**：一个进程写、另一个读的“水管”，本质是一个**共享文件**（pipe 文件）
  - 数据**先进先出**，读完就没了
  - 普通管道是**半双工**的（一个方向），要双向通信需要两根管道

## 8.4 线程

### 🧒 大白话
进程 = 一个**餐厅**（有厨房、食材、桌椅这些资源）
线程 = 餐厅里的**厨师**。一个餐厅可以有好几个厨师**共用厨房和食材**，同时做不同的菜。

- 引入线程的目的：**减小程序并发执行时的时空开销**（创建、切换线程比进程便宜得多）
- **进程是资源分配的基本单位**；**线程是 CPU 调度的基本单位**
- 同一进程的线程**共享**：进程的地址空间（代码、全局变量、堆）、打开的文件
- 每个线程**独有**：线程 ID、**寄存器（含 PC）**、**栈**、线程控制块 TCB

### 📖 用户级线程 vs 内核级线程
| | 用户级线程（ULT） | 内核级线程（KLT） |
|---|---|---|
| 谁管理 | 用户空间的线程库 | 操作系统内核 |
| 内核知道吗 | **不知道**（内核只看到进程） | 知道 |
| 切换 | 不用进内核，**快** | 要进内核，慢 |
| 一个线程阻塞 | **整个进程都被阻塞** | 其他线程照常运行 |
| 多核并行 | **不能** | 能 |

**多线程模型**：多对一（多个 ULT 映射到一个 KLT）、一对一、多对多。

# 第三部分：处理机调度

## 8.5 调度的基本概念

### 📖 三级调度
| 层次 | 做什么 | 频率 |
|---|---|---|
| **高级调度（作业调度）** | 从外存的后备作业中挑一个，调入内存，创建进程 | 最低 |
| **中级调度（内存调度）** | 把暂时不能运行的进程**换出**到外存（挂起），合适时再换入 | 中 |
| **低级调度（进程调度）** | 从就绪队列选一个进程分配 CPU | **最高** |

### 📖 什么时候调度？
**会引起调度**（2021 年第 27 题，全选 D）：
- 进程**运行结束**
- 进程**阻塞**（请求 I/O、wait）
- **时间片用完**
- **中断处理结束**后（可能唤醒了更高优先级的进程，要抢占）
- 有更高优先级的进程进入就绪队列（抢占式）

**不能进行调度**的时候：
- 正在**处理中断**的过程中
- 进程在操作系统**内核的临界区**中
- 其他需要完全屏蔽中断的原子操作过程中

**真题（2021 年第 25 题）**：分时系统实现时间片轮转需要用到？I. 进程控制块 ✓（保存上下文）；II. 时钟中断处理程序 ✓（判断时间片到了没）；III. 就绪队列 ✓（从中选下一个）；IV. 阻塞队列 ✗ → 选 C

### 📖 调度方式
- **非抢占式**：进程一旦拿到 CPU，就一直运行到结束或阻塞，别人不能抢
- **抢占式**：更重要的进程来了可以把 CPU 抢走（分时、实时系统必须用）

### 📖 评价指标（⭐ 计算）
| 指标 | 公式 |
|---|---|
| **周转时间** | 完成时间 − 到达时间 |
| **带权周转时间** | 周转时间 / 实际运行时间（≥ 1，越接近 1 越好） |
| **等待时间** | 周转时间 − 运行时间（在就绪队列里等的时间总和） |
| **响应时间** | 从提交请求到**首次**产生响应的时间 |
| CPU 利用率 | CPU 忙的时间 / 总时间 |
| 吞吐量 | 单位时间内完成的作业数 |

## 8.6 调度算法（⭐⭐⭐）

### ① 先来先服务（FCFS）
🧒 **排队买奶茶**，谁先来谁先买。
- 非抢占；**对长作业有利，对短作业不利**（短作业排在长作业后面要等很久）
- 有利于 CPU 繁忙型作业

### ② 短作业优先（SJF / SPF）
🧒 **要得少的先办**：只买一瓶水的人先结账。
- **平均等待时间、平均周转时间最少**
- 缺点：**长作业可能“饥饿”**（一直有短作业插队）；需要预估运行时间
- 抢占式版本叫**最短剩余时间优先（SRTN）**

### ③ 高响应比优先（HRRN）
**响应比 = (等待时间 + 要求服务时间) / 要求服务时间 = 1 + 等待时间 / 服务时间**
- 每次选**响应比最高**的
- 🧒 等得越久，响应比越高 → **长作业等久了也能轮到**，不会饥饿；短作业的响应比天然较高 → 兼顾了 FCFS 和 SJF

### ④ 优先级调度
按优先级选。分抢占式和非抢占式；静态优先级和动态优先级。
- 低优先级可能饥饿 → 解决：**老化**（等得越久优先级越高）

**真题（2022 年第 25 题）**：基于优先权的**抢占式**调度（值越小优先级越高），从 0 ms 开始到所有进程结束，共发生几次调度？
| 进程 | 到达 | 优先级 | 运行时间 |
|---|---|---|---|
| P0 | 0 | 15 | 100 |
| P1 | 10 | 20 | 60 |
| P2 | 10 | 10 | 20 |
| P3 | 15 | 6 | 10 |

```
t=0   只有 P0 → 调度 P0                             (第 1 次)
t=10  P1(20)、P2(10) 到达，P2 比 P0(15) 高 → 抢占，调度 P2   (第 2 次)
t=15  P3(6) 到达，比 P2 高 → 抢占，调度 P3                (第 3 次)
t=25  P3 完成 → 就绪的 P0(15)、P1(20)、P2(10) 中选 P2     (第 4 次)
t=40  P2 完成（还剩 15ms，已跑完）→ 选 P0                 (第 5 次)
t=130 P0 完成（还剩 90ms）→ 选 P1                        (第 6 次)
t=190 P1 完成
```
共 **6 次**，选 C。

### ⑤ 时间片轮转（RR）
🧒 大家**轮流**玩一个玩具，每人玩 5 分钟，时间到了就排到队尾。
- 适用于**分时系统**，抢占式
- 时间片**太大** → 退化成 FCFS；**太小** → 切换太频繁，开销大
- 新到达的进程和时间片用完的进程同时到队尾时，一般**新到达的排在前面**（题目会说明）

### ⑥ 多级反馈队列（⭐ 综合最好）
🧒 设置多个队列，优先级从高到低，**优先级越高时间片越短**：
1. 新进程先进**第 1 级队列**（最高优先级，时间片最短）
2. 时间片用完还没运行完 → **降级**到下一级队列的末尾
3. 只有高级队列**空了**，才调度低级队列
4. 低级队列的进程运行时，高级队列来了新进程 → **抢占**
- 短作业很快在高级队列里完成；长作业慢慢沉到底部；兼顾了各种需求

**真题（2020 年第 26 题）**：设计多级反馈队列需要考虑：就绪队列的**数量**、各队列的**优先级**、各队列的**调度算法**、进程在队列间的**迁移条件** → **全部**，选 D。

### ✏️ 综合例题
4 个作业，求 FCFS 和 SJF（非抢占）的平均周转时间：
| 作业 | 到达 | 运行 |
|---|---|---|
| J1 | 0 | 8 |
| J2 | 1 | 4 |
| J3 | 2 | 9 |
| J4 | 3 | 5 |

**FCFS**：J1(0~8) → J2(8~12) → J3(12~21) → J4(21~26)
周转：8, 11, 19, 23 → 平均 61/4 = **15.25**

**SJF**：t=0 只有 J1 → J1(0~8)；t=8 时 J2(4)、J3(9)、J4(5) 都到了，选最短 J2(8~12)；再 J4(12~17)；再 J3(17~26)
周转：J1=8, J2=11, J4=14, J3=24 → 平均 57/4 = **14.25**

# 第四部分：同步与互斥（⭐⭐⭐ 第 45 题核心）

## 8.7 基本概念

### 🧒 大白话
- **临界资源**：一次只能给一个进程用的资源（打印机、共享变量）
- **临界区**：进程中**访问临界资源的那段代码**
- **互斥**：你用的时候我不能用（抢**厕所**：一个人进去就锁门）
- **同步**：有先后顺序的协作（**先做饭，后吃饭**：吃饭的人要等做饭的人做好）

### 📖 临界区访问四原则（⭐）
1. **空闲让进**：临界区没人，想进的就让进
2. **忙则等待**：有人在里面，其他人要等
3. **有限等待**：等待的时间是有限的，不会饿死
4. **让权等待**：进不去的时候**立即释放 CPU**，不要占着 CPU 空转（忙等）

前三条是**必须遵守**的，第四条是“**最好**”遵守（很多实现如自旋锁不满足）。
**真题（2020 年第 32 题）**：必须遵循的是 I（互斥）、II（空闲让进）、III（有限等待）→ 选 C。IV（让权等待）不是必须。

## 8.8 实现互斥的方法

### 📖 软件方法（了解思想）
- 单标志法：轮流进，违背“空闲让进”
- 双标志先检查：可能同时进，违背“忙则等待”
- 双标志后检查：可能都进不去，违背“空闲让进”和“有限等待”（会饥饿/死锁）
- **Peterson 算法**：用 flag + turn，“**我想进，但我先让你**”，满足前三条，不满足让权等待

### 📖 硬件方法
- **关中断**：进入临界区前关中断，出来后开中断。简单，但**只适用于单处理机**，而且关中断是**特权指令，用户程序不能用**
- **TestAndSet（TSL）指令**、**Swap 指令**：硬件保证“读出并设置”是一个不可打断的原子操作。适合多处理机，但不满足让权等待（忙等）

**真题（2021 年第 45 题，7 分）**：整型信号量的 wait/signal 用开关中断实现互斥：
```
方法 1:                       方法 2:
wait(S) {                     wait(S) {
  关中断;                        关中断;
  while (S <= 0);                while (S <= 0) {
  S = S - 1;                        开中断;
  开中断;                           关中断;
}                                 }
                                 S = S - 1;
                                 开中断;
                              }
```
1. **为什么对 S 的访问必须互斥？** → S 是多个进程共享的变量，wait/signal 里“读 S、改 S”不是一步完成的；如果并发执行，可能两个进程都读到 S = 1，都减 1，导致错误。所以必须作为原子操作互斥执行。
2. **方法 1 错误**：关中断后如果 S ≤ 0，进程在 while 里**死循环**，而中断被关了，**时钟中断无法发生，别的进程永远得不到 CPU 去执行 signal 让 S 变大** → 系统卡死。
   **方法 2 正确**：在循环里开一下中断，给别的进程执行 signal 的机会。
3. **用户程序能否用开/关中断指令实现临界区互斥？** → **不能**。开/关中断是**特权指令**，只能在内核态执行。

## 8.9 信号量（⭐⭐⭐）

### 🧒 大白话
信号量就是一个**计数器 + 一个等待队列**，像**停车场门口的空位显示牌**：
- 显示牌 S = 当前空位数
- **P 操作（wait）**：“我要停车”→ 空位数 −1；如果减完 < 0，说明没空位，**我在门口排队（阻塞）**
- **V 操作（signal）**：“我开走了”→ 空位数 +1；如果加完 ≤ 0，说明有人在排队，**叫醒一个**

### 📖 记录型信号量（考试默认用这个）
```c
typedef struct {
    int value;            // 资源数
    struct process *L;    // 等待队列
} semaphore;

void wait(semaphore S) {       // P 操作
    S.value--;
    if (S.value < 0) {
        把当前进程加入 S.L;
        block();               // 阻塞自己（让权等待！）
    }
}
void signal(semaphore S) {     // V 操作
    S.value++;
    if (S.value <= 0) {
        从 S.L 中取出一个进程 P;
        wakeup(P);             // 唤醒它
    }
}
```
- **S.value > 0**：还有 value 个资源可用
- **S.value < 0**：有 |value| 个进程在排队等待
- 整型信号量用 `while (S <= 0);` 忙等，不满足让权等待；记录型信号量满足

### 📖 信号量的三种用法（⭐ 解题基础）
**① 实现互斥**：mutex 初值 **1**，临界区前 P，后 V
```c
semaphore mutex = 1;
P(mutex);
临界区;
V(mutex);
```

**② 实现同步（前驱关系）**：S 初值 **0**，“**前 V 后 P**”
🧒 要求 A 做完 B 才能做：A 做完后 V(S) 发个“通知”；B 做之前 P(S) 等通知。
```c
semaphore S = 0;
进程1: A; V(S);
进程2: P(S); B;
```

**③ 管理资源数量**：S 初值 = **资源个数 n**

**真题（2020 年第 45 题）**：A、B 完成后才能执行 C；C、D 完成后才能执行 E。用 PV 描述。
```c
semaphore SAC = 0, SBC = 0, SCE = 0, SDE = 0;  // 每条前驱关系一个信号量
A() { 执行 A; V(SAC); }
B() { 执行 B; V(SBC); }
C() { P(SAC); P(SBC); 执行 C; V(SCE); }
D() { 执行 D; V(SDE); }
E() { P(SCE); P(SDE); 执行 E; }
```

**真题（2022 年第 46 题）**：线程 T1 执行 A、E、F，T2 执行 B、C、D。约束：C 在 A 和 B 之后；D 和 E 在 C 之后；F 在 E 之后。
🧒 **只有跨线程的前驱关系才需要信号量**（同一线程内本来就按顺序执行）：
- A → C（T1 → T2）：需要 SAC
- C → E（T2 → T1）：需要 SCE
- B → C、C → D 都在 T2 内；E → F 在 T1 内，不需要
```c
semaphore SAC = 0, SCE = 0;
T1() { A; V(SAC); P(SCE); E; F; }
T2() { B; P(SAC); C; V(SCE); D; }
```

## 8.10 经典 PV 问题（⭐⭐⭐ 一定要会默写）

### 🎯 PV 题万能解题步骤
1. **找进程**：有哪几类进程？每类在干什么？（写成 while 循环）
2. **找关系**：
   - **互斥**：谁和谁不能同时做？（共享的缓冲区、共享的工具）→ mutex = 1
   - **同步**：谁必须等谁？（“前 V 后 P”）→ 初值通常 0
   - **资源数**：有几个空位/几件东西？→ 初值 = 数量
3. **设信号量**，写清楚**含义和初值**（写不清楚扣分！）
4. **写代码**，然后检查：
   - **互斥的 P 要放在同步的 P 后面**（否则可能死锁！见生产者消费者）
   - 每个 P 都有对应的 V

### ① 生产者–消费者（⭐ 最重要）
🧒 **面包店**：面包师（生产者）做面包放到货架上，顾客（消费者）从货架拿面包。货架有 n 个位置。
- 货架满了，面包师要等（同步）
- 货架空了，顾客要等（同步）
- 同一时刻只能一个人碰货架（互斥）

```c
semaphore mutex = 1;   // 互斥访问货架
semaphore empty = n;   // 空位数
semaphore full = 0;    // 面包数

producer() {
    while (1) {
        生产一个面包;
        P(empty);        // 先要一个空位
        P(mutex);        // 再锁住货架
        把面包放上货架;
        V(mutex);
        V(full);         // 面包数 +1，通知顾客
    }
}
consumer() {
    while (1) {
        P(full);         // 先要一个面包
        P(mutex);
        从货架拿面包;
        V(mutex);
        V(empty);        // 空位 +1，通知面包师
        吃面包;
    }
}
```
⚠️ **为什么 P(empty) 必须在 P(mutex) 前面？**
如果反过来：货架满了，面包师先锁住货架（P(mutex) 成功），再 P(empty) 阻塞 → 顾客想拿面包，P(mutex) 被锁 → 也阻塞 → **死锁**！
**口诀：先同步，后互斥**（先确认有资源，再上锁）。V 的顺序无所谓。

### ② 多生产者–多消费者（水果盘问题）
盘子里只能放一个水果。爸爸放苹果，妈妈放橘子；儿子只吃橘子，女儿只吃苹果。
```c
semaphore plate = 1;   // 盘子空位
semaphore apple = 0, orange = 0;
dad()      { while(1) { 准备苹果; P(plate); 放苹果; V(apple); } }
mom()      { while(1) { 准备橘子; P(plate); 放橘子; V(orange); } }
daughter() { while(1) { P(apple); 拿苹果; V(plate); 吃; } }
son()      { while(1) { P(orange); 拿橘子; V(plate); 吃; } }
```
（盘子容量为 1 时，plate 本身就保证了互斥，可以不要 mutex；容量 > 1 时要加 mutex。）

### ③ 读者–写者（⭐）
- 多个读者可以**同时读**
- 写者必须**独占**（写的时候谁都不能读或写）

**读者优先版**：
```c
int count = 0;           // 正在读的人数
semaphore mutex = 1;     // 保护 count
semaphore rw = 1;        // 读写互斥

writer() {
    while (1) {
        P(rw);
        写;
        V(rw);
    }
}
reader() {
    while (1) {
        P(mutex);
        if (count == 0) P(rw);   // 第一个读者负责“占住”，挡住写者
        count++;
        V(mutex);
        读;
        P(mutex);
        count--;
        if (count == 0) V(rw);   // 最后一个读者负责“放行”写者
        V(mutex);
    }
}
```
🧒 **关键套路**：“**第一个进来的开门，最后一个走的关门**”——用计数器 + mutex 实现一类进程的“同时共享”。
缺点：读者源源不断时，写者会饿死。**写者优先**：再加一个信号量 w = 1，写者来了先 P(w) 挡住后来的读者。

### ④ 哲学家进餐
5 个哲学家围坐圆桌，每两人之间一根筷子，要拿到左右两根才能吃饭。
- 如果每个人都先拿左边筷子 → 所有人都拿着左筷等右筷 → **死锁**
- 解决：
  1. 最多允许 4 个人同时拿筷子
  2. **奇数号先拿左边，偶数号先拿右边**
  3. 用 mutex 保证“拿左右两根筷子”是一个原子动作

### ⑤ 吸烟者问题（一个生产者轮流生产多种产品）
供应者轮流放两种材料，三个吸烟者各缺不同材料。思路：每种“组合”一个同步信号量，吸烟者抽完 V(finish) 通知供应者。

### ✏️ 真题：2025 年第 45 题（植树，8 分）
> 甲挖坑，乙放树苗并填土，丙浇水。步骤依次：挖坑 → 放树苗 → 填土 → 浇水。有**铁锹和水桶各一个**，铁锹用于挖坑和填土，水桶用于浇水。**树坑数量小于 3 时甲才可以挖坑**。设初始坑 = 0，定义尽可能少的信号量。

**分析：**
1. **进程**：甲、乙、丙
2. **关系**：
   - 铁锹：甲（挖）和乙（填）**互斥** → shovel = 1
   - 水桶：只有丙用，**不需要**信号量（题目要“尽可能少”）
   - 挖好坑后乙才能放苗：同步 → pit = 0（已挖好、等待种树的坑数）
   - 填好土后丙才能浇水：同步 → filled = 0
   - 坑数 < 3 才能挖：资源数 → empty = 3（还允许挖的坑数）
3. **代码：**
```c
semaphore shovel = 1;   // 铁锹，互斥
semaphore empty  = 3;   // 还能挖的坑数（保证坑数 < 3 才挖）
semaphore pit    = 0;   // 已挖好、等待放树苗的坑数
semaphore filled = 0;   // 已填土、等待浇水的树数

甲() {
    while (1) {
        P(empty);          // 坑不能太多
        P(shovel);
        挖坑;
        V(shovel);
        V(pit);            // 通知乙：有坑了
    }
}
乙() {
    while (1) {
        P(pit);            // 等坑
        放树苗;
        P(shovel);
        填土;
        V(shovel);
        V(empty);          // 坑被填了，坑数减少，甲可以再挖
        V(filled);         // 通知丙：可以浇水了
    }
}
丙() {
    while (1) {
        P(filled);
        浇水;              // 水桶只有丙用，无需互斥
    }
}
```
检查死锁：乙拿着“坑”去等铁锹，甲只在挖坑的一瞬间拿着铁锹，挖完就放 → 不会互相卡死 ✓

## 8.11 管程

### 🧒 大白话
PV 操作分散在各个进程里，写错一个就出大 bug。**管程**把共享数据和对它的操作**打包成一个“房间”**：
- **同一时刻只允许一个进程进入管程**（互斥由编译器自动保证）
- 管程里用**条件变量**实现同步：`x.wait()`（在 x 上排队，并**释放管程**）、`x.signal()`（唤醒一个在 x 上排队的进程；**如果没人排队，什么都不发生**）

⚠️ 条件变量**没有值**，和信号量不同：信号量的 V 操作一定会让 value+1，“被记住”；条件变量的 signal 如果没人等就**白发了**。

# 第五部分：死锁

## 8.12 死锁的概念

### 🧒 大白话
两辆车在单行道上**迎面相遇**，谁都不肯倒车，就永远卡在那里。
**死锁**：多个进程**互相等待对方手里的资源**，谁都无法往前推进。

### 📖 四个必要条件（⭐⭐ 必背，缺一不可）
1. **互斥**：资源一次只能被一个进程用
2. **不剥夺**：资源不能被强行抢走，只能自己释放
3. **请求并保持**：拿着一些资源，又去申请新的
4. **循环等待**：存在一个进程资源的**等待环**（P1 等 P2，P2 等 P3，…，Pn 等 P1）

> ⚠️ 有循环等待**不一定**死锁（如果某类资源有多个，环外的进程释放后可能打破）；但死锁**一定**有循环等待。

### 📖 资源数计算（⭐ 公式）
n 个进程，每个最多需要 k 个同类资源，**保证不死锁**的最少资源数 = **n × (k − 1) + 1**
🧒 最坏情况：每人都拿到 k−1 个，都差一个。这时只要再多 1 个，就有人能完成并释放资源。

**真题（2021 年第 31 题）**：n 个进程，每个需要 2 个临界资源，不死锁最少需要 n × 1 + 1 = **n + 1**，选 C。

## 8.13 死锁的处理

| 策略 | 做法 | 特点 |
|---|---|---|
| **预防** | **破坏四个必要条件之一** | 限制严格，资源利用率低 |
| **避免** | 分配前**判断会不会进入不安全状态**（银行家算法） | 需要提前知道最大需求 |
| **检测与解除** | 允许发生，定期检测，发现后解除 | 最灵活 |

### 📖 预防：破坏哪个条件？
- 破坏**互斥**：把资源改成可共享（SPOOLing 技术把打印机变成“共享”）——很多资源做不到
- 破坏**不剥夺**：申请不到就释放已有的 → 实现复杂，可能反复申请释放
- 破坏**请求并保持**：**一次性申请所有资源**（静态分配）→ 资源浪费、可能饥饿
- 破坏**循环等待**：**顺序资源分配法**，给资源编号，**只能按编号递增顺序申请** → 不会形成环

### 📖 避免：银行家算法（⭐⭐⭐）

🧒 **大白话**：你是银行家，有一笔钱。几个客户各自有“最大贷款额度”，已经借走一部分。有人又来借钱时，你要想：**如果借给他，我还能不能保证所有人最终都能拿到他们需要的钱、做完生意还钱？**能就借（**安全状态**），不能就先不借。

**几个矩阵：**
- **Max**：每个进程最多需要多少
- **Allocation**：已分配多少
- **Need = Max − Allocation**：还需要多少
- **Available**：系统还剩多少

**安全性检查步骤**：
1. Work = Available
2. 找一个 **Need ≤ Work** 的进程（它能“做完”）
3. 假设它做完了，把它的资源还回来：**Work = Work + Allocation**
4. 重复 2、3。如果所有进程都能做完 → **安全**，找到的顺序就是**安全序列**

**真题（2020 年第 27 题）**：A、B 两类资源各 6 个：
| 进程 | A 已分配 | B 已分配 | A 需求总量 | B 需求总量 |
|---|---|---|---|---|
| P1 | 2 | 3 | 4 | 4 |
| P2 | 2 | 1 | 3 | 1 |
| P3 | 1 | 2 | 3 | 4 |

1. **Need**：P1 = (2, 1)，P2 = (1, 0)，P3 = (2, 2)
2. **Available** = (6 − 5, 6 − 6) = **(1, 0)**
3. 找 Need ≤ (1, 0)：只有 **P2** (1, 0) → P2 做完，Work = (1,0) + (2,1) = **(3, 1)**
4. 找 Need ≤ (3, 1)：**P1** (2, 1) ✓ → Work = (3,1) + (2,3) = **(5, 4)**
5. **P3** (2, 2) ≤ (5, 4) ✓ → 完成
6. 安全序列 **P2, P1, P3**，选 B

**真题（2022 年第 26 题）**：安全序列有几个？
| 进程 | 已分配 A B C | 尚需 A B C |
|---|---|---|
| P0 | 2 0 1 | 0 2 1 |
| P1 | 0 2 0 | 1 2 3 |
| P2 | 1 0 1 | 0 1 3 |
可用 = (1, 3, 2)
- 第一步：P0 (0,2,1) ≤ (1,3,2) ✓；P1 需 C=3 > 2 ✗；P2 需 C=3 > 2 ✗ → **只能先 P0**，Work = (3, 3, 3)
- 之后 P1 (1,2,3) 和 P2 (0,1,3) 都 ≤ (3,3,3)，而且谁先谁后都行
- 安全序列：P0 P1 P2、P0 P2 P1，共 **2 个**，选 B

> ⚠️ **不安全状态 ≠ 死锁**。不安全只是“有可能”死锁；但系统处于安全状态就一定不会死锁。

### 📖 检测：资源分配图化简
- 画资源分配图：进程 → 资源（请求边），资源 → 进程（分配边）
- **化简**：找一个请求都能满足的进程，把它的所有边删掉（假装它完成并释放资源），重复
- 如果能删光所有边 → **可完全简化** → 没有死锁；否则有死锁（**死锁定理**）

### 📖 解除
- **资源剥夺**：抢走某些死锁进程的资源
- **撤销进程**：终止部分或全部死锁进程
- **进程回退**：让进程回退到不会死锁的状态

### 📖 死锁 vs 饥饿
- **死锁**：至少 2 个进程互相等，都处于**阻塞态**
- **饥饿**：某个进程一直得不到资源（可能只有 1 个进程饥饿），可能在**就绪态**（长期得不到 CPU）

## 8.15 课后练习

2. 写出“桌上有一个空盘，最多放 2 个水果，爸爸只放苹果，儿子只吃苹果”的 PV 代码。
3. 进程 P1、P2、P3 到达时间 0、1、2，运行时间 5、3、1，用 RR（时间片 2）求完成顺序。（同时到达队尾时新进程在前）

<details>
<summary>答案</summary>

1. 3 × 3 + 1 = 10 台
2. `empty = 2, full = 0, mutex = 1`；爸爸：P(empty); P(mutex); 放; V(mutex); V(full)；儿子：P(full); P(mutex); 拿; V(mutex); V(empty); 吃
3. 0-2 P1（t=1 时 P2 到达入队；t=2 时 P3 到达，排在刚用完时间片的 P1 前面）→ 队列 P2, P3, P1；2-4 P2（剩 1）→ 队列 P3, P1, P2；4-5 P3 完成；5-7 P1（剩 1）；7-8 P2 完成；8-9 P1 完成。完成顺序 **P3, P2, P1**
