# 第 4 篇 · 计算机网络（三）：传输层 + 应用层

> 传输层（主要是 **TCP**）每年选择题 2~3 道，是**计算题重灾区**：序号确认号、窗口、拥塞控制、连接建立释放的时间。
> 应用层每年 1~2 道，以 DNS、HTTP、邮件协议为主。

# 第一部分：传输层

## 13.1 传输层的功能

### 🧒 大白话
网络层把分组送到了**哪台电脑**（主机到主机），但一台电脑上同时开着微信、浏览器、网易云……数据到底交给**哪个程序**？
传输层负责**进程到进程（端到端）**的通信，靠**端口号**区分。
- **IP 地址** = 小区门牌号（找到哪栋楼）
- **端口号** = 房间号（找到哪个人）
- **套接字（Socket）= IP 地址 : 端口号**，唯一确定网络中的一个进程

### 📖 复用和分用
- **复用**：发送方不同进程的数据都通过同一个传输层协议发出去
- **分用**：接收方传输层根据**端口号**把数据交给正确的进程

### 📖 常用端口号（⭐ 必背）
| 协议 | 端口 | 传输层 |
|---|---|---|
| FTP | 20（数据）、**21（控制）** | TCP |
| SSH | 22 | TCP |
| Telnet | 23 | TCP |
| **SMTP** | **25** | TCP |
| **DNS** | **53** | **UDP**（主要） |
| **DHCP** | 67（服务器）、68（客户） | UDP |
| **HTTP** | **80** | TCP |
| **POP3** | **110** | TCP |
| HTTPS | 443 | TCP |
| SNMP | 161 | UDP |
| RIP | 520 | UDP |
- 0 ~ 1023：**熟知端口**（服务器用）；49152 ~ 65535：客户端临时使用的**短暂端口**

## 13.2 UDP（用户数据报协议）

### 🧒 大白话
UDP 就像**寄明信片**：写好地址就扔进邮筒，**不打招呼、不确认对方收到没有**。简单、快，但可能丢。

### 📖 特点
- **无连接**：发送前不用建立连接
- **不可靠**：尽最大努力交付，不确认、不重传
- **面向报文**：应用层交下来多大就发多大，**不拆分不合并**
- **没有拥塞控制**：网络再堵也照发（适合实时视频、语音）
- 支持一对一、一对多、多对多
- **首部只有 8 字节**：源端口（2）+ 目的端口（2）+ 长度（2）+ 校验和（2）

### 📖 UDP 校验和
计算时临时加一个 12 字节的“**伪首部**”（含源 IP、目的 IP、协议号 17、UDP 长度），伪首部**不发送**，只用于计算。
所以校验和**既检查 UDP 首部和数据，也检查 IP 地址**——这就是为什么 NAT 改了 IP 和端口后，UDP 校验和也要改（2025 年第 37 题）。

**真题（2021 年第 39 题）**：12 B 应用数据，分别用 1 个 UDP 数据报和 1 个 TCP 段传输，最大传输效率？
- UDP：12 / (12 + 8) = **60%**
- TCP：12 / (12 + 20) = **37.5%**（TCP 首部最小 20 B）
- 选 D

## 13.3 TCP（传输控制协议，⭐⭐⭐）

### 🧒 大白话
TCP 像**打电话**：先拨号**建立连接**（“喂，听得到吗？”“听得到！”），说话时对方会**确认**（“嗯嗯”），没听清就**重说**，最后**说再见挂断**。可靠，但麻烦一点。

### 📖 特点
- **面向连接**：通信前三次握手，结束后四次挥手
- **点对点**：一条连接只有两个端点
- **可靠交付**：无差错、不丢失、不重复、按序到达
- **全双工**：双方可以同时发送
- **面向字节流**：TCP 把数据看成一连串**字节**，**每个字节都有序号**

### 📖 TCP 首部（最小 20 字节）
| 字段 | 含义（⭐） |
|---|---|
| 源端口、目的端口 | 各 2 字节 |
| **序号 seq** | 本报文段**数据的第一个字节**的序号 |
| **确认号 ack** | 期望收到对方**下一个**报文段数据的第一个字节序号（“ack = N 表示 N−1 及以前的都收到了”） |
| 数据偏移 | 即**首部长度**，单位 **4 字节** |
| **URG** | 紧急指针有效 |
| **ACK** | 确认号有效（连接建立后所有报文段 ACK 都为 1） |
| PSH | 尽快交付给应用进程 |
| RST | 连接出现严重错误，重置连接 |
| **SYN** | 建立连接 |
| **FIN** | 释放连接 |
| **窗口 rwnd** | **接收方**还能接收多少字节（流量控制用） |
| 校验和 | 同 UDP，也要加伪首部 |
| 选项 | 如 **MSS**（最大报文段长度，指**数据部分**的最大长度） |

### 📖 序号和确认号计算（⭐⭐ 必考）
🧒 规则很简单：**seq 是我这次发的第一个字节的编号；ack 是我想要你下一次发的第一个字节的编号**。

**例**：A 发给 B：seq = 1000，携带 500 字节数据（1000 ~ 1499）
→ B 回复：ack = **1500**
→ A 下一个报文段：seq = **1500**

⚠️ **SYN 和 FIN 报文段虽然不带数据，但各自要消耗 1 个序号**！（纯 ACK 报文段不消耗序号）

**真题（2020 年第 39 题）**：建立连接时甲发的 SYN 序号 1000，断开时甲发的 FIN 序号 5001，无重传，甲共发了多少字节应用数据？
- SYN 消耗 1000 → 数据从 **1001** 开始
- FIN 的序号 5001 → 数据到 **5000** 结束
- 数据字节数 = 5000 − 1001 + 1 = **4000**，选 C

## 13.4 TCP 连接管理（⭐⭐⭐）

### 📖 三次握手（建立连接）
```
客户端 (CLOSED)                                服务器 (LISTEN)
   │── SYN=1, seq=x ──────────────────────────→│
(SYN-SENT)                                  (SYN-RCVD)
   │←─ SYN=1, ACK=1, seq=y, ack=x+1 ───────────│
(ESTABLISHED)
   │── ACK=1, seq=x+1, ack=y+1 ───────────────→│
                                            (ESTABLISHED)
```
🧒 比喻：
1. 客户：“**喂，我想和你通话，我的编号从 x 开始。**”
2. 服务器：“**好的，收到你的 x 了（ack=x+1）；我的编号从 y 开始。**”
3. 客户：“**收到你的 y 了（ack=y+1），我们开始吧！**”（第三次可以**携带数据**）

**为什么要三次？** 防止**已经失效的旧连接请求**突然又到达服务器，导致服务器白白建立连接、浪费资源。
**SYN 洪泛攻击**：攻击者发大量 SYN 却不回第三次 ACK，让服务器维护大量“半连接”而耗尽资源。

### 📖 四次挥手（释放连接）
```
客户端 (ESTABLISHED)                            服务器 (ESTABLISHED)
   │── FIN=1, seq=u ──────────────────────────→│
(FIN-WAIT-1)                                (CLOSE-WAIT)
   │←─ ACK=1, ack=u+1 ──────────────────────────│   ← 服务器可能还有数据没发完，继续发
(FIN-WAIT-2)
   │←─ FIN=1, ACK=1, seq=w, ack=u+1 ────────────│
(TIME-WAIT)                                 (LAST-ACK)
   │── ACK=1, ack=w+1 ────────────────────────→│
   │  等待 2MSL                                  (CLOSED)
(CLOSED)
```
🧒 比喻：
1. 客户：“**我说完了**。”
2. 服务器：“**好的，我知道了**，不过我还有几句要说……”（**半关闭**：服务器 → 客户方向还能发）
3. 服务器：“**我也说完了**。”
4. 客户：“**好的，再见。**”然后**再等一会儿（2MSL）才真正挂断**

**为什么要等 2MSL（TIME-WAIT）？**（MSL：报文段在网络中的最长寿命）
1. 保证最后一个 ACK 能到达服务器——如果丢了，服务器会重发 FIN，客户还在就能再回一次 ACK
2. 让本连接的所有旧报文段都从网络中消失，不影响下一个新连接

**真题（2021 年第 38 题）**：客户先发 FIN，当客户收到服务器的 FIN 并发送 ACK 后，客户状态变为 **B. TIME_WAIT**。

**真题（2022 年第 39 题）**：RTT = 50 ms，MSL = 800 ms，客户 C 主动断开。从 C 发 FIN 开始，C 和 S 进入 CLOSED 状态至少分别需要多长时间？
- 最快情况：服务器收到 FIN 后**把 ACK 和 FIN 合并**一起发（三次挥手）
- t = 0：C 发 FIN；t = 25 ms：S 收到，立即发 ACK+FIN；t = 50 ms：C 收到，发 ACK，进入 TIME-WAIT
- **S**：t = 75 ms 收到最后的 ACK → CLOSED，**75 ms**
- **C**：50 + 2 × 800 = **1650 ms**
- 选 D

## 13.5 TCP 可靠传输

### 📖 机制
- **序号 + 确认**：累积确认
- **超时重传**：发出去后启动计时器，超时没收到确认就重传
  - 超时重传时间 RTO 根据 RTT 动态计算：**加权平均往返时间** RTTs = (1 − α) × 旧 RTTs + α × 新 RTT 样本（推荐 α = 1/8），RTO = RTTs + 4 × RTTd
- **快速重传**：发送方连续收到 **3 个重复的 ACK**（同一个确认号又来了 3 次），说明中间某段丢了，**不用等超时，立即重传**

## 13.6 TCP 流量控制

### 🧒 大白话
接收方的“**水缸**”（接收缓存）就这么大，发送方不能倒水倒得太快，否则会溢出。
接收方在每个报文段里告诉发送方“**我的水缸还能装多少**”（**rwnd，接收窗口**），发送方发送的**未被确认的数据量**不能超过它。

- 基于**滑动窗口**
- rwnd = 0 时发送方停止发送，并启动**持续计时器**，定时发“**零窗口探测报文**”问问窗口开了没有（防止接收方的“窗口已开”通知丢失导致死锁）

**真题（2021 年第 40 题）**：甲在 t₀ 时刻发了 seq = 501、200 B 数据的段（501 ~ 700）；t₁ 时刻收到乙的段 ack = 501，rwnd = 500 B。在未收到新确认前，甲还能发送的数据序号范围？
- ack = 501：乙收到了 500 及以前的，期待 501
- 窗口 = 500 B → 甲可以发的范围是 **501 ~ 1000**
- 其中 501 ~ 700 已经发了（还没确认）
- 还能继续发 **701 ~ 1000**

## 13.7 TCP 拥塞控制（⭐⭐⭐ 必考）

### 🧒 大白话
流量控制是**照顾接收方**（别把对方淹死）；拥塞控制是**照顾整个网络**（别把马路堵死）。
发送方维护一个**拥塞窗口 cwnd**，表示“我估计网络能承受多少”。

**实际发送窗口 = min(rwnd, cwnd)**

### 📖 四个算法
**① 慢开始**：
- 开始时 cwnd = 1 个 MSS
- **每收到一个确认，cwnd + 1** → 结果是**每经过一个 RTT，cwnd 翻倍**（1 → 2 → 4 → 8 …）
- 🧒 “慢开始”不是增长慢，而是**起点低**（从 1 开始试探）

**② 拥塞避免**：
- 当 cwnd 达到**慢开始门限 ssthresh** 后
- **每经过一个 RTT，cwnd + 1**（线性增长，“加法增大”）

**③ 遇到超时（网络很可能严重拥塞）**：
- **ssthresh = cwnd / 2**
- **cwnd = 1**，重新慢开始

**④ 快重传 + 快恢复（收到 3 个重复 ACK，网络轻度拥塞）**：
- 快重传：立即重传丢失的段
- 快恢复：**ssthresh = cwnd / 2，cwnd = ssthresh**（新的门限），然后直接进入**拥塞避免**

**例**：初始 ssthresh = 16（单位 MSS），第 13 轮 cwnd = 24 时发生**超时**：

| 轮次（RTT） | 1 | 2 | 3 | 4 | 5 | 6 | 7 | … | 13 | 14 | 15 | 16 | 17 | 18 | 19 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| cwnd | 1 | 2 | 4 | 8 | **16** | 17 | 18 | … | **24 超时** | 1 | 2 | 4 | 8 | **12** | 13 |
| 阶段 | 慢开始 | | | | 到门限 | 拥塞避免 | | | | 慢开始（新 ssthresh = 12） | | | | 到门限 | 拥塞避免 |

🧒 注意 8 → 12 而不是 8 → 16：慢开始翻倍时**不能超过门限**，到 ssthresh 就改为线性增长。

### ✏️ 真题连击
**真题（2022 年第 38 题）**：MSS = 1 KB，甲一直有数据发送，拥塞窗口为 16 KB 时**超时**，再次增长到 16 KB 至少需要多长时间？
- 超时：ssthresh = 16 / 2 = **8 KB**，cwnd = **1 KB**
- 慢开始：1 → 2 → 4 → 8（**3 个 RTT**）
- 拥塞避免：8 → 9 → … → 16（**8 个 RTT**）
- 共 **11 RTT**，选 C

**真题（2020 年第 38 题）**：MSS = 1 KB，RTT = 2 ms，不出现拥塞，cwnd 从 8 KB 增长到 32 KB 所需的**最长**时间？
- “最长”→ 假设一直处于**拥塞避免**（线性增长）
- 需要 32 − 8 = **24 个 RTT** = **48 ms**，选 D

**真题（2025 年第 38 题）**：甲在 t₀ 时刻 cwnd = 发送窗口 = 2000 B，ssthresh = 8000 B，MSS = 1000 B。甲发了 seq = 2001 和 seq = 3001 两个段（各 1000 B）。t₁ 收到乙的确认：ack = 3001，rwnd = 4000 B。还能继续发几个段？
1. ack = 3001 确认了第一个段（2001 ~ 3000）
2. cwnd < ssthresh，处于**慢开始**，每收到一个确认 cwnd + 1 MSS → cwnd = **3000 B**
3. 发送窗口 = min(cwnd, rwnd) = min(3000, 4000) = **3000 B**
4. 已发出未确认的：3001 ~ 4000（1000 B）
5. 还能发 3000 − 1000 = 2000 B = **2 个段**，选 A

### 📊 TCP vs UDP（⭐ 比较）
| | TCP | UDP |
|---|---|---|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠 | 不可靠 |
| 数据单位 | 字节流 | 报文 |
| 首部 | 20 ~ 60 B | **8 B** |
| 流量/拥塞控制 | 有 | 无 |
| 通信方式 | 一对一 | 一对一、一对多、多对多 |
| 适用 | 文件传输、网页、邮件 | 实时音视频、DNS、DHCP |

**真题（2025 年第 39 题）**：Time 服务支持 UDP 和 TCP，RTT = 8 ms，客户分别用 UDP 和 TCP 请求时间，最少时间？
- UDP：直接请求 → 回答，**1 个 RTT = 8 ms**
- TCP：先握手（1 RTT，第三次握手可以捎带请求）+ 请求回答（1 RTT）= **16 ms**
- 选 B

# 第二部分：应用层

## 13.8 网络应用模型
- **客户/服务器（C/S）**：服务器一直在线、有固定地址；客户主动请求
- **P2P（对等）**：每台主机既是客户又是服务器；可扩展性好

## 13.9 DNS（域名系统，⭐⭐）

### 🧒 大白话
人记不住 IP 地址（142.250.1.1），但记得住 www.google.com。DNS 就是**互联网的“电话簿”**：**域名 → IP 地址**。

### 📖 域名结构
**层次结构**，从右往左级别越来越低：`www.abc.com.cn` → cn（顶级域）→ com（二级域）→ abc → www
- 顶级域名：国家顶级域（cn、us）、通用顶级域（com、org、edu、net）

### 📖 域名服务器
| 类型 | 作用 |
|---|---|
| **根域名服务器** | 最高层，知道所有**顶级域名服务器**的地址 |
| **顶级域名服务器** | 管理某个顶级域下的二级域名 |
| **权限（授权）域名服务器** | 负责一个区，能给出最终的 IP 地址 |
| **本地域名服务器** | 主机最先查询的服务器（一般由 ISP 或学校提供） |

### 📖 两种查询方式（⭐）
- **递归查询**：“你帮我查到底，**把最终结果给我**”——一般**主机向本地域名服务器**用递归查询
- **迭代查询**：“我不知道，但**你可以去问 XX**”——一般**本地域名服务器向根、顶级、权限服务器**用迭代查询

```
迭代查询（常见）：
主机 ──①递归──→ 本地DNS ──②──→ 根DNS
                  │   ←─③“去问 .com 的服务器”
                  │──④──→ 顶级DNS(.com)
                  │   ←─⑤“去问 abc.com 的服务器”
                  │──⑥──→ 权限DNS(abc.com)
                  │   ←─⑦“IP 是 x.x.x.x”
主机 ←─⑧──────────┘
```
- **DNS 主要使用 UDP，端口 53**
- 有**高速缓存**：查过的结果会缓存一段时间，下次直接返回
- 计算“最少/最多需要几个 RTT”的题：**最少**是本地 DNS 缓存命中；**最多**是本地缓存没有，要依次问根、顶级、权限服务器

## 13.10 HTTP 和万维网（⭐⭐）

### 📖 基本概念
- **URL**：`协议://主机:端口/路径`，如 `http://www.abc.com/index.html`
- **HTTP**：基于 **TCP**，端口 **80**，**无状态**（服务器不记得之前的请求）
  - 为了“记住用户”（比如登录状态、购物车）→ 使用 **Cookie**
- **HTML**：网页的格式语言

### 📖 非持久连接 vs 持久连接（⭐ 计算）
- **非持久连接（HTTP/1.0）**：**每请求一个对象都要新建一个 TCP 连接**
  - 每个对象 = **2 RTT**（1 个建连接 + 1 个请求响应）+ 对象传输时间
- **持久连接（HTTP/1.1 默认）**：一个 TCP 连接上可以请求多个对象
  - **非流水线**：收到上一个响应才发下一个请求，每个对象 1 RTT
  - **流水线**：连续发多个请求，**所有引用对象总共约 1 RTT**

**例**：网页 HTML 引用了 10 个小图片，忽略传输时间：
- 非持久、串行：(2 + 10 × 2) RTT = **22 RTT**
- 持久、非流水线：2 + 10 = **12 RTT**
- 持久、流水线：2 + 1 = **3 RTT**

### 📖 HTTP 报文
- 请求方法：**GET**（获取）、**POST**（提交）、HEAD（只要首部）、PUT、DELETE
- 状态码：**200 OK**、301 永久移动、**404 Not Found**、500 服务器错误
- **代理服务器（Web 缓存）**：替用户向原服务器请求，并把结果**缓存**起来，下次同样的请求直接从缓存返回

## 13.11 FTP（文件传输协议）
- 基于 TCP，使用**两个连接**：
  - **控制连接（端口 21）**：**整个会话期间一直保持**，传送命令（“带外”传送控制信息）
  - **数据连接（端口 20，主动模式）**：每传一个文件建立一次，传完就关闭
- FTP 服务器要维护**用户状态**（有状态）

## 13.12 电子邮件（⭐）

```
发件人 ──SMTP──→ 发送方邮件服务器 ──SMTP──→ 接收方邮件服务器 ──POP3/IMAP──→ 收件人
       (推)                        (推)                          (拉)
```
| 协议 | 作用 | 方向 | 端口 |
|---|---|---|---|
| **SMTP** | 用户代理**发送**邮件到服务器、**服务器之间**传送邮件 | **推（push）** | TCP 25 |
| **POP3** | 用户代理从服务器**读取（下载）**邮件 | **拉（pull）** | TCP 110 |
| IMAP | 读取邮件，但邮件**保留在服务器**上，可在服务器上建文件夹 | 拉 | TCP 143 |

- SMTP 只能传 **7 位 ASCII** 文本 → 要发图片、中文、附件需要 **MIME** 扩展
- 用浏览器收发邮件（网页邮箱）：浏览器和邮件服务器之间用 **HTTP**，服务器之间仍用 SMTP

**真题（2025 年第 40 题）**：关于 POP3 正确的是：
- I. 支持用户代理从邮件服务器**读取**邮件 ✓
- II. 支持用户代理向邮件服务器发送邮件 ✗（那是 SMTP）
- III. 支持邮件服务器之间发送和接收 ✗（那是 SMTP）
- IV. 支持通过一条 TCP 连接接收多封邮件 ✓
- 选 **B（I、IV）**

## 13.13 综合：在浏览器输入网址后发生了什么（⭐⭐⭐ 大题最爱的全流程）

假设一台刚开机的电脑，在浏览器输入 `http://www.abc.com/index.html`：

1. **DHCP**：获取自己的 IP、子网掩码、默认网关、DNS 服务器地址（UDP 广播，源 0.0.0.0，目的 255.255.255.255）
2. **ARP**：DNS 服务器不在本网段 → 广播 ARP 请求**默认网关的 MAC 地址**
3. **DNS**：把 DNS 查询（UDP 53）封装后发给网关，最终到达 DNS 服务器，得到 www.abc.com 的 IP
4. **TCP 三次握手**：与 Web 服务器的 80 端口建立连接
5. **HTTP 请求/响应**：发送 GET /index.html，收到网页
6. 网页里引用了图片等对象，继续请求（持久连接复用同一个 TCP 连接）
7. **TCP 四次挥手**：释放连接

在这个过程中：
- 每经过一个路由器，**MAC 地址变**，**IP 地址不变**（除 NAT 外）
- 经过 NAT 路由器时，**源 IP 和源端口**被替换
- 交换机根据 MAC 地址**自学习并转发**

## 13.14 本篇小结

| 知识点 | 一句话 |
|---|---|
| 端口 | FTP 20/21，SMTP 25，DNS 53，HTTP 80，POP3 110，DHCP 67/68 |
| UDP | 8 B 首部；无连接、不可靠、面向报文；校验和含伪首部 |
| seq/ack | seq = 本段第一个字节；ack = 期待的下一个字节 |
| SYN/FIN | 各消耗 1 个序号 |
| 三次握手 | SYN → SYN+ACK → ACK |
| 四次挥手 | 主动方最后 TIME-WAIT 等 2MSL |
| 快速重传 | 3 个重复 ACK |
| 发送窗口 | min(rwnd, cwnd) |
| 慢开始 | 每 RTT 翻倍；每个 ACK +1 MSS |
| 拥塞避免 | 每 RTT +1 MSS |
| 超时 | ssthresh = cwnd/2，cwnd = 1 |
| 快恢复 | ssthresh = cwnd/2，cwnd = ssthresh |
| DNS | UDP 53；主机→本地递归；本地→其他迭代 |
| HTTP | TCP 80，无状态；1.1 默认持久连接 |
| 邮件 | SMTP 推，POP3/IMAP 拉 |

## 13.15 课后练习

1. A 向 B 发送三个连续的 TCP 段，seq 分别为 70、100、150，第一段的数据有多少字节？B 收到第一段后回复的确认号？如果第二段丢了、第三段到达，B 的确认号是多少？
2. ssthresh = 16，cwnd 从 1 开始，第 8 个 RTT 结束时 cwnd = ？（无拥塞）
3. 为什么 DNS 主要用 UDP？
4. 在 cwnd = 24 时收到 3 个重复 ACK（采用快恢复），新的 ssthresh 和 cwnd？

<details>
<summary>答案</summary>

1. 100 − 70 = 30 字节；确认号 100；第二段丢失，B 仍然期待 100，确认号 **100**
2. 1, 2, 4, 8, 16（达到门限），17, 18, 19 → 各轮开始时的 cwnd 依次是 1,2,4,8,16,17,18,19，第 8 轮结束时变成 **20**（若问“第 8 轮发送时的 cwnd”则是 19，注意题目问法）
3. DNS 查询报文很短，一问一答就结束，用 UDP 不需要建立连接，速度快、开销小
4. ssthresh = 12，cwnd = 12，之后进入拥塞避免
</details>
