# 第一部分：查找

## 3.1 基本概念

### 🧒 大白话
查找就是**在一堆东西里找到你要的那个**。衡量一个查找方法好不好，就看**平均要比较几次**，这叫**平均查找长度（ASL）**。

```
ASL = Σ（找第 i 个元素的概率 × 找它需要比较的次数）
```
一般每个元素被找的概率相同，就是**把每个元素的比较次数加起来 ÷ 元素个数**。

- **查找成功 ASL**：要找的东西在表里
- **查找失败 ASL**：要找的东西不在表里

---

## 3.2 顺序查找

从头到尾一个一个比。
- 查找成功 ASL = (1 + 2 + … + n)/n = **(n+1)/2**
- 查找失败 ASL = **n+1**（使用“哨兵”时要比到哨兵）或 n
- 优点：对表没有任何要求（无序也行，链表也行）
- 缺点：慢，O(n)

---

## 3.3 折半查找（二分查找，⭐⭐）

### 🧒 大白话
翻字典找 “猫” 字：不会从第一页翻起，而是翻到中间，看看比 “猫” 大还是小，然后扔掉一半，在剩下的一半里再翻中间……

**前提：表必须有序，且必须是顺序存储（数组）**——链表没法直接“跳到中间”。

### 📖 代码
```c
int BinarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1, mid;
    while (low <= high) {
        mid = (low + high) / 2;       // 向下取整
        if (a[mid] == key) return mid;
        else if (a[mid] > key) high = mid - 1;   // 去左半边找
        else low = mid + 1;                      // 去右半边找
    }
    return -1;                          // 没找到
}
```

### 📖 判定树（⭐ 选择题常考）
把折半查找的过程画成一棵二叉树：第一次比较的 mid 当根，左半部分的 mid 当左孩子，右半部分的 mid 当右孩子……

**例**：11 个元素（下标 1~11）的判定树
```
                6
            /       \
          3           9
        /   \       /   \
       1     4     7     10
        \     \     \      \
         2     5     8      11
```
- 找某个元素比较的次数 = 它在判定树的**层数**
- 成功 ASL = (1×1 + 2×2 + 3×4 + 4×4)/11 = 33/11 = **3**
- 失败时，比较次数 = 空指针所在位置的“父结点层数”
- **最多比较次数 = 判定树高度 = ⌈log₂(n+1)⌉**
- 判定树是一棵**平衡二叉树**（而且是 BST）
- 用 ⌊(low+high)/2⌋ 时，每个结点**右子树结点数 ≥ 左子树结点数**（最多多 1 个）
  → 这个性质可以用来判断“某棵树能不能是折半查找判定树”

时间复杂度 **O(log n)**。

---

## 3.4 分块查找（索引顺序查找）

### 🧒 大白话
图书馆找书：先看**楼层索引牌**（“计算机类在 3 楼”），再到 3 楼里一排排找。
- 把表分成若干**块**，**块内可以无序，块与块之间有序**（前一块最大的 < 后一块最小的）
- 建一个**索引表**，记录每块的最大值和起始位置

### 📖 ASL
n 个元素，分 b 块，每块 s 个（n = b × s）：
- 索引表和块内都用顺序查找：**ASL = (b+1)/2 + (s+1)/2**
- 当 **s = √n** 时 ASL 最小，为 √n + 1

**真题（2025 年第 7 题）**：400 个元素，均匀分块，索引和块内都用顺序查找，每块多少个元素效率最高？
→ s = √400 = **20**，选 C。

## 3.5 B 树（⭐⭐ 几乎年年考）

### 🧒 大白话
BST 每个结点只能放 1 个关键字，树会很高。磁盘上的数据读一次很慢，树越高读的次数越多。
B 树让**一个结点装很多个关键字、有很多个孩子**，树就变得**又矮又胖**，读磁盘次数少。

### 📖 m 阶 B 树的规则（必背）
1. 每个结点**最多 m 棵子树，最多 m−1 个关键字**
2. **根**结点如果不是叶子，至少 2 棵子树（至少 1 个关键字）
3. **除根以外**的非叶结点至少 **⌈m/2⌉ 棵子树**，即至少 **⌈m/2⌉ − 1 个关键字**
4. 所有叶子（失败结点）都在**同一层**（绝对平衡）
5. 结点内关键字从小到大排列，并且像 BST 一样：子树 Pᵢ 里的所有关键字都介于 Kᵢ 和 Kᵢ₊₁ 之间

| 阶数 m | 3 | 4 | 5 |
|---|---|---|---|
| 每个结点关键字数（非根） | 1 ~ 2 | 1 ~ 3 | 2 ~ 4 |
| 每个结点子树数（非根） | 2 ~ 3 | 2 ~ 4 | 3 ~ 5 |

> 📌 n 个关键字的 B 树，**叶子（失败结点）数 = n + 1**。

### 📖 插入（⭐）
1. 先查找，**插到最底层**的某个结点里
2. 如果插完后关键字数 **超过 m−1**（溢出），就**分裂**：
   - 从中间位置 **⌈m/2⌉** 把结点劈开
   - 中间那个关键字**上升**到父结点
   - 左右两半各自成为一个结点
3. 如果父结点也溢出，继续往上分裂；根分裂会让树**长高一层**

**真题（2020 年第 10 题）**：依次插入 5, 6, 9, 13, 8, 2, 12, 15 到空的 4 阶 B 树（每个结点最多 3 个关键字），根结点中的关键字是？
```
插 5, 6, 9:     [5 6 9]
插 13:          [5 6 9 13] 溢出！第 ⌈4/2⌉=2 个（6）上升
                    [6]
                  /     \
               [5]     [9 13]
插 8:          [5]     [8 9 13]
插 2:         [2 5]    [8 9 13]
插 12:        [2 5]    [8 9 12 13] 溢出！第 2 个（9）上升
                    [6 9]
                  /   |   \
             [2 5]  [8]  [12 13]
插 15:       [2 5]  [8]  [12 13 15]
```
根结点是 **6, 9**，选 B。

### 📖 删除
1. 删的是**非叶结点**里的关键字：用它的**直接前驱或后继**（左子树最大 / 右子树最小，一定在最底层）替换，转化为删除底层结点的关键字
2. 删底层结点的关键字后：
   - 关键字数仍 ≥ ⌈m/2⌉ − 1 → 直接删，结束
   - 不够了，但**兄弟够借**（兄弟有多余的）→ **借**：父亲下来一个，兄弟上去一个（“父下兄上”）
   - 兄弟也不够借 → **合并**：和兄弟 + 父结点中夹在中间的那个关键字合成一个结点；父结点少了一个关键字，可能继续往上调整；根被合并空了，树**矮一层**

### 📖 高度（⭐ 计算题）
n 个关键字的 m 阶 B 树（高度不算失败结点那层）：
- **最矮**（每个结点塞满）：h ≥ log_m(n+1)
- **最高**（每个结点尽量少）：h ≤ log_{⌈m/2⌉}((n+1)/2) + 1

**真题（2021 年第 9 题）**：高度为 3 的 3 阶 B 树，第 2 层有 4 个关键字，结点数最多是？
- 3 阶：每个结点 1~2 个关键字，2~3 个孩子；根最多 3 个孩子
- 要结点最多 → 第 2 层结点尽可能多：4 个关键字最多分给 3 个结点（2, 1, 1）
- 第 3 层孩子数 = 3 + 2 + 2 = 7
- 总数 = 1 + 3 + 7 = **11**，选 A

## 3.6 B+ 树

### 🧒 大白话
B+ 树是 B 树的“升级版”，数据库最爱用：
- **所有真正的数据都放在叶子上**，上面的结点只当“路标”（索引）
- 叶子之间用链表**串起来**，想按顺序读一大片数据非常方便

### 📊 B 树 vs B+ 树（⭐ 常考比较）
| | B 树 | m 阶 B+ 树 |
|---|---|---|
| n 个关键字的结点有几棵子树 | n + 1 | **n** |
| 关键字重复吗 | 不重复 | 非叶结点的关键字在叶子中**重复出现** |
| 数据（记录地址）放哪 | 所有结点 | **只在叶子** |
| 查找 | 可能在中间结点就结束 | **一定走到叶子** |
| 支持的查找 | 只能从根随机查找 | 从根随机查找 + **从最小叶子顺序查找** |
| 应用 | 文件索引 | **数据库索引** |

## 3.7 散列表（哈希表，⭐⭐）

### 🧒 大白话
前面的查找都要“比来比去”。散列表很聪明：**用一个公式直接算出东西放在哪**。
就像学校储物柜：学号 20231015 的同学，柜子号 = 学号 % 100 = 15 号柜。找东西时一算就知道在 15 号，不用挨个柜子开。

- **散列函数** H(key)：把关键字变成地址
- **冲突**：两个不同的关键字算出了同一个地址（学号 20231015 和 20241015 都是 15 号柜）
- **同义词**：发生冲突的这些关键字

### 📖 散列函数
- **除留余数法**（最常用）：H(key) = key % p，**p 取不大于表长 m 的最大质数**
- 直接定址法：H(key) = a × key + b（不会冲突，但可能很浪费）
- 数字分析法、平方取中法

### 📖 处理冲突（⭐）
**① 开放定址法**：冲突了就在表里**另找一个空位**
- **线性探测**：往后一个一个找：H, H+1, H+2, …（到表尾绕回表头）
  - 缺点：容易造成**聚集（堆积）**——一堆元素挤在一起，本不是同义词的元素也被迫抢位置
- **平方探测**：H, H+1², H−1², H+2², H−2², …（表长须为 4k+3 形式的质数）
  - 能减少聚集，但**不一定能探测到所有位置**
- **双散列**：用第二个散列函数算步长

⚠️ 开放定址法**不能随便物理删除**元素（会把后面元素的探测链切断），只能做“**已删除**”标记（逻辑删除）。

**② 拉链法（链地址法）**：同一地址的同义词串成一个链表。不会聚集，删除方便。

### ✏️ 例题：线性探测 ASL
表长 7（地址 0~6），H(key) = key % 7，线性探测，依次插入 8, 15, 22, 5, 12。

| 关键字 | H | 探测过程 | 放在 | 比较次数 |
|---|---|---|---|---|
| 8 | 1 | 1 空 | 1 | 1 |
| 15 | 1 | 1 占 → 2 空 | 2 | 2 |
| 22 | 1 | 1、2 占 → 3 空 | 3 | 3 |
| 5 | 5 | 5 空 | 5 | 1 |
| 12 | 5 | 5 占 → 6 空 | 6 | 2 |

```
地址:  0    1    2    3    4    5    6
内容:  —    8   15   22    —    5   12
```
- **成功 ASL** = (1 + 2 + 3 + 1 + 2)/5 = 9/5 = **1.8**
- **失败 ASL**：对每个可能的散列地址 H = 0~6，数一数要比较几次才碰到空位（和空位比较也算 1 次）：
  - H=0：0 空 → 1 次
  - H=1：1,2,3,4(空) → 4 次
  - H=2：2,3,4 → 3 次
  - H=3：3,4 → 2 次
  - H=4：4 → 1 次
  - H=5：5,6,0 → 3 次
  - H=6：6,0 → 2 次
  - 失败 ASL = (1+4+3+2+1+3+2)/7 = **16/7 ≈ 2.29**

> ⚠️ 失败 ASL 的分母是**散列函数可能取到的地址个数**（这里 %7 取 0~6，是 7 个），**不是表长**！表长 16、H = key % 13 时分母是 13。
> 另外，“和空位比较算不算 1 次”各教材约定不同，考试一般算（王道的约定）。

### 📖 影响 ASL 的因素
**装填因子 α = 表中元素个数 / 表长**。α 越大，表越满，冲突越多，ASL 越大。
**散列表的 ASL 与元素个数 n 无关，只和 α 有关。**

**真题（2022 年第 9 题）**：影响散列查找 ASL 的是？装填因子、散列函数、冲突解决策略 → **全部**，选 D。

**真题（2025 年第 9 题）**：正确的是？
- A. **只要散列表不满，线性探测一定能找到空位** ✓（它会一个一个试遍所有位置）
- B. 二次探测也一定能找到 ✗（平方探测只能探到一部分位置）
- C. 线性探测处理的冲突一定发生在同义词之间 ✗（聚集会导致非同义词抢位置）
- D. 二次探测处理的冲突一定发生在非同义词之间 ✗

# 第二部分：排序

## 3.8 排序总览

### 🧒 大白话
排序就是把一堆数**从小到大排好**。
- **稳定性**：两个一样大的数，排序后**先后顺序不变**就叫稳定。
  比如 [3ᵃ, 1, 3ᵇ]，排完是 [1, 3ᵃ, 3ᵇ] 就稳定，是 [1, 3ᵇ, 3ᵃ] 就不稳定。
- **内部排序**：数据全在内存里；**外部排序**：数据太多，要借助硬盘。

### 📊 总表（⭐⭐⭐ 考前必背！）

| 算法 | 平均时间 | 最好 | 最坏 | 空间 | 稳定 | 一趟后能否确定一个元素的最终位置 |
|---|---|---|---|---|---|---|
| 直接插入 | O(n²) | **O(n)** | O(n²) | O(1) | ✓ | ✗ |
| 折半插入 | O(n²) | O(n log n)* | O(n²) | O(1) | ✓ | ✗ |
| 希尔 | 约 O(n^1.3) | — | O(n²) | O(1) | ✗ | ✗ |
| 冒泡 | O(n²) | **O(n)** | O(n²) | O(1) | ✓ | ✓（最大/最小） |
| 快速 | O(n log n) | O(n log n) | **O(n²)** | **O(log n)** | ✗ | ✓（枢轴） |
| 简单选择 | O(n²) | O(n²) | O(n²) | O(1) | ✗ | ✓ |
| 堆 | O(n log n) | O(n log n) | O(n log n) | O(1) | ✗ | ✓（堆顶） |
| 归并 | O(n log n) | O(n log n) | O(n log n) | **O(n)** | ✓ | ✗ |
| 基数 | O(d(n+r)) | 同 | 同 | O(r) | ✓ | ✗ |

\* 折半插入只是比较次数减少到 O(n log n)，移动次数没变，总时间仍然 O(n²)。

🧒 **记忆口诀**：
- **不稳定**的：“**快些选堆**”（快速、希尔、选择、堆）——“心情不稳定，快些选一堆好友来聊天”
- **O(n log n)** 的：“**快归堆**”（快速、归并、堆）
- **空间非 O(1)** 的：快速 O(log n)（递归栈）、归并 O(n)、基数 O(r)
- **比较次数与初始序列无关**的：简单选择（永远 n(n−1)/2 次）、基数（根本不比较）
- **趟数与初始序列无关**的：插入、选择、归并、基数（冒泡和快排与初始状态有关）

## 3.9 插入类排序

### 3.9.1 直接插入排序
🧒 **大白话**：像打扑克牌时**理牌**：手里的牌已经排好，每摸一张新牌，就从右往左找到它该在的位置插进去。

```
初始:   [5] 2 4 6 1 3
第1趟:  [2 5] 4 6 1 3      插入 2
第2趟:  [2 4 5] 6 1 3      插入 4
第3趟:  [2 4 5 6] 1 3      插入 6（不用动）
第4趟:  [1 2 4 5 6] 3      插入 1
第5趟:  [1 2 3 4 5 6]      插入 3
```
```c
void InsertSort(int a[], int n) {
    for (int i = 1; i < n; i++) {
        int temp = a[i], j;
        for (j = i - 1; j >= 0 && a[j] > temp; j--)
            a[j + 1] = a[j];          // 比 temp 大的往后挪
        a[j + 1] = temp;              // 插到空出来的位置
    }
}
```
- **基本有序时特别快**（接近 O(n)），适合元素少或基本有序的情况
- 特点：每一趟后，**前面 i 个元素是有序的，但不一定在最终位置**

**真题（2020 年第 11 题）**：数组大部分已有序时，直接插入比简单选择效率高的原因？
→ 直接插入**比较次数更少**（基本有序时每个元素比 1 次就停）。辅助空间都是 O(1)；移动次数反而是简单选择更少。所以**仅 I**，选 A。

### 3.9.2 希尔排序
🧒 **大白话**：直接插入在“基本有序”时很快，那就先让它变得基本有序！
先把相隔 d 的元素分成一组，组内插入排序；然后缩小 d 再来；最后 d = 1 做一次普通插入排序。

**真题（2025 年第 11 题）**：初始 `5,25,40,30,10,20,45,15,35`，第 1 趟后 `5,10,20,30,15,35,45,25,40`，第 2 趟后 `5,10,15,25,20,30,40,35,45`，是什么排序？
- 试 d = 3：分组 (5,30,45)、(25,10,15)、(40,20,35)，组内排好 → (5,30,45)、(10,15,25)、(20,35,40) → 放回：`5,10,20,30,15,35,45,25,40` ✓ 与第 1 趟吻合！
- 第 2 趟 d = 2 也能验证吻合 → **希尔排序**，选 A
- 🧒 技巧：看“隔几个位置的元素是有序的”，就能猜出增量 d。

## 3.10 交换类排序

### 3.10.1 冒泡排序
🧒 **大白话**：相邻两个比一比，大的往后换。一趟下来，**最大的像气泡一样“冒”到了最后**。
- 某一趟**没有发生交换**，说明已经有序，可以提前结束 → 最好 O(n)

### 3.10.2 快速排序（⭐⭐⭐ 最重要的排序）
🧒 **大白话**：选一个数当“**裁判**”（枢轴 pivot，一般选第一个），把比它小的都赶到左边、比它大的都赶到右边，裁判就站在了**最终位置**上。然后对左右两边**各自递归**。

**一趟划分过程**（以第一个元素为枢轴）：
```c
int Partition(int a[], int low, int high) {
    int pivot = a[low];                 // 第一个元素当裁判，它的位置空出来了
    while (low < high) {
        while (low < high && a[high] >= pivot) high--;
        a[low] = a[high];               // 右边找到比裁判小的，扔到左边的空位
        while (low < high && a[low] <= pivot) low++;
        a[high] = a[low];               // 左边找到比裁判大的，扔到右边的空位
    }
    a[low] = pivot;                     // 裁判归位
    return low;
}
void QuickSort(int a[], int low, int high) {
    if (low < high) {
        int p = Partition(a, low, high);
        QuickSort(a, low, p - 1);
        QuickSort(a, p + 1, high);
    }
}
```

✏️ **例**：对 `49 38 65 97 76 13 27` 做一趟划分（pivot = 49）
```
初始:  [49] 38 65 97 76 13 27     pivot=49，low 位置空出
       high 从右找 <49 的：27 → 放到 low
       27  38 65 97 76 13 [ ]
       low 从左找 >49 的：65 → 放到 high
       27  38 [ ] 97 76 13 65
       high 找 <49：13 → 放到 low
       27  38 13 97 76 [ ] 65
       low 找 >49：97 → 放到 high
       27  38 13 [ ] 76 97 65
       high 左移遇到 low，结束，pivot 放入
结果:  27  38 13 49 76 97 65
```
49 左边都比它小，右边都比它大 ✓

**要点：**
- 最好/平均 O(n log n)；**最坏 O(n²)——当序列本来就有序（或逆序）时**，每次只能分出一个元素
- 空间 O(log n)（递归栈），最坏 O(n)
- **平均性能最好的内部排序**
- 判断“是否是快排第 k 趟结果”：第 k 趟后至少有 k 个元素在最终位置（第 2 趟时，若第 1 趟枢轴在边上，则至少 2 个；否则至少 3 个）

## 3.11 选择类排序

### 3.11.1 简单选择排序
每一趟从未排序部分**选出最小的**，和未排序部分的第一个交换。
- 比较次数永远 n(n−1)/2，与初始状态无关
- **移动次数最少**：最多 3(n−1) 次（每趟最多一次交换）
- **真题（2025 年第 10 题）**：最坏情况下元素移动最少的是？→ **简单选择排序**，选 D。

### 3.11.2 堆排序（⭐⭐⭐）

#### 🧒 什么是堆
**大根堆**：一棵**完全二叉树**，每个爸爸都 ≥ 他的孩子（根是最大的）。
**小根堆**：每个爸爸都 ≤ 孩子（根是最小的）。

因为是完全二叉树，所以直接用**数组**存（下标从 1 开始：i 的孩子是 2i 和 2i+1）。

**真题（2020 年第 9 题）**：关于大根堆，正确的是？
- I. 可以视为一棵完全二叉树 ✓
- II. 可以用顺序存储 ✓
- III. 可以视为二叉排序树 ✗（堆只管上下，不管左右）
- IV. **次大值一定在根的下一层** ✓（次大值的爸爸必须比它大，只能是根）
→ 选 C（I、II、IV）

#### 📖 建堆（自底向上）
从最后一个分支结点 ⌊n/2⌋ 开始，**往前**逐个做“**下沉（向下调整）**”：把这个结点和它较大的孩子比，比孩子小就交换，一直沉到合适位置。
- 建堆时间 **O(n)**（这个结论要记）

✏️ **例**：`53 17 78 09 45 65 87 32` 建大根堆（n = 8，从 ⌊8/2⌋ = 4 号开始）
```
编号:  1   2   3   4   5   6   7   8
初始: 53  17  78  09  45  65  87  32
i=4: 09 与孩子 32 比，下沉 → 53 17 78 32 45 65 87 09
i=3: 78 与孩子 65、87 中较大的 87 比，下沉 → 53 17 87 32 45 65 78 09
i=2: 17 与孩子 32、45 中较大的 45 比，下沉 → 53 45 87 32 17 65 78 09
i=1: 53 与孩子 45、87 中较大的 87 交换 → 87 45 53 32 17 65 78 09
     53 继续与孩子 65、78 中较大的 78 交换 → 87 45 78 32 17 65 53 09
结果: 87 45 78 32 17 65 53 09
```

#### 📖 插入（上浮）
新元素放在**最后**，然后和爸爸比，比爸爸大就交换，一直往上浮。

**真题（2021 年第 11 题）**：依次插入 6, 9, 1, 5, 8, 4, 7 到空的大根堆：
```
插 6:  [6]
插 9:  [6,9] → 9 比爸爸 6 大，上浮 → [9,6]
插 1:  [9,6,1]
插 5:  [9,6,1,5]（5 的爸爸是 6，不动）
插 8:  [9,6,1,5,8] → 8 的爸爸是 6（第 2 个），上浮 → [9,8,1,5,6]
插 4:  [9,8,1,5,6,4] → 4 的爸爸是 1（第 3 个），上浮 → [9,8,4,5,6,1]
插 7:  [9,8,4,5,6,1,7] → 7 的爸爸是 4（第 3 个），上浮 → [9,8,7,5,6,1,4]
```
结果 `9,8,7,5,6,1,4`，选 B。

#### 📖 删除堆顶 & 堆排序
- 把堆顶和**最后一个元素交换**，堆的大小减 1，再把新的堆顶**下沉**。
- 反复做 n−1 次，数组就从小到大排好了（大根堆 → 升序）。
- 每次下沉 O(log n)，总共 **O(n log n)**。

#### 📖 应用：Top-K 问题（⭐ 2022 年 42 题）
**真题**：n（> 100000）个数，找最小的 10 个，平均比较次数尽量少。
🧒 思路：维护一个**大小为 10 的大根堆**（装着“目前为止最小的 10 个”，堆顶是这 10 个里最大的）。
1. 先用前 10 个数建大根堆
2. 后面每来一个数，和堆顶比：比堆顶小，就替换堆顶并下沉；否则扔掉
3. 扫完后堆里就是最小的 10 个
- 时间 O(n log 10) = **O(n)**，空间 **O(1)**（堆大小固定是 10）

## 3.12 归并排序

### 🧒 大白话
“**先拆后合**”：把数组一分为二，各自排好，再把两个有序数组**合并**成一个。合并就像两队按身高排好的小朋友，每次比较两队排头，矮的先出列。

```
[38 27 43 3 9 82 10]
拆: [38 27 43 3] [9 82 10]
拆: [38 27] [43 3] [9 82] [10]
合: [27 38] [3 43] [9 82] [10]
合: [3 27 38 43] [9 10 82]
合: [3 9 10 27 38 43 82]
```
- **合并操作的功能：把两个有序表合并成一个有序表**（2022 年第 10 题原题，选 A）
- 时间永远 O(n log n)，空间 **O(n)**（要辅助数组），**稳定**
- 二路归并趟数 = ⌈log₂n⌉

## 3.13 基数排序

### 🧒 大白话
不比较大小！按“位”来**分配**和**收集**：
- **LSD（最低位优先）**：先按个位分到 0~9 号桶里，按顺序收集；再按十位分配收集；再按百位……

**真题（2021 年第 10 题）**：S = {93, 946, 372, 9, 146, 151, 301, 485, 236, 327, 43, 892}，LSD 第 1 趟后，372 前后紧邻的元素？
按个位分配：
```
桶1: 151, 301
桶2: 372, 892
桶3: 93, 43
桶5: 485
桶6: 946, 146, 236
桶7: 327
桶9: 9
```
收集：`151, 301, 372, 892, 93, 43, 485, 946, 146, 236, 327, 9`
372 前面是 **301**，后面是 **892**，选 C。

- d 位数、每位 r 种取值（基数 r）：时间 O(d(n+r))，空间 O(r)，**稳定**
- 适合：关键字位数少、范围不大的整数

## 3.14 计数排序（2021 年 42 题）

**真题代码：**
```c
void cmpCountSort(int a[], int b[], int n) {
    int i, j, *count = (int *)malloc(sizeof(int) * n);
    for (i = 0; i < n; i++) count[i] = 0;
    for (i = 0; i < n - 1; i++)
        for (j = i + 1; j < n; j++)
            if (a[i] < a[j]) count[j]++;
            else count[i]++;
    for (i = 0; i < n; i++) b[count[i]] = a[i];
    free(count);
}
```
🧒 **看懂它**：count[i] 最后等于“**比 a[i] 小的元素个数**”，这就是 a[i] 在有序数组里的下标！
1. a = {25, −10, 25, 10, 11, 19} → b = **{−10, 10, 11, 19, 25, 25}**
2. 比较次数：每对 (i, j) 比一次 → **n(n−1)/2**
3. 稳定吗？当 a[i] == a[j]（i 在前）时，执行 else → count[i]++，**前面的反而排到后面** → **不稳定**。
   改法：把 `a[i] < a[j]` 改成 **`a[i] <= a[j]`**，相等时让后面的 count[j]++，就稳定了。

## 3.15 外部排序（⭐ 2023 年 42 题大题）

### 🧒 大白话
数据有 100 GB，内存只有 1 GB，怎么排？
1. **生成初始归并段**：每次读一部分进内存，排好序写回硬盘，成为一个个“有序小段”
2. **多路归并**：把这些有序段合并成一个大的有序文件

**外部排序的时间主要花在读写磁盘（I/O）上**，所以要**减少归并趟数**。

### 📖 归并趟数
r 个初始归并段，做 k 路归并，趟数 = **⌈log_k r⌉**
减少趟数的办法：**增大 k**（用败者树）或 **减少 r**（用置换-选择排序）。

### 📖 败者树（多路归并用）
k 路归并时，每次要从 k 个段头里选最小的。普通方法要比 k−1 次。
**败者树**：一棵完全二叉树，叶子是 k 个段头，内部结点记录每场比赛的“**败者**”，冠军单独存。
- 每选出一个最小值，只要沿着一条路径重新比赛 → 只需 **⌈log₂k⌉** 次比较
- 所以 k 增大时比较次数不会跟着暴涨

### 📖 置换-选择排序（生成更长的初始归并段）
内存工作区能放 m 个记录：
1. 从输入读 m 个记录进工作区
2. 从工作区选出**比当前段最后输出的值还大的最小值**输出
3. 读入一个新记录补上；如果新记录比刚输出的小，它**只能进下一段**（“冻结”）
4. 工作区全部冻结时，当前段结束，开始新的段

**真题（2023 年第 42 题）**：m = 4，记录依次为 51, 94, 37, 92, 14, 63, 15, 99, 48, 56, 23, 60, 31, 17, 43, 8, 90, 166, 100。
（带 * 的表示“冻结，留给下一段”）
```
工作区 {51,94,37,92}      输出 37  读 14*
工作区 {51,94,92,14*}     输出 51  读 63
工作区 {94,92,14*,63}     输出 63  读 15*
工作区 {94,92,14*,15*}    输出 92  读 99
工作区 {94,99,14*,15*}    输出 94  读 48*
工作区 {99,14*,15*,48*}   输出 99  读 56*
全部冻结 → 第 1 段: 37, 51, 63, 92, 94, 99

工作区 {14,15,48,56}      输出 14  读 23
工作区 {15,48,56,23}      输出 15  读 60
工作区 {48,56,23,60}      输出 23  读 31
工作区 {48,56,60,31}      输出 31  读 17*
工作区 {48,56,60,17*}     输出 48  读 43*
工作区 {56,60,17*,43*}    输出 56  读 8*
工作区 {60,17*,43*,8*}    输出 60  读 90
工作区 {17*,43*,8*,90}    输出 90  读 166
工作区 {17*,43*,8*,166}   输出 166 读 100*
全部冻结 → 第 2 段: 14, 15, 23, 31, 48, 56, 60, 90, 166

输入读完 → 第 3 段: 8, 17, 43, 100
```
共 **3 个**初始归并段。
（第 2 问：第一个归并段长度**最小 m**（后面读入的都比已输出的小），**最大 n**（输入本来就有序，全部一段）。一般平均长度约 2m。）

### 📖 最佳归并树
归并段长度不同时，先合并短的更省 I/O —— 这就是 **k 叉哈夫曼树**！
- WPL × 2 = 总读写次数（读一次写一次）
- ⚠️ 若 **(r − 1) % (k − 1) ≠ 0**，要补 **(k − 1) − (r − 1) % (k − 1)** 个长度为 0 的“虚段”，才能构成严格 k 叉树

**例**：8 个归并段，3 路归并。(8 − 1) % (3 − 1) = 1 ≠ 0 → 补 (3 − 1) − 1 = **1** 个虚段。
