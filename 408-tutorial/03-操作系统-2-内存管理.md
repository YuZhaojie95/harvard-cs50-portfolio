## 9.1 内存管理的基本概念

### 🧒 大白话
内存是一块大空地，操作系统是**地产商**，要把地分给各个进程（程序）盖房子。要解决四个问题：
1. **分配与回收**：谁用哪块地？用完了怎么收回？
2. **地址转换**：程序里写的“门牌号”（逻辑地址）怎么变成真实位置（物理地址）？
3. **内存保护**：不能让 A 进程闯进 B 进程的地盘
4. **内存扩充**：地不够用怎么办？（虚拟内存）

### 📖 逻辑地址 vs 物理地址
- **逻辑地址（相对地址/虚拟地址）**：程序编译后，每个进程都假设自己从 0 开始编址
- **物理地址（绝对地址）**：内存里真实的地址
- **地址重定位**：逻辑地址 → 物理地址

### 📖 程序的链接和装入
**从源程序到运行：编译 → 链接 → 装入**

**链接的三种方式：**
- **静态链接**：运行前就把所有目标模块和库函数链接成一个完整的可执行文件
- **装入时动态链接**：装入内存时边装入边链接
- **运行时动态链接**：执行中需要某个模块时才链接（Windows 的 DLL、Linux 的 .so）→ 节省内存，便于共享

**装入的三种方式：**
- **绝对装入**：编译时就知道放在内存哪里，直接生成物理地址（只适合单道程序）
- **可重定位装入（静态重定位）**：装入时一次性把所有地址改好，之后**不能移动**
- **动态运行时装入（动态重定位）**：装入后仍是逻辑地址，**执行时**才通过**重定位寄存器**转换 → 程序可以在内存中移动 ⭐ 现代系统都用这个

### 📖 内存保护
- 方法 1：设**上、下限寄存器**，访问的地址必须在两者之间
- 方法 2：**重定位寄存器（基址寄存器）+ 界地址寄存器（限长寄存器）**
  - 逻辑地址先和界地址比较，**小于界地址**才合法
  - 合法的话，物理地址 = 逻辑地址 + 重定位寄存器
  - 这两个寄存器只能用**特权指令**修改

### 📖 进程的内存映像（⭐ 2025 年 46 题）
```
高地址 ┌──────────────┐
       │   内核区       │ ← 操作系统内核（PCB 等内核数据结构），用户程序不能访问
       ├──────────────┤
       │   用户栈  ↓   │ ← 局部变量、函数参数、返回地址（向低地址增长）
       │               │
       │   （未使用）   │
       │               │
       │   堆      ↑   │ ← malloc/new 动态申请的空间（向高地址增长）
       ├──────────────┤
       │ 可读写数据区   │ ← 全局变量、static 变量（.data 已初始化 / .bss 未初始化）
       ├──────────────┤
       │ 只读代码区     │ ← 程序代码（.text）、只读常量（如字符串常量）
低地址 └──────────────┘
```

**真题（2025 年第 46 题）**：
```c
char *ptr;
void main() {
    int length;
    ptr = (char *)malloc(sizeof(char));
    scanf("%s", ptr);
    length = strlen(ptr);
    printf("length=%d\n", length);
    free(ptr);
}
```
1. **PCB 在哪个区？** → **内核区**。**执行 scanf() 等待键盘输入时进程什么状态？** → **阻塞态**
2. **main() 的代码在哪？** → **只读代码区**。**直接调用的哪些函数需要执行驱动程序？** → **scanf（键盘驱动）和 printf（显示器驱动）**。malloc、strlen、free 只在内存里操作，不涉及 I/O 设备
3. **变量 ptr 分配在哪？** → 全局变量 → **可读写数据区**。**length（不在寄存器时）？** → 局部变量 → **用户栈**。**ptr 指向的字符串在哪？** → malloc 申请的 → **堆**

### 📖 覆盖与交换（了解）
- **覆盖**：程序分成几段，常用的段常驻内存，不常用的段**轮流共用**一块“覆盖区”（程序员要自己设计，同一个进程内）
- **交换**：把暂时不运行的**整个进程**换到外存，需要时再换回来（中级调度，不同进程之间）

## 9.2 连续分配管理

### 📖 三种方式
1. **单一连续分配**：内存分系统区和用户区，用户区只放一道程序。无外部碎片，有内部碎片
2. **固定分区分配**：把内存事先切成若干固定大小的分区，每个分区放一个程序
   - 程序比分区小，剩下的浪费了 → **内部碎片**
3. **动态分区分配**：按程序实际需要的大小**现切**一块
   - 用久了会出现很多小空闲块，单个都太小用不了 → **外部碎片**
   - 解决外部碎片：**紧凑**（把程序挪到一起，需要动态重定位支持）

🧒 **内部碎片 vs 外部碎片**：
- **内部碎片**：分给你的房间里**你没用完**的空间（分配给进程了，但进程用不上）
- **外部碎片**：**没分给任何人**，但因为太零碎，谁都用不上的空间

### 📖 动态分区的分配算法（⭐）
| 算法 | 规则 | 空闲分区排序 | 特点 |
|---|---|---|---|
| **首次适应（FF）** | 从头找，第一个够大的就用 | 按**地址递增** | **综合性能最好**，低地址会留下很多小碎片 |
| **邻近适应（NF）** | 从上次找到的位置接着找 | 按地址（循环） | 高地址的大分区也会被切碎 |
| **最佳适应（BF）** | 找**最小的够用**的分区 | 按**容量递增** | 留下的碎片最小，但会产生**大量很小的外部碎片** |
| **最坏适应（WF）** | 找**最大的**分区 | 按**容量递减** | 留下的块较大还能用，但**大分区很快被用光** |

**例**：空闲分区（按地址）：100KB、500KB、200KB、300KB、600KB，依次申请 212KB、417KB、112KB、426KB。
- **首次适应**：212→500（剩 288）；417→600（剩 183）；112→288（剩 176）；426→**无法分配**
- **最佳适应**：212→300（剩 88）；417→500（剩 83）；112→200（剩 88）；426→600（剩 174）✓ 全部成功

### 📖 回收时的合并
回收一块时，看它的**前后邻居**是否空闲，是就合并。共 4 种情况：前空、后空、前后都空（三合一，空闲分区数 −1）、都不空（新增一个空闲分区）。

## 9.3 基本分页存储管理（⭐⭐⭐）

### 🧒 大白话
连续分配的碎片问题太头疼。**分页**的思路：
- 把**内存**切成大小相同的小格子，叫**页框（物理块）**
- 把**进程**也切成同样大小的小块，叫**页（页面）**
- 进程的每一页可以放进**任意一个空闲页框**，**不需要连续**！
- 用一张**页表**记录“第几页放在第几个页框”

就像**快递柜**：一个大包裹拆成几个小箱子，分别放在任意空格子里，手机里记着每个箱子在哪格。
→ **没有外部碎片**，只有每个进程最后一页的**少量内部碎片**。

### 📖 地址结构
```
逻辑地址 = | 页号 P | 页内偏移 W |
```
页大小 L = 2ⁿ 字节 → 页内偏移 n 位
- **页号 P = 逻辑地址 A / L**（整除）
- **页内偏移 W = A % L**
- **物理地址 = 页框号 × L + W**（二进制下就是：把页号换成页框号，偏移不变）

### ✏️ 例题
页大小 1 KB（2¹⁰），页表：页 0 → 页框 5，页 1 → 页框 10，页 2 → 页框 4。逻辑地址 2500 对应的物理地址？
- 页号 = 2500 / 1024 = **2**，偏移 = 2500 % 1024 = **452**
- 页 2 在页框 4 → 物理地址 = 4 × 1024 + 452 = **4548**

**十六进制时更简单**（页大小 4 KB = 2¹² → 低 3 个十六进制位是偏移）：
逻辑地址 2A3FH，页 2 在页框 8 → 物理地址 **8A3FH**（把最高位的页号 2 换成页框号 8）

**真题（2021 年第 28 题）**：页大小 4 KB，进程 P 访问虚拟地址 02A01H，页表：页 0 → 20H（不存在），页 1 → 60H（存在），页 2 → 80H（存在）。物理地址？
- 页号 = 02A01H 的高位 = **2**，偏移 = **A01H**
- 页 2 存在，页框 80H → 物理地址 **80A01H**，选 D
- 🧒 题目里说的“改进型 Clock 置换算法”是**干扰项**——页 2 就在内存里，根本不用置换！

### 📖 页表项和页表
- **页表项**至少包含**页框号**（请求分页还有状态位、访问位、修改位等）
- **页表放在主存里**，页表的起始地址放在 PCB 中；进程运行时装入**页表基址寄存器（PTBR）**
- **页表项的地址 = 页表起始地址 + 页号 × 页表项长度**
- 页表项个数 = 逻辑地址空间的页数 = 2^(页号位数)

### 📖 访存次数和有效访问时间（⭐）
- **无快表**：访问一个数据要访存 **2 次**（先查页表，再访问数据）
- **有快表（TLB）**：命中时只要 1 次访存
- **有效访问时间 EAT**（设 TLB 时间 ε，访存时间 t，TLB 命中率 α，先查 TLB 再查页表）：
  ```
  EAT = α(ε + t) + (1 − α)(ε + 2t)
  ```
  **例**：ε = 20 ns，t = 100 ns，α = 90% → EAT = 0.9 × 120 + 0.1 × 220 = 108 + 22 = **130 ns**

### 📖 两级页表（⭐）
🧒 页表太大：32 位地址、4 KB 页 → 2²⁰ 个页表项 × 4 B = **4 MB**，而且要**连续**放在内存里！
解决：给页表**再分页**。
```
逻辑地址 = | 一级页号（页目录号） | 二级页号 | 页内偏移 |
```
- 一级页表（页目录）：记录每个二级页表放在哪个页框
- 二级页表：记录每个页放在哪个页框
- 只有**用到的**二级页表才需要调入内存
- 代价：没有 TLB 时访问一个数据要访存 **3 次**

**设计原则：每一级页表的大小不超过一页**。
例：32 位地址，页 4 KB，页表项 4 B → 一页能放 4K/4 = 2¹⁰ 个页表项 → 每级页号 10 位 → 20 位页号需要 **2 级**。（2020 年 46 题就是这个结构，详细解答见[组成原理存储系统篇 5.8 节](02-组成原理-2-存储系统.md)。）

**真题（2021 年第 29 题）**：二级页表时，页表基址寄存器里存的是 **B. 当前进程的一级页表的起始物理地址**。

## 9.4 基本分段和段页式

### 📖 分段
🧒 分页是“机械地切成等大小块”，不管程序的逻辑。**分段**按程序的**逻辑模块**划分：代码段、数据段、栈段、某个函数……每段长度不同。
```
逻辑地址 = | 段号 S | 段内偏移 W |
```
- **段表**：每段的**段长**和**基址**
- 地址转换：
  1. 段号 S ≥ 段表长度 → 越界中断
  2. 查段表得到段长 C 和基址 b
  3. **段内偏移 W ≥ 段长 C → 越界中断**（⭐ 分段多了这一步检查）
  4. 物理地址 = b + W
- **优点**：便于**共享和保护**（按逻辑模块共享，比如共享一段代码）；便于动态增长
- **缺点**：段长不一，会有**外部碎片**
- **分页的地址空间是一维的，分段是二维的**（程序员要给出段号和段内地址）

### 📊 分页 vs 分段
| | 分页 | 分段 |
|---|---|---|
| 划分依据 | 物理的、固定大小 | 逻辑的、大小不定 |
| 对用户 | **不可见**（系统自动） | **可见**（程序员/编译器划分） |
| 地址空间 | **一维** | **二维** |
| 碎片 | 内部碎片 | 外部碎片 |
| 共享保护 | 不方便 | **方便** |

### 📖 段页式
先分段，每段再分页。**逻辑地址 = 段号 + 段内页号 + 页内偏移**
- 每个进程**一张段表**，**每个段一张页表**
- 没有快表时访问一个数据要访存 **3 次**（段表 → 页表 → 数据）

## 9.5 虚拟内存（⭐⭐⭐）

### 🧒 大白话
程序运行时，**不需要全部装进内存**！只装正在用的几页，其余留在硬盘，需要时再调进来。
这样：
- 能运行**比内存还大**的程序
- 内存里能同时放**更多进程**

理论基础是**局部性原理**（见组成原理篇 5.7 节）。

**虚拟内存的特征**：**多次性**（一个作业分多次调入）、**对换性**（运行中可换进换出）、**虚拟性**（逻辑上扩大了内存容量）。
**虚拟内存的最大容量**由**计算机的地址结构（地址位数）**决定，实际容量 ≤ min(内存 + 外存, 2^地址位数)。

### 📖 请求分页的页表项
| 字段 | 作用 |
|---|---|
| 页框号 | 在内存哪个页框 |
| **状态位（存在位/有效位）** | 这页在不在内存 |
| **访问字段（访问位）** | 最近有没有被访问（置换算法用） |
| **修改位（脏位）** | 调入后有没有被修改过（被修改过的换出时要写回外存） |
| 外存地址 | 这页在磁盘上的位置 |

### 📖 缺页中断（⭐）
访问的页不在内存（状态位 = 0）→ 产生**缺页中断**（属于**内部异常中的故障**）
处理过程：
1. 保存现场，进入内核
2. 在外存中找到该页
3. 内存有空闲页框 → 直接调入；**没有** → 用置换算法**选一页淘汰**（如果被淘汰的页**修改过**，要先写回外存）
4. 把所需页从外存**读入**内存
5. **修改页表**（页框号、状态位），可能还要更新 TLB
6. 返回，**重新执行**引起缺页的那条指令

**真题（2022 年第 29 题）**：缺页处理中**不一定**包含的是 **A. 淘汰内存中的页**（如果有空闲页框就不用淘汰）。建立页号与页框号的对应、把页 b 读入、修改存在位都是一定要做的。

⚠️ **一条指令执行期间可能产生多次缺页中断**（比如一条 move 指令本身跨页，操作数也跨页）。

**真题（2025 年第 27 题）**：确定进程运行所需的**最少页框数**时，要考虑的是 **D. 指令系统支持的寻址方式**（最少页框数要保证**一条指令执行需要用到的所有页**都能同时在内存里；例如间接寻址时，指令本身、地址单元、操作数可能分别在不同页，都得同时在内存）。

**真题（2020 年第 28 题）**：影响请求分页系统有效访存时间的：缺页率、磁盘读写时间、内存访问时间、执行缺页处理程序的 CPU 时间 → **全部**，选 D。

**有效访问时间（含缺页）**：
```
EAT = (1 − p) × 访存时间 + p × 缺页处理时间     （p 是缺页率）
```

### 📖 页框分配策略
- **驻留集**：分给一个进程的页框集合
- **固定分配**：页框数固定；**可变分配**：可以增减
- **局部置换**：缺页时只能换自己的页；**全局置换**：可以抢别的进程的页框
- 组合：固定分配局部置换、可变分配全局置换、可变分配局部置换（**没有固定分配全局置换**）

**调页策略**：
- **预调页**：根据局部性提前调入（用于进程首次调入）
- **请求调页**：缺页时才调

## 9.6 页面置换算法（⭐⭐⭐ 必考计算）

统一用一个例子：**3 个页框**，访问序列 `7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2`（× 表示缺页）

### ① 最佳置换（OPT）
🧒 **淘汰以后最长时间不会再用到的页**（能“预知未来”，理论最优，**实际无法实现**，只用来比较）
| 访问 | 7 | 0 | 1 | 2 | 0 | 3 | 0 | 4 | 2 | 3 | 0 | 3 | 2 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 内存 | 7 | 0 7 | 0 1 7 | 0 1 2 | 0 1 2 | 0 2 3 | 0 2 3 | 2 3 4 | 2 3 4 | 2 3 4 | 0 2 3 | 0 2 3 | 0 2 3 |
| 缺页 | × | × | × | × | | × | | × | | | × | | |
| 淘汰 | | | | 7 | | 1 | | 0 | | | 4 | | |
缺页 **7 次**。
（第 4 步访问 2 时：内存里有 7、0、1。往后看，0 很快就会再用，而 7 和 1 以后**都不会再出现**，淘汰哪个都行，这里淘汰 7。）

### ② 先进先出（FIFO）
🧒 **淘汰最早进来的页**（像排队，队头出队）
| 访问 | 7 | 0 | 1 | 2 | 0 | 3 | 0 | 4 | 2 | 3 | 0 | 3 | 2 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 缺页 | × | × | × | × | | × | × | × | × | × | × | | |
| 淘汰 | | | | 7 | | 0 | 1 | 2 | 3 | 0 | 4 | | |
缺页 **10 次**。

⚠️ **Belady 异常**：FIFO 算法**分配的页框增多，缺页次数反而可能增加**！
经典例子：序列 `1,2,3,4,1,2,5,1,2,3,4,5`，3 个页框缺页 9 次，4 个页框缺页 **10 次**。
**只有 FIFO 会出现 Belady 异常**（LRU、OPT 不会）。

### ③ 最近最久未使用（LRU）
🧒 **淘汰最长时间没被访问过的页**（“用过去预测未来”，性能接近 OPT，但需要硬件支持——寄存器或栈，开销大）
| 访问 | 7 | 0 | 1 | 2 | 0 | 3 | 0 | 4 | 2 | 3 | 0 | 3 | 2 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 缺页 | × | × | × | × | | × | | × | × | × | × | | |
| 淘汰 | | | | 7 | | 1 | | 2 | 3 | 0 | 4 | | |
缺页 **9 次**。
🧒 做题技巧：要淘汰时，**从当前位置往前看**，内存里的哪个页**最久以前**出现过，就淘汰它。
（访问 4 时，内存有 0、2、3；往前看：0 刚刚用过，3 前一次在第 6 位，2 在第 4 位 → 淘汰 2。）

**真题（2025 年第 26 题）**：LRU，局部置换，3 个页框，访问序列 {0, 1, 2, 0, 5, 1, 4, 3, 0, 2, 3, 2, 0}，**其中 0、1、2 已调入内存**。缺页次数？
- 0、1、2、0：都命中
- 5：缺页，往前看：0 刚用，2 第 3 位，1 第 2 位 → 淘汰 **1** → {0, 2, 5}
- 1：缺页，最久未用的是 2 → {0, 5, 1}
- 4：缺页，淘汰 0 → {5, 1, 4}
- 3：缺页，淘汰 5 → {1, 4, 3}
- 0：缺页，淘汰 1 → {4, 3, 0}
- 2：缺页，淘汰 4 → {3, 0, 2}
- 3、2、0：命中
- 共 **6 次**，选 B

### ④ 时钟置换（CLOCK / NRU）
🧒 LRU 太贵，CLOCK 是它的“**便宜近似版**”：
- 所有页框围成一个**圈**，有一个指针
- 每页有一个**访问位**：被访问时置 1
- 要淘汰时，指针转圈检查：
  - 访问位 = 1 → 给它“**第二次机会**”：置 0，指针往下走
  - 访问位 = 0 → **淘汰它**
- 最多转**两圈**一定能找到

### ⑤ 改进型 CLOCK
同时考虑**访问位 A** 和**修改位 M**（没被修改的页淘汰时不用写回磁盘，更划算）：
1. 第 1 轮：找 **(A=0, M=0)** 的，找到就淘汰。这一轮**不修改**任何访问位
2. 第 2 轮：找 **(A=0, M=1)** 的，找到就淘汰。这一轮扫过的页**访问位置 0**
3. 还没找到 → 重复第 1 轮、第 2 轮（此时所有访问位都是 0 了，一定能找到）
- 最多扫 **4 轮**
- 淘汰优先级：(0,0) > (0,1) > (1,0) > (1,1)

## 9.7 抖动和工作集

### 📖 抖动（颠簸）
🧒 分给进程的页框**太少**，刚换出去的页马上又要用，又换进来……**大部分时间都在换页，几乎不干正事**。
- 原因：同时运行的进程**太多**，每个分到的页框太少
- 解决：减少进程数（挂起一些进程）、增加页框、采用**工作集**策略

### 📖 工作集
**工作集**：在最近一段时间窗口 Δ 内，进程**实际访问过的页面集合**。
例：Δ = 5，访问序列 `… 2 4 5 2 3 | 当前`，工作集 = {2, 3, 4, 5}（最近 5 次访问中出现的不同页）
- 分配给进程的页框数（驻留集）应**不小于工作集大小**，否则会频繁缺页

**真题（2022 年第 30 题）**：**不会**影响缺页率的是 **D. 页缓冲队列的长度**（页缓冲只是让被淘汰的页暂时不真正写出，减少 I/O 开销，不改变缺页次数）。置换算法、工作集大小、进程数量都会影响缺页率。

## 9.8 内存映射文件

### 🧒 大白话
把磁盘上的一个文件，**直接映射到进程的虚拟地址空间**里。之后读写文件就像读写内存数组一样（用指针），操作系统在背后按需把文件的页调入调出。
- 多个进程映射**同一个文件**，就能**共享内存 → 实现进程间通信**

**真题（2025 年第 30 题）**：关于内存映射文件，正确的是：
- I. 可实现进程间通信 ✓
- II. 实现了页面到磁盘块的映射 ✓（虚拟页 ↔ 文件的磁盘块）
- III. 将文件映射到进程的**虚拟地址空间** ✓
- IV. 将文件映射到系统的**物理地址空间** ✗
- 选 **D（I、II、III）**

## 9.9 本篇小结

| 知识点 | 一句话 |
|---|---|
| 动态重定位 | 运行时靠重定位寄存器转换，程序可移动 |
| 内存映像 | 代码（只读）→ 数据（全局/static）→ 堆（malloc）↑ … ↓ 栈（局部变量）→ 内核（PCB） |
| 碎片 | 固定分区、分页：内部碎片；动态分区、分段：外部碎片 |
| 首次适应 | 地址递增找第一个，综合最好 |
| 分页地址 | 页号 = A / L，偏移 = A % L；物理 = 页框号 × L + 偏移 |
| 页表项地址 | 页表起始 + 页号 × 项长 |
| 访存次数 | 一级页表 2 次，二级 3 次；TLB 命中 1 次 |
| 分段 | 二维、用户可见、多一步“段内偏移 < 段长”检查 |
| 缺页中断 | 内部故障；可能不需淘汰；返回后重新执行本指令 |
| OPT / FIFO / LRU | 看未来最远 / 最早进来 / 往回看最久没用 |
| Belady | 只有 FIFO 会 |
| CLOCK | 访问位 1 → 置 0 给第二次机会；改进型最多 4 轮 |
| 抖动 | 页框太少/进程太多；用工作集解决 |

## 9.10 课后练习

1. 页大小 2 KB，逻辑地址 5000 在第几页，页内偏移多少？
2. 某系统 TLB 命中率 80%，TLB 访问 10 ns，内存访问 100 ns，求有效访问时间。
3. 4 个页框，访问序列 `1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5`，用 LRU 缺页几次？
4. 为什么说 FIFO 性能差？

<details>
<summary>答案</summary>

1. 5000 / 2048 = 2（第 2 页），偏移 5000 − 4096 = 904
2. 0.8 × 110 + 0.2 × 210 = 88 + 42 = 130 ns
3. 1,2,3,4 缺 4 次；1,2 命中；5 缺（淘汰 3）；1,2 命中；3 缺（淘汰 4）；4 缺（淘汰 5）；5 缺（淘汰 1）→ 共 **8 次**
4. 最早进来的页可能恰恰是最常用的（如循环里的代码），FIFO 不考虑使用情况，而且会有 Belady 异常
</details>
