## 5.1 存储器的层次结构

### 🧒 大白话
你写作业时：
- **桌面**（寄存器）：放最常用的笔，伸手就拿到，但只能放几样
- **抽屉**（Cache）：放常用的书，拉开就拿到
- **书架**（主存/内存）：书很多，要走过去拿
- **地下室仓库**（辅存/硬盘）：什么都有，但要跑一趟

越往上**越快、越贵、越小**；越往下**越慢、越便宜、越大**。
聪明的做法：把**最近要用的**东西从下面搬到上面来。

```
     寄存器
      Cache        ← Cache–主存层次：解决 CPU 和主存 速度 不匹配（由硬件自动完成）
      主存
      辅存         ← 主存–辅存层次：解决主存 容量 不够（由硬件 + 操作系统完成）→ 虚拟存储器
```

> 📌 **上一层的内容是下一层的副本**（Cache 里的内容主存里也有）。
> Cache–主存之间的调度**对所有程序员透明**；主存–辅存之间的调度对应用程序员透明，但操作系统要参与。

## 5.2 存储器的分类和指标

### 📖 按存取方式
- **随机存取（RAM）**：访问任何地址时间都一样（内存）
- **顺序存取（SAM）**：只能按顺序访问（磁带）
- **直接存取（DAM）**：先找到大致区域，再在区域内顺序找（磁盘）
- **相联存储器（CAM）**：按**内容**找而不是按地址找（TLB、Cache 的比较部分用它）

### 📖 按能否改写
- **RAM**：可读可写，**断电丢失**（易失性）
- **ROM**：只读（或很难写），**断电不丢失**。BIOS 就放在 ROM 里
  - MROM（出厂写死）→ PROM（能写一次）→ EPROM（紫外线擦除）→ EEPROM（电擦除）→ **Flash**（闪存，U 盘、SSD 都是它）
- ⚠️ ROM 和 RAM **都是随机存取**的！

### 📖 性能指标
- **存取时间**：从发出读命令到拿到数据的时间
- **存取周期**：连续两次访问之间的最小间隔（**存取周期 > 存取时间**，因为读完还要“恢复”一下）
- **带宽** = 存储字长 / 存取周期

## 5.3 SRAM 和 DRAM（⭐）

### 🧒 大白话
- **SRAM**（静态 RAM）：每个位用**触发器**（6 个晶体管）存，只要通电就一直记得。**快，贵，大**（占面积）。→ 做 **Cache**
- **DRAM**（动态 RAM）：每个位用一个**电容**存，电容会慢慢漏电，所以要定期“**刷新**”（重新充电）。**慢，便宜，集成度高**。→ 做**主存**

| 比较 | SRAM | DRAM |
|---|---|---|
| 存储元件 | 双稳态触发器 | 电容 |
| 需要刷新 | 否 | **是** |
| 速度 | 快 | 慢 |
| 集成度 | 低 | 高 |
| 地址线 | 一次送全部地址 | **行、列地址分两次送（地址复用）** |
| 用途 | **Cache** | **主存** |
| 读后需要再生 | 否（非破坏性读） | 是（破坏性读） |

**真题（2020 年第 15 题）**：关于 TLB 和 Cache，错误的是 **D. 都由 DRAM 组成**（它们都要很快，都是 **SRAM**）。

### 📖 DRAM 的地址复用（⭐ 陷阱）
DRAM 芯片把地址分成**行地址**和**列地址**，**分两次**通过**同一组引脚**送进去。所以**地址引脚数减半**。
- 一个 2ⁿ 单元的 DRAM 芯片（行列相等），地址引脚只要 **n/2** 根

**真题（2022 年第 17 题）**：内存条有 8 个 8192×8192×8 位的 DRAM 芯片，总线宽 64 位，不正确的是？
- A. 容量 = 8 × 2¹³ × 2¹³ × 1B = 8 × 64 MB = **512 MB** ✓
- B. 8 个芯片各出 8 位拼成 64 位，连续地址分布在不同芯片 → 属于多模块交叉编址 ✓
- C. **芯片地址引脚 26 位** ✗！DRAM 地址复用，行列地址各 13 位，分两次送，**只要 13 根**
- D. 行缓冲存一整行：8192 × 8 位 ✓
- 选 **C**

### 📖 DRAM 刷新
- **按行刷新**：一次刷新一整行
- **刷新周期**：通常 2 ms 内要把所有行都刷一遍
- 三种方式：**集中刷新**（专门抽一段时间全刷，有“死区”）、**分散刷新**（每次存取后刷一行，存取周期变长）、**异步刷新**（把刷新均匀分散到 2 ms 内，最常用）
- 刷新**不需要 CPU 控制**，由存储器内部的刷新电路完成

## 5.4 主存储器与 CPU 的连接（⭐ 芯片扩展计算）

### 🧒 大白话
你想要一个 **8K × 8 位** 的内存，但手上只有 **2K × 4 位** 的小芯片，怎么拼？
- **位扩展**（宽度不够）：2 个 4 位的芯片**并排**，拼成 8 位宽。像把两条窄马路并成一条宽马路。
- **字扩展**（数量不够）：4 组**上下**叠起来，每组 2K，共 8K。像盖楼，每层是一组。
- 需要芯片数 = 总容量 / 单片容量 = (8K × 8) / (2K × 4) = **8 片**

### 📖 片选
字扩展时，每组芯片都用同样的低位地址，靠**高位地址**决定“这次访问哪一组”：
- 8K 需要 13 位地址（A12~A0）；每片 2K 需要 11 位（A10~A0）接到所有芯片
- 剩下的 A12、A11 接一个 **2-4 译码器**，4 个输出分别接 4 组芯片的**片选端 CS**

**真题（2021 年第 15 题）**：24 位地址线，32 位数据线，**按字编址**，字长 32 位。000000H ~ 3FFFFFH 为 RAM 区，用 512K × 8 位的芯片需要几片？
- RAM 区单元数：3FFFFFH + 1 = 400000H = 2²² 个字，每个字 32 位
- 芯片数 = (2²² × 32) / (2¹⁹ × 8) = 2³ × 4 = **32 片**，选 C

> ⚠️ **看清“按字编址”还是“按字节编址”**！地址范围算出来的是“单元个数”，每个单元多大要看编址方式。

## 5.5 多模块存储器（提高主存带宽）

### 🧒 大白话
一个存储体读一次要花时间 T，读完还要“休息”。怎么更快？**多请几个工人轮流干！**

- **高位交叉编址**：高位地址选模块。连续的地址在**同一个模块**里 → 连续访问时没法并行（主要用来**扩容**）
- **低位交叉编址**：**低位地址**选模块。连续的地址**轮流分布**在不同模块 → 可以像**流水线**一样轮流启动

**低位交叉 m 个模块**，每个模块存取周期 T，总线传一个字的时间 r（理想情况 T = m × r）：
- 连续读 m 个字的时间 = **T + (m − 1) × r**
- 如果只用一个模块则要 m × T

**例**：4 体低位交叉，T = 200 ns，r = 50 ns，连续读 4 个字：200 + 3 × 50 = **350 ns**（顺序方式要 800 ns）

## 5.6 外存：磁盘和固态硬盘

### 📖 磁盘结构
🧒 就像**一摞唱片**，每张唱片两面都能写，每面有一圈圈的**磁道**，每个磁道被切成若干**扇区**（一块蛋糕切成若干块）。所有盘面上半径相同的磁道组成一个**柱面**。
- 磁盘地址：**柱面号（磁道号） + 盘面号（磁头号） + 扇区号**
- 各字段位数 = log₂（对应的数量）向上取整

### 📖 磁盘访问时间（⭐）
```
访问时间 = 寻道时间 + 旋转延迟 + 传输时间
```
- **寻道时间**：磁头移动到目标磁道（题目会给平均寻道时间）
- **旋转延迟**：等目标扇区转到磁头下 = **转半圈的时间**
  - 7200 RPM：转一圈 = 60/7200 s ≈ 8.33 ms → 平均旋转延迟 ≈ **4.17 ms**
- **传输时间**：读完这个扇区 = 转一圈的时间 / 每磁道扇区数

### 📖 固态硬盘（SSD）
- 基于 **Flash 闪存**，没有机械部件，随机访问快
- **按页读写，按块擦除**（一块含很多页）；**写之前必须先擦除**
- 每个块擦写次数有限 → 需要**磨损均衡**（让写入均匀分布到所有块）
- 由**闪存翻译层（FTL）**把逻辑块号映射到物理页
- 随机写比读慢得多

## 5.7 Cache（⭐⭐⭐ 重中之重）

### 5.7.1 为什么 Cache 有用：局部性原理
🧒 你写作业时，**刚用过的书**过一会儿很可能还要用（**时间局部性**）；用了第 10 页，接下来很可能看第 11 页（**空间局部性**）。
- **时间局部性**：刚访问的数据，不久后很可能再访问（循环中的变量、循环体指令）
- **空间局部性**：访问了某个地址，附近的地址很可能马上被访问（数组按顺序遍历、顺序执行的指令）

所以 Cache 每次从主存搬数据，都**一次搬一整块**（主存块，如 64B），而不是只搬 1 个字节。

**真题（2020 年第 46 题第 3 问）**：数组 a 按行优先存放，按行遍历还是按列遍历局部性更好？→ **按行遍历**，因为访问的地址是连续的（空间局部性好）。

### 5.7.2 性能计算
- **命中率 h** = 命中次数 / 总访问次数
- **平均访问时间**（设 Cache 时间 tc，主存时间 tm）：
  - 先访问 Cache，不命中再访问主存：**t = tc + (1 − h) × tm**
  - Cache 和主存同时访问：**t = h × tc + (1 − h) × tm**
  - 题目也可能直接给“缺失损失”：**t = 命中时间 + 缺失率 × 缺失损失**

### 5.7.3 地址映射（⭐⭐⭐）

🧒 **大白话**：主存很大（比如 4 GB），Cache 很小（比如 32 KB）。主存里的块要搬进 Cache 的某一行（Cache 行 = Cache 块），**放在哪一行？**

**比喻：停车场**
- **直接映射**：每辆车只能停在**指定的一个车位**（车牌尾号 % 车位数）。简单，但两辆车抢同一个车位时只能互相赶走，冲突多。
- **全相联映射**：**随便停**哪个空位。最灵活，但找车时要**把所有车位都看一遍**（比较器多，贵）。
- **组相联映射**：停车场分成若干**区**，每辆车只能停在**指定的区**，但区内随便停。折中方案。“8 路组相联”= 每个区有 8 个车位。

### 📖 地址划分（⭐ 必会）
主存地址被切成三段：

| 映射方式 | 地址划分（从高到低） |
|---|---|
| 直接映射 | 标记 Tag ｜ **行号** Index ｜ 块内地址 Offset |
| 组相联 | 标记 Tag ｜ **组号** Index ｜ 块内地址 Offset |
| 全相联 | 标记 Tag ｜ 块内地址 Offset |

**计算三步：**
1. **块内地址位数** = log₂(块大小)
2. **行号/组号位数** = log₂(行数 或 组数)；行数 = Cache 容量 / 块大小，组数 = 行数 / 路数
3. **Tag 位数** = 地址总位数 − 行号(组号)位数 − 块内地址位数

**真题（2022 年第 16 题）**：主存地址 32 位，按字节编址，Cache 数据区 32 KB，块大小 64B，8 路组相联。比较器个数和位数？
1. 块内地址：64 = 2⁶ → **6 位**
2. 行数 = 32K / 64 = 512 行，组数 = 512 / 8 = 64 组 → 组号 **6 位**
3. Tag = 32 − 6 − 6 = **20 位**
4. 组相联时，只在**一组**内同时比较 8 行 → 需要 **8 个比较器**，每个比 **20 位**（比 Tag）
5. 选 A

> 📌 比较器个数：直接映射 1 个；k 路组相联 k 个；全相联 = 行数个。比较器位数 = Tag 位数。

### 📖 Cache 行的组成
每一行不只存数据，还要存：
```
┌───────┬───────┬──────────┬──────────┬───────────────┐
│ 有效位 │ 脏位   │ 替换控制位 │   Tag    │  数据（一整块） │
│  1位  │ 1位*  │  若干位*   │          │               │
└───────┴───────┴──────────┴──────────┴───────────────┘
 * 脏位：只有“回写法”才需要；替换控制位：只有组相联/全相联用 LRU 等算法时才需要
```
- **LRU 位数**：k 路组相联用 LRU，每行需要 **log₂k** 位计数器（8 路 → 3 位）

**真题（2021 年第 16 题）**：地址 32 位，Cache 数据区 32 KB，块 32B，**直接映射，回写**。Cache 行至少多少位？
1. 块内地址：log₂32 = 5 位
2. 行数 = 32K / 32 = 1024 → 行号 10 位
3. Tag = 32 − 10 − 5 = **17 位**
4. 行位数 = 数据 32 × 8 = 256 位 + Tag 17 + 有效位 1 + **脏位 1**（回写要脏位）+ 替换位 0（直接映射不需要）= **275**，选 A

### 5.7.4 替换算法
组满了、又要放新块时，赶走谁？
- **随机（RAND）**：随便赶
- **FIFO**：赶走**最早进来**的
- **LRU（最近最少使用）**：赶走**最久没被访问过**的（利用时间局部性，命中率高）⭐
- **LFU（最不经常使用）**：赶走**访问次数最少**的
- 直接映射**不需要**替换算法（只有一个位置可以放）

### 5.7.5 写策略（⭐）
CPU 要**写** Cache 里的数据时，主存里的副本怎么办？

**写命中时：**
- **全写法（写直达，Write Through）**：同时写 Cache 和主存。简单，但慢 → 通常加**写缓冲**
- **回写法（Write Back）**：只写 Cache，把这行标记为“**脏**”（脏位 = 1）；等这行被**替换时**才写回主存。快，但需要**脏位**

**写不命中时：**
- **写分配**：把块调入 Cache 再写（常配合回写）
- **非写分配**：直接写主存，不调入（常配合全写）

**真题（2020 年第 44 题，10 分）**：地址 32 位，按字节编址，指令 Cache、数据 Cache 均为 **8 路组相联**、**直写**、**LRU**，块 64B，数据区各 32 KB。
1. **Tag、LRU 位各几位？有修改位吗？**
   - 块内 6 位；行数 512，组数 64 → 组号 6 位；Tag = 32 − 12 = **20 位**
   - 8 路 LRU → **3 位**
   - **直写 → 不需要修改位（脏位）**
2. `for (k = 0; k < 1024; k++) s[k] = 2 * s[k];` s 是 int 数组，起始地址 0080 00C0H，数据 Cache 缺失几次？
   - 数组大小 1024 × 4 = 4 KB；起始地址 C0H = 192 = 3 × 64，**正好对齐块边界**
   - 共占 4096 / 64 = **64 块**
   - 每块第一次读时缺失，调入后这块里的 16 个 int 的读和写都命中
   - 缺失 **64 次**
3. **CPU 访问主存地址 0001 0003H 的指令，简述 Cache 访问过程（含缺失处理）**：
   - 地址划分：Tag = 00010H（高 20 位），组号 = 0（中间 6 位），块内地址 = 3
   - 用组号 0 找到**指令 Cache** 的第 0 组，把 Tag 与组内 8 行的 Tag 比较（同时检查有效位）
   - 开始时 Cache 为空 → **缺失**
   - 从主存读取 0001 0000H ~ 0001 003FH 这一整块，放到第 0 组的一个空行，设置有效位 = 1、写入 Tag、更新 LRU 位
   - 再按块内地址 3 取出指令送 CPU

### ✏️ 综合大题：2025 年第 43 题（⭐ 最新真题，完整走一遍）
> 32 位机，按字节编址，数据 Cache 数据区 32 KB，8 路组相联，块 64B，命中时间 2 个时钟周期，缺失损失 200 个时钟周期。页式虚拟存储，页大小 4 KB。数组 d 起始虚拟地址 0180 0020H。
> ```c
> int x, d[2048], i;
> for (i = 0; i < 2048; i++) d[i] = d[i] / x;
> ```

**(1) 主存地址中 Cache 组号、块内地址各几位？虚拟地址哪些位可作 Cache 索引？**
- 块内地址 6 位；组数 = 32K/64/8 = 64 → 组号 6 位
- 组号占物理地址的第 11~6 位。页大小 4 KB → **页内偏移是低 12 位，虚拟地址和物理地址的低 12 位完全相同**！
- 所以虚拟地址的 **VA11 ~ VA6** 可以直接作为 Cache 组索引（不必等地址转换完成）

**(2) d[100] 的虚拟地址？所在主存块对应的 Cache 组号？**
- d[100] = 0180 0020H + 100 × 4 = 0180 0020H + 190H = **0180 01B0H**
- 组号 = 第 11~6 位：01B0H = 0001 1011 0000 → 第 11~6 位是 000110 = **6**

**(3) d[0] 在块内的偏移？缺失率和平均访问时间？**
- d[0] 块内偏移 = 低 6 位 = 20H（即 32）
- 数组占 2048 × 4 = 8 KB，从某块的第 32 字节开始，到 0180 2020H 之前结束
  - 第一块只含 8 个元素（32~63 字节），之后每块 16 个元素
  - 覆盖的块数：地址 0180 0020H ~ 0180 201FH，跨越 **129 块**
- 每个元素读一次、写一次 → 共 4096 次访问；每块只在第一次读时缺失 → 缺失 129 次
- 缺失率 = 129 / 4096 ≈ **3.15%**
- 平均访问时间 = 2 + 3.15% × 200 ≈ **8.30 个时钟周期**

**(4) 数组 d 分布在几个页中？缺页几次？**
- 页号 = 虚拟地址高 20 位：0180 0020H → 页 01800H；0180 201FH → 页 01802H
- 跨 01800H、01801H、01802H **3 个页**，缺页 **3 次**

## 5.8 虚拟存储器（⭐⭐⭐ 与操作系统交叉）

### 🧒 大白话
每个程序都以为自己拥有一大片连续的内存（比如 4 GB），这是一个“**假象**”（虚拟地址空间）。
实际上，程序被切成一页一页（比如每页 4 KB），**只把正在用的几页**放进真正的内存里，其余的放在硬盘上。需要时再调进来。

就像**图书馆借书**：你的书单（虚拟地址空间）上有 100 本书，但你桌上（内存）只放了正在看的 5 本，其他在书库（硬盘）里，要看时再去借。

### 📖 页式虚拟存储器
- **虚拟地址** = 虚页号（VPN） + 页内偏移
- **物理地址** = 物理页框号（PFN） + 页内偏移（**页内偏移不变**）
- **页表**：记录每个虚页放在哪个物理页框。页表项（PTE）包含：
  - **有效位（存在位）**：这页在不在内存
  - **物理页框号**
  - **脏位（修改位）**：虚拟存储器一律用**回写**（写硬盘太慢了）
  - **访问位**（给置换算法用）、访问权限位等
- **页表基址寄存器**：存当前进程页表的**起始物理地址**（2021 年第 29 题：二级页表时存的是**一级页表的起始物理地址**）

### 📖 TLB（快表）
🧒 每次访存都要先查页表（页表在主存里）→ 等于访存两次，太慢！
于是把**最近用过的页表项**放在一个小而快的 Cache 里，叫 **TLB（快表）**。
- TLB 本质就是**页表的 Cache**，也有直接映射、组相联、全相联
- TLB 表项 = **Tag（由虚页号得出） + 物理页框号 + 有效位 + …**
- 用虚页号访问 TLB 时：**虚页号 = TLB 标记 ｜ TLB 组号**（组相联时）

**真题（2021 年第 44 题）**：主存地址 24 位，虚拟地址 30 位，页大小 4 KB；TLB 2 路组相联、LRU，共 8 组。
1. 虚页号是哪几位？页内地址？
   - 页内地址：4 KB = 2¹² → **VA11 ~ VA0**
   - 虚页号：**VA29 ~ VA12**（18 位）
2. TLB 标记、TLB 组号是哪几位？
   - 8 组 → 3 位组号：虚页号的低 3 位 **VA14 ~ VA12**
   - TLB 标记：**VA29 ~ VA15**（15 位）
3. TLB 初始为空，依次访问虚页号 10, 12, 16, 7, 26, 4, 12, 20，哪个表项被替换？
   - 组号 = 虚页号 % 8：10→2，12→4，16→0，7→7，26→2，4→4，12→4（**命中**），20→4
   - 第 4 组：先放 12，再放 4，然后访问 12（命中，12 变成最近用过的），再来 20 → 组满，按 LRU 赶走**最久没用的 4**
   - **虚页号 4 对应的表项被替换**
4. 虚拟地址变成 32 位，TLB 表项增加几位？→ 虚页号多了 2 位，都加到 Tag 上 → **增加 2 位**

### 📖 多级页表
🧒 32 位地址、4 KB 页 → 2²⁰ 个页表项 × 4B = 4 MB 的页表，而且要**连续存放**，太大了！
把页表**再分页**：一级页表（页目录）指向二级页表，只有用到的二级页表才需要放在内存。

**真题（2020 年第 46 题）**：32 位，二级页表，页目录号 10 位 + 页号 10 位 + 页内偏移 12 位，页目录项和页表项都 4 字节。数组 a[1024][1024] 起始虚拟地址 1080 0000H，int 元素，页目录起始物理地址 0020 1000H。
1. a[1][2] 的虚拟地址 = 1080 0000H + (1 × 1024 + 2) × 4 = 1080 0000H + 1008H = **1080 1008H**
2. 拆分 1080 1008H = `0001 0000 10 | 00 0000 0001 | 0000 0000 1000`
   - 页目录号 = 00 0100 0010 = **042H**（66）
   - 页号 = **001H**
   - 页内偏移 = 008H
3. 对应页目录项的物理地址 = 页目录起始 + 页目录号 × 4 = 0020 1000H + 042H × 4 = 0020 1000H + 108H = **0020 1108H**
4. 若该目录项中的页框号为 00301H，则页表起始物理地址 = 0030 1000H，页表项地址 = 0030 1000H + 1 × 4 = **0030 1004H**
5. 数组 a 在**虚拟地址空间中连续**，在**物理地址空间中不必连续**（每页可以放在任意页框）

### 📖 一次完整的访存流程（⭐⭐ 必须能讲清楚）
```
CPU 给出虚拟地址
   │
   ▼
查 TLB ──命中──→ 得到物理地址 ─┐
   │不命中                    │
   ▼                          │
查主存中的页表                  │
   │                          │
   ├─ 有效位=1 → 得到页框号，更新 TLB ─┤
   │                          │
   └─ 有效位=0 → 缺页异常 → 操作系统从磁盘调入该页，更新页表 → 重新执行该指令
                              │
                              ▼
                  用物理地址查 Cache ──命中──→ 取出数据
                              │不命中
                              ▼
                  访问主存，把块调入 Cache，再取数据
```
可能的组合（选择题常考“不可能发生的情况”）：
- TLB 命中 → 页表一定命中（TLB 是页表的子集）
- **TLB 命中、页表缺失：不可能**
- **页表缺失、Cache 命中：不可能**（页都不在主存，Cache 里更不可能有）
- TLB 缺失、页表命中、Cache 缺失：可能

### 📖 段式和段页式虚拟存储
- **段式**：按程序的逻辑模块（代码段、数据段、栈段）划分，段长不固定。虚拟地址 = 段号 + 段内偏移
- **段页式**：先分段，段内再分页。虚拟地址 = 段号 + 段内页号 + 页内偏移。每个进程一张段表，每段一张页表
- 详见操作系统篇“内存管理”

## 5.9 本篇小结

| 知识点 | 一句话 |
|---|---|
| 层次 | Cache–主存：硬件，解决速度；主存–辅存：硬件+OS，解决容量 |
| SRAM/DRAM | SRAM 快、做 Cache；DRAM 要刷新、地址复用（引脚减半）、做主存 |
| 芯片扩展 | 片数 = 总容量 / 单片容量；高位地址译码做片选 |
| 低位交叉 | 连续访问 m 字：T + (m−1)r |
| 磁盘 | 寻道 + 半圈 + 传输 |
| Cache 地址 | Tag ｜ 组号/行号 ｜ 块内地址 |
| 比较器 | k 路 → k 个，位数 = Tag 位数 |
| Cache 行 | 数据 + Tag + 有效位 + 脏位（回写）+ LRU 位（log₂k） |
| 写策略 | 直写不要脏位；回写要脏位 |
| TLB | 页表的 Cache；虚页号 = Tag ｜ 组号 |
| 多级页表 | 页目录项地址 = 页目录基址 + 目录号 × 项长 |
| 不可能组合 | TLB 命中而页表缺失；页缺失而 Cache 命中 |

## 5.10 课后练习

1. 主存 256 MB，按字节编址，Cache 64 KB，块 16B，**4 路组相联**。求地址划分。
2. 用 1K × 4 位芯片组成 4K × 8 位存储器，需几片？地址线几根？
3. Cache 命中率 95%，Cache 访问时间 1 ns，主存 50 ns，先访问 Cache 再访问主存，平均访问时间？
4. 页大小 1 KB，虚拟地址 16 位，访问虚拟地址 0x1A2F，虚页号和页内偏移是多少？若该页在第 5 个页框，物理地址是多少？

<details>
<summary>答案</summary>

1. 地址 28 位；块内 4 位；行数 4096，组数 1024 → 组号 10 位；Tag = 28 − 10 − 4 = 14 位
2. (4K × 8) / (1K × 4) = 8 片；地址线 12 根（4K = 2¹²）
3. 1 + 0.05 × 50 = 3.5 ns
4. 页内偏移 10 位：0x1A2F = 0001 1010 0010 1111 → 虚页号 = 000110 = 6，偏移 = 10 0010 1111 = 0x22F；物理地址 = 5 × 1024 + 0x22F = 0x1400 + 0x22F = **0x162F**
</details>
