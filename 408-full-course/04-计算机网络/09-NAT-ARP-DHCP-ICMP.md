## 一、IP 分组的转发流程（⭐⭐⭐）

### 📐 路由表
路由表的每一项通常包括：**目的网络地址、子网掩码（前缀长度）、下一跳地址、接口**。
- **直接交付**：目的主机与本路由器（或本主机）**在同一个网络**上，直接交给目的主机（通过 ARP 获得目的主机的 MAC 地址）
- **间接交付**：目的主机不在同一网络，交给**下一跳路由器**
- **默认路由**：0.0.0.0/0，与任何地址都匹配，**最后**才选
- **特定主机路由**：/32，对特定的目的主机指明一个路由

### 📐 路由器的分组转发算法
1. 从数据报的首部提取**目的主机的 IP 地址 D**，得出目的网络地址 N（**D 与路由表中每一项的子网掩码相与**）
2. 若 N 就是与此路由器**直接相连**的某个网络地址，则进行**直接交付**
3. 若路由表中有目的地址为 D 的**特定主机路由**，则把数据报传送给路由表中所指明的下一跳路由器
4. 若路由表中有到达网络 N 的路由（若有多个匹配，按**最长前缀匹配**），则把数据报传送给路由表指明的下一跳路由器
5. 若路由表中有一个**默认路由**，则把数据报传送给路由表中所指明的默认路由器
6. 否则，报告转发分组出错（丢弃，并发送 ICMP **终点不可达**报文）

### 📐 主机发送 IP 分组时
主机用**自己的子网掩码**与目的 IP 地址相与：
- 结果等于本网络地址 → 目的主机在**同一网络**，直接用 ARP 查目的主机的 MAC 地址，直接发送
- 不等于 → 目的主机在**其他网络**，把分组发给**默认网关**（用 ARP 查默认网关的 MAC 地址）

### 📐 IP 地址与 MAC 地址在转发中的变化（⭐⭐⭐）
**在数据报的传输过程中**：
- **源 IP 地址和目的 IP 地址始终不变**（除非经过 NAT）
- **源 MAC 地址和目的 MAC 地址每经过一跳都会改变**（每一段链路上，MAC 帧的源地址是“这一跳的发送接口”，目的地址是“这一跳的接收接口”）

✏️ **例**：主机 A → 路由器 R → 主机 B（A 和 B 在不同网络）
| 链路段 | 源 IP | 目的 IP | 源 MAC | 目的 MAC |
|---|---|---|---|---|
| A → R | A 的 IP | **B 的 IP** | A 的 MAC | **R 左接口的 MAC** |
| R → B | A 的 IP | B 的 IP | **R 右接口的 MAC** | B 的 MAC |

🧒 **比喻**：寄快递，包裹上的**收件人地址（IP）**从头到尾不变；但每一段运输，**货车的起点站和终点站（MAC）**都不同。

## 二、网络地址转换 NAT（⭐⭐⭐）

### 📐 为什么需要 NAT
- IPv4 地址**不够用**了，很多机构内部使用**私有地址**（10.x、172.16~31.x、192.168.x）
- 私有地址在互联网上**不能路由**，内部主机要访问互联网，必须把私有地址**转换**成合法的**全球 IP 地址（公网地址）**

### 📐 NAT 的原理
在专用网连接到因特网的**路由器上安装 NAT 软件**（称为 **NAT 路由器**），它至少有一个**有效的外部全球 IP 地址**。
- 所有使用本地地址的主机在和外界通信时，都要在 NAT 路由器上将其本地地址**转换成全球 IP 地址**
- 为了让更多的内部主机共享一个公网地址，通常使用**网络地址与端口号转换（NAPT）**：同时转换 **IP 地址和端口号**

### 📐 NAT 转换表
| WAN 端（外网） | LAN 端（内网） |
|---|---|
| 公网 IP : 端口 | 私有 IP : 端口 |
| 138.76.29.7 : 5001 | 10.0.0.1 : 3345 |
| 138.76.29.7 : 5060 | 10.0.0.4 : 80 |

- **内网 → 外网**：NAT 路由器把分组的**源 IP 和源端口**替换成**公网 IP 和新端口**，并在表中记录这个对应关系
- **外网 → 内网**：NAT 路由器根据**目的 IP 和目的端口**查表，替换成对应的**私有 IP 和端口**，转发给内网主机

⚠️ NAT 要修改**传输层**的端口号，严格来说“违反了分层原则”；NAT 对外隐藏了内部网络结构，**外网主机不能主动**访问内网主机——除非在 NAT 路由器上**手动配置静态映射**（端口映射）。

📝 **真题（2023 年第 38 题）**：某网络拓扑如下图所示，其中路由器 R2 实现 NAT 功能。若主机 H 向 Internet 发送一个 IP 分组，则经过 R2 转发后，该 IP 分组的源 IP 地址是：
```
Internet ── R1 ──(195.123.0.34/30)──── R2(NAT) ──(192.168.0.1)──── H（192.168.0.3）
```
A. 195.123.0.33　B. 195.123.0.35　C. 192.168.0.1　D. 192.168.0.3
- 图中 **195.123.0.34/30 标在 R1 的接口旁**，R1 与 R2 之间是一个 /30 子网：195.123.0.32/30，可用地址只有 **.33 和 .34**

📝 **真题（2025 年第 37 题）**：假设路由器实现 NAT 功能，内网中主机 H 的 IP 地址为 192.168.1.5/24。若 H 运行某应用向 Internet 发送一个 UDP 报文段，则路由器在转发封装该 UDP 报文段的 IP 数据报的过程中，UDP 报文的首部字段会被修改的是：I. 源端口号　II. 目的端口号　III. 总长度　IV. 校验和
A. 仅 I、III　B. 仅 I、IV　C. 仅 II、III　D. 仅 II、IV
- NAPT 会修改**源端口号**（I）
- UDP 的**校验和**计算时包括**伪首部**（含源 IP 地址），源 IP 和源端口都变了，校验和必须**重新计算**（IV）
- 目的端口、长度不变
→ 选 **B**

## 三、ARP 协议（地址解析协议）（⭐⭐⭐）

### 📐 为什么需要 ARP
在实际网络的链路上传送数据帧时，最终必须使用 **MAC 地址**。但上层只知道目的主机（或下一跳路由器）的 **IP 地址**——需要把 **IP 地址解析为 MAC 地址**。
- **ARP：IP 地址 → MAC 地址**（在同一局域网内）

### 📐 ARP 的工作过程
每台主机都设有一个 **ARP 高速缓存**，存放本局域网上各主机和路由器的 **IP 地址到 MAC 地址的映射表**（有生存时间，过期删除）。
主机 A 要向本局域网上的主机 B 发送 IP 数据报：
1. 先在 ARP 缓存中查看有无 B 的 IP 地址，**有就直接**写入 MAC 帧
2. **没有**，就通过使用目的 MAC 地址为 **FF-FF-FF-FF-FF-FF** 的帧来封装并**广播 ARP 请求分组**：“我是 IP 为 x、MAC 为 y 的主机，谁的 IP 是 B？请告诉我你的 MAC 地址”
3. 同一局域网里的所有主机都能收到。B 收到后，把 A 的映射写入自己的 ARP 缓存，然后**单播**一个 **ARP 响应分组**给 A：“我的 IP 是 B，MAC 是 z”
4. A 收到后，把 B 的 IP-MAC 映射写入 ARP 缓存，然后发送数据

📌 **ARP 请求是广播，ARP 响应是单播**。
📌 ARP 协议**属于网络层**（有的教材认为在网络层和数据链路层之间），ARP 报文**直接封装在 MAC 帧**中（类型字段 0x0806），不封装在 IP 数据报中。
📌 ARP 只能在**同一局域网内**使用，不能跨越路由器。

### 📐 ARP 的四种典型情况（⭐⭐⭐）
| 情况 | 发送方 | 目的 | ARP 找谁的 MAC 地址 |
|---|---|---|---|
| 1 | **主机** | **本网络**上的另一台主机 | 目的**主机**的 MAC 地址 |
| 2 | **主机** | **另一个网络**上的主机 | 本网络上**某个路由器（默认网关）**的 MAC 地址 |
| 3 | **路由器** | **本网络**上的主机 | 目的**主机**的 MAC 地址 |
| 4 | **路由器** | **另一个网络**上的主机 | 本网络上**另一个路由器（下一跳）**的 MAC 地址 |

🧒 **一句话**：ARP 总是找**“这一跳要交给谁”**的 MAC 地址——同网直接找目的主机，跨网找下一跳路由器。

（2021 年第 47 题中，H1 先后为**本地域名服务器**（同网）和**默认网关 R**（访问外网 Web 服务器）发送了两次 ARP 请求广播，详见第 6 课。）

## 四、DHCP 协议（动态主机配置协议）（⭐⭐⭐）

### 📐 主机获得 IP 地址的方式
- **静态配置**：手动设置 IP 地址、子网掩码、默认网关、DNS 服务器
- **动态配置**：使用 **DHCP**，自动获取

### 📐 DHCP 的特点
- DHCP 是**应用层协议**，使用**客户/服务器**方式，客户端和服务端通过**广播**方式进行交互，**基于 UDP**（服务器端口 **67**，客户端端口 **68**）
- DHCP 提供**即插即用**联网的机制，主机可以从服务器动态获取 IP 地址、子网掩码、默认网关、DNS 服务器名称与 IP 地址，允许地址**重用**，支持**移动用户**加入网络，支持在用地址**续租**
- DHCP 服务器分配的 IP 地址是**临时**的，有**租用期**

### 📐 DHCP 的工作过程（四步）（⭐⭐⭐）
```
客户端（新主机）                                DHCP 服务器
      │ ① DHCP 发现（Discover）  广播 ─────────►  │
      │ ◄───────── ② DHCP 提供（Offer）  广播/单播 │
      │ ③ DHCP 请求（Request）   广播 ─────────►  │
      │ ◄───────── ④ DHCP 确认（ACK）    广播/单播 │
```
1. **DHCP 发现（Discover）**：主机**广播**“有没有 DHCP 服务器呀？”
2. **DHCP 提供（Offer）**：DHCP 服务器（可能有多个）回复“有啊，你用这个 IP 吧”（提供一个 IP 地址、子网掩码、默认网关、租期……）
3. **DHCP 请求（Request）**：主机**广播**“我就用这个 IP 了”（广播的目的是让其他 DHCP 服务器也知道，它们提供的地址没被选中）
4. **DHCP 确认（ACK）**：服务器确认，主机正式使用这个 IP 地址

📐 **四个报文的 IP 地址**（⭐⭐⭐）：
| 报文 | 源 IP 地址 | 目的 IP 地址 | 目的 MAC 地址 |
|---|---|---|---|
| **Discover** | **0.0.0.0**（还没有 IP） | **255.255.255.255** | FF-FF-FF-FF-FF-FF |
| Offer | DHCP 服务器 IP | 255.255.255.255（或分配的 IP） | 广播或客户端 MAC |
| **Request** | **0.0.0.0**（还没有正式获得） | **255.255.255.255** | FF-FF-FF-FF-FF-FF |
| ACK | DHCP 服务器 IP | 255.255.255.255（或分配的 IP） | 广播或客户端 MAC |

📝 **真题（2025 年第 36 题）**：一台新接入网络的主机 H 通过 DHCP 服务器动态请求 IP 地址过程中，与 DHCP 服务器交换 DHCP 报文过程如下图所示（服务器 192.168.5.1 发来 yiaddr: 192.168.5.9 的报文，H 随后发出携带 yiaddr: 192.168.5.9 的报文）。封装 DHCP 的 REQUEST 报文的 IP 数据报的目的 IP 地址和源 IP 地址分别是：
A. 192.168.5.1, 0.0.0.0　B. 192.168.5.1, 192.168.5.9　C. 255.255.255.255, 0.0.0.0　D. 255.255.255.255, 192.168.5.9
→ **C**（Request 报文仍是**广播**，此时 H 还没有正式获得 IP 地址（要等 ACK），源 IP 是 **0.0.0.0**）

📝 **真题（2022 年第 47 题第 3 问）**：在 H4 通过 DHCP 动态获取 IP 地址过程中，H4 首先发送了 DHCP 报文 M，M 是哪种 DHCP 报文？路由器 E0 接口能否收到封装 M 的以太网帧？S 向 DHCP 服务器转发的封装 M 的以太网帧的目的 MAC 地址是什么？
- M 是 **DHCP 发现（Discover）**报文
- M 是**广播**帧，交换机 S 会把它转发到所有端口，**路由器 E0 接口能收到**（但路由器不会把它转发到其他网络）
- 目的 MAC 地址是**广播地址 FF-FF-FF-FF-FF-FF**

## 五、ICMP 协议（网际控制报文协议）（⭐⭐）

### 📐 ICMP 的作用
为了更有效地转发 IP 数据报和**提高交付成功的机会**，在网际层使用了**网际控制报文协议 ICMP**，**让主机或路由器报告差错和异常情况**。
- ICMP 报文作为 IP 数据报的**数据部分**，加上 IP 首部后发送（IP 首部协议字段 = **1**）
- ICMP 是**网络层**协议

### 📐 ICMP 差错报告报文（5 种，现在常考 4 种）
| 类型 | 何时发送 |
|---|---|
| **终点不可达** | 当路由器或主机**不能交付**数据报时就向源点发送终点不可达报文（无法交付） |
| 源点抑制（已不再使用） | 当路由器或主机由于**拥塞**而丢弃数据报时，就向源点发送源点抑制报文，使源点知道应当把数据报的发送速率放慢 |
| **时间超过** | 当路由器收到**生存时间 TTL = 0** 的数据报时，除丢弃该数据报外，还要向源点发送时间超过报文；当终点在预先规定的时间内**不能收到一个数据报的全部数据报片**时，就把已收到的数据报片都丢弃，并向源点发送时间超过报文 |
| **参数问题** | 当路由器或目的主机收到的数据报的**首部中有的字段的值不正确**时，就丢弃该数据报，并向源点发送参数问题报文 |
| **改变路由（重定向）** | 路由器把改变路由报文发送给主机，让主机知道**下次应将数据报发送给另外的路由器**（可通过更好的路由） |

### 📐 不应发送 ICMP 差错报文的情况（⭐⭐）
1. 对 **ICMP 差错报告报文**不再发送 ICMP 差错报告报文（防止无限循环）
2. 对**第一个分片**的数据报片的**所有后续**数据报片都不发送 ICMP 差错报告报文
3. 对具有**组播地址**的数据报都不发送 ICMP 差错报告报文
4. 对具有**特殊地址**（如 127.0.0.0 或 0.0.0.0）的数据报不发送 ICMP 差错报告报文

### 📐 ICMP 询问报文
- **回送请求和回答报文**：主机或路由器向特定目的主机发出的询问，收到此报文的主机必须给源主机或路由器发送 ICMP 回送回答报文。测试目的站是否可达以及了解其有关状态
- **时间戳请求和回答报文**：请某个主机或路由器回答当前的日期和时间。用来进行时钟同步和测量时间
- （掩码地址请求和回答、路由器询问和通告，已不再使用）

### 📐 ICMP 的应用（⭐⭐）
- **ping**：测试两个主机之间的**连通性**，使用了 ICMP **回送请求和回答**报文。ping 工作在**应用层**，直接使用网络层的 ICMP，**没有使用传输层**的 TCP 或 UDP
- **traceroute（Windows 中是 tracert）**：跟踪一个分组从源点到终点的**路径**，使用了 ICMP **时间超过**差错报告报文
  - 原理：源主机依次发送 TTL = 1、2、3……的数据报，第 k 个路由器收到 TTL 减为 0 的数据报，就返回 ICMP 时间超过报文，源主机由此得知路径上第 k 个路由器的地址
  - traceroute 工作在**网络层**

## ⚠️ 易错点

1. 转发过程中 **IP 地址不变（除 NAT），MAC 地址每跳都变**
2. 主机判断目的是否在同一网络：用**自己的**子网掩码与目的 IP 相与
3. NAT（NAPT）修改**源 IP + 源端口**（出去时）；外网主机要主动访问内网需要**静态映射**
4. 经过 NAT，UDP/TCP 的**检验和**要重新计算（伪首部含 IP 地址）
5. **ARP 请求广播，响应单播**；ARP 只在**局域网内**使用；跨网时找**下一跳路由器**的 MAC
6. DHCP 是**应用层**协议，基于 **UDP（67/68）**
7. DHCP **Discover 和 Request** 都是**广播**，源 IP **0.0.0.0**，目的 IP **255.255.255.255**
8. ICMP 报文封装在 **IP 数据报**中；**ping 用回送请求/回答**，**traceroute 用时间超过**
9. 对 ICMP 差错报文不再发差错报文

## 📋 本课小结

| 协议 | 作用 | 要点 |
|---|---|---|
| 转发 | 查路由表 | 直接/间接交付；最长前缀匹配；默认路由 |
| NAT | 私有地址 ↔ 公网地址 | NAPT 换 IP + 端口；转换表；静态映射 |
| ARP | IP → MAC | 请求广播、响应单播；四种情况 |
| DHCP | 动态分配 IP | Discover/Offer/Request/ACK；UDP 67/68；0.0.0.0 → 255.255.255.255 |
| ICMP | 差错报告与询问 | 终点不可达、时间超过、参数问题、重定向；ping、traceroute |

## 🏋️ 课后练习

1. 主机 A（192.168.1.10/24）要给主机 B（192.168.2.20/24）发送数据，A 的默认网关是 192.168.1.1。A 发出的 ARP 请求要查询哪个 IP 地址的 MAC 地址？
2. 一台内网主机 10.0.0.5:3000 访问外网服务器 202.1.1.1:80，NAT 路由器的外网地址是 61.1.1.1，NAT 分配端口 5000。写出 NAT 转换表项；写出服务器回复的分组在 NAT 路由器转换前后的目的地址和端口。
3. 判断：(a) ARP 响应报文是广播的；(b) DHCP 基于 TCP；(c) ping 命令使用了 UDP；(d) traceroute 利用了 ICMP 时间超过报文。
4. 为什么 DHCP 请求（Request）报文要广播而不是单播给选中的服务器？

<details>
<summary>📖 答案</summary>

1. B 不在同一网络，A 要把分组交给默认网关，所以 ARP 查询 **192.168.1.1** 的 MAC 地址
2. 转换表：外网 **61.1.1.1:5000** ↔ 内网 **10.0.0.5:3000**。服务器回复：转换前目的地址 **61.1.1.1:5000**，转换后 **10.0.0.5:3000**
3. (a) **错**，单播；(b) **错**，基于 UDP；(c) **错**，ping 直接使用 ICMP；(d) **对**
4. 网络中可能有多个 DHCP 服务器都发送了 Offer，客户端广播 Request 可以同时通知**所有**服务器：选中了哪一个服务器的地址，其他服务器可以收回它们提供的地址；另外此时客户端还没有正式的 IP 地址
