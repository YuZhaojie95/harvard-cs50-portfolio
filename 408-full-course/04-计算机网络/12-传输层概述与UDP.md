# 计算机网络 第 12 课 · 传输层概述与 UDP 协议

> 🎯 **本课目标**
> 1. 理解**传输层**的功能：**进程之间的逻辑通信**、复用与分用、差错检测
> 2. 掌握**端口号**和**套接字**，记住常用的**熟知端口号**（⭐⭐⭐）
> 3. 理解**面向连接（TCP）**与**无连接（UDP）**服务的区别
> 4. 掌握 **UDP** 的特点、**首部格式（8B）**、**检验和**（伪首部）的计算（⭐⭐⭐）
>
> 真题：2021 年第 39 题、2025 年第 39 题……

---

## 🚪 课前引入

网络层的 IP 协议能把分组从**一台主机**送到**另一台主机**。但一台电脑上同时运行着微信、浏览器、网易云音乐……收到的数据该交给**哪个程序**？

🧒 **比喻：公寓楼的信件**
- IP 地址 = 公寓楼的**地址**（把信送到这栋楼）
- **端口号** = 楼里的**房间号**（把信送到具体哪个住户）
- 传输层 = 楼里的**收发室**：根据房间号把信分发给各户（**分用**），也把各户要寄的信收集起来统一寄出（**复用**）

所以说：**网络层实现主机之间的通信，传输层实现进程之间的通信**。

---

## 一、传输层的功能（⭐⭐）

### 📐 传输层的地位
- 传输层为**应用进程之间**提供**端到端的逻辑通信**（网络层为**主机之间**提供逻辑通信）
- 只有**主机**才有传输层（路由器最高只到网络层）
- 传输层**对高层用户屏蔽了下面网络核心的细节**（如网络拓扑、路由选择协议等），使应用进程看见的就好像是在两个传输层实体之间有一条**端到端的逻辑通信信道**

### 📐 传输层的功能
1. **进程和进程之间的逻辑通信**
2. **复用和分用**：
   - **复用**：应用层**所有的应用进程**都可以通过**传输层**再传输到网络层
   - **分用**：传输层从网络层收到数据后**交付指明的应用进程**
3. **差错检测**：对收到的报文进行差错检测（**首部和数据部分都检测**；而网络层的 IP 只检查首部）
4. 提供两种协议：**面向连接的 TCP** 和**无连接的 UDP**

### 📐 TCP 与 UDP 的对比（⭐⭐⭐）
| | UDP | TCP |
|---|---|---|
| 连接 | **无连接** | **面向连接**（三次握手、四次挥手） |
| 可靠性 | **不可靠**（尽最大努力交付） | **可靠**（无差错、不丢失、不重复、按序到达） |
| 面向 | **报文** | **字节流** |
| 首部 | **8B**，开销小 | **20~60B**，开销大 |
| 流量/拥塞控制 | **无** | **有** |
| 通信方式 | 一对一、一对多、多对一、多对多 | **只能一对一**（点对点） |
| 速度/实时性 | 快、实时性好 | 较慢 |
| 应用 | **DNS**、DHCP、TFTP、SNMP、RIP、**视频/语音**等实时应用 | **HTTP**、FTP、SMTP、Telnet、POP3、BGP 等 |

📌 **TCP 数据传输单位：报文段；UDP 数据传输单位：用户数据报**

---

## 二、端口与套接字（⭐⭐⭐）

### 📐 端口
- **端口**是传输层的**服务访问点（SAP）**，用来标识**应用进程**
- 端口号 **16 位**：0 ~ 65535
- 端口号**只具有本地意义**：只标识本计算机应用层中的各进程，不同计算机中的相同端口号是没有联系的
- ⚠️ TCP 和 UDP 的端口号**相互独立**（TCP 的 80 和 UDP 的 80 是两个不同的端口）

### 📐 端口号的分类
| 类型 | 范围 | 说明 |
|---|---|---|
| **服务端 — 熟知端口号（系统端口号）** | **0 ~ 1023** | 给 TCP/IP 最重要的一些应用程序，让所有用户都知道 |
| 服务端 — 登记端口号 | 1024 ~ 49151 | 为没有熟知端口号的应用程序使用 |
| **客户端 — 短暂端口号** | **49152 ~ 65535** | 仅在客户进程运行时才**动态**选择 |

### 📐 常用熟知端口号（⭐⭐⭐ 必背）
| 应用 | 端口 | 传输层协议 |
|---|---|---|
| **FTP** | **21**（控制连接）、**20**（数据连接，主动模式） | TCP |
| **Telnet** | **23** | TCP |
| **SMTP** | **25** | TCP |
| **DNS** | **53** | **UDP**（主要）/ TCP |
| **TFTP** | **69** | UDP |
| **HTTP** | **80** | TCP |
| **POP3** | **110** | TCP |
| IMAP | 143 | TCP |
| **SNMP** | **161** | UDP |
| **HTTPS** | **443** | TCP |
| **DHCP** | **67**（服务器）、**68**（客户端） | UDP |
| **RIP** | **520** | UDP |
| **BGP** | **179** | TCP |

### 📐 套接字（Socket）
- 在网络中采用**发送方和接收方的套接字组合**来识别端口
- **套接字 = (主机 IP 地址, 端口号)**，唯一标识了网络中的一个主机和它上面的一个进程
- 一条 **TCP 连接**由两端的套接字唯一确定：**{(IP₁, port₁), (IP₂, port₂)}**

## 三、UDP 协议（⭐⭐⭐）

### 📐 UDP 的主要特点
1. **UDP 是无连接的**，减少开销和发送数据之前的时延
2. **UDP 使用最大努力交付**，即不保证可靠交付
3. **UDP 是面向报文的**：发送方 UDP 对应用层交下来的报文，在添加首部后就向下交付 IP 层，**既不合并，也不拆分**，而是**保留这些报文的边界**，一次发送一个报文。所以应用层要选择合适大小的报文（太长 IP 层要分片，太短首部开销比例大）
4. **UDP 没有拥塞控制**，适合很多**实时应用**（网络出现拥塞也不会使源主机的发送速率降低）
5. **UDP 首部开销小**，只有 **8B**（TCP 至少 20B）
6. UDP 支持**一对一、一对多、多对一和多对多**的交互通信

### 📐 UDP 首部格式（8B）
```
 0                16               31
 ┌────────────────┬────────────────┐
 │    源端口号      │    目的端口号     │
 ├────────────────┼────────────────┤
 │    UDP 长度     │    UDP 检验和     │
 └────────────────┴────────────────┘
 │            数据部分               │
```
| 字段 | 长度 | 说明 |
|---|---|---|
| 源端口 | 2B | 源端口号，在需要对方回信时选用，不需要时可全 0 |
| 目的端口 | 2B | 目的端口号，在终点交付报文时必须要使用到 |
| **长度** | 2B | UDP 用户数据报的长度（**首部 + 数据**），**最小值是 8**（仅有首部） |
| **检验和** | 2B | 检测 UDP 用户数据报在传输中是否有错（**首部和数据都检验**），有错就丢弃。该字段是**可选**的，当源主机不想计算检验和，则直接令该字段全为 **0** |

📐 **UDP 的分用**：当传输层从 IP 层收到 UDP 数据报时，就根据首部中的**目的端口**，把 UDP 数据报通过相应的端口，上交给应用进程。如果接收方 UDP 发现收到的报文中的目的端口号**不正确**（即不存在对应于端口号的应用进程），就**丢弃**该报文，并由 ICMP 发送“**端口不可达**”差错报文给发送方

📝 **真题（2021 年第 39 题）**：若大小为 12B 的应用层数据分别通过 1 个 UDP 数据报和 1 个 TCP 段传输，则该 UDP 数据报和 TCP 段实现的有效载荷（应用层数据）最大传输效率分别是：A. 37.5%, 16.7%　B. 37.5%, 37.5%　C. 60.0%, 16.7%　D. 60.0%, 37.5%
- UDP：首部 **8B** → 12 / (12 + 8) = **60%**
- TCP：首部**最小 20B**（求“最大”效率就用最小首部）→ 12 / (12 + 20) = **37.5%**
→ 选 **D**

### 📐 UDP 检验和的计算（⭐⭐）
在计算检验和时，要在 UDP 用户数据报之前**临时**增加 **12B 的伪首部**：
```
伪首部（12B，只用于计算检验和，既不向下传送也不向上递交）：
 ┌─────────────────────────────────┐
 │         源 IP 地址（4B）           │
 ├─────────────────────────────────┤
 │        目的 IP 地址（4B）           │
 ├────────┬────────┬───────────────┤
 │ 0（1B）  │ 17（1B）│ UDP 长度（2B）  │
 └────────┴────────┴───────────────┘
```
- 伪首部中的 **17** 是 UDP 的协议号
- **伪首部只用于计算检验和**，不向下传送，也不向上递交

**计算方法**（发送端）：
1. 填上伪首部
2. **全 0** 填充检验和字段
3. 若数据部分为**奇数**字节，在末尾**填充一个全 0 字节**（也不发送）
4. 把伪首部、UDP 首部、数据部分看成 **16 位字**的串，进行**二进制反码求和**（有进位就**回卷加到最低位**）
5. 把和**求反码**，填入检验和字段

**接收端**：填上伪首部，把所有 16 位字（含检验和）进行二进制反码求和，结果**全为 1** 则无差错，否则丢弃（也可以上交给应用层并附上出错的警告）。

✏️ **例（反码求和）**：三个 16 位字 0x1234、0xF00F、0x8000 求反码和及检验和：
- 0x1234 + 0xF00F = 0x1**0243** → 最高位的进位 1 **回卷**加到最低位：0x0243 + 1 = **0x0244**
- 0x0244 + 0x8000 = **0x8244**
- 检验和 = 反码 = **0x7DBB**

⚠️ 伪首部中包含了 **IP 地址**，所以经过 **NAT** 时，UDP（和 TCP）的检验和必须重新计算（2025 年第 37 题）。

### 📐 为什么需要 UDP
- 很多应用只需要发送**少量数据**（如 DNS 查询），建立连接的开销比传数据还大
- **实时应用**（语音、视频、直播）宁可丢一点数据，也不能等重传（TCP 的重传会造成延迟抖动）
- 应用可以在应用层自己实现可靠性（按需定制）

📝 **真题（2025 年第 39 题）**：Time 是一个提供时间查询服务的 C/S 架构网络应用，支持客户通过 UDP 和 TCP 向 Time 服务器请求时间。若某客户与 Time 服务器通信往返时间为 8ms，则该客户分别通过 UDP 和 TCP 向该服务器请求服务，所需的最少时间分别是：A. 8ms, 8ms　B. 8ms, 16ms　C. 16ms, 8ms　D. 16ms, 16ms
- **UDP**：无连接，直接发请求、收响应 → **1 RTT = 8ms**
- **TCP**：先**三次握手**建立连接（1 RTT，第三次握手的报文可以携带请求数据），再请求-响应（1 RTT）→ **2 RTT = 16ms**
→ 选 **B**

## ⚠️ 易错点

1. **网络层：主机之间**的通信；**传输层：进程之间**的通信
2. 传输层差错检测**首部和数据都检**；IP 只检首部
3. 端口号 **16 位**，只有**本地意义**；**熟知端口 0~1023**
4. 必背：FTP 21/20、Telnet 23、SMTP 25、**DNS 53（UDP）**、TFTP 69、HTTP 80、POP3 110、SNMP 161、HTTPS 443、DHCP 67/68、RIP 520、BGP 179
5. **套接字 = IP 地址 + 端口号**
6. **UDP 首部 8B**；TCP 首部 **20~60B**
7. UDP **面向报文**（不合并、不拆分），TCP **面向字节流**
8. UDP 检验和**可选**（全 0 表示不用）；计算时加 **12B 伪首部**（协议号 **17**），伪首部**不传送**
9. 反码求和：最高位**进位要回卷**；最后**取反**
10. UDP 请求-响应 **1 RTT**；TCP 至少 **2 RTT**（握手 + 请求）

## 🏋️ 课后练习

1. 一个 UDP 用户数据报的首部十六进制表示为 **06 32 00 45 00 1C E2 17**，求源端口、目的端口、数据报总长度、数据部分长度。这个数据报是从客户发送给服务器还是从服务器发送给客户？使用 UDP 的这个服务器程序是什么？
2. 为什么说 UDP 是面向报文的，而 TCP 是面向字节流的？
3. 判断：(a) UDP 检验和只检验首部；(b) 伪首部要随 UDP 数据报一起发送；(c) DNS 主要使用 UDP；(d) 不同主机上相同的端口号代表同一个进程。

<details>
<summary>📖 答案</summary>

1. 源端口 0x0632 = **1586**；目的端口 0x0045 = **69**；总长度 0x001C = **28B**；数据长度 28 − 8 = **20B**。目的端口是熟知端口 69，源端口是非熟知端口 → **客户发给服务器**；69 是 **TFTP**
2. UDP 对应用层交下来的报文**不合并也不拆分**，一次交付一个完整报文，保留报文边界；TCP 把应用层交下来的数据看成**无结构的字节流**，根据窗口和拥塞情况自己决定一个报文段包含多少字节，可能把一个应用层报文拆开，也可能把多个合在一起
3. (a) **错**，首部和数据都检验；(b) **错**；(c) **对**；(d) **错**，端口号只有本地意义
</details>
