## 🚪 课前引入

物理层只负责“**把比特送过去**”，但它不管：
- 这一串比特**从哪开始、到哪结束**？（成帧）
- 传的过程中某些比特**变错了**怎么办？（差错控制）
- 发送方发得太快，接收方**来不及收**怎么办？（流量控制）
- 帧**丢了**怎么办？（可靠传输）

**数据链路层**就在物理层之上，负责在**相邻两个结点**之间，把网络层交下来的数据**可靠地**（或尽力地）送过去。

🧒 **比喻**：物理层是一条传送带，只负责把一粒粒豆子（比特）运过去；数据链路层把豆子**装进盒子**（帧），在盒子上写好**校验码**（差错控制），还要和对方约好“**我每次最多发几盒，你收到了要回个信**”（流量控制、可靠传输）。

## 一、数据链路层的功能（⭐）

### 📐 基本概念
- **结点**：主机、路由器
- **链路**：网络中两个结点之间的**物理通道**，链路的传输介质主要有双绞线、光纤和微波。分为**有线链路**、**无线链路**
- **数据链路**：网络中两个结点之间的**逻辑通道**，把实现控制数据传输**协议的硬件和软件**加到链路上就构成数据链路
- **帧**：链路层的协议数据单元，**封装网络层数据报**

📌 数据链路层负责通过一条链路**从一个结点向另一个物理链路直接相连的相邻结点**传送数据报。

### 📐 主要功能
数据链路层在物理层提供服务的基础上**向网络层提供服务**，其最基本的服务是将源自网络层的数据**可靠地**传输到**相邻结点**的目标机网络层。其主要作用是**加强物理层传输原始比特流的功能**，将物理层提供的可能出错的物理连接改造成为**逻辑上无差错的数据链路**，使之对网络层表现为一条无差错的链路。
1. **为网络层提供服务**：无确认无连接服务（以太网）、有确认无连接服务（无线网）、有确认面向连接服务
2. **链路管理**：连接的建立、维持、释放（用于面向连接的服务）
3. **组帧**
4. **流量控制**
5. **差错控制**（帧错/位错）
6. **介质访问控制**（广播信道，下一课）

## 二、成帧（⭐⭐）

### 📐 封装成帧与透明传输
- **封装成帧**：在一段数据的**前后**分别添加**首部和尾部**，构成一个帧。接收端在收到物理层上交的比特流后，就能根据首部和尾部的标记，从收到的比特流中识别帧的开始和结束
- **首部和尾部**包含许多控制信息，他们的一个重要作用：**帧定界**（确定帧的界限）
- **帧同步**：接收方应当能从接收到的二进制比特流中**区分出帧的起始和终止**
- **组帧的四种方法**：字符计数法、字符（节）填充法、零比特填充法、违规编码法
- **透明传输**：不管所传数据是什么样的比特组合，都应当能够在链路上传送。因此，链路层就“**看不见**”有什么妨碍数据传输的东西——**当所传数据中的比特组合恰巧与某一个控制信息完全一样时，就必须采取适当的措施，使收方不会将这样的数据误认为是某种控制信息**。这样才能保证数据链路层的传输是透明的

### 📐 1. 字符计数法
帧首部使用一个**计数字段**（第一个字节，8 位）来标明帧内字符数（**包括计数字段本身**）。
- ❌ **痛点：若计数字段出错，就无法判断帧的结束和下一帧的开始**，会出现“一错全错”

### 📐 2. 字符（字节）填充法
用特殊字符（如 **SOH** 表示帧开始，**EOT** 表示帧结束）来界定帧的开始和结束。
- 若数据中出现了与 SOH/EOT 相同的字节，就在它前面插入一个**转义字符 ESC**（若数据中出现 ESC，也在它前面再插一个 ESC）
- 接收端收到后，把 ESC 删除，还原数据
- **PPP 协议**在异步传输时使用字节填充（标志字节 **0x7E**，转义字节 **0x7D**）

### 📐 3. 零比特填充法（⭐⭐⭐）
帧的首部和尾部都使用一个特定的比特模式 **01111110（0x7E）**来标志帧的开始和结束。
- **发送方**：扫描整个信息字段，只要连续出现 **5 个“1”**，就立即在后面**填入一个“0”**
- **接收方**：在收到的数据中，每当发现 5 个连续的“1”，就把其后的“0”**删除**
- 保证了在信息字段中**不会出现 6 个连续的 1**，与标志字段不会混淆
- **HDLC、PPP（同步传输时）**使用
- ✅ 很容易由硬件实现，性能优于字符填充方式

✏️ **例**：要发送的数据为 **0110 1111 1111 1100 1**，采用零比特填充后变成？
- 把原数据按 0 分段：`0 11 0 1111111111 001`（第 2~3 位两个 1，第 4 位是 0，第 5~14 位是连续 10 个 1，最后是 001）
- 原数据中间有**连续 10 个 1**（第 5~14 位）：数到第 5 个 1 时插入一个 0，计数清零；再数到第 5 个 1 时又插入一个 0
- 结果：**0110 11111 0 11111 0 001**（共插入 2 个 0）

🧒 **技巧**：从左往右数“1”，数到 5 个连续的 1 就插一个 0，**计数清零**重新数。

### 📐 4. 违规编码法
利用物理层编码中“不会出现”的码元来定界。例如曼彻斯特编码中，每个码元中间都有跳变（高-低或低-高），那么“**高-高**”或“**低-低**”就是**违规**的码元，可以用来定界帧的起始和终止。
- **局域网 IEEE 802 标准**使用
- 不需要任何填充技术，但**只适用于采用冗余编码**的特殊编码环境

📌 由于字节计数法中计数字段的脆弱性和字符填充法实现上的复杂性与不兼容性，目前较常用的组帧方法是**零比特填充法和违规编码法**。

## 三、差错控制（⭐⭐⭐）

### 📐 差错的来源
- 概括来说，传输中的差错都是由于**噪声**引起的
  - **全局性**：由于线路本身电气特性所产生的**随机噪声（热噪声）**，是信道固有的，随机存在的。解决办法：提高信噪比来减少或避免干扰（对传感器下手）
  - **局部性**：外界特定的短暂原因所造成的**冲击噪声**，是产生差错的主要原因。解决办法：通常利用**编码技术**来解决
- 差错类型：
  - **位错**：比特位出错，1 变成 0，0 变成 1
  - **帧错**：**丢失**、**重复**、**失序**

### 📐 检错编码：奇偶校验码
- 由 n − 1 位信息元和 1 位**校验元**组成
- **奇校验码**：“1”的个数为奇数；**偶校验码**：“1”的个数为偶数
- 奇偶校验码**只能检查出奇数个比特错误**，检错能力为 50%

### 📐 检错编码：CRC 循环冗余码（⭐⭐⭐）
**思想**：发送方和接收方事先约定一个**生成多项式 G(x)**（最高次为 r，对应 r + 1 位二进制数）。发送方在数据后面添加 **r 位冗余码（FCS，帧检验序列）**，使得整个帧能被 G(x) **模 2 整除**。接收方用收到的帧除以 G(x)，**余数为 0** 则认为无差错。

**计算冗余码的步骤**：
1. **加 0**：假设生成多项式 G(x) 的阶为 **r**，则在要发送的数据后面加 **r 个 0**
2. **模 2 除法**：数据加 0 后除以多项式 G(x)，**余数为冗余码/FCS/CRC 检验码**（r 位，不足 r 位时前面补 0）
3. **发送的帧 = 原数据 + 余数**

📐 **模 2 运算**：加减法都是**异或**（不借位、不进位）。做除法时，被除数（当前部分）**首位为 1 就商 1、异或除数**；首位为 0 就商 0（相当于直接左移一位）。

✏️ **例**：要发送的数据为 **101001**，生成多项式 **G(x) = x³ + x² + 1**（即 **1101**，r = 3）。
1. 数据后面加 3 个 0：**101001 000**
2. 模 2 除法（逐步异或）：
   ```
   101001000
   1101                  首位 1 → 异或 1101
   ─────
   011101000             
    1101                 首位 1 → 异或 1101
    ─────
   000111000
      1101               首位 1 → 异或 1101
      ─────
   000001100
        1101             首位 1 → 异或 1101
        ─────
   000000001             剩下 3 位：001
   ```
3. 余数 = **001**
4. 发送的帧 = **101001 001**

**接收方检验**：用收到的 101001001 除以 1101，余数为 **000** → 无差错 ✓

📝 **真题（2023 年第 37 题）**：若甲向乙发送数据时采用 CRC 校验，生成多项式为 G(x) = x⁴ + x + 1（即 G = 10011），则乙接收到下列比特串时，可以断定其在传输过程中未发生错误的是：A. 1 0111 0000　B. 1 0111 0100　C. 1 0111 1000　D. 1 0111 1100
- 分别用各选项除以 10011，余数为 0 的才是无差错：
  - A 余 1100；B 余 1000；C 余 0100；**D 余 0000** → 选 **D**

⚠️ CRC 的特点：
- 在数据链路层仅仅使用 CRC 差错检测技术，只能做到对帧的**无差错接收**，即“凡是接收端数据链路层接受的帧，我们都能以非常接近于 1 的概率认为这些帧在传输过程中没有产生差错”。接收端丢弃的帧虽然曾收到了，但是最终还是因为有差错被丢弃，即**没有被接受**
- “**可靠传输**”：数据链路层发送端发送什么，接收端就收到什么——这需要**确认和重传机制**，仅有 CRC 是做不到的
- 链路层使用 CRC 检验，能够实现**无比特差错**的传输，但这还**不是可靠传输**

### 📐 纠错编码：海明码（⭐⭐）
**思想**：发现双比特错，纠正单比特错。
**步骤**：
1. **确定校验码位数 r**：满足海明不等式 **2^r ≥ k + r + 1**（k 为信息位数）
   - k = 4 → r = 3（2³ = 8 ≥ 4 + 3 + 1 = 8 ✓）
   - k = 7 → r = 4（2⁴ = 16 ≥ 12 ✓）
2. **确定校验码和数据的位置**：校验位 Pᵢ 放在 **2 的幂次**位置（第 1、2、4、8……位），数据位依次放在其余位置
3. **求出校验码的值**：每个校验位负责的位置——把位置编号写成二进制，第 i 个校验位负责**二进制编号第 i 位为 1** 的所有位置
4. **检错并纠错**：接收方把每组的所有位异或，得到**校验和 S**，若 S = 0 无错；否则 S 的值就是**出错的位置**

✏️ **例**：信息位 **1010**（k = 4），采用偶校验海明码。
- r = 3，共 7 位：位置 1~7 分别是 **P1 P2 D1 P4 D2 D3 D4**
- 数据 D1 D2 D3 D4 = 1 0 1 0 → 放在位置 3、5、6、7
- P1 负责位置 1、3、5、7（二进制最低位为 1）：P1 = D1 ⊕ D2 ⊕ D4 = 1 ⊕ 0 ⊕ 0 = **1**
- P2 负责位置 2、3、6、7：P2 = D1 ⊕ D3 ⊕ D4 = 1 ⊕ 1 ⊕ 0 = **0**
- P4 负责位置 4、5、6、7：P4 = D2 ⊕ D3 ⊕ D4 = 0 ⊕ 1 ⊕ 0 = **1**
- 海明码（位置 1~7）= **1 0 1 1 0 1 0**

**纠错**：若接收到 **1 0 1 1 1 1 0**（第 5 位出错）
- S1 = 位 1、3、5、7 异或 = 1 ⊕ 1 ⊕ 1 ⊕ 0 = **1**
- S2 = 位 2、3、6、7 异或 = 0 ⊕ 1 ⊕ 1 ⊕ 0 = **0**
- S4 = 位 4、5、6、7 异或 = 1 ⊕ 1 ⊕ 1 ⊕ 0 = **1**
- S4 S2 S1 = **101 = 5** → **第 5 位出错**，取反即可纠正

### 📐 海明距离与检错纠错能力（⭐⭐）
- **码距（海明距离）**：两个合法编码（码字）的对应比特取值不同的比特数
- 一个有效编码集中，**任意两个合法编码之间最小的海明距离**称为该编码集的海明距离（码距）d
- 📐 **检错 k 位**，需要 d ≥ **k + 1**（即能检测 d − 1 位错）
- 📐 **纠错 k 位**，需要 d ≥ **2k + 1**（即能纠正 ⌊(d − 1)/2⌋ 位错）

📝 **真题（2025 年第 34 题）**：有如下编码集 {1001 1010, 0101 1100, 1111 0000, 0000 1111}，它的检错和纠错能力是：
A. 不超过 2 位数错误 100% 检错，不超过 1 位数纠错　B. 不超过 2 位数错误 100% 检错，不超过 2 位数纠错　C. 不超过 3 位数错误 100% 检错，不超过 1 位数纠错　D. 不超过 3 位数错误 100% 检错，不超过 2 位数纠错
- 两两计算海明距离：
  - 10011010 vs 01011100：4；vs 11110000：4；vs 00001111：4
  - 01011100 vs 11110000：4；vs 00001111：4
  - 11110000 vs 00001111：8
- 最小码距 **d = 4**
- 检错：d − 1 = **3 位**；纠错：⌊(4 − 1)/2⌋ = **1 位** → 选 **C**

## 四、流量控制与可靠传输机制（⭐⭐⭐）

### 📐 流量控制
**较高的发送速度**和**较低的接收能力**的不匹配，会造成传输出错，因此流量控制也是数据链路层的一项重要工作。
- 数据链路层的流量控制是**点对点**的（相邻结点之间），而传输层的流量控制是**端到端**的
- 数据链路层流量控制手段：接收方收不下就**不回复确认**
- 传输层流量控制手段：接收端给发送端一个**窗口公告**

### 📐 滑动窗口
- **发送窗口**：发送方维持一组连续的允许发送的帧的序号。发送窗口的大小 **W_T** 表示在还未收到对方确认的情况下，发送方**最多可以发送多少个数据帧**
- **接收窗口**：接收方维持一组连续的允许接收帧的序号。接收窗口大小 **W_R**：只有落在接收窗口内的帧才被接收，否则丢弃
- **收到确认后，发送窗口向前滑动**；**收到正确的帧（且按序），接收窗口向前滑动**

| 协议 | 发送窗口 | 接收窗口 |
|---|---|---|
| **停止-等待（SW）** | **1** | **1** |
| **后退 N 帧（GBN）** | **> 1** | **1** |
| **选择重传（SR）** | **> 1** | **> 1** |

📌 可靠传输机制：用**确认**和**超时重传**两种机制实现
- **确认**：一种无数据的协议数据单元，使得接收方可以让发送方知道哪些内容被正确接收
- **超时重传**：发送方在发送某个数据帧后就开启一个计时器，在一定时间内如果没有得到发送的数据帧的确认帧，那么就重新发送该数据帧，直到发送成功为止
- **自动重传请求（ARQ）**：通过接收方请求发送方重传出错的数据帧来恢复出错的帧，是通信中用于处理信道所带来差错的方法。三种 ARQ：SW、GBN、SR

### 📐 1. 停止-等待协议（SW）
**发送方每发送一个帧，就停下来等待对方的确认**，收到确认后再发送下一个帧。
- 需要对帧**编号**（1 位就够：0 和 1），以区分新帧和重传帧
- 可能出现的情况：
  - 数据帧丢失或检测到帧出错 → 超时重传（**计时器的超时时间要比帧传输的平均 RTT 更长一些**）
  - ACK 丢失 → 超时重传，接收方收到重复帧，**丢弃重复帧并重传确认**
  - ACK 迟到 → 发送方收到迟到的确认后**什么也不做**

📐 **信道利用率**（⭐⭐⭐）：
```
       发送一帧的时间 T_D
U = ─────────────────────────────
     T_D + RTT + T_A（确认帧发送时间）
```
- T_D = 数据帧长 / 数据传输率
- RTT = 2 × 单向传播时延
- T_A = 确认帧长 / 数据传输率（**若确认帧很短，常忽略**）
- **信道吞吐率 = 信道利用率 × 发送方的发送速率**

📝 **真题（2020 年第 36 题）**：假设主机甲采用停-等协议向主机乙发送数据帧，数据帧长与确认帧长均为 1000B，数据传输速率是 10kbps，单项传播延时是 200ms。则甲的最大信道利用率为：A. 80%　B. 66.7%　C. 44.4%　D. 40%
- T_D = 8000 / 10⁴ = **0.8s**；T_A = **0.8s**（确认帧也是 1000B，不能忽略！）
- RTT = 2 × 0.2 = **0.4s**
- U = 0.8 / (0.8 + 0.4 + 0.8) = 0.8 / 2.0 = **40%** → 选 **D**

❌ 停止-等待协议的缺点：**信道利用率太低**（尤其是传播时延很大时）。解决：**流水线传输**（连续发送多个帧），即 GBN 和 SR。

### 📐 2. 后退 N 帧协议（GBN）（⭐⭐⭐）
**发送方**：
- 可以**连续发送**多个帧（不超过发送窗口大小 W_T），不必每发一帧就停下来等待确认
- 上层调用：检查发送窗口是否已满，未满则产生一个帧并发送；满了则告知上层暂时不能发送
- 收到**累积确认**：收到确认帧 ACK n，表明**序号 n 及之前的所有帧**都已被正确接收，窗口滑动到 n + 1
- **超时事件**：如果出现超时，发送方**重传所有已发送但未被确认的帧**——这就是“**后退 N 帧**”名字的由来

**接收方**：
- **接收窗口 W_R = 1**：只**按序**接收帧。如果正确收到 n 号帧，并且按序，那么接收方为 n 帧发送一个 ACK，并将该帧中的数据部分交付给上层
- 其余情况（**失序到达**的帧、出错的帧）**都丢弃**，并为**最近按序接收的帧**重新发送 ACK
- 接收方无需缓存任何失序帧，只需要维护一个信息：expectedseqnum（下一个按序接收的帧序号）

📐 **窗口大小的限制**（⭐⭐⭐）：若采用 **n 位**对帧编号，则
```
1 ≤ W_T ≤ 2ⁿ − 1
```
- 🧒 为什么不能是 2ⁿ？设 n = 3（序号 0~7），若 W_T = 8：发送方发出 0~7，接收方全部收到并都发了确认，但所有确认都丢了。发送方超时重传 0~7，而接收方正在等“新的” 0——它无法区分这是重传的旧 0 还是新一轮的 0，**出错**。

📐 **GBN 的信道利用率**：
```
        W_T × T_D
U = ───────────────  （若 > 1 则 U = 1）
     T_D + RTT
```

📝 **真题（2009 年真题）**：数据链路层采用后退 N 帧（GBN）协议，发送方已经发送了编号为 0~7 的帧。当计时器超时时，若发送方只收到 0、2、3 号帧的确认，则发送方需要重发的帧数是：A. 2　B. 3　C. 4　D. 5
- GBN 采用**累积确认**：收到 **3 号**帧的确认，说明 **0~3 号帧都已正确接收**（1 号的确认虽然丢了，但 3 号的确认已覆盖它）
- 需要重传 **4、5、6、7** 号帧，共 **4** 帧 → 选 **C**

📝 **真题（2014 年真题）**：主机甲与主机乙之间使用后退 N 帧协议（GBN）传输数据，甲的发送窗口尺寸为 1000，数据帧长为 1000 字节，信道带宽为 100Mbps，乙每收到一个数据帧立即利用一个短帧（忽略其传输延迟）进行确认，若甲乙之间的单向传播时延是 50ms，则甲可以达到的最大平均数据传输速率约为：A. 10Mbps　B. 20Mbps　C. 80Mbps　D. 100Mbps
- T_D = 8000 / 10⁸ = **80μs**
- 一个发送周期 = T_D + RTT = 80μs + 100ms ≈ **100.08ms**
- 一个周期内最多发送 1000 帧，用时 1000 × 80μs = 80ms
- 利用率 = 80 / 100.08 ≈ 80% → 速率 ≈ 100Mbps × 80% = **80Mbps** → 选 **C**

📝 **真题（2012 年真题）**：两台主机之间的数据链路层采用后退 N 帧协议（GBN）传输数据，数据传输速率为 16kbps，单向传播时延为 270ms，数据帧长度范围是 128~512 字节，接收方总是以与数据帧等长的帧进行确认。为使信道利用率达到最高，帧序号的比特数至少为：A. 3　B. 4　C. 7　D. 8
- 要让信道利用率最高，要考虑**最坏情况**：帧**最短**时（128B），一个周期内需要发送的帧最多
- T_D = 128 × 8 / 16000 = **64ms**；确认帧也是 128B，T_A = **64ms**
- 从发出第一帧到收到其确认：64 + 270 + 64 + 270 = **668ms**
- 这段时间内要一直发送：W_T ≥ 668 / 64 ≈ 10.4 → **W_T ≥ 11**
- GBN 要求 W_T ≤ 2ⁿ − 1 → 2ⁿ ≥ 12 → **n ≥ 4** → 选 **B**

📐 **GBN 的优缺点**：
- ✅ 因连续发送数据帧而提高了信道利用率
- ❌ 在重传时必须把原来已经正确传送过的数据帧重传，使传送效率降低（一个帧出错，后面全部重传）

### 📐 3. 选择重传协议（SR）（⭐⭐⭐）
可不可以**只重传出错的帧**？——设置单个确认，同时加大接收窗口，**设置接收缓存，缓存乱序到达的帧**。
**发送方**：
- 上层调用：从上层收到数据后，检查下一个可用于该帧的序号，若序号位于发送窗口内，则发送数据帧；否则就像 GBN 一样，要么将数据缓存，要么返回给上层之后再传输
- 收到 ACK：如果收到 ACK，加入该帧序号在窗口内，则 SR 发送方将那个被确认的帧**标记为已接收**。如果该帧序号是窗口的下界（最左边第一个窗口对应的序号），则窗口向前移动到具有**最小序号的未确认帧**处
- **超时事件**：**每个帧都有自己的定时器**，一个超时事件发生后**只重传一个帧**

**接收方**：
- **来者不拒**（窗口内的帧）：SR 接收方将**确认一个正确接收的帧而不管其是否按序**。**失序的帧将被缓存**，并返回给发送方一个该帧的确认帧（**收谁确认谁**），直到所有帧（即序号更小的帧）皆被收到为止，这时才可以将一批帧按序交付给上层，然后向前移动滑动窗口
- 如果收到了窗口序号外（小于窗口下界）的帧，就返回一个 ACK；其他情况，就忽略该帧

📐 **窗口大小的限制**（⭐⭐⭐）：
```
W_T + W_R ≤ 2ⁿ
一般取 W_T = W_R = 2^(n−1)（最大）
```
- 🧒 接收窗口太大时，新一轮的序号可能落在接收窗口内，与旧的重传帧混淆

📐 **三种协议对比**（⭐⭐⭐）
| | SW | GBN | SR |
|---|---|---|---|
| 发送窗口 | 1 | ≤ 2ⁿ − 1 | ≤ 2^(n−1) |
| 接收窗口 | 1 | 1 | ≤ 2^(n−1) |
| 确认方式 | 逐个确认 | **累积确认** | **逐个确认** |
| 失序帧 | —— | **丢弃** | **缓存** |
| 超时重传 | 重传该帧 | **重传所有未确认帧** | **只重传超时的帧** |
| 信道利用率 | 低 | 高 | 高 |

📝 **真题（2023 年第 35 题）**：假设通过同一信道，数据链路层分别采用停止-等待协议、GBN 协议和 SR 协议（发送窗口和接收窗口相等）传输数据，三个协议的数据帧长相同，忽略确认帧长度，帧序号位数为 3 比特。若对应三个协议的发送方最大信道利用率分别是 U1、U2 和 U3，则 U1、U2 和 U3 满足的关系是：A. U1 ≤ U2 ≤ U3　B. U1 ≤ U3 ≤ U2　C. U2 ≤ U3 ≤ U1　D. U3 ≤ U2 ≤ U1
- 3 位序号：SW 窗口 **1**；GBN 最大发送窗口 2³ − 1 = **7**；SR 最大发送窗口 2² = **4**
- 窗口越大，最大信道利用率越高（或者都已达到 100% 而相等）
- 所以 **U1 ≤ U3 ≤ U2** → 选 **B**
- ⚠️ 括号中的“发送窗口和接收窗口相等”是对 **SR** 的说明：SR 满足 W_T + W_R ≤ 2³ 且二者相等，所以最大都是 4

### 📝 真题（2025 年第 47 题第 2 问）卫星链路的 GBN 设计
> 卫星轨道高度 36000km，电磁波传播速度 300000km/s，R1、R2 通过卫星链路通信，收发速率 200kbps。基于 GBN 为卫星链路设计单向可靠的链路层协议 SLP，支持 R1 → R2 发送数据。SLP 数据帧长 1500B，忽略 ACK 帧长度，要求 SLP 单向信道利用率不低于 80%，则发送窗口至少为多少？SLP 帧序号至少为多少（位）？

1. 单向传播时延 = 上行 36000km + 下行 36000km = 72000km / 300000km/s = **0.24s = 240ms**（忽略卫星转发时延）
2. RTT = **480ms**
3. T_D = 1500 × 8 / 200000 = **60ms**
4. 利用率 U = W × T_D / (T_D + RTT) ≥ 0.8 → W × 60 ≥ 0.8 × 540 = 432 → W ≥ 7.2 → **发送窗口至少为 8**
5. GBN 要求 W ≤ 2ⁿ − 1 → 2ⁿ ≥ 9 → **n ≥ 4**，帧序号至少 **4 位**

## ⚠️ 易错点

1. 零比特填充：**5 个连续 1 后插 0**；接收方删除；标志 **01111110**
2. 字节填充：数据中出现标志/转义字节，前面加 **ESC**
3. CRC：加 **r 个 0**（r = G 的最高次 = G 的位数 − 1）；**模 2 除法 = 异或**；余数不足 r 位**前面补 0**
4. CRC 只能检错，**不能实现可靠传输**
5. 海明码校验位数：**2^r ≥ k + r + 1**；校验位在 **2 的幂次**位置
6. 检错 d − 1 位，纠错 ⌊(d − 1)/2⌋ 位
7. SW 利用率 = T_D / (T_D + RTT + T_A)；**确认帧不能忽略时要加上 T_A**
8. **GBN：W_T ≤ 2ⁿ − 1，累积确认，失序丢弃，超时后退重传**
9. **SR：W_T + W_R ≤ 2ⁿ，W 最大 2^(n−1)，逐个确认，失序缓存，只重传出错帧**
10. 求窗口/序号位数：先求**一个周期**能发多少帧（周期 = T_D + RTT (+ T_A)），**帧长取最小**的最坏情况
11. **卫星链路**：单向传播时延要算**上下两段**

| 知识点 | 要点 |
|---|---|
| 成帧 | 字符计数、字节填充、零比特填充（5 个 1 插 0）、违规编码 |

| 海明码 | 2^r ≥ k + r + 1；校验和 = 出错位置 |
| 码距 | 检错 d − 1，纠错 ⌊(d−1)/2⌋ |
| SW | 窗口 1/1；U = T_D/(T_D + RTT + T_A) |
| GBN | 窗口 ≤ 2ⁿ−1 / 1；累积确认；后退重传 |
| SR | 窗口 ≤ 2^(n−1)；逐个确认；缓存乱序；单独重传 |
| 利用率 | U = W × T_D / (T_D + RTT) |

3. 信息位 7 位，需要几位海明校验位？
4. 某信道速率 4kbps，单向传播时延 20ms，采用停止-等待协议（确认帧忽略），要使信道利用率至少 50%，帧长至少多少？
5. 采用 3 位帧序号的 SR 协议，发送窗口最大为多少？GBN 呢？
6. 采用 GBN，发送方发送了 0~6 号帧，收到 1 号和 4 号帧的确认后超时，需要重传哪些帧？若是 SR（假设只有 2 号帧出错、其余帧都正确到达，5 号帧的确认丢失），需要重传哪些帧？

<details>
<summary>📖 答案</summary>

1. 原数据 0 1111111 0 11111 01：前 5 个 1 后插 0，剩下 2 个 1 后遇到 0（计数清零），再 5 个 1 后插 0。结果：**0 11111 0 11 0 11111 0 01**，即 **0111 1101 1011 1110 01**
2. 数据加 4 个 0：11010110110000，除以 10011，余数 **1110**；发送 **11010110111110**
3. 2^r ≥ 7 + r + 1 → r = **4**（16 ≥ 12）
4. U = T_D / (T_D + 40ms) ≥ 0.5 → T_D ≥ 40ms → 帧长 ≥ 4000 × 0.04 = **160 bit**
5. SR：2² = **4**；GBN：2³ − 1 = **7**
6. GBN：累积确认到 4 号，重传 **5、6** 号帧。SR：只重传超时的 **2 号**帧和确认丢失的 **5 号**帧（5 号的确认丢失，发送方会超时重传 5 号；接收方收到后再次确认）
