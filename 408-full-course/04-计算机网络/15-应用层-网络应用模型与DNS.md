## 一、网络应用模型（⭐）

### 📐 客户/服务器（C/S）模型
- 有一个总是打开的主机称为**服务器**，它服务于许多来自其他称为**客户机**的主机请求
- 服务器：**被动**等待请求；有**固定的**、周知的地址（IP 地址、端口号）；一般一直运行
- 客户机：**主动**发起请求；客户机之间**不直接通信**
- 例：Web、FTP、远程登录（Telnet）、电子邮件
- ❌ 可扩展性差：请求多了服务器压力大，需要服务器集群

### 📐 P2P（对等）模型
- **不存在永远在线的服务器**，每个主机既可以提供服务，也可以请求服务（任意端系统/结点之间可以**直接通讯**）
- 结点**间歇性**接入网络，结点可能改变 IP 地址，**可扩展性好**
- **网络健壮性强**（一个结点坏了不影响全局）
- 例：BT 下载、迅雷、P2P 视频直播
- ❌ 难以管理

## 二、域名系统 DNS（⭐⭐⭐）

### 📐 DNS 的作用
**DNS（Domain Name System）**：把便于人们记忆的具有特定含义的**主机名**（如 www.cskaoyan.com）转换为便于机器处理的 **IP 地址**。
- DNS 系统采用 **C/S 模型**，其协议运行在 **UDP** 之上，使用 **53 号端口**
- DNS 是**分布式数据库**，没有一台服务器保存所有映射

### 📐 层次域名空间
因特网采用**层次树状结构**的命名方法。任何一个连接在因特网上的主机或路由器，都有一个**唯一的层次结构名称**——**域名**。
```
                        根（无名）
          ┌───────┬──────┼────────┬────────┐
         com     edu    org       cn      net         ← 顶级域名
          │       │               │
        baidu    mit          ┌───┼────┐
          │                  edu  com  gov             ← 二级域名
         www                  │
                            tsinghua                   ← 三级域名
                              │
                             www                       ← 主机名
```
- 域名 `www.tsinghua.edu.cn`：**从右到左**级别递减（cn 是顶级域名，edu 是二级域名，tsinghua 是三级域名，www 是主机名）
- **标号**：每个标号不超过 63 个字符（为了方便记忆，最好不超过 12 个字符），不区分大小写
- 完整域名不超过 255 个字符
- **顶级域名**：
  - **国家顶级域名**：cn（中国）、us（美国）、uk（英国）
  - **通用顶级域名**：com（公司企业）、net（网络服务机构）、org（非营利性组织）、gov（美国政府部门）、edu（美国教育机构）
  - **基础结构域名**：arpa，用于反向域名解析

### 📐 域名服务器（⭐⭐⭐）
| 服务器 | 作用 |
|---|---|
| **根域名服务器** | **最高层次**的域名服务器，所有的根域名服务器都知道所有的**顶级域名服务器**的域名和 IP 地址。全球共有 **13 个**根域名服务器（以 a~m 命名，但每个都有很多镜像）。本地域名服务器若无法解析，首先求助于根域名服务器 |
| **顶级域名服务器** | 负责管理在该顶级域名服务器注册的**所有二级域名**。收到 DNS 查询请求时，就给出相应的回答（可能是最后的结果，也可能是下一步应当找的域名服务器的 IP 地址） |
| **权限（授权）域名服务器** | 每个主机都**必须在授权域名服务器处注册登记**。负责一个“区”，总能将其管辖的主机名转换为该主机的 IP 地址 |
| **本地域名服务器** | 当一个主机发出 DNS 查询请求时，这个查询请求报文就**发送给本地域名服务器**。每一个因特网服务提供者 ISP，或一个大学，甚至一个大学里的系，都可以拥有一个本地域名服务器（就是你电脑网络设置里的“首选 DNS 服务器”） |

### 📐 域名解析过程（⭐⭐⭐）
**域名解析**：把域名映射成为 IP 地址（正向解析）或把 IP 地址映射成域名（反向解析）。
- 当客户端需要域名解析时，通过本机的 DNS 客户端构造一个 DNS 请求报文，以 **UDP 数据报**方式发往**本地域名服务器**

#### 1. 递归查询
- **主机向本地域名服务器的查询一般都是采用递归查询**：如果本地域名服务器不知道被查询域名的 IP 地址，那么本地域名服务器就**以 DNS 客户的身份**，向其他根域名服务器继续发出查询请求报文（替主机查询），而不是让主机自己进行下一步查询
- 若本地域名服务器也采用递归查询请求根域名服务器，那么根域名服务器再向顶级域名服务器查询……每一个服务器都“**替别人问**”，最后结果**沿原路返回**
```
主机 ──① ──► 本地 DNS ──② ──► 根 DNS ──③ ──► 顶级 DNS ──④ ──► 权限 DNS
     ◄──⑧ ──          ◄──⑦ ──        ◄──⑥ ──           ◄──⑤ ──
```
- ❌ 根域名服务器负担太重，**很少使用**

#### 2. 迭代查询（⭐⭐⭐ 常用）
- **本地域名服务器向根域名服务器的查询通常是采用迭代查询**：当根域名服务器收到本地域名服务器发出的迭代查询请求报文时，要么给出所要查询的 IP 地址，要么告诉本地域名服务器“**你下一步应当向哪一个域名服务器进行查询**”，然后让本地域名服务器**自己**进行后续的查询
```
主机 ──① ──► 本地 DNS ──② ──► 根 DNS
                      ◄──③ ──（去问 com 顶级域名服务器）
                      ──④ ──► 顶级 DNS
                      ◄──⑤ ──（去问 xyz.com 权限服务器）
                      ──⑥ ──► 权限 DNS
                      ◄──⑦ ──（IP 地址是……）
     ◄──⑧ ──
```
- 🧒 递归：“你帮我问到底”；迭代：“你告诉我下一个该找谁，我自己去问”

📌 **最常见的组合**：主机 → 本地域名服务器：**递归**；本地域名服务器 → 其他服务器：**迭代**。

### 📐 DNS 高速缓存
- 为了提高 DNS 查询效率，并减轻根域名服务器的负荷和减少因特网上的 DNS 查询报文数量，在域名服务器中广泛地使用了**高速缓存**
- 每个域名服务器都维护一个高速缓存，存放**最近用过的名字**以及从何处获得名字映射信息的记录
- 为保持高速缓存中的内容正确，域名服务器应为每项内容设置**计时器**，并处理超过合理时间的项
- **主机**也会缓存（在本机的 DNS 缓存中）

### 📐 DNS 与 Web 访问的时间计算（⭐⭐⭐）
📝 **真题（2020 年第 40 题）**：假设下图所示网络中的本地域名服务器只提供**递归**查询服务，其他域名服务器均只提供**迭代**查询服务；局域网内主机访问 Internet 上各服务器的往返时间（RTT）均为 10ms，忽略其他各种时延。若主机 H 通过超链接 http://www.abc.com/index.html 请求浏览纯文本 Web 页 index.html，则从点击超链接开始到浏览器接收到 index.html 页面为止，所需的最短时间与最长时间分别是：
> 图示：局域网内有主机 H 和本地域名服务器，经路由器连到 Internet；Internet 上有根域名服务器、com 顶级域名服务器、abc.com 域名服务器、www.abc.com 服务器。
A. 10ms, 40ms　B. 10ms, 50ms　C. 20ms, 40ms　D. 20ms, 50ms

**最短时间**（本地域名服务器的缓存中已有 www.abc.com 的 IP 地址）：
- H 与本地域名服务器在同一局域网，时延**忽略**
- 与 Web 服务器建立 **TCP 连接**：1 RTT = 10ms
- 发送 HTTP 请求并接收 index.html：1 RTT = 10ms
- 共 **20ms**

**最长时间**（本地域名服务器缓存中什么都没有）：
- 本地域名服务器**迭代**查询：根（10ms）→ com 顶级（10ms）→ abc.com 权限（10ms）= **30ms**
- TCP 连接 + HTTP 请求/响应 = **20ms**
- 共 **50ms**
→ 选 **D**

⚠️ 这类题要注意：
- 主机到本地域名服务器（同一局域网）的时间通常**忽略**
- 每向一个外部域名服务器查询一次 = **1 RTT**
- HTTP 要先建立 **TCP 连接（1 RTT）**，再请求-响应（1 RTT）
- 若是**非持久连接**，每个对象都要重新建立 TCP 连接

## 三、文件传输协议 FTP（⭐⭐）

### 📐 FTP 的功能
**文件传送协议 FTP** 提供不同种类主机系统（硬、软件体系等都可以不同）之间的**文件传输**能力。
- 提供交互式的访问，允许客户指明文件的类型与格式（如指明是否使用 ASCII 码），并允许文件具有存取权限（如访问文件的用户必须经过授权，并输入有效的口令）
- 屏蔽了各计算机系统的细节，因而适合于在异构网络中任意计算机之间传送文件
- FTP 采用 **C/S 方式**，**使用 TCP**

### 📐 FTP 的两个连接（⭐⭐⭐）
FTP 服务器进程由两大部分组成：一个**主进程**，负责接受新的请求；另外有若干个**从属进程**，负责处理单个请求。
- FTP 使用**两个并行的 TCP 连接**：
| 连接 | 服务器端口 | 作用 | 持续时间 |
|---|---|---|---|
| **控制连接** | **21** | 传送**控制信息**（用户名、口令、目录操作、传输命令……），**带外传送** | **持久**：在**整个会话期间一直保持打开** |
| **数据连接** | **20**（主动模式） | 传送**文件数据** | **非持久**：每传送一个文件就建立一个新的数据连接，传完就关闭 |

- 🧒 控制连接像**电话**（一直通着，用来说“把 A 文件发给我”），数据连接像**快递车**（每次运一个文件，送完就走）
- FTP 的控制信息是**带外传送**的（控制连接和数据连接分开）；而 HTTP 是**带内**的

### 📐 主动模式与被动模式（⭐⭐）
- **主动模式（PORT）**：客户端告诉服务器自己的一个端口号，**服务器从 20 端口主动**连接客户端的这个端口建立数据连接
- **被动模式（PASV）**：服务器打开一个临时端口（**不是 20**）并告诉客户端，**客户端主动**连接服务器的这个端口建立数据连接（适合客户端在防火墙/NAT 后面的情况）
- ⚠️ 数据连接的服务器端口**只有在主动模式下才是 20**

📝 **真题（2023 年第 47 题第 1 问）**：FTP 的控制连接是持久的还是非持久的？FTP 的数据连接是持久的还是非持久的？H 登录 FTP 服务器时，建立的 TCP 连接是控制连接还是数据连接？
- 控制连接：**持久**；数据连接：**非持久**；登录时建立的是**控制连接**
（后面几问见第 14 课。）

### 📐 TFTP
**简单文件传送协议 TFTP**：使用 **UDP**（端口 **69**），很小很简单，只支持文件传输，不支持交互，没有目录列表、认证功能。常用于网络设备启动时下载配置文件。

## ⚠️ 易错点

1. DNS 使用 **UDP**，端口 **53**
2. 域名**从右到左**级别递减；根域名服务器知道所有**顶级**域名服务器
3. 每台主机都必须在**权限域名服务器**注册
4. **主机 → 本地域名服务器：递归**；**本地域名服务器 → 其他：迭代**（最常见）
5. 递归查询时**每个服务器替别人问**，结果沿原路返回；迭代查询时**本地域名服务器自己挨个问**
6. DNS 时间计算：本地局域网内的时间**忽略**；每查询一个外部服务器 1 RTT；HTTP 需要 TCP 连接 1 RTT + 请求响应 1 RTT
7. FTP：**控制连接 21，持久**；**数据连接 20（主动模式），非持久**；**带外**传送控制信息
8. 登录 FTP 建立的是**控制连接**
9. TFTP 用 **UDP 69**

## 📋 本课小结

| 知识点 | 要点 |
|---|---|
| C/S vs P2P | 固定服务器 vs 对等结点 |
| DNS | UDP 53；层次域名；根/顶级/权限/本地 |
| 查询 | 递归（替你问）、迭代（告诉你找谁） |
| DNS 时间 | 缓存命中 0；否则根 + 顶级 + 权限各 1 RTT |
| FTP | TCP；控制 21 持久；数据 20 非持久；带外控制 |
| TFTP | UDP 69，简单 |

## 🏋️ 课后练习

1. 主机 H 访问 www.example.com，本地域名服务器采用迭代查询，所有缓存为空，本地域名服务器到外部各域名服务器的 RTT 均为 20ms，H 到本地域名服务器的时延忽略，H 到 Web 服务器的 RTT 为 30ms。求 H 获得该网页（仅一个 HTML 文件）的最短时间。
2. 若本地域名服务器采用递归查询，所有服务器都采用递归查询，本地域名服务器向根查询的 RTT、根向顶级、顶级向权限的 RTT 都是 20ms，DNS 解析需要多少时间？
3. 判断：(a) DNS 使用 TCP 传输；(b) FTP 的数据连接在整个会话期间一直保持；(c) 根域名服务器知道所有二级域名服务器的 IP 地址；(d) 用户下载 3 个文件，FTP 需要建立 3 个数据连接。

<details>
<summary>📖 答案</summary>

1. DNS 迭代：根、顶级、权限各 20ms → 60ms；TCP 连接 30ms + HTTP 请求/响应 30ms = 60ms。共 **120ms**
2. 递归：本地 → 根 → 顶级 → 权限，再原路返回，相当于三段往返各 20ms，共 **60ms**
3. (a) **错**，主要使用 UDP；(b) **错**，数据连接是非持久的；(c) **错**，根域名服务器知道所有**顶级**域名服务器；(d) **对**
</details>
