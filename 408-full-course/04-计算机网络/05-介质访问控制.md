## 🚪 课前引入

一个教室里，**只有一块黑板**（共享信道），很多同学都想上去写字（发送数据）：
- **排班表**：周一张三用、周二李四用……（**信道划分**，静态分配）

在**点对点链路**上（如两台路由器之间的光纤），只有两个结点，不存在争用问题。但在**广播信道**上（早期的以太网总线、无线局域网），多个结点共享同一个信道，就需要**介质访问控制（MAC）**来协调谁在什么时候发送。

## 一、介质访问控制概述（⭐）

### 📐 传输数据使用的两种链路
- **点对点链路**：两个相邻结点通过一个链路相连，没有第三者。应用：**PPP 协议**，常用于广域网
- **广播式链路**：所有主机**共享通信介质**。应用：早期的**总线以太网**、**无线局域网**，常用于局域网
  - 典型拓扑结构：总线型、星型（逻辑总线型）

### 📐 介质访问控制的内容
采取一定的措施，使得两对结点之间的通信**不会发生互相干扰**的情况。
```
                    ┌── 静态划分信道：信道划分介质访问控制（FDM、TDM、WDM、CDMA）
介质访问控制 ────────┤                     ┌── 随机访问（ALOHA、CSMA、CSMA/CD、CSMA/CA）
                    └── 动态分配信道 ──────┤
                                          └── 轮询访问（令牌传递）
```

## 二、信道划分介质访问控制（⭐⭐）

将使用介质的每个设备与来自同一信道上的其他设备的通信**隔离**开，把**时域和频域资源合理地分配**给网络上的设备。
- **多路复用技术**：把多个信号组合在一条物理信道上进行传输，使多个计算机或终端设备**共享信道资源**，提高信道利用率
- 🧒 把一条广播信道，逻辑上分成几条用于两个结点之间通信的互不干扰的子信道，实际就是把广播信道转变为点对点信道

### 📐 1. 频分多路复用（FDM）
用户在分配到一定的**频带**后，在通信过程中**自始至终都占用这个频带**。
- 所有用户在**同样的时间**占用**不同的带宽（频率带宽）**资源
- 🧒 像收音机的不同电台：同时广播，但频率不同
- ✅ 充分利用传输介质带宽，系统效率较高；由于技术比较成熟，实现也比较容易

### 📐 2. 时分多路复用（TDM）
将时间划分为一段段等长的**时分复用帧（TDM 帧）**。每一个时分复用的用户在每一个 TDM 帧中**占用固定序号的时隙**，所有用户轮流占用信道。
- 所有用户在**不同的时间**占用**同样的频带宽度**
- ❌ 若某用户暂时没有数据要发，他的时隙也**空着**，**信道利用率低**

**改进：统计时分复用（STDM，异步时分复用）**：每一个 STDM 帧中的时隙数**小于**连接在集中器上的用户数。各用户有了数据就随时发往集中器的输入缓存，然后集中器按顺序依次扫描输入缓存，把缓存中的输入数据放入 STDM 帧中，一个 STDM 帧满了就发出。STDM 帧**不是固定分配时隙**，而是**按需动态分配时隙**。

### 📐 3. 波分多路复用（WDM）
波分多路复用就是**光的频分多路复用**，在一根光纤中传输多种**不同波长（频率）的光信号**，由于波长（频率）不同，所以各路光信号互不干扰，最后再用波长分解复用器将各路波长分解出来。

### 📐 4. 码分多路复用（CDMA）（⭐⭐）
**码分多址（CDMA）**是码分复用的一种方式。
- 1 个比特分为多个**码片（芯片，chip）**，每一个站点被指定一个**唯一的 m 位的码片序列**
- 发送 **1** 时站点发送**码片序列**，发送 **0** 时发送**码片序列的反码**（通常把码片中的 0 写为 −1，1 写为 +1）
- **多个站点同时发送数据的时候**，要求各个站点**芯片序列相互正交**（规格化内积为 0）
- 各路数据在信道中被**线性相加**
- **数据分离**：合并的数据和源站的码片序列做**规格化内积**（对应分量相乘再求和，再除以 m）：
  - 结果为 **+1** → 该站发送了 **1**
  - 结果为 **−1** → 该站发送了 **0**
  - 结果为 **0** → 该站**没有发送**数据

✏️ **例**：共有 4 个站进行码分多址通信。4 个站的码片序列为：
- A：(−1 −1 −1 +1 +1 −1 +1 +1)
- B：(−1 −1 +1 −1 +1 +1 +1 −1)
- C：(−1 +1 −1 +1 +1 +1 −1 −1)
- D：(−1 +1 −1 −1 −1 −1 +1 −1)

现收到这样的码片序列：**(−1 +1 −3 +1 −1 −3 +1 +1)**。问哪个站发送数据了？发送数据的站发送的是 1 还是 0？
- A · R = (1 − 1 + 3 + 1 − 1 + 3 + 1 + 1) / 8 = 8/8 = **+1** → A 发送 **1**
- B · R = (1 − 1 − 3 − 1 − 1 − 3 + 1 − 1) / 8 = −8/8 = **−1** → B 发送 **0**
- C · R = (1 + 1 + 3 + 1 − 1 − 3 − 1 − 1) / 8 = 0 → C **未发送**
- D · R = (1 + 1 + 3 − 1 + 1 + 3 + 1 − 1) / 8 = 8/8 = **+1** → D 发送 **1**

## 三、随机访问介质访问控制（⭐⭐⭐）

所有用户可**随机**发送信息，发送信息时**占全部带宽**。不协调就会产生**冲突（碰撞）**：若两个或多个用户同时发送信息，就会产生冲突，导致所有冲突用户的发送均以失败告终。随机访问协议就是要解决**如何处理冲突**的问题。

### 📐 1. ALOHA 协议
- **纯 ALOHA**：不监听信道，**不按时间槽**发送，**随机重发**。想发就发
  - 冲突如何检测？如果发生冲突，接收方在就会检测出差错，然后不予确认，发送方在一定时间内收不到就判断发生冲突
  - 冲突如何解决？超时后等**随机时间**再重传
- **时隙 ALOHA**：把时间分成若干个相同的**时间片**，所有用户在时间片**开始时刻**同步接入网络信道，若发生冲突，则必须等到下一个时间片开始时刻再发送
  - 控制想发就发的随意性
- 📌 纯 ALOHA 比时隙 ALOHA 吞吐量更低，效率更低（纯 ALOHA 最大吞吐量约 18.4%，时隙 ALOHA 约 36.8%）

### 📐 2. CSMA 协议（载波监听多路访问）
**CS（Carrier Sense）**：载波侦听/监听，每一个站在发送数据之前要**检测一下总线上是否有其他计算机在发送数据**。当几个站同时在总线上发送数据时，总线上的信号电压摆动值将会增大（互相叠加）。当一个站检测到的信号电压摆动值超过一定门限值时，就认为总线上至少有两个站同时在发送数据，表明产生了碰撞，即发生了冲突。
**MA（Multiple Access）**：多点接入，表示许多计算机以多点接入的方式连接在一根总线上。
- **协议思想**：发送帧之前，**监听信道**
  - 信道空闲：发送完整帧
  - 信道忙：推迟发送

| CSMA 类型 | 信道空闲 | 信道忙 | 特点 |
|---|---|---|---|
| **1-坚持 CSMA** | **马上发** | **继续坚持监听** | 只要空闲，站点就马上发送，**避免了媒体利用率的损失**；但若有 2 个或以上站点同时有数据要发，**冲突不可避免** |
| **非坚持 CSMA** | **马上发** | **放弃监听，等一个随机时间再监听** | 采用随机的重发延迟时间可以**减少冲突发生的可能性**；但可能存在大家都在延迟等待过程中，使得**媒体仍可能处于空闲状态，媒体使用率降低** |
| **p-坚持 CSMA** | 以 **概率 p** 直接发送，以概率 1 − p 等待到下一个时间槽再发送 | **继续监听**（持续监听直到信道空闲） | 既能像非坚持算法那样减少冲突，又能像 1-坚持算法那样减少媒体空闲时间；**冲突后仍会坚持把数据帧发送完**，造成了浪费 |

### 📐 3. CSMA/CD 协议（⭐⭐⭐）
**载波监听多点接入/碰撞检测（Carrier Sense Multiple Access with Collision Detection）**，用于**有线以太网**（总线形网络或半双工网络）。
- **CS**：载波侦听/监听，每一个站在**发送数据之前以及发送数据时**都要检测一下总线上是否有其他计算机在发送数据
- **MA**：多点接入
- **CD**：**碰撞检测（冲突检测）**，“**边发送边监听**”，适配器边发送数据边检测信道上信号电压的变化情况，以便判断自己在发送数据时其他站是否也在发送数据

📐 **为什么先听后发还会冲突？** 因为电磁波在总线上总是以**有限的速率**传播。A 发送的信号还没传到 B，B 监听到信道空闲，也开始发送——冲突！

#### 争用期（⭐⭐⭐）
设单程端到端传播时延为 **τ**：
- 最坏情况下，A 发送后，信号快到 B 时（τ − δ），B 开始发送，B 立即检测到冲突；冲突信号传回 A 又需要约 τ
- 所以 A **最多经过 2τ 时间**就能知道自己发送的数据有没有发生冲突
- **2τ** 称为**争用期（冲突窗口）**
- **经过 2τ 时间还没有检测到碰撞，才能肯定这次发送不会发生碰撞**
- 🧒 **CSMA/CD 只能进行半双工通信**：每个站在发送数据之后的一小段时间内，存在发生碰撞的可能性

```
A                                               B
│ t=0  A 开始发送 ────────────────────►          │
│                                               │ t=τ−δ  B 检测到信道空闲，开始发送
│                                    ◄────────  │ t=τ    B 检测到冲突，停止发送
│ t=2τ−δ  A 检测到冲突                            │
```

#### 最短帧长（⭐⭐⭐）
如果帧太短，A 在**发送完这一帧之前**还没来得及检测到冲突，就以为发送成功了——这是不行的！
所以要求：**帧的发送时间 ≥ 争用期 2τ**
```
最短帧长 = 总线传播时延 × 数据传输速率 × 2 = 2τ × C
```
- **以太网规定最短帧长为 64B（512 bit）**，凡是长度小于 64 字节的帧都是由于冲突而异常中止的**无效帧**
- 10Mbps 以太网：发送 512 bit 需要 **51.2μs**，这就是 10Mbps 以太网的**争用期**，也是退避的基本时间单位
- 如果只发送小于 64B 的帧，需要在 MAC 子层中于数据字段的后面加入一个**整数字节的填充字段**，以保证以太网的 MAC 帧长不小于 64B

✏️ **例**：某 CSMA/CD 网络，数据率 1Gbps，电缆中信号传播速度 200000km/s（2 × 10⁸ m/s）。若最短帧长减少 800 bit，则最远的两个站点之间的距离至少需要增加还是减少多少？
- 最短帧长 = 2τ × C = 2 × (d / v) × C
- Δ帧长 = 2 × Δd / v × C → −800 = 2 × Δd / (2 × 10⁸) × 10⁹ → Δd = −800 × 2 × 10⁸ / (2 × 10⁹) = **−80m**
- 即距离至少需要**减少 80m**

#### 截断二进制指数退避算法（⭐⭐⭐）
发生碰撞后，站点**等待一个随机时间**再重传：
1. 确定基本退避（推迟）时间为争用期 **2τ**
2. 定义参数 **k = min(重传次数, 10)**
3. 从离散的整数集合 **[0, 1, …, 2^k − 1]** 中**随机**取出一个数 r，重传所需要退避的时间就是 **r 倍的基本退避时间**，即 **2rτ**
4. 当重传达 **16 次**仍不能成功时，说明网络太拥挤，认为此帧永远无法正确发出，**抛弃此帧**并向高层报告出错

🧒 冲突次数越多，随机等待的范围越大，**越来越“谦让”**，减少再次冲突的概率。

📝 **真题（2023 年第 36 题）**：已知 10BaseT 以太网的争用时间片为 51.2μs。若网卡在发送某帧时发生了连续 4 次冲突，则基于二进制指数退避算法确定的再次尝试重发该帧前等待的最长时间是：A. 51.2μs　B. 204.8μs　C. 768μs　D. 819.2μs
- 连续 4 次冲突 → k = min(4, 10) = 4 → r ∈ [0, 2⁴ − 1] = [0, 15]
- 最长等待 = 15 × 51.2μs = **768μs** → 选 **C**
- ⚠️ 陷阱：不是 2⁴ = 16 倍（819.2μs），而是 **2^k − 1 = 15** 倍

📝 **真题（2025 年第 35 题）**：现有一 BaseT 以太网，主机甲、乙同属一个冲突域，连续发生 11 次冲突，甲再次发送的最大时间间隔为：A. 0.512ms　B. 0.5632ms　C. 52.3776ms　D. 104.8064ms
- 11 次冲突 → **k = min(11, 10) = 10**（截断！）→ r ∈ [0, 1023]
- 最大 = 1023 × 51.2μs = 52377.6μs = **52.3776ms** → 选 **C**
- ⚠️ 陷阱：若忘记截断用 k = 11，得 2047 × 51.2μs = 104.8064ms（D）

📝 **真题（2022 年第 47 题第 2 问）**：H2 与 H3 通过 100BaseT 集线器（设备 2）相连，处于同一冲突域。若信号传播速度为 2 × 10⁸ m/s，以太网最小帧长为 64B，信号通过设备 2 时会产生额外的 1.51μs 的时间延迟，则 H2 与 H3 之间可以相距的最远距离是多少？
- 100Mbps 下发送最短帧 512 bit 需要 **5.12μs**，这就是允许的最大争用期（往返时间）
- 往返时间 = 2 × (传播时延 + 集线器时延) = 2 × (d / (2 × 10⁸) + 1.51μs) ≤ 5.12μs
- d / (2 × 10⁸) ≤ 2.56 − 1.51 = 1.05μs → d ≤ 1.05 × 10⁻⁶ × 2 × 10⁸ = **210m**

### 📐 4. CSMA/CA 协议（⭐⭐）
**载波监听多点接入/碰撞避免（Collision Avoidance）**，用于**无线局域网（IEEE 802.11）**。

📐 **为什么无线局域网不能用 CSMA/CD？**
1. **无法做到 360° 全面检测碰撞**：无线信号强度随距离迅速衰减，发送端自己的信号远强于远方其他站的信号，**很难在发送的同时检测冲突**
2. **隐蔽站问题**：当 A 和 C 都检测不到信号，认为信道空闲时，同时向终端 B 发送数据帧，就会导致冲突（A 和 C 之间有障碍物或距离太远，互相“听不见”）

#### CSMA/CA 的工作原理
1. 发送数据前，先检测信道是否空闲
2. **空闲则发出 RTS（Request To Send）**，RTS 包括发射端的地址、接收端的地址、下一份数据将持续发送的时间等信息；信道忙则等待
3. 接收端收到 RTS 后，将响应 **CTS（Clear To Send）**
4. 发送端收到 CTS 后，开始发送数据帧（同时**预约信道**：发送方告知其他站点自己要传多久数据）
5. 接收端收到数据帧后，将用 **CRC** 来检验数据是否正确，正确则响应 **ACK 帧**
6. 发送方收到 ACK 就可以进行下一个数据帧的发送，若没有则一直重传至规定重发次数为止（采用**二进制指数退避**算法来确定随机的推迟时间）

📌 CSMA/CA 的要点：
- **预约信道**（RTS/CTS）：解决**隐蔽站**问题（C 听不到 A 的 RTS，但能听到 B 的 CTS，于是知道要等待）
- **ACK 帧**：无线信道误码率高，需要**确认**（**停止-等待**）
- **RTS/CTS 帧**（可选）

#### 帧间间隔（IFS）（⭐⭐）
所有站在完成发送后，必须再等待一段很短的时间（继续监听）才能发送下一帧。**帧间间隔的长短取决于该站要发送的帧的类型**：
| 帧间间隔 | 长度 | 用途 |
|---|---|---|
| **SIFS**（短帧间间隔） | **最短** | 分隔属于一次对话的各帧：发送 **ACK、CTS**、分片后的数据帧 |
| PIFS（点协调帧间间隔） | 中等 | PCF 方式下使用 |
| **DIFS**（分布式协调帧间间隔） | **最长** | 发送**数据帧**和**管理帧**（如 RTS）前使用 |

📌 优先级高的帧等待时间短（SIFS），这样可以**优先**获得信道（如 ACK 要尽快发）。

📝 **真题（2020 年第 37 题）**：某 IEEE 802.11 无线局域网中，主机 H 与 AP 之间发送或接收 CSMA/CA 帧的过程如下图所示。在 H 或 AP 发送帧前所等待的帧间间隔时间（IFS）中，最长的是：
```
H                        AP
│ IFS1                    │
│ ─────── RTS ─────────►  │
│                         │ IFS2
│ ◄─────── CTS ────────── │
│ IFS3                    │
│ ─────── DATA ────────►  │
│                         │ IFS4
│ ◄─────── ACK ────────── │
```
A. IFS1　B. IFS2　C. IFS3　D. IFS4
→ **A**：IFS1 是 H 发送 RTS 之前等待的时间，是 **DIFS**（最长）；IFS2（发 CTS 前）、IFS3（发 DATA 前，属于同一次对话）、IFS4（发 ACK 前）都是 **SIFS**

### 📐 CSMA/CD 与 CSMA/CA 的比较（⭐⭐）
| | CSMA/CD | CSMA/CA |
|---|---|---|
| 应用 | **有线**以太网（总线型、半双工） | **无线**局域网（802.11） |
| 冲突处理 | **碰撞检测**：边发边听，检测到冲突后停止发送 | **碰撞避免**：尽量避免冲突（RTS/CTS 预约信道、帧间间隔、随机退避） |
| 检测方式 | 通过电缆中电压的变化 | 能量检测、载波检测、能量载波混合检测 |
| 确认 | 无 | **有 ACK**（停止-等待） |

## 四、轮询访问介质访问控制（⭐）

既要不产生冲突，又要发送时占全部带宽。
### 📐 1. 轮询协议
**主结点**轮流“邀请”从属结点发送数据。
- ❌ **轮询开销**（主结点要发轮询帧）；**等待延迟**；**单点故障**（主结点坏了全网瘫痪）

### 📐 2. 令牌传递协议
**令牌**：一个特殊格式的 MAC 控制帧，不含任何信息。控制信道的使用，确保同一时刻只有一个结点独占信道。
- 每个结点都可以在一定的时间内（令牌持有时间）获得发送数据的权利，并**不是无限制地持有令牌**
- 令牌环网无碰撞
- ❌ 令牌开销、等待延迟、单点故障（令牌丢失）
- 应用于令牌环网（物理星型拓扑，逻辑环形拓扑），采用令牌传送方式的网络常用于**负载较重、通信量较大**的网络中

### 📐 三类方法比较
| | 信道划分 | 随机访问 | 轮询访问 |
|---|---|---|---|
| 冲突 | 无 | **有** | 无 |
| 网络负载**重**时 | 共享信道效率高，且公平 | 冲突开销大 | 效率高 |
| 网络负载**轻**时 | 共享信道效率低 | 共享信道效率高，单个结点可利用信道全部带宽 | 有轮询/令牌开销 |

## ⚠️ 易错点

1. **FDM 同时不同频；TDM 同频不同时**；STDM 按需分配时隙；WDM 是光的 FDM
2. CDMA：规格化内积 **+1 发 1，−1 发 0，0 未发送**；码片序列**两两正交**
3. 1-坚持：空闲马上发，忙继续听；非坚持：忙就等随机时间；p-坚持：空闲以概率 p 发
4. CSMA/CD：**争用期 = 2τ**；**最短帧长 = 2τ × C**；以太网最短帧 **64B**
5. 二进制指数退避：**k = min(冲突次数, 10)**，r ∈ [0, **2^k − 1**]；**16 次**失败丢弃
6. 10Mbps 以太网争用期 **51.2μs**；100Mbps 为 **5.12μs**
7. 求最远距离时，**往返**时延（含中间设备时延 × 2）≤ 最短帧发送时间
8. CSMA/CA：用于**无线**，**RTS/CTS 解决隐蔽站问题**；需要 **ACK**
9. **SIFS 最短**（ACK、CTS）；**DIFS 最长**（数据帧、RTS 前）
10. CSMA/CD 只能**半双工**；全双工以太网（交换机）不需要 CSMA/CD

## 📋 本课小结

| 方法 | 要点 |
|---|---|
| FDM/TDM/STDM/WDM | 频率/时间/按需时隙/波长划分 |
| CDMA | 码片正交，内积 +1/−1/0 |
| ALOHA | 想发就发；时隙 ALOHA 按时间片 |
| CSMA | 先听后发；1-坚持/非坚持/p-坚持 |
| CSMA/CD | 先听后发、边发边听、冲突停发、随机重发；2τ、64B、指数退避 |
| CSMA/CA | 无线；RTS/CTS、SIFS/DIFS、ACK |
| 轮询/令牌 | 无冲突；开销、单点故障 |

## 🏋️ 课后练习

1. 某 CSMA/CD 网络，传输速率 10Mbps，两站间最远距离 2km，信号传播速度 2 × 10⁸ m/s，求最短帧长。
2. 采用 CSMA/CD 的 10Mbps 以太网，某站连续发生 3 次冲突后，重传前可能等待的最长时间是多少？
3. 站 A 的码片序列为 (+1 −1 +1 −1)，站 B 为 (+1 +1 −1 −1)，A 发送 1、B 发送 0，信道上合成的信号是什么？接收方如何分离？
4. 为什么无线局域网要使用确认机制，而有线以太网不需要？
5. 判断：(a) 1-坚持 CSMA 在信道忙时会等待随机时间；(b) CSMA/CD 可以用于全双工通信；(c) SIFS 比 DIFS 短。

<details>
<summary>📖 答案</summary>

1. τ = 2000 / (2 × 10⁸) = 10μs，最短帧长 = 2 × 10μs × 10Mbps = **200 bit**（25B）
2. k = 3，r 最大 = 7，最长等待 7 × 51.2 = **358.4μs**
3. A 发 1 → (+1 −1 +1 −1)；B 发 0 → 反码 (−1 −1 +1 +1)；合成 **(0 −2 +2 0)**。与 A 内积：(0 + 2 + 2 + 0)/4 = +1 → A 发 1；与 B 内积：(0 − 2 − 2 + 0)/4 = −1 → B 发 0
4. 无线信道误码率高，且发送方**无法检测冲突**（不能边发边听），只能靠接收方的 **ACK** 来确认帧是否被正确接收；有线以太网中发送方可以通过碰撞检测知道是否发生冲突，而且有线信道误码率低，可靠性交给上层（如 TCP）处理
5. (a) **错**，1-坚持会继续监听；(b) **错**，只用于半双工；(c) **对**
</details>
