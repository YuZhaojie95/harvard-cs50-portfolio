## 🚪 课前引入

数据链路层只能把帧送到**相邻**的结点（同一个局域网内）。但你要访问的网站服务器可能在地球另一端，中间隔着几十个不同的网络（有的是以太网，有的是 Wi-Fi，有的是光纤骨干网）。

**网络层**要解决的问题：
- 怎么给全世界的主机**编址**？（IP 地址）
- 数据从源主机出发，**走哪条路**到目的主机？（路由选择）
- 路由器收到一个分组，**从哪个端口转发出去**？（转发）
- 不同网络能传的最大分组大小（MTU）不同，太大的分组怎么办？（分片）

🧒 **比喻：寄国际快递**
- IP 地址 = 收件人的**详细地址**（国家-城市-街道-门牌号）
- 路由器 = 各地的**快递分拣中心**：看地址，决定下一站送到哪
- 路由选择 = 规划**全局路线**；转发 = 每个分拣中心根据路线表把包裹放到**正确的传送带**上

## 一、网络层的功能（⭐⭐）

### 📐 1. 异构网络互联
**网络互联**：将两个以上的计算机网络，通过一定的方法，用一种或多种通信处理设备（**中间设备**）相互连接起来，以构成更大的网络系统。
- 中间设备：
  - 物理层：中继器、集线器
  - 数据链路层：网桥、交换机
  - 网络层：**路由器**
  - 网络层以上：网关
- 📌 **网络互联通常指网络层的互联**：使用路由器进行互联，所有网络都使用相同的网际协议 **IP**，看起来就像一个“**虚拟互连网络**”

### 📐 2. 路由与转发（⭐⭐）
路由器的主要功能：
- **路由选择**（确定哪一条路径）：根据特定的**路由选择协议**构造出**路由表**，同时经常或定期地和相邻路由器交换路由信息而不断更新和维护路由表
- **分组转发**（当一个分组到达时所采取的动作）：根据**转发表**把用户的 IP 数据报从合适的端口转发出去
- 🧒 **路由选择**是“规划路线”（控制层面，软件，较慢）；**转发**是“按表执行”（数据层面，硬件，很快）

### 📐 3. SDN 基本概念（⭐⭐）
- **数据平面（转发）**：负责**转发**分组。依据转发表，对到达的分组进行处理（转发、丢弃、修改首部……），时间尺度为纳秒级，通常由**硬件**实现
- **控制平面（路由选择）**：负责**路由选择**（计算转发表），时间尺度为毫秒/秒级，通常由**软件**实现
  - **传统方法（每路由器法）**：路由选择算法运行在**每台路由器**中，每台路由器中都包含转发和路由选择两种功能（控制平面与数据平面紧耦合）
  - **SDN 方法（逻辑集中式控制）**：**控制平面从路由器中分离出来**，由一个逻辑上集中的**远程控制器**计算转发表，并将转发表**下发**给各个路由器（此时路由器只负责转发，称为 **SDN 交换机 / 分组交换机**）
- **SDN 的接口**（⭐⭐⭐）：
  - **北向接口**：SDN 控制器向**上层网络应用**提供的编程接口（网络应用通过北向接口告诉控制器要做什么）
  - **南向接口**：SDN 控制器与**下层数据平面（SDN 交换机）**之间的接口，控制器通过南向接口**下发流表**（如 **OpenFlow** 协议）
  - **东西向接口**：SDN 控制器集群内部控制器之间的通信接口
- SDN 的特点：**基于流的转发**（流表：匹配 + 动作，可以根据多个首部字段进行转发，而不仅是目的 IP 地址）、**数据平面与控制平面分离**、网络控制功能位于数据平面交换机外部、**可编程**的网络

📝 **真题（2022 年第 37 题）**：在 SDN 网络体系结构中，SDN 控制器向数据平面的 SDN 交换机下发流表时所使用的接口是：A. 东向接口　B. 南向接口　C. 西向接口　D. 北向接口
→ **B**（🧒 **地图上北在上、南在下**：控制器的上层是应用（北向），下层是交换机（南向））

### 📐 4. 拥塞控制
**拥塞**：因出现过量的分组而引起网络性能下降的现象（如网络吞吐量随输入负载增大而下降）。
- **判断网络是否拥塞**：观察网络的吞吐量与网络负载的关系。若随着网络负载的增加，网络的吞吐量明显**小于正常的吞吐量**，那么网络就可能已进入“**轻度拥塞**”状态；若网络的吞吐量随着网络负载的增大反而**下降**，那么网络就可能已进入**拥塞**状态；若网络的负载继续增大，而网络的吞吐量**下降到零**，网络就可能已进入**死锁**状态
- **拥塞控制的作用**：确保子网能够承载所达到的流量，这是一个**全局性**的过程，涉及各方面的行为（主机、路由器、路由器内部的转发处理过程）
- **与流量控制的区别**：**流量控制**往往是指在给定的发送端和接收端之间的**点对点**通信量的控制，它所要做的是抑制发送端发送数据的速率，以便使接收端来得及接收；**拥塞控制**是**全局性**的
- 两种方法：
  - **开环控制**：在设计网络时事先将有关发生拥塞的因素考虑周到，力求网络在工作时不产生拥塞（**静态**的预防方法）
  - **闭环控制**：事先不考虑有关发生拥塞的各种因素，采用**监测网络系统**去监视，及时检测哪里发生了拥塞，然后将拥塞信息传到合适的地方，以便调整网络系统的运行，并解决出现的问题（**动态**的方法）

## 二、数据报与虚电路（⭐⭐）

网络层可以向上提供两种服务：

### 📐 数据报服务（无连接）
- 网络在发送分组前**不需要先建立连接**，每个分组（IP 数据报）**独立发送**，与其前后的分组无关（**不进行编号**）
- 网络层向上只提供简单灵活的、无连接的、**尽最大努力交付**的数据报服务：不保证分组交付的时限，所传送的分组可能**出错、丢失、重复和失序**
- 每个分组都携带**完整的目的地址**，每个分组**独立选择路由**
- **因特网（IP）采用数据报服务**

### 📐 虚电路服务（面向连接）
- 虚电路方式试图将数据报方式与电路交换方式结合起来，充分发挥两种方法的优点，以达到最佳的数据交换效果
- **虚电路**：一条源主机到目的主机类似于电路的路径（**逻辑连接**），路径上所有结点都要维持这条虚电路的建立，都维持一张**虚电路表**，每一项记录了一个打开的虚电路的信息
- 通信过程：**建立连接（虚电路）→ 数据传输 → 释放连接**
- 每个分组携带**虚电路号（VCID）**，而不是完整的目的地址
- 所有分组**沿同一条路径**按序到达
- ⚠️ 虚电路是**逻辑**上的连接，**并不独占**线路（与电路交换不同），其他虚电路的分组也可以使用同一条物理链路

📝 **真题（2020 年第 34 题）**：下列关于虚电路网络的叙述中，**错误**的是：
A. 可以确保数据分组传输顺序　B. 需要为每条虚电路预分配带宽　C. 建立虚电路时需要进行路由选择　D. 依据虚电路号（VCID）进行数据分组转发
→ **B**（虚电路只是逻辑连接，**不需要预先分配带宽**，链路是分组交换、统计复用的；预分配带宽是电路交换的特点）

### 📐 数据报与虚电路的比较（⭐⭐）
| | 数据报服务 | 虚电路服务 |
|---|---|---|
| 连接的建立与释放 | **不需要** | **需要** |
| 目的地址 | 每个分组都有**完整的**目的地址 | 仅在建立连接阶段使用，之后每个分组使用长度较短的**虚电路号** |
| 路由选择 | 每个分组**独立**地进行路由选择和转发 | 属于同一条虚电路的分组按照**同一路由**转发 |
| 分组顺序 | **不保证**分组的有序到达 | **保证**分组的有序到达 |
| 可靠性 | 不保证可靠通信，可靠性由**用户主机**来保证 | 可靠性由**网络**来保证 |
| 对网络故障的适应性 | 出故障的结点丢失分组，**其他分组路径选择发生变化**时可以正常传输 | 所有经过故障结点的虚电路**均不能正常工作** |
| 差错处理和流量控制 | 由**用户主机**进行 | 可由**分组交换网**负责，也可由用户主机负责 |

## 三、IPv4 分组（⭐⭐⭐）

### 📐 IPv4 分组的格式
**一个 IP 分组由首部和数据部分组成**。首部前一部分是**固定长度**，共 **20B**，是所有 IP 分组必须具有的；后面是可选字段，长度可变。

```
 0       4       8              16  19                     31
 ┌───────┬───────┬──────────────┬───────────────────────────┐
 │ 版本   │首部长度│  区分服务      │         总长度              │
 ├───────┴───────┴──────────────┼───┬───────────────────────┤
 │           标识                │标志│       片偏移            │
 ├───────────────┬──────────────┼───┴───────────────────────┤
 │   生存时间 TTL  │    协议       │       首部检验和             │
 ├───────────────┴──────────────┴───────────────────────────┤
 │                        源 IP 地址                          │
 ├──────────────────────────────────────────────────────────┤
 │                       目的 IP 地址                          │
 ├──────────────────────────────────────────────────────────┤
 │                  可选字段（长度可变）         │   填充        │
 ├──────────────────────────────────────────────────────────┤
 │                          数据部分                          │
 └──────────────────────────────────────────────────────────┘
```

| 字段 | 长度 | 含义 | 要点 |
|---|---|---|---|
| **版本** | 4 位 | IP 的版本，IPv4 为 **4** | |
| **首部长度** | 4 位 | 首部长度，**单位是 4B** | 最小值 5（20B），最大值 15（**60B**） |
| 区分服务 | 8 位 | 希望获得哪种服务 | 一般不用 |
| **总长度** | 16 位 | **首部 + 数据**的长度，**单位是 1B** | 最大 2¹⁶ − 1 = **65535B**；但受 MTU 限制 |
| **标识** | 16 位 | 同一数据报的**分片使用同一标识** | 分片重组时依据 |
| **标志** | 3 位 | 最高位保留；中间位 **DF**（Don't Fragment）；最低位 **MF**（More Fragments） | DF = 1 **禁止分片**；MF = 1 表示**后面还有分片**，MF = 0 表示这是**最后一片**（或没分片） |
| **片偏移** | 13 位 | 指出较长分组分片后，某片在原分组中的**相对位置**，**以 8B 为单位** | 除最后一片外，每片数据长度必须是 **8B 的整数倍** |
| **生存时间 TTL** | 8 位 | 数据报在网络中可通过的**路由器数的最大值** | 每经过一个路由器 **减 1**，为 0 时**丢弃**，防止无限循环 |
| **协议** | 8 位 | 数据部分的协议 | **TCP = 6，UDP = 17**，ICMP = 1，OSPF = 89 |
| **首部检验和** | 16 位 | **只检验首部**，不检验数据部分 | 每经过一个路由器都要**重新计算**（因为 TTL 变了） |
| 源 IP 地址 | 32 位 | 发送方 IP 地址 | |
| 目的 IP 地址 | 32 位 | 接收方 IP 地址 | |
| 可选字段 | 0~40B | 排错、测量、安全等 | 很少使用 |
| 填充 | —— | 全 0，把首部补成 **4B 的整数倍** | |

⚠️ **三个长度字段的单位**（⭐⭐⭐ 必背）：
- **首部长度：4B**
- **总长度：1B**
- **片偏移：8B**
🧒 口诀：“**一首四，片偏八**”（总长度 1B，首部长度 4B，片偏移 8B）

✏️ **例**：某 IP 首部的前几个字节为 **45 00 05 DC ……**
- 4 → 版本 IPv4；5 → 首部长度 5 × 4 = **20B**
- 05DC = 1500 → 总长度 **1500B**，数据部分 1500 − 20 = **1480B**

⚠️ **IP 首部检验和的计算**：把首部看成 16 位的数的序列，检验和字段先置 0，所有 16 位数进行**反码求和**，结果取反码填入检验和字段。（与 UDP/TCP 的检验和方法相同，但 IP 只检验首部。）

## 四、IP 数据报分片（⭐⭐⭐）

### 📐 最大传送单元 MTU
链路层数据帧可封装数据的上限（如以太网 **MTU = 1500B**）。IP 数据报的总长度**不能超过**下一段链路的 MTU，否则就要**分片**。

### 📐 分片规则
1. 每个分片都有自己的 **IP 首部**（通常 20B），**标识字段相同**
2. 每片的**数据部分长度**必须是 **8 的整数倍**（最后一片除外），且 **首部 + 数据 ≤ MTU**
3. **片偏移** = 该片数据在原数据中的起始字节 / 8
4. 除最后一片外，**MF = 1**；最后一片 **MF = 0**
5. 所有分片的 **DF = 0**（若 DF = 1 且超过 MTU，则**丢弃**并发送 ICMP 差错报文）
6. 分片在**目的主机**重组（中间路由器不重组）

### 📐 计算步骤
1. 每片最大数据长度 = **MTU − 首部长度**，再**向下取 8 的整数倍**
2. 原数据长度 = 总长度 − 首部长度
3. 依次切分，算出每片的数据长度、总长度、片偏移、MF

✏️ **例 1（经典）**：一个总长度为 **4000B** 的 IP 数据报（首部 20B，数据 3980B），经过 MTU = **1500B** 的以太网，如何分片？
- 每片最大数据 = 1500 − 20 = **1480B**（1480 / 8 = 185，正好是 8 的倍数）
- 3980 = 1480 + 1480 + 1020 → 3 片

| 分片 | 数据长度 | 总长度 | 片偏移 | MF | DF |
|---|---|---|---|---|---|
| 原数据报 | 3980 | 4000 | 0 | 0 | 0 |
| 分片 1 | 1480（字节 0~1479） | 1500 | **0** | 1 | 0 |
| 分片 2 | 1480（字节 1480~2959） | 1500 | 1480/8 = **185** | 1 | 0 |
| 分片 3 | 1020（字节 2960~3979） | 1040 | 2960/8 = **370** | **0** | 0 |

📝 **真题（2021 年第 36 题）**：若路由器向 MTU = 800B 的链路转发一个总长度为 1580B 的 IP 数据报（首部长度为 20B）时，进行了分片，且每个分片尽可能大，则第 2 个分片的总长度字段和 MF 标志位的值分别是：A. 796, 0　B. 796, 1　C. 800, 0　D. 800, 1
1. 原数据 = 1580 − 20 = **1560B**
2. 每片最大数据：800 − 20 = 780，但**必须是 8 的倍数** → 向下取 **776B**（776 = 97 × 8）
3. 1560 = 776 + 776 + 8 → 3 片
4. 第 2 片：数据 776B，总长度 776 + 20 = **796B**；后面还有第 3 片 → **MF = 1**
→ 选 **B**
- ⚠️ 陷阱：若直接用 780 做分片数据长度，780 不是 8 的倍数，片偏移无法表示，这是**不允许**的

✏️ **例 2（再次分片）**：分片 1（总长 1500B，数据 1480B，偏移 0，MF = 1）在后续路径上遇到 MTU = **576B** 的链路，如何分片？
- 每片最大数据 = 576 − 20 = 556 → 向下取 8 倍数 = **552B**
- 1480 = 552 + 552 + 376
- 片偏移（相对于**原始**数据报）：0、552/8 = 69、1104/8 = 138
- MF：前两片 1，第三片**仍为 1**（因为原来的分片 1 后面还有别的分片！）

⚠️ **再次分片时**：片偏移要相对**原始数据报**计算；原片 MF = 1 的，其所有子片的 MF 都为 1。

## ⚠️ 易错点

1. **路由选择**是控制平面（软件）；**转发**是数据平面（硬件）
2. SDN：控制器 → 交换机是**南向接口**；控制器 → 应用是**北向接口**
3. **因特网采用数据报服务**；虚电路**不预分配带宽**
4. IP 首部固定 **20B**，最大 **60B**
5. 首部长度单位 **4B**，总长度单位 **1B**，片偏移单位 **8B**
6. **TTL 每经过一个路由器减 1**；首部检验和**只检验首部**，每跳都要重新计算
7. 协议字段：**TCP 6、UDP 17、ICMP 1**
8. **DF = 1 禁止分片**；**MF = 1 后面还有分片**
9. 分片数据长度必须是 **8 的倍数**（最后一片除外）；**向下取整**
10. 分片在**目的主机**重组

## 🏋️ 课后练习

1. 某 IP 数据报首部长度字段为 **1000**（二进制），总长度字段为 **0x03E8**，求首部长度和数据长度。
2. 一个数据部分为 3000B 的 IP 数据报（首部 20B）要经过 MTU = 1000B 的链路，求分片数和每片的总长度、片偏移、MF。
3. IP 数据报的 TTL 初值为 64，经过 10 个路由器到达目的主机，到达时 TTL 为多少？
4. 判断：(a) IP 首部检验和检验整个数据报；(b) 分片可以在中间路由器重组；(c) SDN 中控制器通过北向接口向交换机下发流表。

<details>
<summary>📖 答案</summary>

1. 首部长度 = 8 × 4 = **32B**；总长度 = 0x3E8 = 1000B；数据长度 = 1000 − 32 = **968B**
2. 每片最大数据 = 1000 − 20 = 980 → 取 976（976 = 122 × 8）。3000 = 976 + 976 + 976 + 72 → **4 片**：总长度 996、996、996、92；片偏移 0、122、244、366；MF 1、1、1、0
3. 64 − 10 = **54**
4. (a) **错**，只检验首部；(b) **错**，在目的主机重组；(c) **错**，是南向接口
</details>
