## 🚪 课前引入

IPv4 地址只有 32 位，总共约 **43 亿**个。可全世界的手机、电脑、智能家电、摄像头加起来远不止这个数。2011 年，IANA 已经分配完了最后的 IPv4 地址块。

**IPv6** 把地址扩展到 **128 位**——大约是 3.4 × 10³⁸ 个，据说“可以给地球上每一粒沙子都分配一个 IP 地址”。

## 一、IPv6（⭐⭐⭐）

### 📐 为什么要 IPv6
解决“**IP 地址耗尽**”问题的措施：
- 采用**无类别编址 CIDR**，使 IP 地址的分配更加合理
- 采用**网络地址转换 NAT** 方法以节省全球 IP 地址
- 采用具有更大地址空间的新版本的 IP 协议 **IPv6**（根本办法）

### 📐 IPv6 的主要特点（⭐⭐⭐）
1. **更大的地址空间**：地址从 IPv4 的 32 位增大到 **128 位**
2. **扩展的地址层次结构**
3. **灵活的首部格式**：IPv6 定义了许多可选的**扩展首部**
4. **改进的选项**：IPv6 允许分组包含选项的控制信息，其选项放在有效载荷中
5. **允许协议继续扩充**
6. **支持即插即用（自动配置）**：不需要使用 DHCP
7. **支持资源的预分配**：支持实时视像等要求保证一定的带宽和时延的应用
8. **IPv6 首部改为 8B 对齐**（IPv4 是 4B 对齐）
9. IPv6 **只有在包的源结点才能分片**，是**端到端**的，传输路径中的**路由器不能分片**（所以从一般意义上说，IPv6 不允许分片）
10. **增加了安全性**：身份验证和保密功能
11. IPv6 **取消了首部检验和**字段（加快路由器处理速度；差错检验交给数据链路层和传输层）
12. IPv6 首部**长度固定**（基本首部 **40B**）

### 📐 IPv6 数据报格式
IPv6 数据报 = **基本首部（40B，固定）** + **有效载荷**（扩展首部 + 数据部分，最多 64KB）
```
 0      4          12                    31
 ┌──────┬──────────┬─────────────────────┐
 │ 版本  │ 通信量类   │       流标签          │
 ├──────┴──────────┴─────┬───────┬───────┤
 │      有效载荷长度         │下一个首部│跳数限制 │
 ├────────────────────────┴───────┴───────┤
 │         源地址（128 位 = 16B）             │
 ├────────────────────────────────────────┤
 │        目的地址（128 位 = 16B）            │
 └────────────────────────────────────────┘
```
| 字段 | 长度 | 作用 |
|---|---|---|
| 版本 | 4 位 | 协议版本，IPv6 为 **6** |
| 通信量类（优先级） | 8 位 | 区分数据报的类别或优先级 |
| **流标签** | 20 位 | “**流**”是互联网络上从特定源点到特定终点的一系列数据报，所有属于同一个流的数据报都具有同样的流标签（用于资源预分配） |
| 有效载荷长度 | 16 位 | 数据报**除基本首部外**的字节数（最大 64KB） |
| **下一个首部** | 8 位 | 相当于 IPv4 的**协议字段或可选字段**，指出基本首部后面的扩展首部类型或上层协议 |
| **跳数限制** | 8 位 | 相当于 IPv4 的 **TTL**，每经过一个路由器减 1，为 0 时丢弃 |
| 源地址、目的地址 | 各 128 位 | |

### 📐 IPv6 与 IPv4 的区别（⭐⭐⭐）
| | IPv4 | IPv6 |
|---|---|---|
| 地址长度 | 32 位 | **128 位**（地址空间是 IPv4 的 **2⁹⁶** 倍） |
| 首部长度 | **可变**（20~60B） | **固定**基本首部 **40B**（扩展首部可选） |
| 首部检验和 | 有 | **取消** |
| 分片 | 源主机和**路由器**都可分片 | **只在源主机**分片 |
| 生存时间 | TTL | **跳数限制** |
| 协议字段 | 协议 | **下一个首部** |
| 地址配置 | 手动或 DHCP | **即插即用**（自动配置） |
| 对齐 | 4B 对齐 | **8B 对齐** |
| 广播 | 有 | **取消广播**，用**多播**代替 |

📝 **真题（2023 年第 40 题）**：下列关于 IPv4 和 IPv6 的叙述中，正确的是：I. IPv6 地址空间是 IPv4 地址空间的 96 倍　II. IPv4 首部和 IPv6 的基本首部的长度均可变　III. IPv4 向 IPv6 过渡可以采用双协议栈和隧道技术　IV. IPv6 首部的 Hop-Limit 字段等价于 IPv4 首部的 TTL 字段
A. 仅 I、II　B. 仅 I、IV　C. 仅 II、III　D. 仅 III、IV
- I：错误，是 2¹²⁸ / 2³² = **2⁹⁶ 倍**，不是 96 倍
- II：错误，IPv6 基本首部**固定 40B**
- III、IV：正确
→ 选 **D**

### 📐 IPv6 地址的表示（⭐⭐）
**冒号十六进制记法**：128 位分为 8 组，每组 16 位用 4 个十六进制数表示，用冒号分隔：
```
4BF5:AA12:0216:FEBC:BA5F:039A:BE9A:2170
```
**压缩规则**：
1. 每组中**前导的 0 可以省略**：`0216` → `216`，`039A` → `39A`
2. **零压缩**：一连串连续的**全 0 组**可以用一对冒号 **“::”** 取代
   - ⚠️ **“::”在一个地址中只能出现一次**（否则无法确定每个 :: 代表几组）
   - 例：`FF05:0:0:0:0:0:0:B3` → `FF05::B3`
3. IPv4 兼容：可以把 IPv4 地址写在最后，如 `::FFFF:192.168.0.1`

### 📐 IPv6 地址的类型
- **单播**：传统的点对点通信
- **多播**：一点对多点的通信，数据报交付到一组计算机中的每一台
- **任播**（**IPv6 新增**）：终点是一组计算机，但数据报**只交付给其中的一台**计算机（通常是距离最近的一台）
- ⚠️ IPv6 **没有广播**地址

### 📐 IPv4 向 IPv6 的过渡（⭐⭐）
1. **双栈协议**：在一台设备上**同时装有 IPv4 和 IPv6 协议栈**，那么这台设备既能和 IPv4 网络通信，又能和 IPv6 网络通信。如果这台设备是一个路由器，那么这台路由器的不同接口上分别配置了 IPv4 地址和 IPv6 地址，并很可能分别连接了 IPv4 网络和 IPv6 网络；如果这台设备是一个计算机，那么它将同时拥有 IPv4 地址和 IPv6 地址，并具备同时处理这两个协议地址的功能
2. **隧道技术**：将整个 **IPv6 数据报封装到 IPv4 数据报的数据部分**，使得 IPv6 数据报可以在 IPv4 网络的隧道中传输（IPv4 首部协议字段 = 41）

## 二、IP 多播（⭐）

### 📐 多播的概念
- **单播**：一对一；**广播**：一对全部；**多播（组播）**：一对多（一组）
- 多播：发送方只发送**一份**数据，在路由器处**才复制**，沿多播树分发到多个接收者。能大大**节约网络资源**（如视频会议、网络直播）
- 多播数据报**使用 UDP**（不可靠、尽最大努力交付），因为 TCP 是一对一的

### 📐 IP 多播地址
- 使用 **D 类地址**：**224.0.0.0 ~ 239.255.255.255**
- 每一个 D 类 IP 地址标志**一个多播组**
- 多播地址**只能用于目的地址**，不能用于源地址
- 对多播数据报**不产生 ICMP 差错报文**

### 📐 硬件多播（多播 IP 地址映射到以太网 MAC 地址）
- 以太网多播 MAC 地址的前 25 位固定为 **01-00-5E**（+ 1 位 0），后 **23 位**取自 IP 多播地址的**低 23 位**
- D 类 IP 地址中有 28 位可变（前 4 位 1110 固定），但只有低 23 位映射到 MAC 地址——所以有 **2⁵ = 32** 个 IP 多播地址映射到**同一个** MAC 多播地址，收到多播帧后主机还要在 IP 层**进行过滤**

✏️ 多播地址 **224.128.64.32** 对应的以太网地址：
- 低 23 位：第 2 字节 128 = 1000 0000，取后 7 位 = 000 0000；第 3、4 字节 64、32
- MAC = 01-00-5E-**00**-**40**-**20**

### 📐 IGMP 与多播路由选择
- **网际组管理协议（IGMP）**：让连接在本地局域网上的**多播路由器**知道本局域网上是否有主机（上的进程）参加或退出了某个多播组。IGMP 报文封装在 IP 数据报中，属于**网络层**
  - 某主机要加入某个多播组时，向多播组的多播地址发送一个 **IGMP 报文**，声明自己要成为该组的成员
  - 本地多播路由器收到后，利用多播路由选择协议把这组成员关系发给互联网上的其他多播路由器
  - 本地多播路由器**周期性**地探询本地局域网上的主机，以便知道这些主机是否还是组的成员
- **多播路由选择协议**：目的是找出以源主机为根结点的**多播转发树**。常用：基于链路状态的路由选择（MOSPF）、基于距离向量的路由选择（DVMRP）、协议无关的多播（PIM-SM、PIM-DM）

## 三、移动 IP（了解）

### 📐 移动 IP 的概念
**移动 IP**：支持移动性的因特网体系结构与协议，使移动结点（主机）在移动中保持**原来的 IP 地址不变**，仍然能够通信。
- **移动结点**：具有永久 IP 地址（**归属地址/主地址**）的移动设备
- **归属代理（本地代理）**：一个移动结点拥有的就“居所”称为**归属网络**，在归属网络中代表移动结点执行移动管理功能的实体叫做归属代理
- **外部代理（外地代理）**：在外部网络中帮助移动结点完成移动管理功能的实体称为外部代理
- **永久地址（归属地址/主地址）**：移动站点在归属网络中的原始地址
- **转交地址（辅地址）**：移动站点在外部网络使用的临时地址

### 📐 移动 IP 通信过程
1. 移动结点在**本地网**时，按传统的 TCP/IP 方式进行通信
2. 移动结点**漫游**到一个外地网络时，仍然使用固定的 IP 地址进行通信。为了能够收到通信对端发给它的 IP 分组，移动结点需要**向本地代理注册**当前的位置地址，这个位置地址可以是外部代理的地址或动态配置的一个地址（**转交地址**）
3. 本地代理接收来自转交地址的注册后，会构建一条通向转交地址的**隧道**，将截获的发给移动结点的 IP 分组通过隧道送到转交地址处
4. 在转交地址处解除隧道封装，恢复原始的 IP 分组，最后送到移动结点，这样移动结点在外网就能够收到这些发送给它的 IP 分组
5. 移动结点在外网通过外网的路由器或外部代理向通信对端**直接**发送 IP 分组（三角路由）
6. 当移动结点回到本地网时，移动结点向本地代理**注销**转交地址，这时移动结点又将使用传统的 TCP/IP 方式进行通信

🧒 **比喻**：你出差（漫游）了，但朋友的信仍然寄到你家（归属地址）。你告诉家里人（归属代理）你住在哪个酒店（转交地址），家里人收到信后**转寄**给你；你回信则可以直接从酒店寄出。

## ⚠️ 易错点

1. IPv6 地址 **128 位**，空间是 IPv4 的 **2⁹⁶ 倍**
2. IPv6 基本首部**固定 40B**；**取消首部检验和**；**路由器不分片**（只在源点分片）
3. **跳数限制 ≈ TTL**；**下一个首部 ≈ 协议字段**
4. IPv6 **没有广播**，新增**任播**
5. 零压缩 **“::” 只能用一次**
6. 过渡技术：**双协议栈**、**隧道**（IPv6 封装在 IPv4 中）
7. 多播用 **D 类**地址（224~239），只能作**目的地址**；多播使用 **UDP**
8. 多播 MAC：**01-00-5E** + IP 地址**低 23 位**；32 个 IP 多播地址对应一个 MAC 地址
9. IGMP 在**网络层**

## 🏋️ 课后练习

1. 把 IPv6 地址 `2001:0DB8:0000:0000:0000:FF00:0042:8329` 写成最简形式。
2. 下列 IPv6 地址写法是否正确：(a) `::1`；(b) `2001::25DE::CADE`；(c) `FE80::1:0:0:1`
3. IPv6 为什么取消首部检验和？
4. 多播地址 230.200.100.10 对应的以太网 MAC 地址是什么？

<details>
<summary>📖 答案</summary>

1. 去前导 0：2001:DB8:0:0:0:FF00:42:8329；零压缩：**2001:DB8::FF00:42:8329**
2. (a) **正确**（环回地址）；(b) **错误**，“::”出现了两次；(c) **正确**
3. 数据链路层和传输层都有差错检验（CRC、TCP/UDP 检验和），网络层再检验是重复的；取消后路由器**不需要**在每一跳重新计算检验和（IPv4 中因 TTL 变化每跳都要重算），**加快了分组转发速度**
4. 低 23 位：第 2 字节 200 = 1100 1000，去掉最高位 → 100 1000 = 0x48；第 3 字节 100 = 0x64；第 4 字节 10 = 0x0A。MAC = **01-00-5E-48-64-0A**
</details>
