## 🚪 课前引入

两个问题：
1. **接收方来不及收**：你给朋友传文件，你的网速很快，但朋友的电脑很慢，数据都堆在他那里——需要 **流量控制**（让**接收方**告诉发送方“慢点”）
2. **网络堵车了**：成千上万的人同时下载，路由器的队列满了，开始丢包——需要 **拥塞控制**（发送方根据**网络状况**自己放慢速度）

🧒 **比喻：往水桶里倒水**
- 流量控制：水桶（接收缓存）快满了，看水桶的人喊“慢点倒”
- 拥塞控制：水管（网络）太细，倒太快会溢出来，倒水的人要**试探着**加快：先慢慢倒，没溢出就越倒越快；一旦溢出，马上减速

## 一、TCP 流量控制（⭐⭐⭐）

### 📐 流量控制的概念
**流量控制**：让发送方慢点，要让接收方来得及接收。
- TCP 利用**滑动窗口机制**实现流量控制
- 在通信过程中，接收方根据自己**接收缓存的大小**，动态地调整发送方的发送窗口大小，即**接收窗口 rwnd**（接收方设置确认报文段的**窗口字段**来将 rwnd 通知给发送方）
- 发送方的发送窗口取接收窗口 rwnd 和拥塞窗口 cwnd 的**最小值**

### 📐 发送窗口
TCP 的发送窗口以**字节**为单位：
```
          已发送并确认 │  已发送但未确认  │  允许发送但尚未发送 │  不允许发送
  ────────────────────┼────────────────┼──────────────────┼─────────────
                      ↑ 后沿（最小的未确认序号 = 确认号）         ↑ 前沿
                      |<──────────── 发送窗口 ─────────────>|
```
- **发送窗口 = min(rwnd, cwnd)**
- **还可以发送的数据量 = 发送窗口 − 已发送但未确认的数据量**
- 可以发送的**序号范围**：从 **(已发送的最大序号 + 1)** 到 **(确认号 + 发送窗口 − 1)**

📝 **真题（2021 年第 40 题）**：设主机甲通过 TCP 向主机乙发送数据，部分过程如下图所示。甲在 t₀ 时刻发送一个序号 seq = 501、封装 200B 数据的段，在 t₁ 时刻收到乙发送的序号 seq = 601、确认序号 ack_seq = 501、接收窗口 rcvwnd = 500B 的段，则甲在未收到新的确认段之前，可以继续向乙发送的数据序号范围是：A. 501~1000　B. 601~1100　C. 701~1000　D. 801~1100
- 确认号 **501**：乙期望收到 501 开始的数据（甲在 t₀ 发的 501~700 还没被确认）
- 接收窗口 500B → 允许发送的范围是 **501 ~ 1000**
- 但 **501~700 已经发送过了**（未确认），所以还能继续发送的是 **701 ~ 1000** → 选 **C**

### 📐 零窗口与持续计时器
- 若接收方的缓存满了，发送 **rwnd = 0** 的报文段，发送方就停止发送
- 之后接收方有了空间，发送 rwnd > 0 的报文段——但若这个报文段**丢失**了，双方就会**互相等待**，形成**死锁**
- 解决：TCP 为每个连接设有一个**持续计时器**。只要 TCP 连接的一方收到对方的**零窗口通知**，就启动持续计时器；若持续计时器设置的时间到期，就发送一个**零窗口探测报文段**（仅携带 1 字节的数据），对方在确认这个探测报文段时给出现在的窗口值。若窗口仍然是 0，收到这个报文段的一方就重新设置持续计时器
- ⚠️ 即使接收窗口为 0，也必须接收**零窗口探测报文段、确认报文段、携带紧急数据的报文段**

## 二、TCP 拥塞控制（⭐⭐⭐）

### 📐 拥塞的概念
**出现拥塞的条件**：对资源需求的总和 > 可用资源
- 网络中有许多资源同时呈现供应不足 → 网络性能变坏 → 网络吞吐量将随输入负荷增大而下降
- **拥塞控制**：防止过多的数据注入到网络中，**全局性**的
- **拥塞控制与流量控制的区别**：
  - **拥塞控制**是一个**全局性**的过程，涉及到所有的主机、所有的路由器，以及与降低网络传输性能有关的所有因素
  - **流量控制**往往是指**点对点**通信量的控制，是个**端到端**的问题（接收端控制发送端）

### 📐 拥塞控制的基本变量
假定：
1. 数据**单方向传送**，而另一个方向**只传送确认**
2. **接收方总是有足够大的缓存空间**，因而发送窗口大小取决于拥塞程度（发送窗口 = min{rwnd, cwnd} = cwnd）
- **拥塞窗口（cwnd）**：发送方根据**自己估算的网络拥塞程度**而设置的窗口值，反映网络当前容量。只要网络未出现拥塞，拥塞窗口就再增大一些；只要网络出现拥塞，拥塞窗口就减少一些
- **慢开始门限（ssthresh）**：慢开始和拥塞避免算法的**分界点**
- **传输轮次**：发送了一批报文段并收到它们的确认的时间，即**一个往返时延 RTT**。每一个传输轮次，把拥塞窗口所允许发送的报文段都连续发送出去，并收到了对已发送的最后一个报文段的确认

### 📐 1. 慢开始（⭐⭐⭐）
- 连接刚建立时，**cwnd = 1 MSS**（一个最大报文段长度）
- 每收到一个确认，cwnd 增加 1 MSS → **每经过一个传输轮次（RTT），cwnd 加倍**（指数增长）
- 1 → 2 → 4 → 8 → 16 ……
- 当 **cwnd 达到 ssthresh** 时，改用**拥塞避免**算法
- 🧒 “**慢**”开始并不是说 cwnd 增长得慢，而是说**一开始只发 1 个报文段**试探网络

⚠️ 若慢开始时 cwnd 加倍后会**超过** ssthresh，一般**只增加到 ssthresh**（例如 ssthresh = 12，cwnd 从 8 下一轮直接到 12，而不是 16）。

### 📐 2. 拥塞避免（⭐⭐⭐）
- 当 **cwnd ≥ ssthresh** 时使用
- **每经过一个传输轮次（RTT），cwnd 加 1 MSS**（**加法增大**，线性增长）
- 🧒 拥塞避免并不能完全避免拥塞，而是让 cwnd **缓慢增长**，使网络比较不容易出现拥塞

### 📐 网络出现拥塞时（超时）
无论在慢开始阶段还是拥塞避免阶段，只要发送方判断网络出现拥塞（**没有按时收到确认，即超时**）：
1. **ssthresh = max(cwnd / 2, 2)**（乘法减小）
2. **cwnd = 1**
3. 执行**慢开始**算法

### 📐 3. 快重传（⭐⭐⭐）
- 要求接收方**每收到一个失序的报文段后就立即发出重复确认**
- 发送方只要**一连收到 3 个重复确认**就应当**立即重传**对方尚未收到的报文段，而不必继续等待设置的重传计时器到期

### 📐 4. 快恢复（⭐⭐⭐）
当发送方收到 **3 个重复确认**时（说明网络**没有严重拥塞**，因为还能收到后面的报文段的确认）：
1. **ssthresh = cwnd / 2**（乘法减小）
2. **cwnd = ssthresh**（新的 ssthresh，**不是 1**）
3. 执行**拥塞避免**算法（线性增长）

（有的实现中 cwnd = ssthresh + 3 MSS，考试一般按 **cwnd = ssthresh** 处理，以题目为准。）

### 📐 四种算法总结（⭐⭐⭐）
| 事件 | ssthresh | cwnd | 之后 |
|---|---|---|---|
| 连接建立 | 初始值（题目给） | **1** | 慢开始 |
| 慢开始阶段每个 RTT | 不变 | **× 2** | cwnd ≥ ssthresh 时转拥塞避免 |
| 拥塞避免阶段每个 RTT | 不变 | **+ 1** | |
| **超时** | **cwnd / 2** | **1** | **慢开始** |
| **3 个重复确认** | **cwnd / 2** | **= 新 ssthresh** | **拥塞避免**（快恢复） |

### ✏️ 例：画出 cwnd 变化（⭐⭐⭐）

📝 **真题（2020 年第 38 题）**：若主机甲与主机乙已建立一条 TCP 连接，最大段长（MSS）为 1KB，往返时间（RTT）为 2ms，则在不出现拥塞的前提下，拥塞窗口从 8KB 增长到 32KB 所需的**最长**时间是：A. 4ms　B. 8ms　C. 24ms　D. 48ms
- “**最长**”时间 → cwnd 全程处于**拥塞避免**阶段（每个 RTT 只加 1KB）
- 从 8KB 到 32KB 需要 32 − 8 = **24 个 RTT** = 24 × 2 = **48ms** → 选 **D**
- （若全程是慢开始，只需 8 → 16 → 32，2 个 RTT = 4ms，这是“最短”时间）

📝 **真题（2022 年第 38 题）**：假设主机甲和主机乙已建立一个 TCP 连接，最大段长 MSS = 1KB，甲一直有数据向乙发送，当甲的拥塞窗口为 16KB 时，计时器发生了超时，则甲的拥塞窗口再次增长到 16KB 所需要的时间至少是：A. 4 RTT　B. 5 RTT　C. 11 RTT　D. 16 RTT
- 超时：ssthresh = 16 / 2 = **8KB**，cwnd = **1KB**
- 慢开始：1 → 2 → 4 → 8（**3 个 RTT**，到达门限）
- 拥塞避免：8 → 9 → … → 16（**8 个 RTT**）
- 共 3 + 8 = **11 RTT** → 选 **C**

📝 **真题（2025 年第 38 题）**：主机甲通过 TCP 向主机乙发送数据的部分过程如下图，seq 为序号，ack-seq 为确认序号，rcwnd 为接收窗口。甲在 t₀ 时刻的拥塞窗口和发送窗口均为 2000B，拥塞控制阈值为 8000B，MSS = 1000B。甲始终以 MSS 发送 TCP 段。若甲在 t₁ 时刻收到如图所示的确认段，则甲在未收到新的确认段之前，还可以继续向乙发送的 TCP 段数是：
> 图示：t₀ 时刻甲发送 seq = 2001（1000B 数据）、seq = 3001（1000B 数据）两个段；t₁ 时刻甲收到乙的段 seq = 4001, ack_seq = 3001, rcwnd = 4000B。
A. 2　B. 3　C. 4　D. 5
1. 收到 ack = 3001，确认了 2001~3000（1 个 MSS 的新数据）
2. cwnd = 2000 < ssthresh = 8000，处于**慢开始**：每收到一个确认 cwnd + 1 MSS → cwnd = **3000B**
3. 发送窗口 = min(rwnd = 4000, cwnd = 3000) = **3000B**，从 3001 开始，范围 3001~6000
4. 已发送未确认：3001~4000（**1000B**）
5. 还可以发送 3000 − 1000 = **2000B** = **2 个段**（4001~5000、5001~6000）→ 选 **A**

## 三、真题精讲：2023 年第 47 题（9 分）⭐⭐⭐

> 某网络拓扑如下图所示，主机 H 登录到 FTP 服务器后，向服务器上传一个大小为 18000B 的文件 F。假设 H 为传输 F 建立数据连接时，选择的初始序号为 **100**，**MSS = 1000B**，拥塞控制的**初始阈值为 4MSS**，**RTT = 10ms**，忽略 TCP 的传输时延。在 F 的传输过程中，H 均以 MSS 段向服务器发送数据，且未发生差错、丢包和乱序现象。
> ```
> H ── 交换机 ── 路由器 ── Internet（FTP 服务器）
> ```
> (1) FTP 的控制连接是持久的还是非持久的？FTP 的数据连接是持久的还是非持久的？H 登录 FTP 服务器时，建立的 TCP 连接是控制连接还是数据连接？
> (2) H 通过数据连接发送 F 时，F 的第一个字节序号是多少？在断开数据连接的过程中，FTP 服务器发送的第二次挥手 ACK 段的确认序号是多少？
> (3) H 通过数据连接发送 F 的过程中，当 H 收到确认序号为 2101 的确认时，H 的拥塞窗口调整为多少？收到确认序号为 7101 的确认段时，H 的拥塞窗口调整为多少？
> (4) H 从请求建立数据连接开始，到确认 F 已被服务器全部接收为止，至少需要多长时间？在这期间应用层数据的平均发送速率是多少？

**(1)**
- FTP 的**控制连接是持久的**（在整个会话期间一直保持打开）
- FTP 的**数据连接是非持久的**（每传送一个文件就建立一次，传完就关闭）
- H 登录 FTP 服务器时建立的是**控制连接**（登录时传送的是用户名、密码等**命令**）

**(2)**
- 初始序号 100 被 **SYN 段**消耗，所以 F 的第一个字节序号是 **101**
- F 共 18000B，占序号 **101 ~ 18100**
- 断开连接时，H（上传完毕，主动关闭）发送的 **FIN 段序号为 18101**
- 服务器第二次挥手的 ACK 段确认号 = 18101 + 1 = **18102**

**(3)**
初始 cwnd = 1 MSS = 1000B，ssthresh = 4 MSS = 4000B：
- 发送第 1 个段（101~1100），收到 **ack = 1101**：慢开始，cwnd = **2000B**
- 接着发送 2 个段（1101~2100、2101~3100），收到 **ack = 2101**：cwnd = **3000B**
- 收到 ack = 3101：cwnd = **4000B**，达到 ssthresh，进入**拥塞避免**
- 此时已发出、待确认的段是 3101~7100（4 个段，一个窗口）；拥塞避免阶段**每个 RTT（收到整个窗口的确认）cwnd 加 1 MSS**
- 收到 ack = 4101、5101、6101、**7101**（这个窗口的 4 个确认都收到）→ cwnd = **5000B**

所以：收到 ack = 2101 时 cwnd 调整为 **3000B**（3MSS）；收到 ack = 7101 时 cwnd 调整为 **5000B**（5MSS）

**(4)**
| 时间 | 事件 | cwnd |
|---|---|---|
| 0 ~ 10ms | **三次握手**（第三次握手的 ACK 可以和数据一起发） | |
| 10 ~ 20ms | 发送第 1 个段（1 个） | 1 → 2 |
| 20 ~ 30ms | 发送第 2~3 个段（2 个） | 2 → 4 |
| 30 ~ 40ms | 发送第 4~7 个段（4 个） | 4 → 5 |
| 40 ~ 50ms | 发送第 8~12 个段（5 个） | 5 → 6 |
| 50 ~ 60ms | 发送第 13~18 个段（6 个） | |
- 共 1 + 2 + 4 + 5 + 6 = 18 个段，正好传完 18000B
- 至少需要 **60ms**（1 个 RTT 建立连接 + 5 个 RTT 传数据）
- 平均发送速率 = 18000B / 60ms = **300KB/s**（= 3 × 10⁵ B/s = 2.4Mbps）

## ⚠️ 易错点

1. **发送窗口 = min(rwnd, cwnd)**
2. 还能发送的数据 = 发送窗口 − **已发送未确认**的数据
3. 可发送的序号范围 **起点是确认号**，终点 = 确认号 + 窗口 − 1
4. rwnd = 0 时启动**持续计时器**，发送零窗口探测报文段
5. **慢开始：每 RTT 加倍；拥塞避免：每 RTT 加 1**
6. 慢开始加倍时**不超过 ssthresh**
7. **超时：ssthresh = cwnd/2，cwnd = 1，慢开始**
8. **3 个重复 ACK：ssthresh = cwnd/2，cwnd = ssthresh，拥塞避免**
9. 流量控制是**端到端**（接收方控制）；拥塞控制是**全局**的（发送方自己估计）
10. “最长时间”按拥塞避免算；“最短时间”按慢开始算
11. 慢开始阶段**每收到一个 ACK** cwnd 就加 1 MSS

## 📋 本课小结

| 知识点 | 要点 |
|---|---|
| 流量控制 | 接收方通过窗口字段告知 rwnd；零窗口 + 持续计时器 |
| 发送窗口 | min(rwnd, cwnd) |
| 慢开始 | cwnd 从 1 开始，每 RTT × 2，直到 ssthresh |
| 拥塞避免 | 每 RTT + 1 |
| 超时 | ssthresh = cwnd/2，cwnd = 1 |
| 快重传 | 3 个重复 ACK 立即重传 |
| 快恢复 | ssthresh = cwnd/2，cwnd = ssthresh，拥塞避免 |

1. TCP 的 ssthresh = 32KB，MSS = 1KB，cwnd 从 1KB 开始，不出现拥塞，经过多少个 RTT cwnd 能达到 40KB？
2. cwnd = 40 时收到 3 个重复确认，之后 cwnd 和 ssthresh 各是多少？若是超时呢？
3. 主机甲的发送窗口由 min(rwnd, cwnd) 决定，已知 rwnd = 5000B，cwnd = 3000B，确认号为 2001，甲已发送到序号 3500，甲还能发送多少字节？序号范围是？
4. 为什么收到 3 个重复确认后执行快恢复而不是慢开始？

<details>
<summary>📖 答案</summary>

1. 慢开始 1 → 2 → 4 → 8 → 16 → 32（**5** 个 RTT），拥塞避免 32 → 40（**8** 个 RTT），共 **13** 个 RTT
2. 3 个重复确认：ssthresh = **20**，cwnd = **20**（之后拥塞避免）；超时：ssthresh = **20**，cwnd = **1**（之后慢开始）
3. 发送窗口 = min(5000, 3000) = 3000B，范围 2001~5000；已发送未确认 2001~3500（1500B），还能发送 **1500B**，序号范围 **3501~5000**
4. 能收到 3 个重复确认，说明后续的报文段都到达了接收方，**网络并没有严重拥塞**（只是个别报文段丢失），没必要把 cwnd 降到 1 从头开始，直接从一半开始线性增长即可，效率更高
</details>
