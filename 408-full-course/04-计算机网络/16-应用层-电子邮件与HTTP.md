## 🚪 课前引入

**发电子邮件**像寄信：
- 你写好信（**用户代理**，如 Outlook、网页邮箱）
- 交给你家附近的**邮局**（发送方**邮件服务器**）——用 **SMTP** 协议“**推**”过去
- 邮局把信送到收件人所在城市的**邮局**（接收方邮件服务器）——还是用 **SMTP**
- 收件人去邮局**取信**——用 **POP3** 或 **IMAP** 协议“**拉**”回来

## 一、电子邮件（⭐⭐⭐）

### 📐 电子邮件系统的组成
1. **用户代理（UA）**：用户与电子邮件系统的**接口**，一般是一个运行在 PC 上的程序（如 Outlook、Foxmail）。功能：撰写、显示、处理、通信（发信收信）
2. **邮件服务器**：功能是**发送和接收**邮件，同时还要向发信人报告邮件传送的情况（已交付、被拒绝、丢失等）。采用 **C/S** 方式工作，但它必须能够同时充当客户和服务器
3. **协议**：
   - **SMTP**：用于**用户代理向邮件服务器发送**邮件，或**邮件服务器之间**发送邮件（“**推**”）
   - **POP3 / IMAP**：用于**用户代理从邮件服务器读取**邮件（“**拉**”）

### 📐 电子邮件的发送和接收过程
```
发件人 ──SMTP──► 发送方邮件服务器 ──SMTP──► 接收方邮件服务器 ──POP3/IMAP──► 收件人
用户代理    （推）                  （推）                    （拉）        用户代理
```
1. 发信人调用 PC 中的**用户代理**撰写和编辑要发送的邮件
2. 发信人点击屏幕上的“发送邮件”按钮，发送方用户代理把邮件用 **SMTP** 协议发给**发送方邮件服务器**（用户代理充当 SMTP 客户）
3. 发送方邮件服务器将邮件放入**邮件缓存队列**中，等待发送
4. 运行在发送方邮件服务器的 SMTP 客户进程，发现在邮件缓存中有待发送的邮件，就向运行在**接收方邮件服务器**的 SMTP 服务器进程发起 **TCP 连接**的建立
5. TCP 连接建立后，SMTP 客户进程开始向远程 SMTP 服务器发送邮件。当所有待发送邮件发完了，SMTP 就关闭所建立的 TCP 连接
6. 运行在接收方邮件服务器中的 SMTP 服务器进程收到邮件后，将邮件放入**收信人的用户邮箱**，等待收信人在方便时进行读取
7. 收信人在打算收信时，调用用户代理，使用 **POP3（或 IMAP）**协议将自己的邮件从接收方邮件服务器的用户邮箱中取回（如果邮箱中有来信的话）

### 📐 SMTP 协议（⭐⭐）
**简单邮件传送协议 SMTP** 是一种提供可靠且有效的电子邮件传输的协议，它控制两个相互通信的 SMTP 进程交换信息。
- 使用 **TCP** 连接，端口号 **25**
- C/S 方式：负责发送邮件的 SMTP 进程就是 SMTP 客户，负责接收邮件的 SMTP 进程就是 SMTP 服务器
- 通信的三个阶段：**连接建立、邮件传送、连接释放**
- SMTP 是“**推（Push）**”协议
- ❌ SMTP **只能传送一定长度的 7 位 ASCII 码**，不能传送可执行文件或其他二进制对象；SMTP 不能传送非英语国家的文字（汉字等）→ 解决：**MIME**

### 📐 MIME（通用因特网邮件扩充）
**MIME** 并没有改动 SMTP 或取代它，而是在 SMTP 的基础上，把**非 ASCII 码数据**（中文、图片、音视频、二进制文件）**转换为 7 位 ASCII 码**，使其可以通过 SMTP 传送。
```
非 ASCII 码 ──► MIME ──► 7 位 ASCII 码 ──SMTP──► 7 位 ASCII 码 ──► MIME ──► 非 ASCII 码
```
- MIME 定义了新的邮件首部字段（MIME-Version、Content-Type……）、多种邮件内容格式、传送编码（如 Base64）

### 📐 POP3 与 IMAP（⭐⭐）
**邮局协议 POP3**：一个非常简单、但功能有限的**邮件读取**协议。
- 使用 **TCP**，端口号 **110**
- POP3 是“**拉（Pull）**”协议
- 工作方式：
  - **下载并保留**：用户从邮件服务器上读取邮件后，邮件依然会保存在邮件服务器上，用户可再次从服务器上读取该邮件
  - **下载并删除**：邮件一旦被读取，就被从邮件服务器上删除，用户不能再次从服务器上读取
- ❌ 只能把邮件下载到本地，**不能在服务器上管理邮件**（如建立文件夹）

**网际报文存取协议 IMAP**：比 POP3 复杂得多
- 使用 **TCP**，端口号 **143**
- 用户在自己的计算机上就可以**操纵邮件服务器的邮箱**，就像在本地操纵一样（建立文件夹、移动邮件、在远程文件夹中查询邮件等）——**联机协议**
- IMAP 允许用户代理**只获取报文的某些部分**（如只读邮件首部）
- 🧒 POP3 像“把信取回家”；IMAP 像“在邮局租了个信箱，远程整理”

### 📐 基于万维网的电子邮件
用户使用**浏览器**收发邮件（如 Gmail、QQ 网页邮箱）：
- 用户浏览器与邮件服务器之间：**HTTP**（发信和收信都用 HTTP）
- 邮件服务器之间：仍然是 **SMTP**

📝 **真题（2025 年第 40 题）**：下列关于 POP3 协议的叙述，正确的是：I. 支持用户代理从邮件服务读取邮件　II. 支持用户代理从邮件服务发送邮件　III. 支持邮件服务器之间发送和接收邮件　IV. 支持通过一条 TCP 连接收取多封邮件
A. I、III　B. I、IV　C. II、III　D. I、II、III
- I：POP3 就是**读取**邮件的协议 ✓
- II：发送邮件用 **SMTP**，不是 POP3 ✗
- III：邮件服务器之间用 **SMTP** ✗
- IV：用户在一次 POP3 会话（一条 TCP 连接）中可以列出并取回**多封**邮件 ✓
→ 选 **B**

### 📐 邮件协议对比（⭐⭐⭐）
| 协议 | 作用 | 方向 | 传输层 | 端口 |
|---|---|---|---|---|
| **SMTP** | 发送邮件（UA → 服务器、服务器 → 服务器） | 推 | TCP | **25** |
| **POP3** | 读取邮件（服务器 → UA） | 拉 | TCP | **110** |
| **IMAP** | 读取并在服务器上管理邮件 | 拉 | TCP | **143** |
| **MIME** | 扩展 SMTP，传送非 ASCII 内容 | —— | —— | —— |
| **HTTP** | 网页邮箱：浏览器 ↔ 邮件服务器 | —— | TCP | 80 |

## 二、万维网 WWW（⭐⭐）

### 📐 WWW 的概念
**万维网 WWW（World Wide Web）**是一个**资料空间**，是一个大规模的、联机式的信息储藏所。在这个空间中，一样有用的事物称为一样“资源”，并由一个全域“**统一资源定位符（URL）**”标识。这些资源通过**超文本传输协议（HTTP）**传送给使用者，而后者通过点击**链接**来获取资源。
- 万维网使用**链接**的方法能非常方便地从因特网上的一个站点访问另一个站点，从而主动地按需获取丰富的信息
- 万维网的内核部分是由三个标准构成的：
  1. **统一资源定位符（URL）**：负责标识万维网上的各种文档，并使每个文档在整个万维网的范围内具有**唯一的标识符 URL**
  2. **超文本传输协议（HTTP）**：一个应用层协议，它使用 **TCP 连接**进行可靠的传输，HTTP 是万维网客户程序和服务器程序之间交互所必须严格遵守的协议
  3. **超文本标记语言（HTML）**：一种文档结构的标记语言，它使用一些约定的标记对页面上的各种信息（包括文字、声音、图像、视频等）、格式以及超级链接进行描述

### 📐 URL 的格式
```
<协议>://<主机>:<端口>/<路径>
http://www.abc.com:80/index.html
```
- 协议：http、https、ftp……
- 主机：域名或 IP 地址
- 端口：HTTP 默认 80，可省略
- 路径：服务器上的文件路径

### 📐 访问网页的过程（⭐⭐⭐）
用户点击 http://www.tsinghua.edu.cn/chn/yxsz/index.htm：
1. 浏览器分析链接指向页面的 URL
2. 浏览器向 **DNS** 请求解析 www.tsinghua.edu.cn 的 IP 地址
3. 域名系统 DNS 解析出清华大学服务器的 IP 地址
4. 浏览器与服务器建立 **TCP 连接**（默认端口号 80）
5. 浏览器发出 **HTTP 请求**：GET /chn/yxsz/index.htm
6. 服务器通过 **HTTP 响应**把文件 index.htm 发送给浏览器
7. **释放 TCP 连接**（非持久连接时）
8. 浏览器解释文件 index.htm，并将 Web 页显示给用户

## 三、HTTP 协议（⭐⭐⭐）

### 📐 HTTP 的特点
1. HTTP 使用 **TCP** 作为运输层协议，保证了数据的可靠传输（端口 **80**；HTTPS 为 443）
2. HTTP 协议本身是**无连接**的：虽然 HTTP 使用了 TCP 连接，但通信双方在交换 HTTP 报文之前**不需要先建立 HTTP 连接**
3. HTTP 是**无状态**的：服务器**不记得**曾经访问过它的客户（同一个客户第二次访问同一个服务器上的页面时，服务器的响应与第一次被访问时的相同）
   - 为了识别用户，使用 **Cookie**：服务器在响应中给用户分配一个识别码（Set-Cookie），浏览器把它保存下来，以后每次请求都带上这个 Cookie，服务器就能“认出”这个用户（如购物车、登录状态）
4. HTTP 报文是**面向文本**的（ASCII 码）

### 📐 非持久连接与持久连接（⭐⭐⭐）
- **非持久连接（HTTP/1.0）**：**每个网页元素对象**（HTML 文件、图片、音频……）的传输都需要**单独建立一个 TCP 连接**
  - 每个对象需要 **2 RTT**：1 RTT 建立 TCP 连接 + 1 RTT 请求并接收对象（+ 文件传输时间）
  - 可以用多个**并行**的 TCP 连接来同时请求多个对象
- **持久连接（HTTP/1.1 默认）**：万维网服务器在发送响应后**仍然保持这条连接**，使同一个客户（浏览器）和该服务器可以继续在这条连接上传送后续的 HTTP 请求报文和响应报文
  - **非流水线方式**：客户在收到**前一个响应后**才能发出下一个请求。服务器在发送完一个对象后，其 TCP 连接就处于空闲状态，浪费了服务器资源 → 每个对象需要 **1 RTT**
  - **流水线方式（HTTP/1.1 默认）**：客户在收到 HTTP 的响应报文之前就能够**接着发送新的请求报文**。一个接一个的请求报文到达服务器后，服务器就可连续发回响应报文 → **所有引用对象总共只需要约 1 RTT**

### 📐 获取网页时间的计算（⭐⭐⭐）
设一个网页包含 **1 个 HTML 文件**，HTML 中引用了 **n 个对象**（如图片），忽略传输时延：
| 方式 | 总时间 |
|---|---|
| **非持久连接（串行）** | HTML：2 RTT；每个对象 2 RTT → **2(n + 1) RTT** |
| **非持久连接（并行，并行数 ≥ n）** | HTML：2 RTT；所有对象并行 2 RTT → **4 RTT** |
| **持久连接（非流水线）** | TCP 连接 1 RTT；HTML 1 RTT；每个对象 1 RTT → **(n + 2) RTT** |
| **持久连接（流水线）** | TCP 连接 1 RTT；HTML 1 RTT；所有对象 1 RTT → **3 RTT** |

✏️ **例**：网页有 1 个 HTML 和 5 张图片，RTT = 10ms，忽略传输时间：
- 非持久串行：2 × 6 × 10 = **120ms**
- 非持久并行（5 个并行连接）：20 + 20 = **40ms**
- 持久非流水线：(5 + 2) × 10 = **70ms**
- 持久流水线：3 × 10 = **30ms**

📝 **真题（2022 年第 40 题）**：假设主机 H 通过 HTTP/1.1 请求浏览某 Web 服务器 S 上的 Web 页 news408.html，news408.html 引用了同目录下的 1 幅图像，news408.html 文件大小为 1MSS（最大段长），图像文件大小为 3MSS，H 访问 S 的往返时间 RTT = 10ms，忽略 HTTP 响应报文的首部开销和 TCP 段传输时延。若 H 已完成域名解析，则从 H 请求与 S 建立 TCP 连接时刻起，到接收到全部内容止，所需的时间至少是：A. 30ms　B. 40ms　C. 50ms　D. 60ms
- HTTP/1.1 **持久连接**，但要考虑 **TCP 的拥塞控制（慢开始）**：
  1. 建立 TCP 连接：**10ms**
  2. 请求 news408.html（1 MSS）：服务器 cwnd = 1，发送 1 个段 → **10ms**
  3. 浏览器解析 HTML 后才知道要请求图像，请求图像（3 MSS）：此时服务器 cwnd 已增为 **2**，第一轮只能发 2 个段 → **10ms**；cwnd 增为 4，第二轮发最后 1 个段 → **10ms**
- 共 10 + 10 + 10 + 10 = **40ms** → 选 **B**
- ⚠️ 若忽略慢开始，会误选 30ms（A）

### 📐 HTTP 报文结构
HTTP 有两类报文：**请求报文**（客户 → 服务器）、**响应报文**（服务器 → 客户）。都由三部分组成：
**请求报文**：
```
请求行：   GET /index.html HTTP/1.1          ← 方法 URL 版本
首部行：   Host: www.abc.com
          Connection: close                  ← 非持久连接（keep-alive 表示持久）
          User-Agent: Mozilla/5.0
          Accept-Language: cn
          （空行）
实体主体： （GET 一般没有；POST 放表单数据）
```
**响应报文**：
```
状态行：   HTTP/1.1 200 OK                    ← 版本 状态码 短语
首部行：   Date: ...
          Content-Type: text/html
          Content-Length: 1024
          （空行）
实体主体： <html>……</html>
```

### 📐 常用请求方法
| 方法 | 含义 |
|---|---|
| **GET** | 请求读取由 URL 所标志的信息 |
| **HEAD** | 请求读取由 URL 所标志的信息的**首部**（不要实体主体） |
| **POST** | 给服务器**添加信息**（如提交表单、注释） |
| PUT | 在指明的 URL 下**存储**一个文档 |
| DELETE | **删除**指明的 URL 所标志的资源 |
| CONNECT | 用于代理服务器 |
| OPTIONS | 请求一些选项的信息 |

### 📐 状态码
| 状态码 | 含义 | 例子 |
|---|---|---|
| 1xx | 通知信息 | 100 Continue |
| **2xx** | **成功** | **200 OK** |
| **3xx** | **重定向** | 301 Moved Permanently |
| **4xx** | **客户端差错** | **404 Not Found**、403 Forbidden |
| **5xx** | **服务器差错** | 500 Internal Server Error、503 Service Unavailable |

### 📐 代理服务器（Web 缓存）
**代理服务器**把最近的一些请求和响应**暂存在本地磁盘**中。当新请求到达时，若代理服务器发现这个请求与暂时存放的请求相同，就返回暂存的响应，而不需要按 URL 的地址再次去因特网访问该资源。
- 可以减少对远程服务器的访问、**减少访问延迟**、**减轻链路负载**

## ⚠️ 易错点

1. **SMTP 推、POP3/IMAP 拉**；SMTP 用于**发送**（UA → 服务器、服务器之间），POP3/IMAP 用于**读取**
2. **SMTP 25、POP3 110、IMAP 143、HTTP 80**，都基于 **TCP**
3. **MIME** 让 SMTP 能传非 ASCII 数据，不取代 SMTP
4. 网页邮箱：浏览器与服务器之间用 **HTTP**，服务器之间仍用 **SMTP**
5. HTTP **无连接、无状态**；用 **Cookie** 记住用户
6. **HTTP/1.0 非持久；HTTP/1.1 默认持久 + 流水线**
7. 非持久：每个对象 **2 RTT**；持久非流水线：每个对象 **1 RTT**；持久流水线：所有对象共 **1 RTT**
8. 计算时要看题目是否要求考虑 **TCP 慢开始**（2022 年第 40 题）
9. 状态码：**2xx 成功，3xx 重定向，4xx 客户端错误，5xx 服务器错误**

## 🏋️ 课后练习

1. 用户 A 通过网页邮箱（浏览器）给用户 B 发邮件，B 用 Outlook（POP3）收邮件。从 A 发出到 B 收到，依次用到了哪些应用层协议？
2. 一个网页包含 1 个 HTML 文件和 3 个图片，RTT = 20ms，忽略传输时延，分别求非持久（串行）、持久非流水线、持久流水线方式下获取整个网页的时间。
3. 判断：(a) POP3 可以用来发送邮件；(b) HTTP 是有状态的协议；(c) HTTP/1.1 默认使用持久连接；(d) MIME 取代了 SMTP。

<details>
<summary>📖 答案</summary>

1. A 的浏览器 → A 的邮件服务器：**HTTP**；A 的邮件服务器 → B 的邮件服务器：**SMTP**；B 的 Outlook 从 B 的邮件服务器读取：**POP3**
2. 非持久串行：2 × 4 × 20 = **160ms**；持久非流水线：(3 + 2) × 20 = **100ms**；持久流水线：3 × 20 = **60ms**
3. (a) **错**；(b) **错**，无状态；(c) **对**；(d) **错**，MIME 是对 SMTP 的扩充
</details>
