## 🚪 课前引入

上节课的连续分配有个大麻烦：**碎片**。
- 固定分区：分区里空着的浪费了（内部碎片）
- 动态分区：到处都是小空洞，一个大进程来了哪都放不下（外部碎片）

🧒 想想**停车场**：
- 连续分配像**大巴停车场**：一辆大巴必须占用**连续的** 5 个车位，零散的空位再多也停不下
- 分页像**把大巴拆成 5 节小车厢**，每节随便找个空位停，只要记住“第 1 节在 A3，第 2 节在 C7……”（**页表**）就行

**分页的核心思想**：把进程和内存都切成**同样大小的小块**，进程的每一块可以放到内存的**任意**一个空块中，**不需要连续**。这样就几乎没有碎片了（只有每个进程最后一块可能装不满）。

## 一、基本分页存储管理（⭐⭐⭐）

### 📐 基本概念
- **页框（页帧、物理块、内存块）**：把**内存**分成大小相等的小分区，每个叫一个页框，编号为**页框号**（从 0 开始）
- **页（页面）**：把**进程的逻辑地址空间**也分成与页框**大小相等**的部分，每个叫一个页，编号为**页号**（从 0 开始）
- OS 以**页框为单位**为各进程分配内存，进程的每个页面分别放入一个页框中，**各页框可以不连续**
- **页面大小**：一般是 **2 的整数次幂**（如 4KB），以便地址转换（页号和页内偏移可以直接“切”出来）
  - 页面**太小**：页数多，**页表过长**，占用内存多；换入换出频繁
  - 页面**太大**：**页内碎片**增大，内存利用率降低

⚠️ 分页也有碎片：进程最后一页可能装不满一个页框 → **内部碎片**（但平均只有半页，很小）。**没有外部碎片**。

### 📐 逻辑地址结构
```
|<------------ 逻辑地址（m 位）------------>|
|     页号 P（m − n 位）  |  页内偏移量 W（n 位） |
```
- 页面大小 **2ⁿ B** → 页内偏移量 **n 位**
- 页号位数 = 逻辑地址位数 − n，最多有 2^(m−n) 个页

📐 **计算公式**（设页面大小为 L，逻辑地址为 A）：
```
页号 P = A / L       （整除）
页内偏移 W = A % L
```
若 L 是 2 的幂，直接把二进制地址**切开**即可。

### 📐 页表（⭐⭐⭐）
- 系统为**每个进程**建立一张**页表**，记录进程的每一页存放在内存的哪个页框中
- 页表通常存放在**内存**中（在进程的 PCB 中记录页表的起始地址和长度）
- **页表项（PTE）**：由**页号**和**块号（页框号）**组成
  - ⚠️ **页号不需要存储**！页表项是**按页号顺序连续存放**的，页号就是**下标**（与数组一样）
  - 所以页表项只需存**页框号**（以及后面要讲的状态位等）
- 页表的作用：实现从**页号到物理块号的映射**

✏️ **页表项大小计算**（⭐⭐⭐）：
> 某系统物理内存 **4GB**，页面大小 **4KB**，页表项至少占多少字节？
- 页框数 = 4GB / 4KB = 2³² / 2¹² = **2²⁰** 个 → 页框号需要 **20 位**
- 20 位 = 2.5 字节，页表项按字节对齐，至少需要 **3B**
- 实际中为了方便访问，通常取 **4B**（剩下的位可以存放状态位、保护位等）

✏️ **页表大小计算**：
> 逻辑地址 32 位，页面 4KB，页表项 4B，一个进程的页表最多多大？
- 页数 = 2³² / 2¹² = 2²⁰
- 页表大小 = 2²⁰ × 4B = **4MB**（而且要**连续**存放！这就是需要多级页表的原因）

### 📐 基本地址变换机构（⭐⭐⭐）
系统中设置一个**页表寄存器（PTR）**，存放**页表在内存中的起始地址 F** 和**页表长度 M**。进程未执行时，这些信息放在 PCB 中；进程被调度时，OS 把它们装入 PTR。

**地址转换过程**（设页面大小为 L，逻辑地址为 A）：
```
            逻辑地址 A
      ┌────────┬────────┐
      │ 页号 P  │ 偏移 W  │
      └───┬────┴────┬───┘
          │         │
   P ≥ M？─是─► 越界中断
          │否
          ▼
  页表项地址 = F + P × 页表项长度   ← 访问内存（第 1 次）
          │
          ▼
     取出页框号 b
          │
          ▼
  物理地址 E = b × L + W           ← 访问内存（第 2 次）取数据
```
1. 根据逻辑地址算出**页号 P** 和**页内偏移量 W**
2. **判断页号是否越界**：若 **P ≥ 页表长度 M**，产生越界中断（⚠️ 页号从 0 开始，所以 P = M 也越界）
3. 查页表：页表项地址 = **页表始址 F + 页号 P × 页表项长度**，取出**页框号 b**
4. 物理地址 **E = b × L + W**（页框号与页内偏移**拼接**）
5. 用物理地址访问内存

⚠️ **基本分页需要访问两次内存**：第一次查页表，第二次访问数据。

✏️ **例**：页面大小 1KB，某进程页表如下（十进制）：页 0 → 块 2，页 1 → 块 5，页 2 → 块 8，页表长度 3。求逻辑地址 **2500** 的物理地址。
- 页号 P = 2500 / 1024 = **2**，偏移 W = 2500 − 2048 = **452**
- P = 2 < 3，不越界
- 页 2 → 块 **8**
- 物理地址 = 8 × 1024 + 452 = **8644**

✏️ **例（十六进制）**：页面大小 4KB，逻辑地址 **2A3CH**，页表中页 2 → 页框 **5H**。
- 4KB → 偏移 12 位 = 低 3 个十六进制位 → 偏移 **A3CH**，页号 **2**
- 物理地址 = 5H 拼接 A3CH = **5A3CH**

📝 **真题（2023 年第 30 题）**：进程 R 和 S 共享数据 data，若 data 在 R 和 S 中所在页的页号分别为 p1 和 p2，两个页所对应的页框号分别为 f1 和 f2，则下列叙述中，正确的是：
A. p1 和 p2 一定相等，f1 和 f2 一定相等　B. p1 和 p2 一定相等，f1 和 f2 不一定相等　C. p1 和 p2 不一定相等，f1 和 f2 一定相等　D. p1 和 p2 不一定相等，f1 和 f2 不一定相等
→ **C**（共享数据在物理内存中**只有一份**，它所在的物理页框是同一个，所以 **f1 = f2 一定成立**；但两个进程可以把这个页框映射到各自虚拟地址空间中**不同的虚页**，所以 p1 和 p2 **不一定相等**。🧒 同一间房（页框），在两个人的通讯录里可以记成不同的“房号昵称”（页号）。）

📝 **真题（2023 年第 25 题）**：某系统采用页式存储管理，用**位图**管理空闲页框。若页大小为 4KB，物理内存大小为 16GB，则位图所占空间的大小是：A. 128B　B. 128KB　C. 512KB　D. 4MB
- 页框数 = 16GB / 4KB = 2³⁴ / 2¹² = 2²² 个
- 每个页框用 **1 位**表示空闲/占用 → 2²² 位 = 2¹⁹ B = **512KB** → 选 **C**

## 二、具有快表的地址变换机构（⭐⭐⭐）

### 📐 快表（TLB）
基本分页每次访存都要**两次**访问内存（页表 + 数据），速度减半。利用**局部性原理**，在 CPU 中设置一个**高速缓冲存储器**，存放**最近访问过的页表项的副本**，这就是**快表**（联想寄存器、**TLB**）。内存中的页表相应地叫**慢表**。

### 📐 带快表的地址转换
1. CPU 给出逻辑地址，由硬件算出页号、页内偏移量
2. 将页号与**快表中所有页号**同时比较：
   - **命中**：直接取出页框号，与偏移拼接成物理地址，访问内存（**只访问内存 1 次**）
   - **未命中**：访问内存中的**慢表**，取出页框号形成物理地址，访问内存（**访问内存 2 次**）；同时把该页表项**存入快表**（快表满时按某种算法替换）

### 📐 有效访问时间（EAT）的计算（⭐⭐⭐）
设访问快表时间 t，访问内存时间 T，快表命中率 α：

**① 先查快表，未命中再查慢表（串行，默认）**：
```
EAT = α × (t + T) + (1 − α) × (t + T + T)
    = t + T + (1 − α) × T
```
**② 快表和慢表同时查（并行）**：命中时慢表的访问被中止
```
EAT = α × (t + T) + (1 − α) × (T + T)
```

✏️ **例**：访问一次内存 100ns，访问快表 20ns，快表命中率 90%。
- 无快表：EAT = 100 + 100 = **200ns**
- 有快表（串行）：EAT = 0.9 × (20 + 100) + 0.1 × (20 + 100 + 100) = 108 + 22 = **130ns**
- 有快表（并行）：EAT = 0.9 × 120 + 0.1 × 200 = 108 + 20 = **128ns**

⚠️ 快表与 Cache 的区别：快表中存的是**页表项的副本**；Cache 中存的是**主存块（数据/指令）的副本**。

## 三、两级页表与多级页表（⭐⭐⭐）

### 📐 单级页表的问题
1. **页表必须连续存放**：前面算过，32 位逻辑地址、4KB 页、4B 页表项，一个进程的页表要 **4MB 连续**的内存，即 1024 个**连续**的页框——违背了分页“离散存储”的初衷
2. **没必要让整个页表常驻内存**：进程在一段时间内可能只访问几个页面

### 📐 两级页表的思想
🧒 **比喻：书的目录**
- 一本 1000 页的书，如果目录把每一页都列出来，目录本身就有好几十页
- 改成**两级目录**：一级目录只列“第 1 章在第 X 页”，二级目录（每章开头）再列“本章第 1 节在第 Y 页”
- 一级目录很短；某一章你不读，它的二级目录就不需要翻开

**做法**：把页表**也分页**，页表的每一页（叫**二级页表**）离散地存放在内存中；再为这些二级页表建立一张**页目录表**（**一级页表、外层页表、顶级页表**），记录每个二级页表存放在哪个页框中。

### 📐 地址结构（32 位、4KB 页、4B 页表项）
- 一个页框 4KB 能存放 4KB / 4B = **1024 = 2¹⁰** 个页表项
- 所以每一级页表的索引 **10 位**
```
|  一级页号（页目录号）10 位 |  二级页号（页号）10 位  |  页内偏移 12 位 |
    31 ~ 22                   21 ~ 12                 11 ~ 0
```

### 📐 两级页表的地址转换
1. 按地址结构把逻辑地址拆成**三部分**：一级页号、二级页号、页内偏移
2. 从 **PCB 中读出页目录表始址**（页目录基址寄存器，如 x86 的 CR3），根据**一级页号**查页目录表，找到对应**二级页表在内存中的存放位置**（页框号）
3. 根据**二级页号**查二级页表，找到最终要访问的**内存块号**
4. 结合**页内偏移量**得到**物理地址**

⚠️ 两级页表**没有快表**时需要访问内存 **3 次**（页目录、二级页表、数据）；n 级页表需要 **n + 1** 次。

📝 **真题（2021 年第 29 题）**：在采用二级页表的分页系统中，CPU 页表基址寄存器中的内容是：
A. 当前进程的一级页表的起始虚拟地址　B. 当前进程的一级页表的起始物理地址　C. 当前进程的二级页表的起始虚拟地址　D. 当前进程的二级页表的起始物理地址
→ **B**（地址转换从一级页表开始；硬件查页表时不能再用虚拟地址（否则又要转换，陷入循环），所以必须是**物理地址**）

### 📝 真题（2020 年第 46 题，8 分）⭐⭐⭐
> 某 32 位系统采用基于二级页表的请求分页存储管理方式，按字节编址，页目录项和页表项长度均为 4 字节，虚拟地址结构如下所示：
>
> | 页目录号（10 位） | 页号（10 位） | 页内偏移量（12 位） |
> |---|---|---|
>
> 某 C 程序中数组 a[1024][1024] 的起始虚拟地址为 **1080 0000H**，数组元素占 4 字节，该程序运行时，其进程的页目录起始物理地址为 **0020 1000H**，请回答下列问题。
> 1）数组元素 a[1][2] 的虚拟地址是什么？对应的页目录号和页号分别是什么？对应的页目录项的物理地址是什么？若该目录项中存放的页框号为 **00301H**，则 a[1][2] 所在页对应的页表项的物理地址是什么？
> 2）数组 a 在虚拟地址空间中所占的区域是否必须连续？在物理地址空间中所占区域是否必须连续？
> 3）已知数组 a 按行优先方式存放，若对数组 a 分别按行遍历和按列遍历，则哪种遍历方式的局部性更好？

**1）**
- **a[1][2] 的虚拟地址** = 1080 0000H + (1 × 1024 + 2) × 4 = 1080 0000H + 1026 × 4 = 1080 0000H + 4104 = 1080 0000H + **1008H** = **1080 1008H**
- 写成二进制并划分：
  ```
  1080 1008H = 0001 0000 10 | 00 0000 0001 | 0000 0000 1000
               页目录号        页号           页内偏移
  ```
  - **页目录号** = 00 0100 0010 = **042H**（即十进制 66）
  - **页号** = 00 0000 0001 = **001H**
  - 页内偏移 = 008H
- **页目录项的物理地址** = 页目录起始物理地址 + 页目录号 × 4 = 0020 1000H + 42H × 4 = 0020 1000H + 108H = **0020 1108H**
- **页表项的物理地址** = 页表所在页框的起始地址 + 页号 × 4 = 00301H × 4KB + 1 × 4 = 0030 1000H + 4 = **0030 1004H**

🧒 **技巧**：虚拟地址高 10 位 = 地址 >> 22。1080 0000H >> 22：1080 0000H = 0001 0000 1000 0000 …，取前 10 位 0001 0000 10 = 042H。

**2）**
- **虚拟地址空间中必须连续**：数组是一个整体，C 语言通过“首地址 + 偏移”访问数组元素，要求虚拟地址连续
- **物理地址空间中不必连续**：分页管理下，数组所在的各个虚页可以映射到任意不连续的页框

**3）** **按行遍历的局部性更好**。数组按行优先存放，按行遍历时访问的地址是连续的（空间局部性好，同一页内连续访问 1024 个元素）；按列遍历时，相邻两次访问相差 1024 × 4B = 4KB，**每次访问都在不同的页**，局部性差。

（补充：数组 a 共 1024 × 1024 × 4B = 4MB = 1024 页，恰好由**一个页目录项**（042H）对应的整张二级页表来映射。）

### 📐 多级页表
若逻辑地址更长（如 64 位），两级页表的页目录也会很大，就需要**三级、四级**页表。
- **原则：各级页表的大小不能超过一个页面**
✏️ **例**：虚拟地址 48 位，页面 4KB，页表项 8B，需要几级页表？
- 页内偏移 12 位，页号共 48 − 12 = 36 位
- 一个页面可存 4KB / 8B = 512 = 2⁹ 个页表项，每级 9 位
- 级数 = ⌈36 / 9⌉ = **4 级**（这正是 x86-64 的四级页表）

## 四、基本分段存储管理（⭐⭐）

### 📐 分段的思想
分页是**从 OS 的角度**、按物理大小机械地切分，一页中可能既有代码又有数据。而程序员习惯**按逻辑**来看程序：主程序、子程序、栈、数据……

**分段**：按照程序**自身的逻辑关系**把进程的地址空间划分为若干个**段**，每个段有一个**段名**（在低级语言中，程序员用段名编程），每段**从 0 开始编址**。
- 内存分配以**段为单位**，**每个段在内存中占据连续空间**，但**各段之间可以不相邻**
- 段的长度**不固定**，由程序的逻辑决定

### 📐 逻辑地址结构
```
|  段号 S  |  段内偏移量 W  |
```
- 段号位数决定**每个进程最多能分几个段**
- 段内偏移位数决定**每个段的最大长度**
- 分段的逻辑地址是**二维**的：程序员需要**显式地**给出段号和段内偏移（分页是一维的，程序员只给出一个地址，OS 自动切分）

### 📐 段表
每个进程一张**段表**，每个段表项对应一个段：
| 段号（隐含） | **段长** | **基址**（段在内存中的起始物理地址） |
|---|---|---|
- 段号可以隐含（按顺序存放）
- ⚠️ 与页表不同：**段表项要记录段长**，因为每个段的长度不同

### 📐 地址转换过程（⭐⭐）
系统中设置**段表寄存器**，存放段表始址 F 和段表长度 M。
1. 根据逻辑地址得到**段号 S**、**段内偏移 W**
2. **判断段号是否越界**：若 **S ≥ M**，越界中断
3. 查段表：段表项地址 = F + S × 段表项长度，取出**段长 C** 和**基址 b**
4. **检查段内偏移是否越界**：若 **W ≥ C**，越界中断（⚠️ 分页没有这一步，因为页长固定）
5. 物理地址 = **b + W**（基址**相加**偏移，不是拼接）

✏️ **例**：某进程段表：段 0 基址 219、段长 600；段 1 基址 2300、段长 14；段 2 基址 90、段长 100。求逻辑地址 (0, 430)、(1, 10)、(2, 500) 的物理地址。
- (0, 430)：430 < 600 → 219 + 430 = **649**
- (1, 10)：10 < 14 → 2300 + 10 = **2310**
- (2, 500)：500 ≥ 100 → **越界中断**

### 📐 段的共享与保护
- **共享**：多个进程的段表中，某段的表项指向**同一个物理段**。只有**不能被修改的代码**（**纯代码、可重入代码**）或只读数据才适合共享
- **保护**：
  - **存储控制保护**：段表项中增加**存取控制字段**（读/写/执行权限）
  - **地址越界保护**：段号与段表长度比较、段内偏移与段长比较
- 分段比分页**更容易实现信息的共享和保护**：因为段是按逻辑划分的，一个段就是一个完整的逻辑单位（如一个函数）；而一页可能混杂了可共享和不可共享的内容

### 📐 分页与分段的比较（⭐⭐⭐）
| | 分页 | 分段 |
|---|---|---|
| 单位 | **页是信息的物理单位** | **段是信息的逻辑单位** |
| 目的 | 实现离散分配，**提高内存利用率**，是系统管理的需要，**对用户不可见** | 更好地**满足用户需要**，**对用户可见**（程序员编程时要显式给出段名） |
| 大小 | **固定**，由系统决定 | **不固定**，由用户程序决定 |
| 地址空间 | **一维**（给出一个记忆符即可表示地址） | **二维**（要给出段名和段内地址） |
| 碎片 | **内部碎片**（最后一页） | **外部碎片**（段需要连续空间） |
| 共享与保护 | 较难 | **容易** |
| 访存次数（无快表） | 2 次 | 2 次 |

## 五、段页式存储管理（⭐⭐）

### 📐 思想
**结合分页和分段的优点**：
- 先把进程按逻辑模块**分段**
- 再把**每个段分页**
- 内存空间分为大小相同的页框，按页框分配

### 📐 逻辑地址结构
```
|  段号 S  |  页号 P  |  页内偏移量 W  |
```
- 段号位数 → 每个进程最多几个段
- 页号位数 → 每个段最大有几页
- 页内偏移位数 → 页面大小
- 段页式的地址结构仍是**二维**的（程序员给出段号和段内地址，段内地址再由系统自动分为页号和偏移）

### 📐 数据结构
- 每个进程**一张段表**，每个段表项记录：**段号（隐含）、页表长度、页表存放的块号（页表始址）**
- 每个**段**对应**一张页表**，页表项记录：页号（隐含）、页框号

### 📐 地址转换过程
1. 由逻辑地址得到**段号、页号、页内偏移量**
2. 段号与段表寄存器中的**段表长度**比较，检查是否越界
3. 由段表始址和段号找到对应段表项，得到该段的**页表始址**和**页表长度**
4. **检查页号是否越界**（页号 ≥ 页表长度则越界）
5. 由页表始址和页号查页表，得到**页框号**
6. 页框号与页内偏移拼接得到物理地址

⚠️ 段页式**没有快表**时要访问内存 **3 次**：查段表、查页表、访问数据。引入快表后，用**段号和页号**作为查询快表的关键字，命中时只需 1 次。

### 📐 三种方式对比
| 方式 | 优点 | 缺点 |
|---|---|---|
| 分页 | 内存利用率高，碎片小，分配管理简单 | 不方便按照逻辑模块实现信息的共享和保护 |
| 分段 | 方便按逻辑模块共享和保护 | 段长过大时不便分配连续空间；有外部碎片 |
| 段页式 | 兼具两者优点 | 访存次数多、表格占用空间多 |

---

## ⚠️ 易错点

1. 分页：**页内偏移位数由页面大小决定**；页号位数 = 逻辑地址位数 − 偏移位数
2. **页表项不存页号**（页号是下标），只存页框号等
3. 页号越界判断是 **P ≥ M**（页号从 0 开始）
4. 分页物理地址 = 页框号 **拼接** 偏移（或 b × L + W）；分段物理地址 = 基址 **+** 偏移
5. 分段要**额外检查段内偏移是否越界**
6. 基本分页访存 **2 次**；两级页表 **3 次**；段页式 **3 次**（无快表时）
7. 有效访问时间：看清是串行还是并行查快表
8. **页表基址寄存器存的是物理地址**
9. 多级页表的原则：**每级页表不超过一页**
10. 分页对用户**透明**，地址**一维**；分段对用户**可见**，地址**二维**
11. 分页有**内部碎片**，分段有**外部碎片**
12. 看清题目中页号是**十进制还是十六进制**

## 📋 本课小结

| 知识点 | 要点 |
|---|---|
| 分页 | 页 = 页框大小；页表存页框号；E = b × L + W |
| 快表 | 页表项的 Cache；命中访存 1 次，未命中 2 次 |
| EAT | 串行：t + T + (1−α)T |
| 两级页表 | 页目录号 \| 页号 \| 偏移；访存 3 次；页目录基址是物理地址 |
| 分段 | 段表（段长、基址）；E = b + W；检查 W < 段长 |
| 段页式 | 段号 \| 页号 \| 偏移；一段一张页表 |

## 🏋️ 课后练习

1. 某系统逻辑地址 16 位，页面大小 1KB，一个进程最多有多少页？页内偏移几位？逻辑地址 0x1A2B 的页号和偏移是多少？
2. 物理内存 64MB，页面 2KB，页表项至少几字节？
3. 访问内存 200ns，访问快表 10ns，快表命中率 85%（串行查找），求有效访问时间。若要求 EAT 不超过 250ns，命中率至少多少？
4. 某系统采用两级页表，逻辑地址 32 位，页面 4KB，页表项 4B，逻辑地址 0x00403004 的页目录号、页号、页内偏移各是多少？
5. 某段表：段 0（基址 1000，段长 300），段 1（基址 2000，段长 500）。求 (0, 250)、(1, 550)、(2, 10) 的物理地址（段表长度为 2）。
6. 判断：(a) 分页存储管理中，页的大小由程序员决定；(b) 分段管理便于共享；(c) 段页式的逻辑地址是三维的。

<details>
<summary>📖 答案</summary>

1. 偏移 10 位，页号 6 位，最多 **64** 页；0x1A2B = 0001 1010 0010 1011，页号 = 高 6 位 000110 = **6**，偏移 = 10 0010 1011 = **0x22B**（555）
2. 页框数 64MB / 2KB = 2¹⁵ → 15 位 → 至少 **2B**
3. EAT = 10 + 200 + 0.15 × 200 = **240ns**；要求 10 + 200 + (1 − α) × 200 ≤ 250 → (1 − α) ≤ 0.2 → **α ≥ 80%**
4. 0x00403004 = 0000 0000 01 | 00 0000 0011 | 0000 0000 0100 → 页目录号 **1**，页号 **3**，偏移 **0x004**
5. (0, 250)：250 < 300 → **1250**；(1, 550)：550 ≥ 500 → **越界**；(2, 10)：段号 2 ≥ 段表长度 2 → **越界**
6. (a) **错**，由系统决定；(b) **对**；(c) **错**，是二维的（段号 + 段内地址，页号和偏移由系统划分）
</details>
