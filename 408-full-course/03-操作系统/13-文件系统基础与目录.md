## 一、文件的基本概念（⭐）

### 📐 文件的定义
**文件**：以**硬盘**为载体的、存储在计算机上的**信息集合**。可以是文本文档、图片、程序……
- 从用户角度：文件是一组有意义的信息的集合
- 从 OS 角度：文件系统负责管理这些信息的存储、检索、更新、共享和保护

### 📐 文件的属性
| 属性 | 说明 |
|---|---|
| **名称** | 文件名，同一目录下**不能重名** |
| **标识符** | 系统内唯一的标签（通常是数字，如 inode 号），对用户不可读 |
| **类型** | 如 .txt、.exe、.jpg |
| **位置** | 文件存放的路径（让用户使用）、在外存中的地址（OS 使用，对用户不可见） |
| **大小** | 文件当前大小、允许的最大值 |
| **保护信息** | 对文件进行保护的访问控制信息（谁能读、写、执行） |
| **时间、日期和用户标识** | 创建、修改、访问时间，创建者 |

### 📐 文件控制块 FCB（⭐⭐）
**FCB（File Control Block）**：用来存放控制文件所需的各种信息的**数据结构**，以实现“**按名存取**”。
- **FCB 与文件一一对应**，FCB 的有序集合称为**文件目录**，**一个 FCB 就是一个文件目录项**
- 创建一个新文件，系统就会分配一个 FCB 并存放在文件目录中，成为目录项
- FCB 中包含：
  - **基本信息**：文件名、文件的物理位置、文件的逻辑结构、文件的物理结构
  - **存取控制信息**：文件主的存取权限、核准用户的存取权限、一般用户的存取权限
  - **使用信息**：建立时间、上次修改时间、当前使用信息等
- 最重要、最基本的是**文件名**和**文件存放的物理地址**

### 📐 索引结点（inode）（⭐⭐⭐）
**问题**：检索目录文件时，要把目录文件**一块一块地从磁盘读入内存**，逐个比较文件名。在查找时，**只需要文件名**，FCB 的其他信息（大小、时间、位置……）暂时用不到——但它们占用了大量空间，使目录文件变得很大，需要读更多的磁盘块。

**解决**：把**文件名**和**文件描述信息**分开：
- **目录项**中只保留：**文件名 + 索引结点号（指针）**
- 其他描述信息放到**索引结点（inode）**中

```
目录项（很小）             索引结点（inode）
┌──────────┬───────┐      ┌─────────────────────┐
│ 文件名    │ inode号├─────►│ 文件主、类型、权限、   │
└──────────┴───────┘      │ 大小、时间、链接计数、 │
                          │ 物理地址（直接/间接）… │
                          └─────────────────────┘
```

- **磁盘索引结点**：存放在磁盘上的索引结点。每个文件有唯一的一个磁盘索引结点
- **内存索引结点**：文件被**打开**时，将磁盘索引结点**复制到内存**中，并增加了一些字段：索引结点编号、状态（是否上锁/修改）、**访问计数**（有多少个进程正在访问）、逻辑设备号、链接指针等

✏️ **例：引入索引结点后查找效率的提高**（⭐⭐⭐）
> 某文件系统中，一个 FCB 占 **64B**，盘块大小 **1KB**。某目录下有 **3200** 个文件（目录项）。
> (1) 采用 FCB 作为目录项，查找该目录下一个文件平均需要启动磁盘多少次？
> (2) 若采用索引结点，目录项中文件名占 **8B**、索引结点号占 **2B**，平均需要启动磁盘多少次？

**(1)**
- 目录大小 = 3200 × 64B = 204800B = **200 块**
- 平均需要查找一半：(1 + 200) / 2 = **100.5 次**
**(2)**
- 目录项 = 8 + 2 = **10B**，目录大小 = 3200 × 10B = 32000B → ⌈32000 / 1024⌉ = **32 块**
- 查找目录平均 (1 + 32) / 2 = 16.5 次，找到后还要**读一次索引结点** → 共 **17.5 次**

🧒 目录变小了 6 倍多，查找速度大大提高！

📝 **真题（2020 年第 31 题）**：某文件系统的目录项由文件名和索引结点号构成。若每个目录项长度为 64 字节，其中 4 字节存放索引结点号，60 字节存放文件名。文件名由小写英文字母构成，则该文件系统能创建的文件数量的上限为：A. 2²⁶　B. 2³²　C. 2⁶⁰　D. 2⁶⁴
→ **B**（每个文件对应一个唯一的索引结点，索引结点号 4B = 32 位，最多 **2³²** 个索引结点，也就最多 2³² 个文件。文件名 60 字节的组合数远大于此，不是瓶颈）

## 二、文件的基本操作与“打开文件”（⭐⭐⭐）

### 📐 基本操作
| 操作 | 系统调用 | 过程 |
|---|---|---|
| **创建** | create | ① 在外存中**找到文件所需的空间**（用空闲空间管理算法）② 根据文件存放路径的信息，找到该目录对应的目录文件，在目录中**创建该文件对应的目录项**（包含文件名、在外存中的存放位置等信息） |
| **删除** | delete | ① 根据文件存放路径找到相应的**目录文件**，从目录中找到文件名对应的目录项 ② 根据该目录项记录的文件在外存的存放位置、文件大小等信息，**回收文件占用的磁盘块** ③ 从目录表中**删除文件对应的目录项** |
| **打开** | open | 见下 |
| **关闭** | close | 见下 |
| **读** | read | 指明读入多少数据、读入的数据放在内存中的什么位置；OS 在处理 read 时，会从读指针指向的外存中，将用户指定大小的数据读入用户指定的内存区域 |
| **写** | write | 指明写出多少数据、写回外存的数据放在内存中的什么位置；OS 会从用户指定的内存区域中，将指定大小的数据写回写指针指向的外存 |

📝 **真题（2025 年第 29 题）**：某文件系统采用索引节点方式。用户在目录中新建文件 F 时，文件系统**不会做**的是：
A. 初始化文件 F 的索引节点　B. 在目录文件中写入 F 的索引节点号　C. 在目录文件中写入 F 的访问权限信息　D. 在目录文件中增加一条文件 F 对应的目录项
→ **C**（采用索引结点方式时，目录项只包含**文件名 + 索引结点号**；访问权限等信息存放在**索引结点**中，不写入目录文件）

📝 **真题（2021 年第 30 题）**：若目录 dir 下有文件 file1，则为删除该文件内核**不必完成**的工作是：
A. 删除 file1 的快捷方式　B. 释放 file1 的文件控制块　C. 释放 file1 占用的磁盘空间　D. 删除目录 dir 中与 file1 对应的目录项
→ **A**（快捷方式（软链接）是**另一个独立的文件**，删除原文件时内核并不知道哪里有它的快捷方式，也不负责删除——删除原文件后，快捷方式会变成“失效链接”）

### 📐 打开文件（open）（⭐⭐⭐）
**为什么要“打开”**：每次读写文件都要检索目录找到文件的位置，太费时间。所以在第一次使用文件之前，先调用 open：
1. 根据**文件名**搜索目录，找到该文件的**目录项（FCB/索引结点）**
2. 检查用户是否有**相应的访问权限**
3. 把该文件的 FCB/索引结点**复制到内存**中的“**打开文件表**”中
4. 返回一个**文件描述符**（打开文件表中的**表项编号**），之后用户就通过这个编号来操作文件，**不再需要**文件名和检索目录

### 📐 两级打开文件表（⭐⭐⭐）
| 表 | 数量 | 内容 |
|---|---|---|
| **系统打开文件表** | **整个系统只有一张** | 每个被打开的文件**只有一个表项**：FCB/索引结点副本（文件的物理位置、大小……）、**打开计数器**（有多少个进程打开了该文件） |
| **用户（进程）打开文件表** | **每个进程一张**（在 PCB 中） | 该进程打开的每个文件一个表项：**读写指针**（本进程读写到哪了）、**访问权限**（本进程以什么方式打开，如只读、读写）、**指向系统打开文件表中对应表项的指针** |

```
进程 A 的打开文件表         系统打开文件表                  磁盘
┌─────┬──────────┬───┐    ┌──────────────────────┐
│ fd=3│读写指针=100│ ●─┼──► │ 文件 F 的 FCB 副本     │ ──► 文件 F
│     │只读       │   │  ┌►│ 打开计数 = 2           │
└─────┴──────────┴───┘  │ └──────────────────────┘
进程 B 的打开文件表       │
┌─────┬──────────┬───┐  │
│ fd=5│读写指针=0 │ ●─┼──┘
│     │读写       │   │
└─────┴──────────┴───┘
```

⚠️ 关键点：
- **多个进程打开同一个文件**时，**系统打开文件表中只有一个表项**（打开计数 +1），每个进程的用户打开文件表中各有一个表项
- **读写指针在用户打开文件表中**：因为每个进程读写的位置不同
- 各进程**访问权限可以不同**（一个只读、一个读写）

### 📐 关闭文件（close）
1. 将**进程的打开文件表**中的相应表项**删除**
2. 回收分配给该文件的内存空间等资源
3. **系统打开文件表**中该文件的**打开计数器减 1**；若**打开计数 = 0**，则**删除**系统打开文件表中的对应表项（释放内存中的索引结点副本）

📝 **真题（2020 年第 23 题）**：若多个进程共享同一个文件 F，则下列叙述中，正确的是：
A. 各进程只能用“读”方式打开文件 F　B. 在系统打开文件表中仅有一个表项包含 F 的属性　C. 各进程的用户打开文件表中关于 F 的表项内容相同　D. 进程关闭 F 时，系统删除 F 在系统打开文件表中的表项
→ **B**
- A：可以有进程以写方式打开（需要同步互斥）
- C：各进程的读写指针、访问权限可能不同
- D：只有打开计数减到 0 时才删除

📝 **真题（2023 年第 31 题）**：若文件 F 仅被进程 P 打开并访问，则当进程 P 关闭 F 时，文件系统需要完成的是：
A. 删除目录中文件 F 的目录项　B. 释放 F 的索引节点所占的内存空间　C. 释放 F 的索引节点所占的外存空间　D. 将文件磁盘索引节点中链接计数器减 1
→ **B**
- 只有 P 打开了 F，关闭时打开计数减为 0，系统打开文件表中 F 的表项（**内存索引结点**）被删除，释放其**内存空间**
- A、C、D 都是**删除文件**时才做的操作（D 中的“**链接计数**”记录的是有几个目录项指向该索引结点，与打开无关；注意区分**打开计数**和**链接计数**）

## 三、文件的逻辑结构（⭐⭐）

**逻辑结构**：从**用户观点**出发看到的文件的组织形式（数据在逻辑上如何组织）。
**物理结构**（下一课）：从**实现观点**出发，文件在**外存**上的存放方式。

### 📐 1. 无结构文件（流式文件）
文件内部的数据就是**一系列二进制流或字符流**组成，没有明显的结构特性。
- 如 Windows 的 .txt 文件、源程序、可执行文件
- 以**字节**为单位，访问时通过读写指针指出下一个要访问的字节

### 📐 2. 有结构文件（记录式文件）
由一组**相似的记录**组成。每条记录由若干个**数据项**组成（如学生记录：学号、姓名、成绩）。一般来说，每条记录有一个数据项可作为**关键字**。
- 根据各条记录的长度是否相等，可分为**定长记录**和**可变长记录**

#### (1) 顺序文件
文件中的记录**一个接一个地顺序排列**（逻辑上），记录可以是定长的或可变长的。各个记录在物理上可以**顺序存储**或**链式存储**。
- **串结构**：记录之间的顺序与关键字**无关**（通常按存入时间排序）
- **顺序结构**：记录之间的顺序**按关键字排列**

| | 链式存储 | 顺序存储（可变长） | 顺序存储（定长） |
|---|---|---|---|
| 随机存取第 i 条记录 | ❌ | ❌ | ✅（地址 = 起始 + i × L） |
| 按关键字快速检索 | ❌ | ❌ | ✅（若按关键字排序，可折半查找） |

- ✅ **批量**处理记录时效率高；只有顺序文件才能存储在**磁带**上
- ❌ 增加或删除一条记录比较困难（可以用“日志文件”暂存改动，定期合并）

#### (2) 索引文件
为**可变长记录**文件建立一张**索引表**，每条记录对应一个索引表项：`| 索引号 | 长度 | 指针 |`
- 索引表本身是**定长记录**的顺序文件，可以快速找到第 i 条记录的索引项
- 可以把关键字作为索引号内容，若按关键字顺序排列，还可以**按关键字折半查找**
- ✅ 支持**随机访问**，检索快；适用于对信息**处理及时性**要求较高的场合
- ❌ 每条记录都有一个索引项，**索引表可能很大**，存储空间利用率低

#### (3) 索引顺序文件（⭐⭐）
索引文件和顺序文件的结合。把顺序文件中的所有记录**分为若干组**，为顺序文件建立一张索引表，**每组的第一条记录**在索引表中建立一个索引项。
- 🧒 像查字典：先查“拼音首字母索引”找到 L 开头的那一页（组），再在这一页里顺序找
- **索引表很小**（一组一个索引项）

✏️ **计算**：一个顺序文件有 **10000** 条记录。
- **直接顺序查找**：平均要查 10000 / 2 = **5000** 次
- **索引顺序文件**：分成 √10000 = **100** 组，每组 100 条。先在索引表中顺序找组（平均 50 次），再在组内顺序找（平均 50 次），共约 **100** 次
- **多级索引顺序文件**：若记录数为 10⁶，可建两级索引：分成 100 个大组，每个大组 100 个小组，每小组 100 条 → 平均查找约 50 + 50 + 50 = **150** 次

📐 一般地，N 条记录的索引顺序文件（一级），分 √N 组，平均查找次数 ≈ **√N**（= √N/2 + √N/2）。

#### (4) 直接文件（散列文件、哈希文件）
给定记录的键值或通过**散列函数**转换的键值直接决定记录的物理地址。
- ✅ 存取速度很快
- ❌ 可能发生**冲突**；不能进行顺序访问

## 四、目录结构（⭐⭐）

### 📐 目录的功能
- **实现“按名存取”**：用户只需提供文件名，即可对文件进行存取
- 提高对目录的**检索速度**
- **文件共享**：允许多个用户共享一个文件
- 允许**文件重名**：不同用户可以对不同文件使用相同的名字

### 📐 1. 单级目录结构
整个系统中**只建立一张目录表**，每个文件占一个目录项。
- ❌ 查找速度慢；**不允许重名**；不便于文件共享；不适用于多用户操作系统

### 📐 2. 两级目录结构
分为**主文件目录（MFD）**和**用户文件目录（UFD）**：
- MFD 记录用户名及相应 UFD 的存放位置
- UFD 由该用户的文件 FCB 组成
- ✅ 解决了**不同用户之间文件重名**问题；可以在目录上实现访问限制
- ❌ 缺乏灵活性，**用户不能对自己的文件进行分类**

### 📐 3. 树形目录结构（多级目录）（⭐⭐）
大多数 OS 采用的目录结构（Windows、Linux）。
- **绝对路径**：从**根目录**出发的路径，如 `/home/user/a.txt`
- **当前目录（工作目录）**：进程当前所在的目录
- **相对路径**：从**当前目录**出发的路径，如当前目录为 `/home` 时，`user/a.txt`
- 引入“当前目录”和“相对路径”后，**减少了磁盘 I/O 的次数**（不需要从根目录开始逐级读入目录文件），提高了检索效率

✏️ **例**：用绝对路径 `/usr/bin/gcc` 访问文件，假设所有目录文件都在磁盘上、每个目录文件占一个磁盘块，要读几次磁盘？
- 读根目录（找 usr）→ 读 usr 目录（找 bin）→ 读 bin 目录（找 gcc）→ 共 **3 次**（若还要读 gcc 的索引结点则再加若干次）
- 若当前目录已是 `/usr/bin`（已在内存中），用相对路径 `gcc` → **0 次**读目录

- ✅ 便于分类，层次清楚，能有效地进行文件的管理和保护
- ❌ **不便于实现文件的共享**

### 📐 4. 无环图目录结构
在树形目录的基础上，增加一些指向**同一结点**的**有向边**，使整个目录成为一个**有向无环图**，从而**实现文件共享**。
- 可以用不同的文件名指向同一个文件，甚至可以指向同一个目录
- 需要为每个共享结点设置一个**共享计数器**，删除时计数减 1，只有计数为 0 时才真正删除
- ⚠️ 共享文件 ≠ 复制文件：共享文件只有一份，一个用户修改后，所有共享者都能看到

---

## 五、文件共享（⭐⭐⭐）

### 📐 1. 基于索引结点的共享方式（硬链接）
- 多个目录项**直接指向同一个索引结点**（索引结点中存放文件的物理地址等信息）
- 索引结点中设置一个**链接计数 count**，记录有多少个目录项链接到该索引结点
- 用户 B 建立到文件 F 的硬链接 → count + 1
- 用户“删除”文件时，只是删除自己的目录项，**count − 1**；**只有 count = 0 时，才真正删除文件**（回收索引结点和磁盘块）

```
用户 A 的目录           用户 B 的目录
│ F │ inode 10 │      │ G │ inode 10 │
        │                     │
        └──────────┬──────────┘
                   ▼
            索引结点 10
          （count = 2，物理地址……）
```

📝 **2022 年第 45 题**中，文件 course1 和 doc 的**索引结点号都是 10**，说明它们是**同一个文件**的两个硬链接，所以 doc 的磁盘块号 x 与 course1 的相同，都是 **30**（完整讲解见下一课）。

### 📐 2. 基于符号链的共享方式（软链接）
- 为共享文件建立一个 **LINK 类型的新文件**，这个新文件中**只包含被链接文件的路径名**
- 访问时，OS 发现是 LINK 文件，就根据其中的路径名去找真正的文件
- 🧒 就像 Windows 的“**快捷方式**”
- 原文件被删除后，符号链接**失效**（找不到文件，“悬空链接”）

### 📐 硬链接 vs 软链接（⭐⭐⭐）
| | 硬链接 | 软链接（符号链接） |
|---|---|---|
| 本质 | 目录项直接指向**同一个索引结点** | 一个**新文件**，内容是被链接文件的**路径** |
| 是否有自己的 inode | **没有**（共享原文件的 inode） | **有**（它是一个独立的文件） |
| 链接计数 | 建立硬链接使 count **+1** | 不影响原文件的 count |
| 删除原文件 | count − 1，只要 count > 0 **文件仍存在**，其他链接仍可访问 | 原文件被删除，软链接**失效** |
| 访问速度 | **快**（直接找到 inode） | **慢**（要按路径逐级查找，多次磁盘 I/O） |
| 跨文件系统 | ❌ 不能（inode 号只在一个文件系统内有效） | ✅ 可以，甚至可以链接网络上的文件 |
| 链接目录 | 一般不允许 | 可以 |

✏️ **例**：文件 F 的 count = 1。用户 A 为 F 建立硬链接 F1，用户 B 为 F 建立软链接 F2。
- 建立 F1 后，F 的 count = **2**；建立 F2 后，count 仍为 **2**，F2 有自己的 inode（count = 1）
- 此后删除 F：count = **1**，文件没有真正删除，**F1 仍可正常访问**；**F2 失效**（路径 F 已不存在）

## 六、文件保护（⭐）

### 📐 1. 口令保护
为文件设置一个**口令**，用户访问文件时需要提供口令。
- ✅ 保存口令的空间开销不多，验证口令的时间开销也很小
- ❌ 正确的“口令”存放在**系统内部**，不够安全

### 📐 2. 加密保护
用一个“**密码**”对文件进行**加密**，访问文件时需要提供正确的密码才能正确解密。
- ✅ **保密性强**，不需要在系统中存储“密码”
- ❌ 编码/译码（加密/解密）要花费一定时间

### 📐 3. 访问控制（⭐⭐）
在每个文件的 FCB（或索引结点）中增加一个**访问控制列表（ACL）**，记录各个用户可以对该文件执行哪些操作（读、写、执行、添加、删除、列表清单……）。
- 精简的访问控制列表：以“**组**”为单位，如 Linux 中把用户分为 **文件主（owner）、同组用户（group）、其他用户（others）** 三类，每类用 **rwx** 三位表示权限
  - 例：`rwxr-x---` 表示文件主可读写执行、同组用户可读和执行、其他用户无权限
- 若对某个目录进行了访问权限的控制，那也要对目录下的所有文件进行相同的访问权限控制

⚠️ 口令和密码保护是防止用户文件被他人**存取或窃取**，而**没有控制用户对文件的访问类型**；访问控制可以控制**访问类型**。

---

## ⚠️ 易错点

1. **一个 FCB 就是一个目录项**；引入索引结点后，目录项 = **文件名 + 索引结点号**
2. 文件数量上限由**索引结点号的位数**决定（2020 年第 31 题）
3. 查找次数：目录块数 n，平均 (n + 1)/2；用索引结点还要**再读一次索引结点**
4. **系统打开文件表只有一张**，每个打开的文件一个表项（含**打开计数**）；**读写指针在进程打开文件表**中
5. 关闭文件：打开计数 − 1，**为 0 才删除**系统打开文件表项
6. **打开计数 ≠ 链接计数**：前者记录打开该文件的进程数（内存），后者记录硬链接数（磁盘 inode）
7. 新建文件时，采用索引结点方式，访问权限写在**索引结点**中，不写在目录项中
8. 删除文件**不负责删除**它的快捷方式（软链接）
9. 硬链接共享 inode，count + 1；软链接是新文件，原文件删除后失效
10. 相对路径可以**减少磁盘 I/O**
11. 索引顺序文件（N 条记录）平均查找 ≈ √N 次

## 🏋️ 课后练习

1. 某文件系统 FCB 占 128B，盘块 2KB，某目录有 1600 个文件。(1) 直接用 FCB 作目录项，查找一个文件平均启动磁盘几次？(2) 改用索引结点，目录项 16B（文件名 14B + inode 号 2B），平均启动磁盘几次？
2. 进程 A 以只读方式、进程 B 以读写方式打开同一文件 F。系统打开文件表中有几个 F 的表项？F 的打开计数是多少？A、B 的读写指针是否相同？A 关闭 F 后呢？
3. 某文件的索引结点中链接计数为 3，表示什么？用户删除其中一个目录项后，文件会被删除吗？
4. 一个有 90000 条记录的顺序文件，改成索引顺序文件后平均查找次数约为多少？
5. 判断：(a) 软链接文件被删除时，原文件也被删除；(b) 硬链接可以跨文件系统建立；(c) 使用相对路径可以减少磁盘访问次数。

<details>
<summary>📖 答案</summary>

1. (1) 目录 1600 × 128B = 200KB = 100 块，平均 (1 + 100)/2 = **50.5 次**；(2) 1600 × 16B = 25600B = 12.5 → 13 块，平均 (1 + 13)/2 = 7，再读 1 次 inode，共 **8 次**
2. 系统打开文件表中 **1 个**表项，打开计数 = **2**；读写指针**各自独立**（在各自的进程打开文件表中），可以不同；A 关闭后打开计数 = **1**，表项仍保留
3. 有 **3 个目录项**（硬链接）指向该索引结点；删除一个后 count = 2，文件**不会被删除**
4. √90000 = 300，平均约 **300 次**（150 + 150）
5. (a) **错**；(b) **错**；(c) **对**
</details>
