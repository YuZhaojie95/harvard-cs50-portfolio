## 一、内存管理的概念与功能（⭐）

### 📐 为什么需要内存管理
多道程序环境下，多个程序同时在内存中运行，需要 OS 对内存进行合理的划分和动态分配。

### 📐 内存管理的主要功能
1. **内存空间的分配与回收**：由 OS 完成主存空间的分配和管理
2. **地址转换**：把程序中的**逻辑地址**转换为内存中的**物理地址**
3. **内存空间的扩充**：利用**虚拟存储技术**或**自动覆盖技术**，从**逻辑上**扩充内存
4. **内存共享**：允许多个进程访问内存的同一部分（如共享代码）
5. **存储保护**：保证各道作业在各自的存储空间内运行，**互不干扰**

## 二、程序的链接与装入（⭐⭐）

### 📐 从源程序到进程
```
源程序 ──编译──► 目标模块 ──链接──► 装入模块 ──装入──► 内存中的进程
 .c      编译程序  .o（多个）  链接程序  可执行文件  装入程序
```
1. **编译**：由编译程序把用户源代码编译成若干个**目标模块**。每个模块都从地址 **0** 开始编址（**相对地址/逻辑地址**）
2. **链接**：由链接程序把一组目标模块以及所需的**库函数**链接在一起，形成一个完整的**装入模块**，形成**完整的逻辑地址空间**
3. **装入**：由装入程序把装入模块**装入内存**运行

### 📐 三种链接方式
| 方式 | 何时链接 | 特点 |
|---|---|---|
| **静态链接** | 程序**运行之前**，把各目标模块及库函数链接成一个完整的可执行程序，以后**不再拆开** | 简单；可执行文件大；库更新后要重新链接 |
| **装入时动态链接** | 在**装入内存时**，**边装入边链接** | 便于修改和更新，便于实现目标模块的共享 |
| **运行时动态链接** | 在程序**执行中需要**某目标模块时，才对它进行链接 | **加快装入过程**，**节省内存空间**；凡执行过程中未用到的模块都不会被调入和链接。如 Windows 的 DLL、Linux 的 .so |

### 📐 三种装入方式（⭐⭐⭐）
| 方式 | 地址转换时机 | 特点 |
|---|---|---|
| **绝对装入** | **编译时**就知道程序将驻留在内存的什么位置，编译程序直接产生**绝对地址** | 只适用于**单道程序**环境；程序中的地址必须与实际内存地址完全相同 |
| **可重定位装入（静态重定位）** | **装入时**，由装入程序对目标程序中的指令和数据地址进行修改（逻辑地址 → 物理地址），**一次完成**，之后不再改变 | 适用于多道程序环境；作业装入时必须**一次分配全部内存**，否则不能装入；**运行期间不能移动**，也不能再申请内存 |
| **动态运行时装入（动态重定位）** | 装入内存后**并不立即转换**，而是把地址转换推迟到**程序真正执行时**才进行。装入内存后所有地址**仍是逻辑地址** | 需要**重定位寄存器**的硬件支持；**程序可以在内存中移动**；可以把程序分配到**不连续**的存储区；可以只装入部分代码就运行；便于共享 |

🧒 **比喻**：
- 绝对装入：出生时就确定了**一辈子**住几号房
- 静态重定位：搬进公寓时，把所有写着“3 号”的地方**一次性**改成“503 号”，之后不能换房
- 动态重定位：门上始终写“3 号”，每次快递员（CPU）来找你，**前台**（重定位寄存器）当场帮他加上“500”——你随时可以换房，只需通知前台

### 📐 逻辑地址与物理地址
- **逻辑地址（相对地址）**：编译后每个目标模块都从 0 开始编址；链接后形成的地址也是逻辑地址。**用户程序和程序员只需知道逻辑地址**
- **物理地址（绝对地址）**：内存中物理单元的地址，是地址转换的**最终地址**
- **地址重定位**：把逻辑地址转换为物理地址的过程

动态重定位的地址转换（硬件完成）：
```
物理地址 = 逻辑地址 + 重定位寄存器（基址寄存器）的值
```

⚠️ 操作系统通过**内存管理部件（MMU）**把进程使用的逻辑地址转换为物理地址。

### 📐 进程的内存映像
（第 3 课已讲）代码段、数据段（全局变量、静态变量）、**堆**（malloc 动态分配，向高地址增长）、**栈**（局部变量、函数调用，向低地址增长）、**内核区**。

## 三、内存保护（⭐⭐）

保证每个进程只能访问**自己的内存空间**。两种方法：

### 📐 方法 1：上、下限寄存器
在 CPU 中设置一对**上、下限寄存器**，存放用户作业在主存中的上限和下限地址。每当 CPU 要访问一个地址时，分别和两个寄存器的值比较，判断有无越界。

### 📐 方法 2：重定位寄存器 + 界地址寄存器（⭐⭐⭐）
- **重定位寄存器（基址寄存器）**：存放进程的**最小物理地址**
- **界地址寄存器（限长寄存器）**：存放进程的**最大逻辑地址**（即进程的长度）
```
          逻辑地址
             │
             ▼
     ┌── < 界地址寄存器？──┐
     │否                  │是
     ▼                    ▼
  越界中断          + 重定位寄存器
                          │
                          ▼
                       物理地址 ──► 内存
```
1. 先把逻辑地址与**界地址寄存器**比较，若 **≥ 界地址**，产生**越界中断**
2. 若未越界，加上**重定位寄存器**的值得到物理地址

⚠️ 注意：
- **界地址寄存器与逻辑地址比较**（不是与物理地址比较）
- 加载重定位寄存器和界地址寄存器的指令是**特权指令**，只有 OS 内核才能加载，用户程序不能修改
- 进程切换时，OS 把新进程的基址和界限值装入这两个寄存器

📝 **真题（2009 年真题）**：分区分配内存管理方式的主要保护措施是：A. 界地址保护　B. 程序代码保护　C. 数据保护　D. 栈保护
→ **A**

✏️ **例**：某进程的重定位寄存器值为 **10000**，界地址寄存器值为 **5000**。
- 逻辑地址 **3000** → 3000 < 5000，不越界 → 物理地址 = 10000 + 3000 = **13000**
- 逻辑地址 **6000** → 6000 ≥ 5000 → **越界中断**

## 四、覆盖与交换（⭐）

早期内存很小，程序比内存大怎么办？——**内存扩充**技术。

### 📐 覆盖技术
**把用户空间分成一个固定区和若干个覆盖区**：
- **固定区**：放经常活跃的部分（如 main 函数），**不会被调出**
- **覆盖区**：放即将要访问的段，其余段放在外存中；需要时**调入覆盖区，替换**覆盖区中原有的段
- 🧒 比喻：一张小书桌（覆盖区），不同时期用的书轮流放上来
- 缺点：**对用户不透明**，必须由**程序员声明覆盖结构**，增加了编程负担
- 覆盖是在**同一个程序或进程**中进行的；已被淘汰

### 📐 交换技术（⭐⭐）
内存空间紧张时，系统把内存中某些进程**暂时换出到外存**，把外存中某些已具备运行条件的进程**换入内存**（进程在内存与磁盘间**动态调度**）。
- **中级调度**就是交换技术的体现
- 换出的进程处于**挂起态**
- 交换的对象是**整个进程**（或其一部分）
- 通常把磁盘空间分为**文件区**和**对换区**：
  - **文件区**：存放文件，追求**存储空间利用率**，采用**离散分配**方式
  - **对换区**：存放被换出的进程数据，追求**换入换出速度**，采用**连续分配**方式。**对换区的 I/O 速度比文件区快**
- 何时交换：许多进程运行且内存吃紧时进行；系统负荷降低时暂停
- 换出哪个：优先换出**阻塞进程**、**优先级低**的进程；（为了防止优先级低的进程在被调入内存后很快又被换出，有的系统还会考虑进程在内存中的驻留时间）
- ⚠️ **PCB 会常驻内存**，不会被换出

### 📐 覆盖与交换的区别
| | 覆盖 | 交换 |
|---|---|---|
| 对象 | **同一个程序或进程**中的段 | **不同进程（或作业）**之间 |
| 透明性 | 对用户**不透明**（程序员要设计覆盖结构） | 对用户**透明**（由 OS 完成） |
| 现状 | 已淘汰 | 仍在使用（与虚拟内存结合） |

## 五、连续分配管理方式（⭐⭐⭐）

**连续分配**：为一个用户程序分配**一个连续的内存空间**。

### 📐 1. 单一连续分配
内存分为**系统区**（低地址，放 OS）和**用户区**。用户区内存中**只有一道**用户程序，独占整个用户区。
- ✅ 实现简单；**无外部碎片**；可以采用覆盖技术扩充内存；不一定需要内存保护
- ❌ 只能用于**单用户、单任务**的 OS；**有内部碎片**；存储器利用率极低

### 📐 2. 固定分区分配
把用户空间划分为若干个**固定大小**的区域，每个分区只装入**一道**作业。
- **分区大小相等**：缺乏灵活性，适合控制多个相同对象的场合
- **分区大小不等**：划分为多个较小的、适量中等的、少量大的分区
- 用**分区说明表**记录每个分区的大小、起始地址、状态（是否已分配）
- ✅ 实现简单，**无外部碎片**
- ❌ 程序可能太大而放不进任何一个分区，只能用覆盖技术
- ❌ 程序小于分区时，分区剩余部分被浪费 → **内部碎片**，内存利用率低

### 📐 3. 动态分区分配（可变分区分配）（⭐⭐⭐）
**不预先划分**内存，而是在进程**装入内存时**，根据进程的**实际需要**，动态地为之分配内存，使分区的大小**正好适合**进程的需要。
- 分区的大小和数目是**可变**的
- ✅ **没有内部碎片**
- ❌ 会产生**外部碎片**：随着进程的装入和撤销，内存中出现许多**小的空闲分区**，它们都太小，无法利用

#### 记录空闲分区的数据结构
- **空闲分区表**：每个空闲分区一个表项（分区号、分区大小、起始地址、状态）
- **空闲分区链**：每个空闲分区的起始部分和末尾部分分别设置前向指针和后向指针

#### 内部碎片 vs 外部碎片（⭐⭐⭐）
| | 内部碎片 | 外部碎片 |
|---|---|---|
| 位置 | 分配给某进程的内存区域中，**没有被用上**的部分 | 内存中的某些**空闲分区太小**，难以利用 |
| 属于谁 | **已分配**给进程（在分区内部） | **未分配**（在分区之外） |
| 产生于 | 单一连续、**固定分区**、**分页**（最后一页） | **动态分区**、**分段** |

🧒 比喻：
- 内部碎片：你订了一个 4 人间，只住了 3 个人，空出的那张床（**分给你了但没用**）
- 外部碎片：酒店里零零散散空着很多单人间，但一个 4 人的团来了，**哪个房间都住不下**

#### 紧凑（拼接）技术
解决外部碎片：OS 不时地对进程进行**移动和整理**，把分散的小空闲分区**拼接**成一个大的空闲分区。
- 需要**动态重定位**寄存器的支持（程序移动后只需修改重定位寄存器）
- 相对**费时**

### 📐 动态分区的分配算法（⭐⭐⭐）
当很多个空闲分区都能满足需求时，选哪个？

| 算法 | 思想 | 空闲分区排列 | 优点 | 缺点 |
|---|---|---|---|---|
| **首次适应（First Fit）** | 从**头**开始查找，找到**第一个**能满足要求的空闲分区 | 按**地址递增** | 综合看**性能最好**，**算法开销小**（回收后一般不需要对空闲分区队列重新排序）；保留了高地址部分的大空闲区 | 低地址部分会出现很多小碎片，每次查找都要经过这些分区，增加开销 |
| **最佳适应（Best Fit）** | 找**能满足要求的最小**的空闲分区 | 按**容量递增** | 能更多地留下大的连续空间 | 每次都选最小的分区进行分配，会留下越来越多**很小的、难以利用的碎片**，**外部碎片最多**；算法开销大（回收后要重新排序） |
| **最坏适应（Worst Fit）** | 找**最大**的空闲分区 | 按**容量递减** | 减少难以利用的小碎片 | 很快把大分区用完，后面大进程到来时**没有大分区**可用；算法开销大 |
| **邻近适应（Next Fit，循环首次适应）** | 从**上次查找结束的位置**开始，找第一个能满足的 | 按地址递增（**循环链表**） | 空闲分区分布更均匀，查找开销小 | 导致**高地址**的大分区也被用完；性能不如首次适应 |

🧒 记忆：
- **首次**：从头找，第一个合适的就用
- **最佳**：找“刚好够”的，最省——但留下一堆小渣
- **最坏**：找最大的，切一块——留下的还挺大，但大分区很快被用完
- **邻近**：接着上次的位置找

📌 **综合性能：首次适应算法最好**；最佳适应算法**并不是最佳的**（外部碎片最多）！

### ✏️ 例：四种算法对比
内存中空闲分区（按地址顺序）：**100KB、500KB、200KB、300KB、600KB**。依次到达 **212KB、417KB、112KB、426KB** 的进程。

**首次适应**：
- 212KB → 第一个 ≥ 212 的是 **500**，分配后剩 288。空闲：100、288、200、300、600
- 417KB → 从头找：100 ✗、288 ✗、200 ✗、300 ✗、**600** ✓，剩 183。空闲：100、288、200、300、183
- 112KB → 100 ✗、**288** ✓，剩 176。空闲：100、176、200、300、183
- 426KB → 都不够 → **等待**

**最佳适应**：
- 212KB → 能满足的最小是 **300**，剩 88。空闲：100、500、200、88、600
- 417KB → 最小的是 **500**，剩 83。空闲：100、83、200、88、600
- 112KB → 最小的是 **200**，剩 88。空闲：100、83、88、88、600
- 426KB → **600**，剩 174 ✓（**全部分配成功**）

**最坏适应**：
- 212KB → 最大 **600**，剩 388。空闲：100、500、200、300、388
- 417KB → 最大 **500**，剩 83。空闲：100、83、200、300、388
- 112KB → 最大 **388**，剩 276。空闲：100、83、200、300、276
- 426KB → 最大才 300 → **等待**

📝 **真题（2010 年真题）**：某基于动态分区存储管理的计算机，其主存容量为 55MB（初始为空），采用**最佳适配（Best Fit）**算法，分配和释放的顺序为：分配 15MB，分配 30MB，释放 15MB，分配 8MB，分配 6MB，此时主存中**最大空闲分区**的大小是：A. 7MB　B. 9MB　C. 10MB　D. 15MB
1. 分配 15MB：[0, 15) 已用，空闲 [15, 55) = 40MB
2. 分配 30MB：[15, 45) 已用，空闲 [45, 55) = **10MB**
3. 释放 15MB：空闲 [0, 15) = **15MB** 和 [45, 55) = **10MB**
4. 分配 8MB（最佳适应，选能满足的**最小**的）→ 选 **10MB** 分区，剩 **2MB**。空闲：15MB、2MB
5. 分配 6MB → 2MB 不够，选 **15MB**，剩 **9MB**。空闲：9MB、2MB
6. 最大空闲分区 **9MB** → 选 **B**

### 📐 动态分区的回收（⭐⭐）
进程运行完毕释放内存时，根据回收区的**首地址**，从空闲分区表中找到相应的插入点。有 4 种情况：
| 情况 | 处理 | 空闲分区数变化 |
|---|---|---|
| ① 回收区与**前一个**空闲分区相邻 | **合并**，修改前一个分区的**大小** | 不变 |
| ② 回收区与**后一个**空闲分区相邻 | **合并**，修改后一个分区的**起始地址和大小** | 不变 |
| ③ 回收区与**前、后两个**空闲分区都相邻 | **三个合并**，删除后一个分区的表项，修改前一个的大小 | **减 1** |
| ④ 回收区**不与**任何空闲分区相邻 | 新建一个空闲分区表项 | **加 1** |

🧒 “**相邻就合并**”——把相邻的空房间打通变成大房间。

## 六、连续分配方式对比

| 方式 | 内部碎片 | 外部碎片 | 多道 | 特点 |
|---|---|---|---|---|
| 单一连续 | 有 | 无 | ❌ | 最简单 |
| 固定分区 | **有** | 无 | ✅ | 分区大小固定 |
| 动态分区 | **无** | **有** | ✅ | 按需分配，需紧凑 |

连续分配的根本问题：**要求进程占用一块连续的内存**，要么浪费（内部碎片），要么零碎（外部碎片）。
→ 解决办法：**离散分配**——下一课的**分页**和**分段**。

---

## ⚠️ 易错点

1. 编译后形成**逻辑地址**（从 0 开始）；**运行时动态链接**最节省内存
2. **动态重定位**：地址转换推迟到**执行时**，需要**重定位寄存器**；程序可在内存中移动
3. **静态重定位**：装入时一次转换，**运行期间不能移动**
4. 内存保护：**界地址寄存器与逻辑地址比较**，重定位寄存器用来加
5. 覆盖在**同一程序内**，对用户**不透明**；交换在**进程之间**，对用户透明
6. 对换区用**连续分配**，速度比文件区快
7. **固定分区有内部碎片**，**动态分区有外部碎片**
8. **首次适应综合性能最好**；最佳适应外部碎片最多；最坏适应让大分区迅速耗尽
9. 最佳适应按**容量递增**排列，最坏适应按**容量递减**排列，首次/邻近按**地址递增**
10. 回收时与前后都相邻，空闲分区数**减 1**；都不相邻**加 1**

## 📋 本课小结

| 知识点 | 要点 |
|---|---|
| 链接 | 静态、装入时动态、运行时动态 |
| 装入 | 绝对（编译时）、静态重定位（装入时）、动态重定位（运行时，重定位寄存器） |
| 保护 | 上下限寄存器；重定位寄存器 + 界地址寄存器 |
| 扩充 | 覆盖（程序内、不透明）、交换（进程间、透明） |
| 连续分配 | 单一连续、固定分区（内碎片）、动态分区（外碎片） |
| 分配算法 | 首次（最好）、最佳（碎片多）、最坏、邻近 |
| 回收 | 相邻就合并，4 种情况 |

## 🏋️ 课后练习

1. 某进程的重定位寄存器内容为 4000，界地址寄存器内容为 1500。逻辑地址 1000、1500、2000 分别对应什么？
2. 在动态分区分配中，当前空闲分区（按地址）为 [10KB, 4KB, 20KB, 18KB, 7KB, 9KB, 12KB, 15KB]。依次申请 12KB、10KB、9KB，分别用首次适应、最佳适应、最坏适应，写出每次分配的分区。
3. 判断：(a) 最佳适应算法的外部碎片最少；(b) 采用静态重定位的程序在执行过程中可以移动；(c) 分页存储管理会产生内部碎片。
4. 一个回收区与上下两个空闲分区都相邻，回收后空闲分区数如何变化？
5. 为什么动态分区需要紧凑技术？紧凑需要什么硬件支持？

<details>
<summary>📖 答案</summary>

1. 1000 < 1500 → 物理地址 **5000**；1500 ≥ 1500 → **越界**；2000 → **越界**
2. 首次适应：12KB → **20KB**（剩 8）；10KB → **10KB**；9KB → **18KB**（剩 9）。
   最佳适应：12KB → **12KB**；10KB → **10KB**；9KB → **9KB**。
   最坏适应：12KB → **20KB**（剩 8）；10KB → **18KB**（剩 8）；9KB → **15KB**（剩 6）
3. (a) **错**，最佳适应外部碎片最多；(b) **错**；(c) **对**（最后一页可能装不满）
4. 减少 **1** 个（三个合并为一个）
5. 动态分区会产生大量外部碎片，单个碎片太小无法利用，但总和可能很大；紧凑把它们拼接成大的空闲区。紧凑需要移动进程，移动后进程地址改变，需要**动态重定位（重定位寄存器）**的支持
</details>
