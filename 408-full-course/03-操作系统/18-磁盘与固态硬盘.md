## 🚪 课前引入

磁盘就像一台**老式唱片机**：盘片在不停地转，磁头（唱针）要先**移动到正确的圈上**（寻道），再**等要读的那一段转到磁头下面**（旋转延迟），然后才能**读出数据**（传输）。

其中**移动磁头最慢**（机械运动）。如果有一堆读写请求，按什么顺序处理才能让磁头**少跑路**？这就是**磁盘调度**要解决的问题。

## 一、磁盘的结构（复习）（⭐）

组成原理第 9 课已经讲过，这里简单回顾：
- **磁盘**：表面涂有磁性物质的圆形盘片，通过一个称为“**磁头**”的导体线圈从磁盘存取数据
- **磁道**：磁盘的盘面被划分成一个个**同心圆**，每个圆就是一个磁道
- **扇区**：一个磁道又被划分成一个个**扇区**，每个扇区就是一个“**磁盘块**”，**各个扇区存放的数据量相同**（如 512B、4KB）。最内侧磁道上的扇区面积最小，因此**数据密度最大**
- **柱面**：所有盘面中**相对位置相同的磁道**组成柱面
- 可以用（**柱面号，盘面号，扇区号**）来定位任意一个“磁盘块”

📐 **磁盘的分类**：
- **活动头磁盘**：磁头可以移动（需要寻道）
- **固定头磁盘**：每个磁道有一个磁头（不需要寻道）
- **可换盘磁盘**、**固定盘磁盘**

### 📐 读取一个块的步骤
1. 根据“柱面号”**移动磁臂**，让磁头指向指定柱面
2. **激活**指定盘面对应的磁头
3. 磁盘旋转的过程中，指定的扇区会从磁头下面划过，这样就完成了对指定扇区的读/写

## 二、磁盘的读写时间（⭐⭐⭐）

```
一次磁盘读/写操作的时间 T_a = 寻道时间 T_s + 延迟时间 T_r + 传输时间 T_t
```
### 📐 1. 寻道时间 T_s
在读/写数据前，**将磁头移动到指定磁道**所花的时间。
- 启动磁头臂是需要时间的，假设耗时为 s
- 移动磁头也是需要时间的，假设磁头匀速移动，每跨越一个磁道耗时为 m，总共需要跨越 n 条磁道
- **T_s = s + m × n**
- 寻道时间**与磁盘调度算法直接相关**（算法决定 n 的大小）

### 📐 2. 延迟时间（旋转延迟时间）T_r
通过**旋转磁盘**，使磁头定位到目标**扇区**所需要的时间。
- 设磁盘转速为 r（单位：转/秒，或转/分），则**平均所需的延迟时间 T_r = (1/2) × (1/r) = 1/(2r)**
- 1/r 就是转一圈需要的时间。找到目标扇区平均需要转**半圈**，因此再乘以 1/2
- 典型的硬盘转速为 5400 转/分或 **7200 转/分**
- ✏️ 7200 转/分 = 120 转/秒，转一圈 1/120 s ≈ 8.33ms，**平均延迟 ≈ 4.17ms**

### 📐 3. 传输时间 T_t
从磁盘**读出或向磁盘写入数据**所经历的时间。
- 设磁盘转速为 r，此次读/写的字节数为 b，每个磁道上的字节数为 N
- 每个磁道要可存 N 字节的数据，因此 b 字节的数据需要 b/N 个磁道才能存储。而读/写一个磁道所需的时间刚好又是转一圈所需要的时间 1/r
- **T_t = (1/r) × (b/N) = b/(rN)**
- 若读一个扇区，传输时间 = 转一圈的时间 / 每磁道的扇区数

✏️ **例**：某磁盘转速 7200 转/分，平均寻道时间 5ms，每磁道 500 个扇区，读一个扇区的平均访问时间？（这正是 **2022 年第 44 题**）
- 延迟：60 / 7200 / 2 s ≈ **4.17ms**
- 传输：(60 / 7200) / 500 s ≈ **0.017ms**
- 总时间 ≈ 5 + 4.17 + 0.017 ≈ **9.19ms**

📌 **延迟时间和传输时间都与磁盘转速相关，且为线性相关**。而转速是硬件的固有属性，因此**操作系统也无法优化延迟时间和传输时间**，操作系统能优化的只有**寻道时间**（通过调度算法）。

## 三、磁盘调度算法（⭐⭐⭐）

统一例题：磁盘有 **200 个磁道（0~199）**，磁头当前在 **53** 号磁道，并且**向磁道号增加的方向**移动。请求队列（按到达顺序）：**98, 183, 37, 122, 14, 124, 65, 67**。

### 📐 1. 先来先服务（FCFS）
根据进程**请求访问磁盘的先后顺序**进行调度。
```
53 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67
```
移动距离 = 45 + 85 + 146 + 85 + 108 + 110 + 59 + 2 = **640**
- ✅ **公平**；如果请求访问的磁道比较集中的话，算法性能还算过得去
- ❌ 如果有大量进程竞争使用磁盘，请求访问的磁道很分散，则 FCFS 在性能上很差，**寻道时间长**

### 📐 2. 最短寻找时间优先（SSTF）
**优先处理的磁道是与当前磁头最近的磁道**。可以保证每次的寻道时间最短，但是**并不能保证总的寻道时间最短**（其实就是**贪心**算法的思想，只是选择眼前最优，但是总体未必最优）。
```
53 → 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183
```
- 53 最近的是 65（距离 12），然后 67（2），然后 37（30，比 98 的 31 近），然后 14（23），然后 98（84），122、124、183
- 移动距离 = 12 + 2 + 30 + 23 + 84 + 24 + 2 + 59 = **236**
- ✅ 性能较好，平均寻道时间短
- ❌ 可能产生“**饥饿**”现象：如果不断有磁头附近的新请求到来，远处的请求可能永远得不到服务
- ⚠️ 距离相等时，题目一般会说明往哪边走（或按磁头当前的移动方向）

📝 **真题（2021 年第 26 题）**：某系统中磁盘的磁道数为 200（0~199），磁头当前在 **184** 号磁道上。用户进程提出的磁盘访问请求对应的磁道号依次为 **184, 187, 176, 182, 199**。若采用最短寻道时间优先调度算法（SSTF）完成磁盘访问，则磁头移动的距离（磁道数）是：A. 37　B. 38　C. 41　D. 42
- 184（距离 0，直接服务）
- 当前 184：182（距离 2）vs 187（距离 3）→ **182**
- 当前 182：187（距离 5）vs 176（距离 6）→ **187**
- 当前 187：176（距离 11）vs 199（距离 12）→ **176**
- 当前 176：**199**（距离 23）
- 总距离 = 0 + 2 + 5 + 11 + 23 = **41** → 选 **C**

### 📐 3. 扫描算法（SCAN，电梯算法）
SSTF 产生饥饿的原因在于：磁头有可能在一个小区域内来回移动。为了防止这个问题，可以规定：**只有磁头移动到最外侧磁道的时候才能往内移动，移动到最内侧磁道的时候才能往外移动**。
```
53 → 65 → 67 → 98 → 122 → 124 → 183 → [199] → 37 → 14
```
- 向磁道号增大方向走到**尽头 199**，再掉头
- 移动距离 = (199 − 53) + (199 − 14) = 146 + 185 = **331**
- ✅ 性能较好，平均寻道时间较短，**不会产生饥饿**现象
- ❌ 只有到达最边上的磁道时才能改变磁头移动方向，事实上，处理了 183 号磁道的访问请求之后就不需要再往右移动磁头了
- ❌ SCAN 算法对于各个位置磁道的**响应频率不平均**（如：假设此时磁头正在往右移动，且刚处理过 90 号磁道，那么下次处理 90 号磁道的请求就需要等磁头移动很长一段距离；而响应了 184 号磁道的请求之后，很快又可以再次响应 184 号磁道的请求了）

### 📐 4. LOOK 调度算法
**SCAN 的改进**：如果在磁头移动方向上**已经没有别的请求**，就可以**立即改变磁头移动方向**（边移动边观察，因此叫 LOOK）。
```
53 → 65 → 67 → 98 → 122 → 124 → 183 → 37 → 14
```
- 移动距离 = (183 − 53) + (183 − 14) = 130 + 169 = **299**

### 📐 5. 循环扫描算法（C-SCAN）
SCAN 算法对于各个位置磁道的响应频率不平均，而 C-SCAN 算法就是为了解决这个问题。规定**只有磁头朝某个特定方向移动时才处理磁道访问请求**，而**返回时直接快速移动至起始端而不处理任何请求**。
```
53 → 65 → 67 → 98 → 122 → 124 → 183 → [199] → [0] → 14 → 37
```
- 移动距离 = (199 − 53) + (199 − 0) + (37 − 0) = 146 + 199 + 37 = **382**（返回的距离一般**计入**总移动距离，题目若有说明以题目为准）
- ✅ 比起 SCAN，对于各个位置磁道的**响应频率很平均**
- ❌ 只有到达最边上的磁道时才能改变磁头移动方向；并且磁头返回时不一定需要返回到最边缘的磁道上

### 📐 6. C-LOOK 调度算法
**C-SCAN 的改进**：如果磁头移动的方向上已经没有磁道访问请求了，就可以立即让磁头返回，并且磁头**只需要返回到有磁道访问请求的位置**即可。
```
53 → 65 → 67 → 98 → 122 → 124 → 183 → 14 → 37
```
- 移动距离 = (183 − 53) + (183 − 14) + (37 − 14) = 130 + 169 + 23 = **322**

### 📐 算法对比（⭐⭐⭐）
| 算法 | 本例移动距离 | 优点 | 缺点 |
|---|---|---|---|
| FCFS | 640 | 公平 | 寻道时间长 |
| SSTF | 236 | 每次寻道最短，性能较好 | **可能饥饿**；总体不一定最优 |
| SCAN | 331 | 不饥饿 | 要走到尽头；响应频率不均 |
| LOOK | 299 | 不必走到尽头 | 响应频率不均 |
| C-SCAN | 382 | 响应频率平均 | 要走到尽头并返回起点 |
| C-LOOK | 322 | 响应频率平均，不必走到尽头 | —— |

⚠️ **做题注意**：
1. 看清**磁头当前位置**和**移动方向**
2. SCAN/C-SCAN 要不要走到**尽头**（0 或 199）？LOOK/C-LOOK 不用
3. C-SCAN/C-LOOK 的**返回距离**是否计入（一般计入）
4. 若题目没说 SCAN，只说“电梯调度”，一般按 **LOOK** 处理（很多教材中“电梯算法”指的就是走到最后一个请求就掉头）——看题目描述

## 四、减少延迟时间的方法（⭐）

### 📐 问题
假设要连续读取橙色区域的 2、3、4 号扇区：磁头读取一块的内容（也就是一个扇区的内容）后，**需要一小段时间处理**（如把数据从控制器缓冲区传到内存），而**盘片又在不停地旋转**。因此，如果 2、3 号扇区相邻着排列，则读完 2 号扇区后**无法连续不断地读入 3 号扇区**，必须等盘片继续旋转，3 号扇区再次划过磁头，才能完成扇区读入——**转一整圈**！

### 📐 方法 1：交替编号
若采用**交替编号**的策略，即**让逻辑上相邻的扇区在物理上有一定的间隔**，可以使读取连续的逻辑扇区所需要的延迟时间更小。
```
物理位置：  0  1  2  3  4  5  6  7
逻辑扇区号：0  4  1  5  2  6  3  7      （间隔 1 个扇区编号）
```
- 读完逻辑扇区 0 后，磁头经过物理位置 1（逻辑 4）的时间正好用来处理数据，接着就读到逻辑扇区 1

### 📐 方法 2：错位命名
磁盘地址结构为什么是（**柱面号，盘面号，扇区号**），而不是（盘面号，柱面号，扇区号）？
- 读取地址连续的磁盘块时，采用（柱面号，盘面号，扇区号）的地址结构**可以减少磁头移动消耗的时间**：连续的块先放满**同一柱面的所有盘面**，再换下一个柱面——同一柱面的不同盘面切换只需**激活不同的磁头**（电子切换，极快），不需要移动磁臂

**错位命名**：让相邻盘面的扇区编号“错位”：
- 若相邻的盘面相对位置相同处扇区编号相同，则读完 0 号盘面的最后一个扇区后，切换到 1 号盘面，1 号盘面的 0 号扇区刚刚转过去了，又要等一圈
- 错位命名：1 号盘面的 0 号扇区相对于 0 号盘面的 0 号扇区**错开一个位置**，这样激活 1 号盘面磁头的时间里，恰好转到 1 号盘面的 0 号扇区

## 五、磁盘的管理（⭐）

### 📐 1. 磁盘初始化
1. **低级格式化（物理格式化）**：将磁盘的各个磁道**划分为扇区**。一个扇区通常可分为**头、数据区域（如 512B）、尾**三个部分组成。管理扇区所需要的各种数据结构一般存放在头、尾两个部分，包括**扇区校验码**（如奇偶校验、CRC 循环冗余校验码等，校验码用于校验扇区中的数据是否发生错误）
2. **将磁盘分区**，每个分区由若干柱面组成（即分为我们熟悉的 C 盘、D 盘、E 盘）
3. **进行逻辑格式化**，**创建文件系统**。包括创建文件系统的**根目录**、初始化存储空间管理所用的数据结构（如**位示图、空闲分区表**）

（第 2 课、2021 年第 46 题：物理格式化 → 分区 → 逻辑格式化 → 安装 OS）

### 📐 2. 引导块
- 计算机开机时需要进行一系列初始化的工作，这些初始化工作是通过执行**初始化程序（自举程序）**完成的
- 初始化程序可以放在 **ROM（只读存储器）**中。ROM 中的数据在出厂时就写入了，并且以后不能再修改。但若把完整的自举程序放在 ROM 中，则自举程序不方便更新
- 所以 **ROM 中只存放很小的“自举装入程序”**，开机时计算机先运行“自举装入程序”，通过执行该程序就可找到**引导块**，并将**完整的“自举程序”**读入内存，完成初始化
- **完整的自举程序放在磁盘的启动块（即引导块/启动分区）上**，启动块位于磁盘的**固定位置**。拥有启动分区的磁盘称为**启动磁盘或系统磁盘**（C 盘）

### 📐 3. 坏块的管理
**坏块**：坏了、无法正常使用的扇区（属于“硬件故障”，操作系统是无法修复的）。应该将坏块**标记出来**，以免错误地使用到它。
- 对于**简单的磁盘**，可以在逻辑格式化时（建立文件系统时）对整个磁盘进行坏块检查，标明哪些扇区是坏扇区，比如在 **FAT 表**上标明（在这种方式中，**坏块对操作系统不透明**）
- 对于**复杂的磁盘**，磁盘控制器（磁盘设备内部的一个硬件部件）会维护一个**坏块链表**。在磁盘出厂前进行低级格式化（物理格式化）时就将坏块链进行初始化。会保留一些“**备用扇区**”，用于替换坏块。这种方案称为**扇区备用**，且这种处理方式中，**坏块对操作系统透明**

## 六、固态硬盘（SSD）（⭐⭐）

### 📐 SSD 的原理与结构
- 基于**闪存**技术（NAND Flash），属于**电可擦除 ROM（EEPROM）**，没有机械部件
- **闪存翻译层（FTL）**：负责把操作系统访问的**逻辑块号映射为对应的物理地址**（逻辑块号 → 闪存芯片中的物理页）
- 一个 SSD 由若干个**闪存芯片**组成，一个闪存芯片由若干个**块**组成（每块 32~128 页，大小 16KB~512KB），**一个块由若干页组成**（每页 512B~4KB）
- **SSD 以“页”为单位读写**，相当于磁盘的“扇区”；SSD 的“块”相当于**多个扇区**

### 📐 读写性能特性（⭐⭐）
- 以**页（page）**为单位读/写
- 以**块（block）**为单位“**擦除**”，擦干净的块，其中的每页都可以写一次，读无限次
- 支持随机访问，系统给定一个逻辑地址，闪存翻译层可通过电路迅速定位到对应的物理地址
- **读快、写慢**：要写的页如果有数据，则**不能写入**，需要将块内其他页全部**复制到一个新的（擦除过的）块中**，再写入新的页
- 🧒 像一本只能用铅笔写一次的本子：要改某一页，必须把整本（块）擦干净才能重写——所以先把其他页抄到新本子上，再在新本子上写新内容

### 📐 与机械硬盘相比
- SSD **读写速度快**，**随机访问性能高**，用电路控制访问位置；机械硬盘通过移动磁臂旋转磁盘控制访问位置，有**寻道时间和旋转延迟**
- SSD **安静无噪音**、耐摔抗震、能耗低、造价更贵
- SSD 的一个“块”被**擦除次数过多**（重复写同一个块）可能会**坏掉**，而机械硬盘的扇区不会因为写的次数太多而坏掉

### 📐 磨损均衡技术（⭐⭐）
**思想：将“擦除”平均分布在各个块上，以提升使用寿命**。
- **动态磨损均衡**：写入数据时，**优先选择累计擦除次数少的新闪存块**
- **静态磨损均衡**：SSD 监测并自动进行数据分配、迁移，让**老旧的闪存块承担以读为主的储存任务**，让**较新的闪存块承担更多的写任务**（静态磨损均衡更优秀）
- 磨损均衡由 SSD 内部的**闪存翻译层（控制器固件）**实现，不是由操作系统的文件系统实现

✏️ **SSD 寿命估算**：某固态硬盘采用磨损均衡技术，大小为 1TB = 2⁴⁰ B，闪存块的擦写寿命只有 2¹⁰ 次（1000 次左右）。某男子平均每天会对该固态硬盘写 1GB = 2³⁰ B 数据。在最理想的情况下，这个固态硬盘可以用多久？
- SSD 采用磨损均衡技术，最理想情况下，SSD 中每个块被擦除的次数都是完全均衡的
- 总共可写入 2⁴⁰ × 2¹⁰ = 2⁵⁰ B
- 可用 2⁵⁰ / 2³⁰ = 2²⁰ 天 ≈ **2872 年**

📝 **真题（2025 年第 32 题）**：下列选项中，文件系统能为温彻斯特硬盘和固态硬盘提供的功能是：A. 划分扇区　B. 确定盘块大小　C. 降低寻道时间　D. 实现均衡磨损
→ **B**
- A：划分扇区是**物理格式化（低级格式化）**完成的，不是文件系统的功能
- B：**盘块（逻辑块）的大小**是在创建文件系统（逻辑格式化）时确定的，对机械硬盘和 SSD 都适用 ✓
- C：降低寻道时间只对机械硬盘（温彻斯特硬盘）有意义，而且是磁盘调度算法的功能，SSD 没有寻道
- D：均衡磨损只针对 SSD，由 SSD 的**闪存翻译层（控制器）**实现，不是文件系统的功能

---

## ⚠️ 易错点

1. 磁盘访问时间 = **寻道 + 延迟 + 传输**；OS 只能优化**寻道时间**
2. 平均旋转延迟 = **转半圈**的时间
3. **SSTF 可能饥饿**，且总距离不一定最短
4. **SCAN 要走到磁盘尽头**，LOOK 只走到最远的请求
5. **C-SCAN/C-LOOK 返回时不处理请求**；返回距离一般计入总距离
6. 注意磁头当前的**移动方向**
7. 磁盘地址（柱面号，盘面号，扇区号）的原因：**减少磁头移动**
8. 交替编号：减少**旋转延迟**
9. 物理格式化划分**扇区**；逻辑格式化创建**文件系统**（根目录、空闲管理结构）
10. SSD：**按页读写，按块擦除**；**读快写慢**；磨损均衡由 **FTL（控制器）**实现

| 知识点 | 要点 |
|---|---|
| 访问时间 | 寻道 s + m×n；延迟 1/(2r)；传输 b/(rN) |
| FCFS | 公平，慢 |
| SSTF | 最近优先，可能饥饿 |
| SCAN/LOOK | 电梯，到尽头/到最远请求再掉头 |

| 延迟优化 | 交替编号、错位命名 |
| 磁盘管理 | 物理格式化、分区、逻辑格式化；引导块；坏块 |
| SSD | FTL；页读写、块擦除；磨损均衡 |

## 🏋️ 课后练习

1. 某磁盘有 100 个柱面（0~99），磁头在 30 号柱面，正向磁道号增大的方向移动。请求序列：55, 58, 39, 18, 90, 38, 84, 5。分别用 SSTF、SCAN、LOOK、C-LOOK 求磁头移动距离。
2. 某磁盘转速 6000 转/分，每磁道 100 个扇区，平均寻道时间 4ms。读一个扇区的平均时间是多少？
3. 判断：(a) 磁盘调度可以减少旋转延迟时间；(b) SSD 以块为单位进行擦除；(c) SCAN 算法会产生饥饿；(d) 磨损均衡由操作系统的文件系统实现。
4. 为什么说 SSTF 算法“每次的寻道时间最短，但总的寻道时间不一定最短”？

<details>
<summary>📖 答案</summary>

1. 请求 {55, 58, 39, 18, 90, 38, 84, 5}，磁头 30，向大方向：
   - SSTF：30 → 38(8) → 39(1) → 55(16) → 58(3) → 84(26) → 90(6) → 18(72) → 5(13)，共 **145**（从 30 看，38 距离 8，18 距离 12，先 38）
   - SCAN：30 → 38 → 39 → 55 → 58 → 84 → 90 → 99 → 18 → 5，共 (99 − 30) + (99 − 5) = 69 + 94 = **163**
   - LOOK：30 → … → 90 → 18 → 5，共 (90 − 30) + (90 − 5) = 60 + 85 = **145**
   - C-LOOK：30 → … → 90 → 5 → 18，共 (90 − 30) + (90 − 5) + (18 − 5) = 60 + 85 + 13 = **158**
2. 转一圈 10ms，平均延迟 **5ms**；传输 10ms / 100 = **0.1ms**；总计 4 + 5 + 0.1 = **9.1ms**
3. (a) **错**，调度算法只能减少寻道时间；(b) **对**；(c) **错**；(d) **错**，由 SSD 的闪存翻译层（控制器）实现
4. SSTF 是**贪心**算法，每一步只选距离当前磁头最近的请求，是局部最优；但这样可能让磁头在某一区域来回移动，最后再长途跋涉去处理远处的请求，整体移动距离不一定是全局最短
</details>
