## 🚪 课前引入

上节课的软件和硬件方法都有一个共同的毛病：**忙等**。进不去临界区的进程在那里空转，浪费 CPU。

1965 年，荷兰计算机科学家 **Dijkstra** 提出了一种非常优雅的工具——**信号量（Semaphore）**。

🧒 **比喻：停车场的电子牌**
- 停车场门口有个电子牌，显示“**剩余车位：3**”——这就是**信号量**的值
- 来一辆车：先看牌子，有车位就进去，牌子**减 1**（**P 操作 / wait**）；没车位就在门口**排队睡觉**（阻塞，不占 CPU）
- 走一辆车：牌子**加 1**（**V 操作 / signal**）；如果门口有车在排队，就**叫醒**一辆让它进来
- 牌子显示 **−2** 是什么意思？表示没有空位，而且门口**有 2 辆车在排队**

信号量把“**检查 + 修改 + 阻塞/唤醒**”包装成**原语**（不可中断），既保证互斥，又不忙等。

## 一、信号量机制（⭐⭐⭐）

### 📐 基本概念
- **信号量**：一个变量（可以是整数，也可以是更复杂的记录型变量），表示**系统中某种资源的数量**
- 只能通过两个**标准原语**访问：
  - **wait(S)**，也记作 **P(S)**（荷兰语 proberen，“尝试”）：**申请**一个资源
  - **signal(S)**，也记作 **V(S)**（荷兰语 verhogen，“增加”）：**释放**一个资源
- **原语**：执行时不可中断（用关中断/开中断或硬件指令实现），保证了 P、V 操作的原子性

### 📐 1. 整型信号量
用一个**整数 S** 表示资源数：
```c
int S = 1;                     // 初始化资源数

void wait(int S) {             // P 操作
    while (S <= 0);            // 资源不够，一直循环等待
    S = S - 1;                 // 占用一个资源
}
void signal(int S) {           // V 操作
    S = S + 1;                 // 释放一个资源
}
```
- ✅ “检查”和“上锁”一气呵成（原语），避免了双标志法的问题
- ❌ **不满足“让权等待”**：资源不够时 while 循环**忙等**

### 📐 2. 记录型信号量（⭐⭐⭐ 考试默认）
为了解决忙等问题，增加一个**等待队列**：
```c
typedef struct {
    int value;                 // 剩余资源数
    struct process *L;         // 等待该资源的进程队列
} semaphore;

void wait(semaphore S) {
    S.value--;                 // 先减 1（申请一个）
    if (S.value < 0) {         // 减完 < 0：说明资源已经不够了
        block(S.L);            // 把自己阻塞，插入等待队列（让权等待！）
    }
}

void signal(semaphore S) {
    S.value++;                 // 先加 1（释放一个）
    if (S.value <= 0) {        // 加完仍 ≤ 0：说明有进程在等
        wakeup(S.L);           // 唤醒等待队列中的一个进程（变为就绪态）
    }
}
```

### 📐 S.value 的含义（⭐⭐⭐）
- **S.value > 0**：表示**可用资源数**
- **S.value = 0**：资源恰好用完，**没有**进程在等待
- **S.value < 0**：**|S.value|** 表示**等待该资源的进程数**（阻塞队列长度）

📐 **wait 和 signal 的判断条件**：
- wait：减 1 后 **< 0** 则阻塞
- signal：加 1 后 **≤ 0** 则唤醒

✏️ **例**：某信号量 S 初值为 3，先后有 5 个进程执行 wait(S)，然后有 1 个进程执行 signal(S)。
- 5 次 wait 后，S = 3 − 5 = **−2**，前 3 个进程获得资源，**后 2 个阻塞**
- 1 次 signal 后，S = −1 ≤ 0，**唤醒 1 个**等待进程；此时还有 **1 个**进程在等待

📐 **记录型信号量满足“让权等待”**：资源不够时进程**阻塞**，放弃 CPU。

⚠️ 考试中，**除非特别说明是“整型信号量”，一律默认为记录型信号量**。

## 二、用信号量实现互斥、同步、前驱关系（⭐⭐⭐）

### 📐 1. 实现进程互斥
1. 分析并发进程的关键活动，划定**临界区**
2. 设置**互斥信号量 mutex，初值为 1**（临界区只允许 1 个进程进入）
3. 在临界区**前**执行 **P(mutex)**，**后**执行 **V(mutex)**
```c
semaphore mutex = 1;

P1() {                         P2() {
    ...                            ...
    P(mutex);    // 加锁            P(mutex);
    临界区;                          临界区;
    V(mutex);    // 解锁            V(mutex);
    ...                            ...
}                              }
```
⚠️ 注意：
- **对不同的临界资源要设置不同的互斥信号量**
- **P、V 必须成对出现**：缺少 P 不能保证互斥；缺少 V 会导致资源永不释放，等待进程永不被唤醒

### 📐 2. 实现进程同步（⭐⭐⭐ 核心口诀：**前 V 后 P**）
要求：进程 P2 中的代码 y **必须在** P1 中的代码 x **之后**执行。
1. 设置**同步信号量 S，初值为 0**
2. 在“**前操作**”（x）**之后**执行 **V(S)**
3. 在“**后操作**”（y）**之前**执行 **P(S)**
```c
semaphore S = 0;

P1() {                         P2() {
    代码 1;                         P(S);      // 等 x 完成
    代码 x;                         代码 y;
    V(S);      // 通知：x 完成了      代码 2;
    代码 2;                         ...
}                              }
```
🧒 **为什么初值为 0？** 可以理解为：信号量 S 代表“**x 已完成**”这种“资源”，一开始没有这种资源（0 个）。P1 执行完 x 后“生产”了一个（V），P2 要“消费”它（P）才能执行 y。
- 若 P2 先运行到 P(S)：S = −1，P2 **阻塞**，等 P1 执行 V(S) 后被唤醒
- 若 P1 先执行 V(S)：S = 1，之后 P2 执行 P(S) 时 S = 0，**直接通过**

### 📐 3. 实现前驱关系（⭐⭐⭐）
**前驱图**：有向无环图，每个结点是一个操作（代码段），有向边 A → B 表示 **A 必须在 B 之前完成**。

**方法**：**每一条边**都是一个“同步关系”，为每条边设置一个**初值为 0 的同步信号量**：
- 在边的**起点**操作之后执行 **V**
- 在边的**终点**操作之前执行 **P**

📝 **真题（2020 年第 45 题，7 分）**：现有 5 个操作 A、B、C、D 和 E，操作 C 必须在 A 和 B 完成后执行，操作 E 必须在 C 和 D 完成后执行，请使用信号量的 wait()、signal() 操作（P、V 操作）描述上述操作之间的同步关系，并说明所用信号量及其初值。

前驱图：
```
A ──┐
    ├──► C ──┐
B ──┘        ├──► E
D ───────────┘
```
共 4 条边：A→C、B→C、C→E、D→E。设信号量（初值均为 **0**）：
- **SAC**：A 完成后通知 C；**SBC**：B 完成后通知 C
- **SCE**：C 完成后通知 E；**SDE**：D 完成后通知 E

```c
semaphore SAC = 0, SBC = 0, SCE = 0, SDE = 0;

A() {                    B() {                    D() {
    完成 A;                  完成 B;                  完成 D;
    signal(SAC);             signal(SBC);             signal(SDE);
}                        }                        }

C() {                    E() {
    wait(SAC);               wait(SCE);
    wait(SBC);               wait(SDE);
    完成 C;                  完成 E;
    signal(SCE);         }
}
```
（也可以只用两个信号量：C 前 wait(S1) 两次，A、B 后各 signal(S1)；E 前 wait(S2) 两次，C、D 后各 signal(S2)。初值都为 0。两种写法都对。）

📝 **真题（2022 年第 46 题，8 分）**：某进程的两个线程 T1 和 T2 并发执行 A、B、C、D、E 和 F 共 6 个操作，其中 **T1 执行 A、E 和 F**，**T2 执行 B、C 和 D**。下图表示上述 6 个操作的执行顺序所必须满足的约束：C 在 A 和 B 完成后执行，D 和 E 在 C 完成后执行，F 在 E 完成后执行。请使用信号量的 wait()、signal() 操作描述 T1 和 T2 之间的同步关系，并说明所用信号量的作用及其初值。
```
A ──┐        ┌──► D
    ├──► C ──┤
B ──┘        └──► E ──► F
```
**分析**：
- 同一个线程内的操作本来就是**顺序执行**的，不需要信号量：
  - T2：B → C → D（B→C、C→D 自然满足）
  - T1：A → E → F（E→F 自然满足）
- **跨线程**的约束才需要信号量：
  - **A → C**（A 在 T1，C 在 T2）：设 **SAC = 0**
  - **C → E**（C 在 T2，E 在 T1）：设 **SCE = 0**

```c
semaphore SAC = 0;    // 控制 A 先于 C 执行，A 完成后 signal
semaphore SCE = 0;    // 控制 C 先于 E 执行，C 完成后 signal

T1() {                        T2() {
    执行 A;                        执行 B;
    signal(SAC);  // A 已完成       wait(SAC);    // 等 A 完成
    wait(SCE);    // 等 C 完成      执行 C;
    执行 E;                        signal(SCE);  // C 已完成
    执行 F;                        执行 D;
}                             }
```
⚠️ **易错**：不要给同一线程内的顺序关系（如 E→F、B→C）也设信号量——不算错，但题目要求“描述 T1 和 T2 之间的同步关系”，多余的信号量可能被扣分。

## 三、经典同步问题 1：生产者-消费者问题（⭐⭐⭐）

### 📐 问题描述
- 一组**生产者进程**和一组**消费者进程**共享一个初始为空、大小为 **n** 的**缓冲区**
- **只有缓冲区没满时**，生产者才能把产品放入缓冲区，否则必须等待
- **只有缓冲区不空时**，消费者才能从中取出产品，否则必须等待
- 缓冲区是临界资源，**各进程必须互斥地访问**

### 📐 分析关系
1. **互斥**：生产者和消费者对缓冲区的访问互斥（生产者之间、消费者之间也互斥）
2. **同步**：
   - 缓冲区**满**时，生产者要等消费者取走产品（消费者取 → 生产者放）
   - 缓冲区**空**时，消费者要等生产者放入产品（生产者放 → 消费者取）

### 📐 设置信号量
- **mutex = 1**：互斥访问缓冲区
- **empty = n**：**空闲缓冲区**的数量
- **full = 0**：**产品（非空缓冲区）**的数量

### 📐 代码
```c
semaphore mutex = 1;
semaphore empty = n;
semaphore full = 0;

producer() {
    while (1) {
        生产一个产品;
        P(empty);          // ① 申请一个空缓冲区
        P(mutex);          // ② 进入临界区
        把产品放入缓冲区;
        V(mutex);          // 离开临界区
        V(full);           // 产品数 +1
    }
}

consumer() {
    while (1) {
        P(full);           // ③ 申请一个产品
        P(mutex);          // ④ 进入临界区
        从缓冲区取出一个产品;
        V(mutex);
        V(empty);          // 空缓冲区数 +1
        使用产品;
    }
}
```

### 📐 P 操作的顺序不能颠倒！（⭐⭐⭐）
若把生产者的 ① ② 交换（先 P(mutex) 后 P(empty)）：
- 假设缓冲区已**满**（empty = 0），生产者先 P(mutex) 成功进入，再 P(empty) → **阻塞**（但它**拿着 mutex 没放**）
- 消费者想取产品，P(full) 成功，P(mutex) → **阻塞**（mutex 被生产者占着）
- 生产者等消费者腾出空位，消费者等生产者释放 mutex → **死锁**！

同理，消费者的 ③ ④ 也不能交换（缓冲区空时会死锁）。

📌 **规则**：**实现互斥的 P 操作一定要在实现同步的 P 操作之后**。
（V 操作的顺序可以交换，不会导致阻塞。）

🧒 比喻：你要进一个房间（mutex）拿东西（full）。正确做法是**先确认有东西可拿，再进房间**；如果先进房间、锁上门，才发现没东西，你就在房间里等，而送东西的人被锁在门外——大家永远等下去。

### 📐 能否把“生产产品”“使用产品”放进临界区？
**可以但不应该**：会使临界区变长，降低并发度。临界区应该尽量**短**，只包含真正访问共享资源的代码。

## 四、经典同步问题 2：多生产者-多消费者问题（⭐⭐）

### 📐 问题描述（水果盘问题）
桌上有一个**盘子**，每次只能向其中放入**一个**水果。**爸爸**专向盘子中放**苹果**，**妈妈**专向盘子中放**橘子**；**儿子**专等着吃盘子中的**橘子**，**女儿**专等着吃盘子中的**苹果**。只有盘子为空时，爸爸或妈妈才可向盘子中放一个水果；仅当盘子中有自己需要的水果时，儿子或女儿可以从盘子中取出。

### 📐 分析
- **互斥**：对盘子的访问
- **同步**：
  - 爸爸放苹果 → 女儿取苹果
  - 妈妈放橘子 → 儿子取橘子
  - 盘子空（儿子或女儿取走） → 爸爸或妈妈才能放

### 📐 信号量
- **plate = 1**：盘子中还可以放多少个水果
- **apple = 0**：盘子中苹果的个数
- **orange = 0**：盘子中橘子的个数
- mutex = 1（互斥访问盘子，本题可省略，见下）

```c
semaphore plate = 1, apple = 0, orange = 0;

dad() {                    mom() {
    while (1) {                while (1) {
        准备一个苹果;               准备一个橘子;
        P(plate);                  P(plate);
        把苹果放入盘子;             把橘子放入盘子;
        V(apple);                  V(orange);
    }                          }
}                          }

daughter() {               son() {
    while (1) {                while (1) {
        P(apple);                  P(orange);
        从盘中取出苹果;             从盘中取出橘子;
        V(plate);                  V(plate);
        吃掉苹果;                   吃掉橘子;
    }                          }
}                          }
```

📐 **为什么可以不要 mutex？** 因为盘子容量为 **1**，plate、apple、orange 三个信号量**同一时刻最多只有一个为 1**，最多只有一个进程能通过 P 操作进入访问盘子的代码，天然互斥。
- 若盘子容量为 **2**（plate = 2），两个家长可能**同时**放水果，就**必须**加 mutex

📌 **分析技巧**：从“**事件**”的角度分析，而不是从单个进程的角度。“盘子变空”这个事件既可能由儿子引起、也可能由女儿引起；“盘子变空”后，爸爸或妈妈都可以放。所以只需要一个 plate 信号量，而不是分别设置。

## 五、经典同步问题 3：吸烟者问题（⭐）

### 📐 问题描述
三个吸烟者进程和一个供应者进程。每个吸烟者卷烟并抽掉，卷烟需要三种材料：**烟草、纸、胶水**。三个吸烟者分别拥有**烟草、纸、胶水**中的一种。供应者**无限提供**三种材料，每次把**两种材料**放到桌上，拥有剩下那种材料的吸烟者卷一根烟抽掉，并给供应者一个**完成信号**，供应者再放另外两种材料……如此循环，**三个吸烟者轮流吸烟**。

### 📐 信号量
- **offer1 = 0**：桌上组合一（纸 + 胶水），给拥有烟草的吸烟者 1
- **offer2 = 0**：组合二（烟草 + 胶水），给吸烟者 2
- **offer3 = 0**：组合三（烟草 + 纸），给吸烟者 3
- **finish = 0**：抽烟完成
- 整型变量 i 实现“轮流”

```c
int i = 0;
semaphore offer1 = 0, offer2 = 0, offer3 = 0, finish = 0;

provider() {
    while (1) {
        if (i == 0) { 放纸和胶水; V(offer1); }
        else if (i == 1) { 放烟草和胶水; V(offer2); }
        else { 放烟草和纸; V(offer3); }
        i = (i + 1) % 3;
        P(finish);                 // 等吸烟者抽完
    }
}

smoker1() {                        // 拥有烟草
    while (1) {
        P(offer1);
        从桌上拿走纸和胶水; 卷烟; 抽掉;
        V(finish);
    }
}
// smoker2、smoker3 类似，分别 P(offer2)、P(offer3)
```
📌 这是“**可生产多种产品的单生产者**”问题。

## 六、经典同步问题 4：读者-写者问题（⭐⭐⭐）

### 📐 问题描述
有读者和写者两组并发进程，**共享一个文件**：
1. **允许多个读者同时读**
2. **只允许一个写者写**
3. 任一写者在完成写操作之前**不允许其他读者或写者工作**
4. 写者执行写操作前，应让**已有的读者和写者全部退出**

即：**读-读不互斥**，**读-写互斥**，**写-写互斥**。

### 📐 核心思路：“第一个读者加锁，最后一个读者解锁”
- 用 **rw = 1** 实现读写互斥、写写互斥
- 用计数器 **count** 记录当前有几个读者在读
- **第一个**读者负责 P(rw)（把写者挡在外面），后面的读者直接进
- **最后一个**读者负责 V(rw)（放写者进来）
- count 本身是共享变量，对它的访问要互斥：**mutex = 1**

### 📐 解法一：读者优先
```c
int count = 0;              // 当前读者数量
semaphore mutex = 1;        // 保护 count
semaphore rw = 1;           // 读者与写者互斥访问文件

writer() {
    while (1) {
        P(rw);              // 写之前加锁
        写文件;
        V(rw);              // 写完解锁
    }
}

reader() {
    while (1) {
        P(mutex);           // 互斥访问 count
        if (count == 0)     // 我是第一个读者
            P(rw);          //   负责加锁，阻止写者
        count++;
        V(mutex);

        读文件;

        P(mutex);
        count--;
        if (count == 0)     // 我是最后一个读者
            V(rw);          //   负责解锁，允许写者
        V(mutex);
    }
}
```
🧒 **为什么 count 要用 mutex 保护？** 若两个读者同时执行 `if (count == 0)`，都发现 count = 0，都去 P(rw)：第一个成功，第二个阻塞在 rw 上——但其实读者之间不应互斥！所以“检查 count 并 P(rw)”必须一气呵成。

❌ **问题**：只要一直有读者源源不断地到来，count 就不会降到 0，**写者可能永远饥饿**（读者优先）。

### 📐 解法二：读写公平（“写者优先”的一种）
增加一个信号量 **w = 1**，用于实现“**写优先**”（更准确地说是**读写公平**、先来先服务）：
```c
int count = 0;
semaphore mutex = 1;        // 保护 count
semaphore rw = 1;           // 读写互斥
semaphore w = 1;            // 实现写者“插队”：写者到来后，阻止新读者进入

writer() {
    while (1) {
        P(w);               // 有写者来了，后来的读者都要排在它后面
        P(rw);              // 等当前的读者读完
        写文件;
        V(rw);
        V(w);
    }
}

reader() {
    while (1) {
        P(w);               // 若有写者在等，读者在这里阻塞
        P(mutex);
        if (count == 0) P(rw);
        count++;
        V(mutex);
        V(w);               // 放行，让后面的读者或写者能继续排队

        读文件;

        P(mutex);
        count--;
        if (count == 0) V(rw);
        V(mutex);
    }
}
```
- 写者到来时 P(w)，之后新来的读者会阻塞在 P(w) 上，不能再“插队”
- 当前正在读的读者读完后，最后一个读者 V(rw)，写者得以写
- 这样**写者不会饥饿**，读者和写者按到达顺序**公平**竞争

📌 读者-写者问题的核心：**用计数器 count 实现“第一个/最后一个”的特殊操作**。这是解决复杂互斥问题的一个重要技巧（2025 年植树问题中也有类似的计数思想）。

## 七、经典同步问题 5：哲学家进餐问题（⭐⭐）

### 📐 问题描述
一张圆桌上坐着 **5 名哲学家**，每两名哲学家之间放**一根筷子**（共 5 根），桌子中间是一碗米饭。哲学家只做两件事：**思考和进餐**。饥饿时，哲学家**试图拿起左右两根筷子**（一根一根地拿），若筷子已在他人手上，则等待。只有**同时拿到两根**筷子才能进餐，吃完后放下筷子继续思考。

### 📐 错误解法：直接拿
```c
semaphore chopstick[5] = {1, 1, 1, 1, 1};

Pi() {                               // 第 i 号哲学家
    while (1) {
        P(chopstick[i]);             // 拿左边
        P(chopstick[(i + 1) % 5]);   // 拿右边
        吃饭;
        V(chopstick[i]);
        V(chopstick[(i + 1) % 5]);
        思考;
    }
}
```
❌ 若 5 名哲学家**同时**拿起左边的筷子，每人都在等右边的筷子——**死锁**！

### 📐 三种防止死锁的方法
**方法 1：最多允许 4 名哲学家同时进餐**
- 设信号量 **seat = 4**，拿筷子之前先 P(seat)，吃完后 V(seat)
- 这样至少有一名哲学家能拿到两根筷子

**方法 2：奇数号哲学家先拿左边的筷子，偶数号先拿右边的**
- 相邻两个哲学家会先争抢同一根筷子，抢到的人一定能拿到第二根（因为另一侧的邻居是先拿另一根的）
- 破坏了“循环等待”

**方法 3：仅当一个哲学家左右两根筷子都可用时，才允许他拿起筷子**
- 用 mutex 把“拿两根筷子”变成一个**原子**动作：
```c
semaphore chopstick[5] = {1, 1, 1, 1, 1};
semaphore mutex = 1;                 // 互斥地取筷子

Pi() {
    while (1) {
        P(mutex);
        P(chopstick[i]);             // 拿左
        P(chopstick[(i + 1) % 5]);   // 拿右
        V(mutex);
        吃饭;
        V(chopstick[i]);
        V(chopstick[(i + 1) % 5]);
        思考;
    }
}
```
- 注意：这种方法并不严格保证“两边都可用才拿”，而是保证**同一时刻只有一个哲学家在拿筷子**，拿筷子的过程中其他人不能拿。若该哲学家拿到一根而另一根被别人占着，他会在持有 mutex 的情况下阻塞，其他想拿筷子的哲学家也要等——但正在吃饭的哲学家吃完会放下筷子，所以**不会死锁**

📌 哲学家问题的关键：**每个进程需要同时持有两个临界资源**，处理不当容易死锁。解决思路就是破坏死锁的必要条件（下下课详讲）。

## ⚠️ 易错点

1. 记录型信号量：wait 中**减 1 后 < 0 阻塞**；signal 中**加 1 后 ≤ 0 唤醒**
2. **S.value < 0 时，|S.value| = 等待进程数**
3. **互斥信号量初值 1**；**同步信号量初值 0**（一般）；**资源信号量初值 = 资源数**
4. 同步口诀：**前 V 后 P**
5. 前驱图：**每条跨进程的边**一个信号量；同一进程内的顺序不需要信号量
6. **互斥的 P 必须放在同步的 P 之后**，否则可能死锁；V 的顺序无所谓
7. 盘子容量为 1 时可以不设 mutex；容量 > 1 时必须设
8. 读者-写者：**第一个读者 P(rw)，最后一个读者 V(rw)**，count 要用 mutex 保护
9. 读者优先会导致**写者饥饿**；加 w 信号量实现读写公平
10. 哲学家问题：5 人同时拿左筷子会死锁；**最多 4 人**、**奇偶不同顺序**、**一次拿两根**可避免
