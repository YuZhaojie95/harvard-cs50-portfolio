## 🚪 课前引入

假设你写了一个程序，里面有一句：
```c
关中断();          // 禁止 CPU 响应中断
while (1) { }     // 死循环
```
如果普通程序可以随便执行这种指令，那一个坏程序就能让整台电脑“卡死”——时钟中断不响应了，操作系统再也夺不回 CPU！

再比如，普通程序能不能直接去改页表、直接往磁盘任意位置写数据？当然不能，否则它可以偷看、破坏别人的数据。

所以，计算机必须区分：
- 哪些指令**危险**（只能由操作系统执行）——**特权指令**
- 当前 CPU 在执行**谁的代码**（操作系统的还是普通程序的）——**内核态 / 用户态**

🧒 **比喻：银行**
- 普通客户（用户程序）只能在**大厅**（用户态）办理存取款业务
- **金库**（特权操作：改页表、I/O、关中断）只有**银行职员**（操作系统内核）能进
- 客户想取钱，要在柜台**提交申请**（系统调用），由职员进金库去拿，再交给客户

## 一、处理器的运行模式（⭐⭐⭐）

### 📐 特权指令与非特权指令
- **特权指令**：**不允许用户直接使用**的指令。如：
  - **I/O 指令**（启动设备、读写设备端口）
  - **置中断指令、开/关中断指令**
  - **修改程序状态字（PSW）的指令**、**设置/修改页表基址寄存器**等存储保护相关指令
  - **设置时钟**、停机指令
  - **切换到用户态**的指令（如 x86 的 iret 在某些情况下）
- **非特权指令**：允许用户直接使用，不能直接访问系统中的软硬件资源，**仅限于访问用户的地址空间**。如：算术运算、数据传送（mov）、跳转、**陷入指令（trap / int / syscall）**
  - ⚠️ **陷入指令（访管指令）是非特权指令**！它正是用户程序**主动请求**进入内核态的方式

### 📐 内核态与用户态
CPU 有两种运行模式（状态），用**程序状态字寄存器（PSW）中的某个标志位**来标识：
| 状态 | 别名 | 运行的程序 | 能执行的指令 |
|---|---|---|---|
| **内核态** | 核心态、**管态**、特权态 | **操作系统内核** | **特权指令 + 非特权指令**（全部指令） |
| **用户态** | **目态** | 应用程序 | **只能执行非特权指令** |

📝 **真题（2022 年第 27 题）**：下列关于 CPU 模式的叙述中，正确的是：
A. CPU 处于用户态时只能执行特权指令　B. CPU 处于内核态时只能执行特权指令　C. CPU 处于用户态时只能执行非特权指令　D. CPU 处于内核态时只能执行非特权指令
→ **C**（内核态可以执行**所有**指令，不是“只能执行特权指令”）

📝 **真题（2021 年第 23 题）**：下列指令中，只能在内核态执行的是：A. trap 指令　B. I/O 指令　C. 数据传送指令　D. 设置断点指令
→ **B**（trap 指令是用户程序进入内核的“入口”，必须能在用户态执行；设置断点指令用于调试，也是用户可执行的）

### 📐 用户态 ↔ 内核态的切换（⭐⭐⭐）
- **用户态 → 内核态**：**唯一途径是通过中断或异常**（包括用户程序执行**陷入指令**引发的系统调用）。由**硬件**完成切换（中断隐指令把 PSW 中的模式位置为内核态）
- **内核态 → 用户态**：由操作系统执行一条**特权指令**（如中断返回指令 iret），把 PSW 中的模式位改为用户态

🧒 进金库（内核态）只有一个门：**中断/异常**；出金库由职员自己开门（特权指令）。

📝 **真题（2023 年第 26 题）**：下列操作完成时，导致 CPU 从内核态转为用户态的是：A. 阻塞进程　B. 执行 CPU 调度　C. 唤醒进程　D. 执行系统调用
→ **B**
- 执行 CPU 调度（进程调度 + 切换）后，CPU 就要去运行被选中的**用户进程**，于是返回用户态
- A、C 是内核中对进程状态的操作，完成后仍在内核中继续执行（例如之后还要进行调度）
- D 执行系统调用是**用户态 → 内核态**

## 二、操作系统内核（⭐⭐）

### 📐 内核（Kernel）
计算机上配置的**最底层的软件**，是 OS 最基本、最核心的部分，运行在**内核态**。

内核一般包括以下 4 方面内容：
1. **时钟管理**
   - 向用户提供标准的系统时间
   - 通过**时钟中断**实现进程切换（如分时系统中的**时间片轮转**、实时系统中按截止时间控制）
2. **中断机制**
   - 现代 OS 是**靠中断驱动**的软件
   - 中断机制中，只有一小部分功能属于内核（保护和恢复现场、转移控制权到相关处理程序），以减少中断处理时间
3. **原语（Primitive）**
   - 处于 OS **最底层**、最接近硬件的小程序
   - 具有**原子性**：运行**一气呵成、不可中断**（通过**关中断/开中断**实现）
   - 运行时间较短、调用频繁
   - 例：进程的创建、撤销、阻塞、唤醒原语；P、V 操作原语
4. **系统控制的数据结构及处理**
   - **进程管理**：进程状态管理、调度与分派、创建与撤销 PCB 等
   - **存储器管理**：存储器空间分配与回收、内存信息保护、代码对换
   - **设备管理**：缓冲区管理、设备分配与回收

📝 **真题（2021 年第 25 题）**：下列内核的数据结构或程序中，分时系统实现时间片轮转调度需要使用的是：I. 进程控制块　II. 时钟中断处理程序　III. 进程就绪队列　IV. 进程阻塞队列
A. 仅 II、III　B. 仅 I、IV　C. 仅 I、II、III　D. 仅 I、II、IV
→ **C**（时间片用完由**时钟中断**触发；要把当前进程的状态保存到 **PCB**、放回**就绪队列**，再从就绪队列选下一个；时间片用完的进程进入的是就绪队列而不是阻塞队列）

## 三、中断和异常（OS 的视角）（⭐⭐）

组成原理第 19、21 课已经讲过中断和异常的硬件机制，这里从操作系统的角度再梳理一遍。

### 📐 为什么需要中断
- 早期计算机中，CPU 和 I/O 串行工作，效率低
- 引入中断后：CPU 与 I/O 并行；**操作系统借助中断夺回 CPU 控制权**
- 🧒 **没有中断，就没有并发**：时间片用完，靠时钟中断让 OS 收回 CPU；I/O 完成，靠 I/O 中断唤醒等待的进程

### 📐 中断的分类
| 类别 | 来源 | 例子 |
|---|---|---|
| **内中断（异常、例外）** | 与当前执行的**指令有关**，来自 CPU 内部 | **陷入（trap）**：系统调用；**故障（fault）**：缺页、除 0；**终止（abort）**：硬件故障 |
| **外中断（中断）** | 与当前指令**无关**，来自 CPU 外部 | **时钟中断**、**I/O 中断**（I/O 完成） |

### 📐 中断处理过程中，硬件和 OS 的分工
| 由硬件完成（中断隐指令） | 由操作系统完成 |
|---|---|
| 关中断 | **保存现场**（通用寄存器）和**中断屏蔽字** |
| **保存断点**（PC）和 PSW | **中断服务**（执行中断处理程序） |
| 引出中断服务程序（入口地址送 PC） | 恢复现场和屏蔽字 |
| 切换到内核态 | **初始化中断向量表**（系统启动时） |
| | 中断返回（执行 iret 特权指令） |

📝 **真题（2020 年第 25 题）**：下列与中断相关的操作中，由操作系统完成的是：I. 保存被中断程序的中断点　II. 提供中断服务　III. 初始化中断向量表　IV. 保存中断屏蔽字
→ **D（仅 II、III、IV）**

📝 **真题（2022 年第 24 题）**：下列选项中，需要在操作系统进行初始化过程中创建的是：A. 中断向量表　B. 文件系统的根目录　C. 硬盘分区表　D. 文件系统的索引结点表
→ **A**（中断向量表在 OS 初始化时由 OS 建立；B、D 在对磁盘进行**逻辑格式化**（创建文件系统）时建立；C 在**磁盘分区**时建立——它们都在装 OS 之前/时写到磁盘上，不是每次 OS 初始化时创建的）

## 四、系统调用（⭐⭐⭐）

### 📐 定义
**系统调用**是操作系统提供给**应用程序（程序员/编程人员）**使用的**接口**，可以理解为一种**可供应用程序调用的特殊函数**。应用程序通过系统调用**请求操作系统的服务**。

- 凡是与**共享资源**有关的操作（存储分配、I/O 操作、文件管理等），都必须通过系统调用向 OS 提出服务请求，由 OS 代为完成
- 这样可以保证系统的**稳定性和安全性**，防止用户进行非法操作

### 📐 系统调用的分类（按功能）
| 类别 | 例子 |
|---|---|
| **设备管理** | 设备的请求/释放、启动 |
| **文件管理** | 文件的读、写、创建、删除（open、read、write、close） |
| **进程控制** | 进程的创建（fork）、撤销（exit）、阻塞、唤醒 |
| **进程通信** | 消息传递、信号量、管道、共享存储 |
| **内存管理** | 内存的分配与回收（brk、mmap） |

📝 **真题（2021 年第 32 题）**：下列选项中，通过系统调用完成的操作是：A. 页置换　B. 进程调度　C. 创建新进程　D. 生成随机整数
→ **C**
- A、B 是 OS 内部的行为，不是应用程序**请求**的（缺页时由缺页异常触发页置换；进程调度由 OS 自己决定），不是系统调用
- D 生成随机数用普通库函数（纯计算）即可，不需要 OS 服务

### 📐 系统调用 vs 库函数
```
应用程序 ──调用──► C 库函数（printf、fopen、malloc）──►系统调用（write、open、brk）──► 内核
应用程序 ──调用──► C 库函数（strlen、sqrt）      ──► 不涉及系统调用
```
- 有的库函数是对系统调用的**封装**（printf 封装了 write）
- 有的库函数**不涉及**系统调用（strlen、abs、rand）
- 系统调用在**内核态**执行，库函数本身在**用户态**执行

### 📐 系统调用的执行过程（⭐⭐⭐）
以 Linux 的 `read` 为例：
1. **传递系统调用参数**：用户程序把**系统调用号**和**参数**放到指定的**寄存器**中（或栈中）——在**用户态**
2. 执行**陷入指令（trap / int 0x80 / syscall）**——**用户态**执行这条非特权指令
3. **硬件**：引发一个**内中断**，CPU 从**用户态切换到内核态**，**保存断点和 PSW**，转到**系统调用入口程序**
4. **OS**：保存现场（通用寄存器等），根据**系统调用号**查**系统调用表**，找到并执行相应的**系统调用服务例程**
5. **OS**：恢复现场，执行**中断返回**指令，**返回用户态**，回到用户程序中陷入指令的**下一条指令**继续执行

📝 **真题（2022 年第 31 题）**：执行系统调用的过程涉及下列操作，其中由操作系统完成的是：I. 保存断点和程序状态字　II. 保存通用寄存器的内容　III. 执行系统调用服务例程　IV. 将 CPU 模式改为内核态
A. 仅 I、III　B. 仅 II、III　C. 仅 II、IV　D. 仅 II、III、IV
→ **B**（I、IV 由**硬件**在执行陷入指令时自动完成）

⚠️ **考点总结**：
- **陷入指令在用户态执行**，执行后引发内中断，CPU 转入内核态
- **系统调用的处理在内核态**
- 系统调用返回后，回到**陷入指令的下一条**（陷入是“自陷”，返回下一条）

## 五、操作系统的体系结构（⭐⭐）

### 📐 1. 分层法
把 OS 分成若干层，**最底层（层 0）是硬件，最高层（层 N）是用户接口**，**每层只能调用紧邻它的低层**的功能和服务（单向依赖）。
- ✅ **便于系统的调试和验证**（自底向上逐层调试）；**易扩充和维护**（增删某层不影响其他层，只要接口不变）
- ❌ **合理定义各层比较困难**（依赖关系固定，不灵活）；**效率较差**（每次调用都要逐层穿越）

### 📐 2. 模块化
把 OS 按**功能**划分为若干个具有一定独立性的**模块**，每个模块具有某方面的管理功能，模块之间通过接口通信。还可以进一步细分为子模块。
- 衡量模块独立性：**内聚性**（模块内部联系紧密程度，越高越好）、**耦合度**（模块间联系程度，越低越好）
- ✅ 提高了 OS 设计的正确性、可理解性和可维护性；增强了适应性；加速开发
- ❌ 模块间的接口规定很难满足实际需求；各模块设计者**齐头并进**，每个决定无法建立在上一个已验证的正确决定的基础上，无法找到可靠的决定顺序

### 📐 3. 宏内核（大内核、单内核）
把 OS 的**主要功能模块**（进程管理、存储管理、文件管理、设备管理……）都作为一个**紧密联系的整体**运行在**内核态**。
- ✅ 各模块共享信息，**性能高**（模块间直接函数调用）
- ❌ 内核庞大复杂，难以维护；某个模块出错可能导致整个系统崩溃
- 例：**Linux**、UNIX、Windows（混合）

### 📐 4. 微内核（⭐⭐）
**只把最基本的功能保留在内核**（中断处理、进程/线程管理与调度、**低级存储管理**、**进程间通信（IPC）**、时钟管理），而把其他功能（文件系统、设备驱动、网络协议栈等）移到**用户态**，作为**服务器进程**运行。
- 基于**客户/服务器模式**：应用程序（客户）通过内核的**消息传递**机制请求服务器进程提供服务
- 微内核的基本功能：**进程（线程）管理**、**低级存储器管理**、**中断和陷入处理**
- ✅ **扩展性和灵活性好**（增加新功能只需添加服务器进程）
- ✅ **可靠性和安全性高**（服务器进程在用户态运行，一个服务出错不会导致整个系统崩溃）
- ✅ **可移植性强**（与硬件有关的部分都在微内核中）
- ✅ 支持**分布式计算**
- ❌ **性能较差**：需要频繁地在**用户态和内核态之间切换**、**消息传递**开销大
- 例：Minix、QNX、鸿蒙（微内核）

📝 **真题（2023 年第 23 题）**：与宏内核操作系统相比，下列特征中，微内核操作系统具有的是：I. 较好的性能　II. 较高的可靠性　III. 较高的安全性　IV. 较强的可扩展性
A. 仅 II、IV　B. 仅 I、II、III　C. 仅 I、III、IV　D. 仅 II、III、IV
→ **D**（微内核**性能较差**）

### 📐 5. 外核（Exokernel）
内核负责**进程调度、进程通信**等功能；外核负责为用户进程**分配未经抽象的硬件资源**，且由外核负责保证资源使用安全。
- ✅ 外核可直接给用户进程分配“不虚拟、不抽象”的硬件资源，使用户进程可以**更灵活**地使用硬件资源；减少了虚拟硬件资源的“映射层”，提升效率
- ❌ 降低了系统的一致性；使系统变得更复杂

### 📐 对比
| 结构 | 特点 | 优点 | 缺点 |
|---|---|---|---|
| 分层 | 只调用相邻低层 | 易调试、易维护 | 层次难定义、效率低 |
| 模块化 | 按功能分模块 | 可理解、可维护 | 接口难定、无法可靠验证 |
| 宏内核 | 功能都在内核态 | **性能高** | 难维护、可靠性差 |
| **微内核** | 只保留基本功能，其余在用户态 | **可靠、安全、可扩展、可移植** | **性能差**（频繁切换） |
| 外核 | 直接分配原始硬件资源 | 灵活、高效 | 复杂 |

## 六、操作系统引导（⭐⭐）

### 📐 什么是引导
**操作系统引导（boot）**：计算机开机后，**利用 CPU 运行特定程序，通过程序识别硬盘，识别硬盘分区，识别硬盘分区上的操作系统，最后通过程序启动操作系统**。

### 📐 相关概念
- **主引导记录（MBR）**：硬盘的**第一个扇区**（0 号扇区），包含**磁盘引导程序**和**分区表**
  - 磁盘引导程序：选择要引导哪个分区的操作系统
  - 分区表：记录硬盘上各分区的位置、大小等信息
- **分区引导记录（PBR）**：每个分区的第一个扇区，包含**分区引导程序**，用于引导该分区中的操作系统
- **活动分区**：安装了操作系统、可以启动的分区

### 📐 引导过程（⭐⭐⭐）
1. **激活 CPU**：CPU 加电，读取 **ROM 中的 boot 程序**（BIOS/UEFI 中的**自举程序**），执行
2. **硬件自检**：检查硬件（内存、显卡……）是否正常
3. **加载带有操作系统的硬盘**：BIOS 读取启动顺序，把控制权交给启动设备，读取硬盘的 **MBR**
4. **加载主引导记录 MBR**：执行 MBR 中的**磁盘引导程序**，它根据**分区表**找到**活动分区**
5. **扫描硬盘分区表，加载分区引导记录 PBR**：读入活动分区的第一个扇区（PBR），执行其中的**分区引导程序**
6. **加载启动管理器**：分区引导程序找到并加载操作系统的**启动管理器**（如 Linux 的 GRUB、Windows 的 bootmgr）
7. **加载操作系统**：把 OS 内核装入内存，执行 OS 的**初始化程序**（建立中断向量表、初始化各种数据结构、创建第一个进程……）

📝 **真题（2021 年第 46 题，8 分）**：某计算机用硬盘作为启动盘，硬盘第一个扇区存放主引导记录，其中包含磁盘引导程序和分区表。磁盘引导程序用于选择要引导哪个分区的操作系统，分区表记录硬盘上各分区的位置等描述信息。硬盘被划分成若干个分区，每个分区的第一个扇区存放分区引导程序，用于引导该分区中的操作系统。系统采用多阶段引导方式，除了执行磁盘引导程序和分区引导程序外，还需要执行 ROM 中的引导程序。请回答下列问题。
1）系统启动过程中操作系统的初始化程序、分区引导程序、ROM 中的引导程序、磁盘引导程序的执行顺序是什么？
2）把硬盘制作为启动盘时，需要完成操作系统的安装、磁盘的物理格式化、逻辑格式化、对磁盘进行分区，执行这 4 个操作的正确顺序是什么？
3）磁盘扇区的划分和文件系统根目录的建立分别是在第 2）问的哪个操作中完成的？

**1）** **ROM 中的引导程序 → 磁盘引导程序 → 分区引导程序 → 操作系统的初始化程序**
- 🧒 CPU 一开机只能执行 ROM 里的程序（内存里还什么都没有）；ROM 程序去读硬盘第一个扇区（MBR）并执行磁盘引导程序；磁盘引导程序查分区表，找到活动分区，执行其分区引导程序；分区引导程序把 OS 装入内存并执行其初始化程序

**2）** **物理格式化 → 分区 → 逻辑格式化 → 安装操作系统**
- 物理格式化（低级格式化）：把磁盘划分成扇区
- 分区：把磁盘分成若干个逻辑盘（写分区表）
- 逻辑格式化（高级格式化）：在分区上创建文件系统
- 安装 OS：把 OS 的文件写入文件系统

**3）** **磁盘扇区的划分**在**物理格式化**中完成；**文件系统根目录的建立**在**逻辑格式化**中完成

（第 18 课“磁盘”中会再讲物理格式化和逻辑格式化。）

## 七、虚拟机（⭐）

### 📐 概念
**虚拟机**：使用**虚拟化技术**，把一台物理机器**虚拟化为多台虚拟机器**，每台虚拟机都能运行自己的操作系统。
- **虚拟机管理程序（VMM，Virtual Machine Monitor，也叫 Hypervisor）**：负责管理和调度虚拟机，把物理资源分配给各虚拟机

### 📐 两类 VMM（⭐⭐）
| | 第一类 VMM（裸金属型） | 第二类 VMM（寄居型/托管型） |
|---|---|---|
| 运行位置 | **直接运行在硬件上** | **运行在宿主操作系统上** |
| 地位 | 相当于一个操作系统，运行在**最高特权级（内核态）** | 是宿主 OS 上的一个**普通应用程序**，运行在**用户态**（部分驱动在内核态） |
| 资源分配 | 直接分配物理资源 | 向宿主 OS 申请资源 |
| 性能 | **性能好** | 性能较差（要经过宿主 OS） |
| 可支持虚拟机数量 | 更多 | 较少 |
| 可迁移性 | 较差 | **好**（安装在 OS 上即可，更方便） |
| 例子 | VMware ESXi、Xen、Hyper-V | VMware Workstation、VirtualBox |

- **客户操作系统（Guest OS）**：运行在虚拟机上的 OS。在第一类 VMM 中，Guest OS 认为自己运行在内核态，但实际上运行在**用户态**（“虚拟内核态”）。当 Guest OS 执行特权指令时，会陷入 VMM，由 VMM 模拟执行

📝 **真题（2025 年第 24 题）**：关于虚拟机技术，下列说法**错误**的是：
A. 操作系统可以在虚拟机上运行　B. 一台主机可以支持多个虚拟机　C. VMM 与操作系统特权级相同　D. 通过虚拟机技术，可以用一台主机上模拟多种 ISA
→ **C**（第二类 VMM 运行在宿主 OS 上，其特权级低于操作系统；即使第一类 VMM，Guest OS 也被降到用户态运行，VMM 的特权级比 Guest OS 高。所以“VMM 与操作系统特权级相同”不对）

### 📐 进程上下文切换与寄存器（补充）
📝 **真题（2025 年第 23 题）**：在采用页式虚拟存储管理方式的系统中，当发生上下文切换时，下列寄存器中操作系统**不需要更新**的是：A. 通用寄存器　B. 页表基址寄存器　C. 程序寄存器　D. 内核中断向量表基址寄存器
→ **D**
- 通用寄存器、程序计数器（程序寄存器）属于进程的上下文，每个进程不同，要保存/恢复
- 每个进程有自己的页表，**页表基址寄存器**必须更新
- **中断向量表是整个系统共用的**，属于内核，与具体进程无关，不需要更新

## ⚠️ 易错点

1. **陷入（trap）指令是非特权指令**，在用户态执行；**I/O 指令、开关中断、修改 PSW、设置页表基址**是特权指令
2. **内核态能执行全部指令**，用户态只能执行非特权指令
3. 用户态 → 内核态**只能通过中断/异常**；内核态 → 用户态通过**特权指令**（如 iret）
4. **原语**：原子性，不可中断，靠**关/开中断**实现
5. 系统调用中：**保存断点/PSW、切换模式由硬件**；保存通用寄存器、执行服务例程由 **OS**
6. 页置换、进程调度**不是**系统调用
7. **微内核：可靠、安全、可扩展、可移植，但性能差**
8. 引导顺序：**ROM 引导程序 → 磁盘引导程序（MBR）→ 分区引导程序（PBR）→ OS 初始化**
9. 制作启动盘：**物理格式化 → 分区 → 逻辑格式化 → 安装 OS**
10. 中断向量表在 **OS 初始化**时建立；根目录在**逻辑格式化**时建立；分区表在**分区**时建立
11. 第一类 VMM 直接运行在硬件上；第二类运行在宿主 OS 上

## 📋 本课小结

| 知识点 | 要点 |
|---|---|
| 两种状态 | 内核态（全部指令）、用户态（非特权指令），PSW 标志位区分 |
| 状态切换 | 用户→内核：中断/异常（陷入）；内核→用户：特权指令 |
| 内核 | 时钟管理、中断机制、原语、资源管理数据结构 |
| 系统调用 | 传参 → 陷入（硬件切换、保存断点）→ OS 执行服务例程 → 返回 |
| OS 结构 | 分层、模块化、宏内核（快）、微内核（可靠）、外核 |
| 引导 | ROM → MBR → PBR → OS 初始化 |
| 虚拟机 | 第一类（裸金属）、第二类（寄居） |

4. 判断：(a) 系统调用的服务例程在用户态执行；(b) 原语可以被中断打断；(c) 库函数都会引起系统调用；(d) 中断处理程序在内核态执行。
5. 在计算机启动过程中，下列程序谁最先执行：OS 初始化程序、BIOS 自举程序、GRUB 启动管理器、MBR 中的引导程序？写出完整顺序。

<details>
<summary>📖 答案</summary>

1. 特权指令：**(a)、(c)、(e)、(g)**。读时钟、trap、加法是非特权指令
2. printf 在用户态执行库函数代码（格式化字符串）→ 调用 write 系统调用：把系统调用号和参数放入寄存器，执行陷入指令（用户态）→ 硬件切换到**内核态**，保存断点和 PSW → OS 执行 write 服务例程，调用显示器驱动程序输出 → 执行中断返回，切换回**用户态**，继续执行 printf 之后的代码
3. 微内核把文件系统、驱动等放在用户态的服务器进程中，应用程序请求服务要经过“应用 → 微内核 → 服务器 → 微内核 → 应用”的消息传递，需要**多次用户态与内核态的切换**和消息复制，开销大
4. (a) **错**，在内核态；(b) **错**，原语不可中断；(c) **错**，如 strlen 不需要；(d) **对**
5. **BIOS 自举程序 → MBR 中的引导程序 → （分区引导程序）→ GRUB 启动管理器 → OS 初始化程序**
