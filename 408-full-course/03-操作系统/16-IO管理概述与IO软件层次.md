## 🚪 课前引入

你在程序里写了一句 `scanf("%d", &x);`，然后按下键盘上的“5”和回车。从你按下按键到 x 变成 5，中间发生了什么？
- 键盘把按键转成电信号，**键盘控制器**把它变成字符 '5'，放进自己的寄存器
- 键盘控制器发出**中断**
- CPU 暂停当前工作，执行**键盘中断处理程序**
- 中断处理程序调用**键盘驱动程序**，把字符从控制器读到**内核缓冲区**
- 等待这个字符的进程被**唤醒**
- 进程从系统调用返回，C 库函数把字符转换成整数，存进 x

这一连串动作涉及**硬件、中断处理程序、驱动程序、设备独立性软件、用户层软件**——这就是本课要讲的 **I/O 软件层次结构**。

## 一、I/O 设备的基本概念（⭐）

### 📐 I/O 设备
**I/O 设备**就是可以将数据**输入**到计算机，或者可以接收计算机**输出**数据的外部设备，属于计算机中的**硬件部件**。
- UNIX 系统将外部设备抽象为一种**特殊的文件**，用户可以使用与文件操作相同的方式对外部设备进行操作（write 向外部设备写数据，read 从外部设备读数据）

### 📐 I/O 设备的分类
**按使用特性**：
- **人机交互类外部设备**：鼠标、键盘、打印机——用于与计算机用户之间交互，**数据传输速度慢**
- **存储设备**：移动硬盘、光盘——用于数据存储，**数据传输速度快**
- **网络通信设备**：调制解调器、网卡——用于与远程设备通信，传输速度介于上述二者之间

**按传输速率**：低速设备（键盘、鼠标，每秒几字节到几百字节）、中速设备（激光打印机，每秒数千至上万字节）、高速设备（磁盘，每秒数千字节至千兆字节）

**按信息交换的单位**（⭐⭐）：
- **块设备**：数据传输的基本单位是“**块**”。传输速率较高，**可寻址**，即对它可随机地读/写任一块。如**磁盘**
- **字符设备**：数据传输的基本单位是**字符**。传输速率较慢，**不可寻址**，在输入/输出时常采用**中断驱动**方式。如**鼠标、键盘**

### 📐 I/O 控制器（设备控制器）
I/O 设备由**机械部件**和**电子部件（I/O 控制器）**组成。
- **CPU 无法直接控制 I/O 设备的机械部件**，因此 I/O 设备还要有一个电子部件作为 CPU 和 I/O 设备机械部件之间的“中介”，用于实现 CPU 对设备的控制。这个电子部件就是 **I/O 控制器**，又称**设备控制器**
- CPU 可控制 I/O 控制器，又由 I/O 控制器来控制设备的机械部件
- 功能：**接受和识别 CPU 发出的命令**（控制寄存器）、**向 CPU 报告设备的状态**（状态寄存器）、**数据交换**（数据寄存器）、**地址识别**
- 组成：**CPU 与控制器的接口**、**I/O 逻辑**、**控制器与设备的接口**
- 寄存器编址：**统一编址**（存储器映射 I/O）或**独立编址**（I/O 端口，专门的 I/O 指令）——见组成原理第 21 课

📝 **2021 年第 20 题**（组成原理）：磁盘驱动器**不属于** I/O 接口（它是设备本身的一部分）。

## 二、I/O 控制方式（OS 视角）（⭐⭐）

组成原理第 21 课已详细讲过，这里从 **CPU 干预程度**、**数据传送单位**、**数据流向**的角度再梳理：

| 方式 | 完成一次读/写的过程 | CPU 干预频率 | 每次 I/O 的数据传输单位 | 数据的流向 | 优缺点 |
|---|---|---|---|---|---|
| **程序直接控制（轮询）** | CPU 发出 I/O 命令后需要**不断轮询** | **极高** | **字** | 设备 → **CPU 寄存器** → 内存 | 简单；CPU 与 I/O 只能串行工作，CPU 长期处于“忙等”状态 |
| **中断驱动** | CPU 发出 I/O 命令后可以做其他事，本次 I/O 完成后设备控制器发出中断信号 | 高 | **字** | 设备 → **CPU 寄存器** → 内存 | CPU 和 I/O 可并行；频繁中断处理会消耗较多 CPU 时间 |
| **DMA** | CPU 发出 I/O 命令后可以做其他事，本次 I/O 完成后 DMA 控制器发出中断信号 | 中 | **块** | 设备 → **内存**（不经过 CPU） | 数据传输以“块”为单位，CPU 介入频率进一步降低；CPU 发出一条 I/O 指令，只能读/写**一个或多个连续**的数据块 |
| **通道** | CPU 发出 I/O 命令后可以做其他事。**通道会执行通道程序**以完成 I/O，完成后通道向 CPU 发出中断信号 | **低** | **一组块** | 设备 → **内存** | CPU、通道、I/O 设备可**并行**工作，资源利用率很高；实现复杂，需要专门的通道硬件支持 |

- **通道**：一种**硬件**，可以理解为是“**弱鸡版的 CPU**”。通道可以识别并执行一系列**通道指令**（通道程序）
  - 与 CPU 相比，通道可以执行的指令很单一，并且通道程序是放在**主机内存**中的，也就是说通道与 CPU **共享内存**
  - 通道与一般处理器的区别：通道指令的种类单一；**通道没有自己的内存**

📌 **发展趋势**：尽可能减少 CPU 对 I/O 的干预，把 CPU 从繁杂的 I/O 控制事务中解脱出来，以便更多地去完成数据处理任务。

## 三、I/O 软件的层次结构（⭐⭐⭐）

```
┌──────────────────────────────┐
│  用户层软件（库函数 printf、scanf）│  ← 用户态
├──────────────────────────────┤ ─ ─ ─ 系统调用 ─ ─ ─
│  设备独立性软件（与设备无关的软件）│  ↑
├──────────────────────────────┤  │
│  设备驱动程序                  │  │ 内核态（I/O 核心子系统）
├──────────────────────────────┤  │
│  中断处理程序                  │  ↓
├──────────────────────────────┤
│  硬件（设备控制器 + 设备）      │
└──────────────────────────────┘
```
- **越靠近上层**，越接近用户，与设备的**具体硬件细节越无关**
- **越靠近下层**，越接近硬件
- **用户的 I/O 请求自上而下**地逐层处理；**I/O 完成后的应答信息自下而上**地传递

### 📐 1. 用户层软件
- 实现了与用户交互的接口，用户可直接使用该层提供的、与 I/O 操作相关的**库函数**对设备进行操作（如 printf("hello")）
- 用户层软件将用户请求**翻译成格式化的 I/O 请求**，并通过“**系统调用**”请求操作系统内核的服务
- **SPOOLing 系统**（假脱机）也在这一层实现（下一课）

### 📐 2. 设备独立性软件（与设备无关的软件）（⭐⭐⭐）
与设备的硬件特性无关的功能几乎都在这一层实现，主要功能：
1. **向上层提供统一的调用接口**（如 read/write 系统调用）
2. **设备的保护**：原理类似于文件保护。设备被看做是一种特殊的文件，不同用户对各个文件的访问权限是不一样的，同理，对设备的访问权限也不一样
3. **差错处理**：设备独立性软件需要对一些设备的错误进行处理
4. **设备的分配与回收**（下一课）
5. **数据缓冲区管理**：可以通过缓冲技术屏蔽设备之间数据交换单位大小和传输速度的差异（下一课）
6. **建立逻辑设备名到物理设备名的映射关系**；根据设备类型选择调用相应的**驱动程序**

### 📐 设备独立性（设备无关性）（⭐⭐）
**用户编程时使用的设备与实际使用的设备无关**。
- 用户编程时使用**逻辑设备名**（如“打印机”），由系统把它映射到具体的**物理设备名**（如“3 号激光打印机”）
- 设备独立性软件需要通过“**逻辑设备表（LUT，Logical Unit Table）**”来确定逻辑设备对应的物理设备，并找到该设备对应的设备驱动程序

| 逻辑设备名 | 物理设备名 | 驱动程序入口地址 |
|---|---|---|
| /dev/打印机1 | 3 | 1024 |
| /dev/打印机2 | 5 | 2046 |

- LUT 的设置方式：
  - **整个系统只设置一张 LUT**：各用户所用的逻辑设备名**不允许重复**，适用于**单用户**操作系统
  - **为每个用户设置一张 LUT**：各个用户使用的逻辑设备名**可以重复**，适用于**多用户**操作系统。系统会在用户登录时为其建立一个用户管理进程，而 LUT 就存放在用户管理进程的 PCB 中

📐 **设备独立性的好处**：
- 设备分配时的**灵活性**：若某台打印机坏了或忙，系统可以分配另一台同类打印机，**用户程序不需要修改**
- **易于实现 I/O 重定向**：改变 LUT 的映射，就能让程序的输出从显示器改到打印机，而不必修改程序

📝 **真题（2020 年第 30 题）**：对于具备设备独立性的系统，下列叙述中，**错误**的是：
A. 可以使用文件名访问物理设备　B. 用户程序使用逻辑设备名访问物理设备　C. 需要建立逻辑设备与物理设备之间的映射关系　D. 更换物理设备后必须修改访问该设备的应用程序
→ **D**（设备独立性的意义就是**更换物理设备后不需要修改**应用程序；A 对，UNIX 把设备当作特殊文件，可以用文件名如 /dev/sda 访问）

### 📐 3. 设备驱动程序（⭐⭐⭐）
**主要负责对硬件设备的具体控制**，将上层发出的一系列命令（如 read/write）**转化成特定设备“能听得懂”的一系列操作**。包括**设置设备寄存器、检查设备状态**等。
- 不同的 I/O 设备有不同的硬件特性，具体细节只有设备的厂家才知道。因此**厂家需要根据设备的硬件特性设计并提供相应的驱动程序**
- 驱动程序一般会以一个**独立进程**的方式存在（或作为内核模块）
- **每一类设备配置一个驱动程序**

驱动程序的功能：
1. 接收由上层软件发来的抽象 I/O 要求（如 read、write），转换为具体要求
2. **检查用户 I/O 请求的合法性**，了解 I/O 设备的工作状态，传递有关参数，设置设备的工作方式
3. **发出 I/O 命令**：启动 I/O 设备；如果设备忙，则把请求挂在设备队列上等待
4. **及时响应**由设备控制器发来的**中断请求**，根据其中断类型调用相应的中断处理程序进行处理（在一些系统中，中断处理程序被看作驱动程序的一部分）

📝 **真题（2022 年第 32 题）**：下列关于驱动程序的叙述中，**不正确**的是：
A. 驱动程序与 I/O 控制方式无关　B. 初始化设备是由驱动程序控制完成的　C. 进程在执行驱动程序时可能进入阻塞态　D. 读/写设备的操作是由驱动程序控制完成的
→ **A**（驱动程序直接和设备控制器打交道，采用轮询、中断还是 DMA，驱动程序的写法完全不同，**与 I/O 控制方式密切相关**。C 对：驱动程序发出 I/O 命令后，进程要等待 I/O 完成，会阻塞）

### 📐 4. 中断处理程序
当 I/O 任务完成时，I/O 控制器会发送一个**中断信号**，系统会根据中断信号类型找到相应的中断处理程序并执行。
中断处理程序的处理流程：
1. **从 I/O 控制器读出设备状态**，判断本次 I/O 是否**正常结束**
2. 若正常结束，则从设备控制器中**读出一个字的数据**（或者设备把数据经 DMA 直接写入了内存），经由 CPU 放入**内存缓冲区**中
3. 若非正常结束，则根据异常原因做相应的处理
4. **唤醒**因等待该 I/O 而阻塞的进程
- 中断处理程序**与硬件密切相关**，它是 I/O 软件中与硬件最接近的一层

### 📐 各层功能归属速查（⭐⭐⭐ 选择题常考）
| 功能 | 所在层次 |
|---|---|
| 向用户提供库函数（printf、scanf） | 用户层软件 |
| SPOOLing 假脱机 | 用户层软件 |
| **向上层提供统一的系统调用接口** | **设备独立性软件** |
| **逻辑设备名 → 物理设备名映射（LUT）** | **设备独立性软件** |
| **设备的分配与回收** | **设备独立性软件** |
| **缓冲区管理** | **设备独立性软件** |
| 设备保护（访问权限检查） | 设备独立性软件 |
| **计算磁盘的柱面号、磁头号、扇区号**（物理地址） | **设备驱动程序** |
| **设置设备寄存器、检查设备状态、启动设备** | **设备驱动程序** |
| 读出设备状态、判断 I/O 是否正常结束、唤醒进程 | **中断处理程序** |
| 执行 I/O 操作（读写磁头、打印） | 硬件 |

✏️ **例**：用户进程请求读磁盘上某文件的第 5 条记录，以下工作分别在哪一层完成？
- 把文件名/记录号转换成逻辑块号 → **文件系统**（在设备独立性软件之上）
- 检查用户是否有读权限 → **设备独立性软件**（或文件系统）
- 把逻辑块号转换为柱面号、磁头号、扇区号 → **设备驱动程序**
- 向磁盘控制器的寄存器写入命令 → **设备驱动程序**
- 磁盘读完后检查状态、唤醒进程 → **中断处理程序**

## 四、真题精讲：一次 I/O 的完整过程（⭐⭐⭐）

📝 **真题（2023 年第 46 题，8 分）**：进程 P 通过执行系统调用从键盘接收一个字符的输入。已知此过程中与进程 P 相关的操作包括：
① 将进程 P 插入就绪队列；② 将进程 P 插入阻塞队列；③ 将字符从键盘控制器读入系统缓冲区；④ 启动键盘中断处理程序；⑤ 进程 P 从系统调用返回；⑥ 用户在键盘上输入字符。
以上编号 ①~⑥ 仅用于标记操作，与操作的先后顺序无关。请回答下列问题。
(1) 按照正确的操作顺序，操作 ① 的前一个和后一个操作分别是上述操作中的哪一个？操作 ⑥ 的后一个操作是上述操作中的哪一个？
(2) 在上述哪个操作之后，CPU 一定从进程 P 切换到其他进程？在上述哪个操作之后 CPU 调度程序才能选中进程 P 执行？
(3) 完成上述哪个操作的代码属于键盘驱动程序？
(4) 键盘中断处理程序执行时，进程 P 处于什么状态？CPU 处于内核态还是用户态？

**先排出正确顺序**：
1. 进程 P 执行系统调用请求读键盘，此时还没有字符，P 需要等待 → **② 将进程 P 插入阻塞队列**
2. 用户按键 → **⑥ 用户在键盘上输入字符**
3. 键盘控制器发出中断 → **④ 启动键盘中断处理程序**
4. 中断处理程序调用驱动程序 → **③ 将字符从键盘控制器读入系统缓冲区**
5. 数据已到，唤醒 P → **① 将进程 P 插入就绪队列**
6. P 被调度执行，从系统调用中返回 → **⑤ 进程 P 从系统调用返回**

正确顺序：**② → ⑥ → ④ → ③ → ① → ⑤**

**(1)** 操作 ① 的**前一个是 ③**，**后一个是 ⑤**；操作 ⑥ 的**后一个是 ④**

**(2)**
- 在 **②** 之后，CPU **一定**从进程 P 切换到其他进程（P 阻塞了，不能继续占用 CPU）
- 在 **①** 之后，CPU 调度程序**才能**选中进程 P 执行（只有就绪进程才能被调度）

**(3)** 操作 **③**（将字符从键盘控制器读入系统缓冲区）的代码属于**键盘驱动程序**（直接读取设备控制器的数据寄存器，与具体设备有关）

**(4)**
- 键盘中断处理程序执行时，进程 P 处于**阻塞态**（它还在阻塞队列中，要等中断处理程序处理完后才会被唤醒）
- CPU 处于**内核态**（中断处理程序是操作系统内核代码）

## 五、I/O 核心子系统提供的服务（了解）

I/O 核心子系统（设备独立性软件 + 驱动程序 + 中断处理程序）要实现的功能：
- **I/O 调度**：用某种算法确定一个好的顺序来处理各个 I/O 请求（如磁盘调度算法）
- **设备保护**
- **假脱机技术（SPOOLing）**（用户层软件实现）
- **设备分配与回收**
- **缓冲区管理**
- **差错处理**

---

## ⚠️ 易错点

1. **块设备**（磁盘）可寻址，**字符设备**（键盘、鼠标）不可寻址
2. 程序直接控制和中断驱动方式中，数据要**经过 CPU 寄存器**；DMA 和通道直接在设备与内存间传送
3. 通道**没有自己的内存**，与 CPU 共享内存
4. **设备独立性软件**：统一接口、LUT 映射、设备分配回收、**缓冲区管理**、设备保护、差错处理
5. **设备驱动程序**：把抽象命令转换为具体操作，**计算磁盘物理地址**，设置寄存器、启动设备；**与 I/O 控制方式有关**
6. **中断处理程序**：检查状态、读数据、**唤醒进程**
7. 设备独立性：用户用**逻辑设备名**；更换设备**不需要修改程序**
8. 单用户系统一张 LUT；多用户系统每用户一张 LUT
9. 中断处理程序执行时，等待 I/O 的进程仍是**阻塞态**，CPU 在**内核态**

## 📋 本课小结

| 层次 | 主要功能 |
|---|---|
| 用户层软件 | 库函数、SPOOLing；把请求翻译成系统调用 |
| 设备独立性软件 | 统一接口、LUT、设备分配、缓冲管理、保护、差错处理 |
| 设备驱动程序 | 命令转换、设置寄存器、启动设备、计算物理地址 |
| 中断处理程序 | 检查状态、读数据、唤醒进程 |
| 硬件 | 执行 I/O |

## 🏋️ 课后练习

1. 将下列工作归入 I/O 软件的相应层次：(a) 把逻辑设备名“LPT”映射为物理打印机 2；(b) 向打印机控制器的控制寄存器写入“开始打印”命令；(c) 打印完成后唤醒等待的进程；(d) 用户调用 printf 格式化输出；(e) 为进程分配一个缓冲区。
2. 为什么说设备驱动程序与 I/O 控制方式有关？举例说明。
3. 采用 DMA 方式时，一个数据块传送完毕后，由谁向 CPU 发出中断？中断处理程序主要做什么？
4. 多用户系统中，为什么每个用户需要一张逻辑设备表？

<details>
<summary>📖 答案</summary>

1. (a) **设备独立性软件**；(b) **设备驱动程序**；(c) **中断处理程序**；(d) **用户层软件**；(e) **设备独立性软件**
2. 驱动程序要直接操作设备控制器。若采用轮询方式，驱动程序要循环读取状态寄存器；若采用中断方式，驱动程序发出命令后让进程阻塞，数据由中断处理程序读取；若采用 DMA 方式，驱动程序要设置 DMA 控制器的内存地址、传送长度等寄存器。写法完全不同
3. 由 **DMA 控制器**发出中断；中断处理程序检查传送是否正常结束、做必要的后处理（如校验），并**唤醒**等待该数据的进程
4. 不同用户可能使用相同的逻辑设备名（如都叫“打印机 1”）却希望对应不同的物理设备，每个用户一张 LUT 可以**允许逻辑设备名重复**，互不干扰
</details>
