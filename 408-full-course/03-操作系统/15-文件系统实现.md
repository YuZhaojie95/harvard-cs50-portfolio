# 操作系统 第 15 课 · 文件系统的实现：层次结构、磁盘与内存布局、VFS、挂载

> 🎯 **本课目标**
> 1. 了解**文件系统的层次结构**：每一层做什么
> 2. 了解文件系统在**磁盘上的布局**（MBR、分区、引导块、超级块、inode 区……）和在**内存中的数据结构**

> 4. 理解**文件系统挂载（安装）**
> 5. 把“**打开一个文件、读一个字节**”的全过程串起来

## 🚪 课前引入

你插上一个 U 盘（FAT32 格式），又打开一个硬盘上的文件（NTFS 或 ext4 格式），还访问了一个网络共享文件夹……它们的存储方式完全不同，为什么你用的都是同一个“打开”“读取”“保存”？

因为操作系统在各种不同的文件系统之上，建立了一层**统一的接口**——**虚拟文件系统（VFS）**。

🧒 **比喻：万能充电器**
- 各种手机的充电口不同（Type-C、Lightning、Micro USB）= 各种文件系统（FAT32、NTFS、ext4）
- 万能充电器（VFS）对外只有一个插头（统一接口），内部根据手机型号选用对应的转接头（具体文件系统的实现）

## 一、文件系统的层次结构（⭐）

从上到下：
```
         用户 / 应用程序
              │  系统调用（open、read、write……）
┌─────────────────────────────┐
│ 用户调用接口                  │  向上提供文件操作的系统调用
├─────────────────────────────┤
│ 文件目录系统                  │  根据路径名查找目录，找到文件的 FCB/索引结点；管理文件目录
├─────────────────────────────┤
│ 存取控制验证模块              │  验证用户是否有权限访问（文件保护）
├─────────────────────────────┤
│ 逻辑文件系统与文件信息缓冲区   │  把用户要读写的记录号转换为逻辑地址（逻辑块号）
├─────────────────────────────┤
│ 物理文件系统                  │  把逻辑地址转换为物理地址（物理块号）
├──────────────┬──────────────┤
│ 辅助分配模块  │ 设备管理模块   │  辅助分配：空闲空间的分配与回收；设备管理：分配设备、启动 I/O
└──────────────┴──────────────┘
              │
            磁盘
```

✏️ **例**：用户请求删除文件 D:/工作目录/学生信息.xlsx 的最后 100 条记录：
1. 用户通过**用户接口**发出上述请求
2. **文件目录系统**根据路径找到相应的 FCB/索引结点
3. **存取控制模块**检验该用户是否有删除权限
4. **逻辑文件系统**把“最后 100 条记录”换算成**逻辑地址**（逻辑块号）
5. **物理文件系统**把逻辑地址转换为**物理地址**
6. 要删除记录，所以要通知**辅助分配模块**回收存储空间
7. 最后的删除操作由**设备管理模块**完成（启动磁盘 I/O）

## 二、文件系统的全局结构（布局）（⭐⭐）

### 📐 磁盘上的布局（外存）
```
┌──────┬────────────────┬────────────────┬────────────────┐
│ MBR  │    分区 1       │    分区 2       │    分区 3       │
│（主引导│                │                │                │
│记录+分│                │                │                │
│区表） │                │                │                │
└──────┴────────────────┴────────────────┴────────────────┘
               │
               ▼  一个分区（文件系统）的内部结构：
┌────────┬────────┬──────────────┬──────────┬─────────┬──────────────┐
│ 引导块  │ 超级块  │ 空闲空间管理   │ i 结点区  │ 根目录   │ 其他文件和目录  │
│（PBR）  │        │（位示图等）    │          │         │               │
└────────┴────────┴──────────────┴──────────┴─────────┴──────────────┘
```
- **主引导记录（MBR）**：磁盘的 0 号扇区，包含**磁盘引导程序**和**分区表**
- **引导块（PBR，分区引导记录）**：每个分区的第一个块，包含**分区引导程序**（用于启动该分区的操作系统；若分区中没有 OS，引导块为空）
- **超级块**：包含**文件系统的所有关键信息**：分区的块数、块的大小、空闲块的数量和指针、空闲 FCB 的数量和指针……在计算机启动时（或该文件系统首次使用时）被**读入内存**
- **空闲空间管理**：位示图、成组链接的信息等
- **i 结点区（索引结点区）**：存放所有文件的**索引结点**（是一个数组，按 inode 号访问）
- **根目录**：文件系统的根目录文件
- 其余是**文件和目录的数据块**

📌 把磁盘“做成”一个可用的启动盘的顺序（第 2 课，2021 年第 46 题）：
**物理格式化（低级格式化，划分扇区）→ 分区（写分区表）→ 逻辑格式化（高级格式化，在分区上创建文件系统：超级块、空闲空间管理、inode 区、根目录）→ 安装操作系统**

### 📐 内存中的数据结构
- **内存中的安装表（挂载表）**：包含每个已安装文件系统分区的有关信息
- **目录结构的缓存**：最近访问的目录信息（加快路径查找）
- **系统范围的打开文件表**：包含每个打开文件的 FCB（索引结点）副本及其他信息（打开计数等）
- **每个进程的打开文件表**：读写指针、访问权限、指向系统打开文件表的指针
- （以及文件数据的**缓冲区**）

📐 **open 系统调用的全过程**（结合上一课）：
1. 根据路径名检索目录（可能先在**目录缓存**中查找，找不到才读磁盘）
2. 找到文件的索引结点，检查权限
3. 若该文件**已经在系统打开文件表**中（其他进程打开过），则打开计数 + 1；否则把索引结点读入内存，在系统打开文件表中新建表项
4. 在**进程打开文件表**中新建一个表项，指向系统打开文件表中的表项
5. 返回**文件描述符**（进程打开文件表中的下标）

📐 **read 系统调用**：
1. 通过文件描述符找到进程打开文件表项 → 系统打开文件表项 → 索引结点
2. 根据**读写指针**和要读的字节数，算出**逻辑块号**
3. 通过索引结点中的地址项（直接/间接）把逻辑块号转换为**物理块号**
4. 若数据已在**缓冲区（高速缓存）**中则直接复制；否则启动磁盘 I/O 读入（进程可能阻塞）
5. 把数据复制到用户缓冲区，更新读写指针

## 三、虚拟文件系统（VFS）（⭐⭐）

### 📐 为什么需要 VFS
- 普通用户希望：无论访问哪种文件系统，都使用**同样的接口**
- 不同的文件系统（ext4、NTFS、FAT32、NFS 网络文件系统……）的实现方式、数据结构都不同，若直接让应用程序面对它们，编程会非常麻烦

### 📐 VFS 的作用
1. **向上层用户进程提供统一标准的系统调用接口**，**屏蔽底层具体文件系统的实现差异**
2. VFS **要求下层的文件系统必须实现某些规定的函数功能**，如 open、read、write……一个新的文件系统想在某 OS 上被使用，就必须满足该 OS 的 VFS 的要求
3. 每打开一个文件，VFS 就在主存中新建一个 **vnode（虚拟结点）**，用**统一的数据结构**表示文件，无论该文件存储在哪个文件系统中
   - vnode 只存在于**主存**中，而 inode 既会被调入主存，也会在外存中存储
   - 打开文件后，创建 vnode，并将文件信息复制到 vnode 中，vnode 的**函数功能指针**指向具体文件系统的函数功能

```
    用户进程（open、read、write）
               │
               ▼
   ┌──────────────────────┐
   │   虚拟文件系统 VFS     │  统一接口，vnode
   └──┬───────┬────────┬──┘
      ▼       ▼        ▼
    ext4    FAT32     NFS
   （本地）  （U盘）   （网络）
```

📐 **VFS 的对象（Linux）**：超级块对象（一个已安装的文件系统）、索引结点对象（一个文件）、目录项对象（一个目录项，路径的一部分）、文件对象（一个被进程打开的文件）

📝 **真题（2025 年第 28 题）**：关于虚拟文件系统，下列说法正确的是：
A. 虚拟文件系统是运行在虚拟内存的文件系统　B. VFS 可以加快文件系统的访问速度　C. VFS 定义了可访问不同文件系统的统一接口　D. VFS 只能访问本地文件系统，不能访问网络文件系统
→ **C**
- A：“虚拟”指的是对多种文件系统的**抽象**，与虚拟内存无关
- B：VFS 多了一层抽象，并不能加快访问速度
- D：VFS 也支持网络文件系统（如 NFS）

## 四、文件系统挂载（⭐）

### 📐 概念
**文件系统挂载（mounting，安装）**：把一个新的文件系统**“接入”**到现有的目录树中，使其可以被访问。
- 🧒 比喻：插上 U 盘后，Windows 把它显示为“E:”盘；Linux 把它“挂”到某个目录下，如 `/mnt/usb`，之后访问 `/mnt/usb/a.txt` 就是访问 U 盘里的 a.txt
- 挂载的那个目录称为**挂载点**

### 📐 挂载要做的事
1. 在 VFS 中**注册**新挂载的文件系统。内存中的**挂载表（mount table）**包含每个文件系统的相关信息，包括文件系统类型、容量大小等
2. 新挂载的文件系统，要向 VFS 提供一个**函数地址列表**（实现 VFS 规定的函数）
3. 将新文件系统加到**挂载点**，也就是将新文件系统挂载在某个父目录下

## 五、文件系统的效率与可靠性（了解）

### 📐 提高效率
- **目录缓存**、**磁盘高速缓存（缓冲区）**：把常用的磁盘块留在内存中
- **提前读**：顺序访问时，读当前块的同时把下一块也读入
- **延迟写**：写入的数据先放在缓冲区中，不立即写回磁盘
- **合理分配**：把一个文件的块尽量放在同一柱面或相邻柱面，减少寻道

### 📐 提高可靠性
- **备份**：定期把文件复制到其他存储介质
- **日志文件系统**：先把要做的修改记到日志中，崩溃后可以根据日志恢复一致性
- **一致性检查**：开机时检查文件系统（如 fsck），修复不一致（例如某块既在空闲链表中又被某文件占用）

## ⚠️ 易错点

1. 文件系统层次中，**逻辑文件系统**把记录号转换为逻辑块号，**物理文件系统**把逻辑块号转换为物理块号
2. **超级块**包含文件系统的关键信息，启动时读入内存
3. 分区的第一块是**引导块**（分区引导记录）；整个磁盘的第一个扇区是 **MBR**
4. 逻辑格式化创建**文件系统**（超级块、inode 区、根目录……）；物理格式化划分**扇区**
5. **VFS 提供统一接口**，屏蔽差异，支持本地和网络文件系统；**不能加快访问速度**；与虚拟内存无关
6. vnode **只在内存**中；inode 在内存和外存中都有
7. 挂载：注册到挂载表 + 提供函数列表 + 挂到挂载点

## 🏋️ 课后练习

1. 用户读取文件的第 1000 条记录时，哪一层把“第 1000 条记录”转换为逻辑块号？哪一层把逻辑块号转换为物理块号？
2. 超级块中存放什么信息？为什么要在启动时读入内存？
3. 判断：(a) VFS 可以让应用程序用相同的系统调用访问 ext4 和 FAT32 文件；(b) VFS 中的 vnode 会写回磁盘；(c) 文件系统的根目录是在物理格式化时建立的。
4. 进程第一次 open 一个文件和第二个进程再 open 同一个文件，系统打开文件表的处理有何不同？

<details>
<summary>📖 答案</summary>

1. **逻辑文件系统**把记录号转换为逻辑块号；**物理文件系统**把逻辑块号转换为物理块号
2. 超级块存放文件系统的关键信息：分区块数、块大小、空闲块数量及位置、空闲 inode 数量及位置、inode 区位置等。分配/回收块和 inode 时都要频繁使用这些信息，读入内存可以避免每次都访问磁盘
3. (a) **对**；(b) **错**，vnode 只在内存中；(c) **错**，在**逻辑格式化**时建立
4. 第一次 open：系统打开文件表中没有该文件，需要把索引结点从磁盘读入，**新建**表项，打开计数 = 1；第二个进程 open：系统打开文件表中已有该表项，只需**打开计数 + 1**，不需要再读索引结点；两个进程各自在自己的进程打开文件表中新建表项
</details>
