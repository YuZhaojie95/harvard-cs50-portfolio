## 🚪 课前引入

想象你刚买了一台**裸机**——只有 CPU、内存、硬盘、键盘、显示器，没装任何软件。
你想让它帮你计算 1 + 1，得怎么做？
- 你得知道 CPU 的指令编码，用二进制写出程序
- 你得自己决定程序放在内存的哪个地址
- 你得自己写代码去控制键盘、显示器的每一个寄存器
- 如果你想同时听歌、打字、下载文件……那就更复杂了：谁先用 CPU？内存怎么分？

这显然太难了！于是人们编写了一个“**大管家**”程序，它：
1. **管理**计算机的所有硬件和软件资源（CPU、内存、硬盘、打印机、文件……）
2. **组织、调度**多个程序有条不紊地运行
3. 给用户和其他程序提供**方便好用的接口**（点鼠标、敲命令、调用函数）

这个“大管家”就是**操作系统（Operating System，OS）**。Windows、macOS、Linux、Android、iOS 都是操作系统。

🧒 **比喻：酒店**
- 硬件（CPU、内存、硬盘……）= 酒店的**房间、餐厅、电梯**
- 应用程序 = **客人**
- 操作系统 = **酒店前台 + 管理团队**：分配房间（内存）、安排电梯（CPU）、管理行李寄存（文件）、处理客人的各种请求（系统调用）
- 客人不需要知道电梯怎么修、房间钥匙怎么做，只需要找前台就行

## 一、操作系统的概念（⭐⭐）

### 📐 计算机系统的层次结构
```
┌───────────────────────────────┐
│            用  户              │
├───────────────────────────────┤
│ 应用程序（浏览器、微信、游戏）   │
├───────────────────────────────┤
│ 系统程序/工具（编译器、Shell）   │   ← 也常被看作“操作系统之上的软件”
├───────────────────────────────┤
│         操 作 系 统             │   ← 最基本的系统软件
├───────────────────────────────┤
│   裸机（CPU、内存、I/O 设备）    │
└───────────────────────────────┘
```
- 操作系统**直接运行在裸机之上**，是**最基本的系统软件**
- 裸机 + 操作系统 = 一台功能更强、使用更方便的“**虚拟机器**”（扩充机器）

### 📐 定义
**操作系统**是指**控制和管理**整个计算机系统的**硬件与软件资源**，合理地**组织、调度**计算机的工作与资源的分配，进而为用户和其他软件提供**方便的接口与环境**的程序集合。

记住三个关键词：
1. **管理资源**（对下：管理硬件）
2. **组织调度**（对内：让程序高效运行）
3. **提供接口**（对上：服务用户和应用程序）

### 📐 操作系统的目标和作用
| 角度 | 作用 |
|---|---|
| 作为**用户与计算机硬件之间的接口** | 让用户方便地使用计算机（命令接口、程序接口、图形界面） |
| 作为**计算机系统资源的管理者** | 管理处理机、存储器、文件、设备四大资源 |
| 作为**扩充机器（虚拟机器）** | 在裸机上覆盖一层软件，把硬件“包装”成功能更强、更好用的机器 |

## 二、操作系统的基本特征（⭐⭐⭐）

操作系统有四个基本特征：**并发、共享、虚拟、异步**。其中**并发和共享是最基本的特征**，二者**互为存在条件**。

### 📐 1. 并发（Concurrence）
**两个或多个事件在同一时间间隔内发生**。
- 在**单 CPU** 系统中，宏观上多个程序“同时”运行，**微观上是交替执行**的（CPU 快速切换）
- ⚠️ **并发 ≠ 并行**：
  - **并发**：同一**时间间隔**内（一段时间内）发生，微观上可能交替
  - **并行**：同一**时刻**发生，真正的“同时”，需要**多个 CPU（多核）**或多个部件
- 🧒 比喻：一个厨师**轮流**炒三个菜——并发；三个厨师**同时**各炒一个菜——并行
- 操作系统的并发性是通过**引入进程**实现的（下一课详讲）

### 📐 2. 共享（Sharing）
**系统中的资源可供内存中多个并发执行的进程共同使用**。两种方式：
1. **互斥共享**：一段时间内只允许**一个进程**访问，如**打印机**、磁带机、某些变量。这类资源叫**临界资源（独占资源）**
   - 🧒 公共厕所的一个隔间：同一时间只能一个人用
2. **同时访问**：一段时间内允许**多个进程“同时”**访问（宏观上同时，微观上可能交替），如**磁盘**、可重入代码
   - 🧒 图书馆的一本电子书：很多人可以同时读

### 📐 并发与共享的关系
- **没有并发，就谈不上共享**：如果同一时刻只运行一个程序，资源给它独用就行了，谈何共享？
- **没有共享，就无法并发**：如果多个程序不能共享 CPU、内存、磁盘，它们就不可能同时运行
- 所以二者**互为存在条件**，是 OS **最基本**的两个特征

### 📐 3. 虚拟（Virtual）
**把一个物理上的实体变为若干个逻辑上的对应物**。
- **时分复用技术**：
  - **虚拟处理器**：一个 CPU 被多个进程轮流使用，每个进程觉得自己有一个 CPU
  - **虚拟设备**：SPOOLing 技术把一台打印机变成多台“逻辑打印机”
- **空分复用技术**：
  - **虚拟存储器**：把有限的物理内存“变大”，每个进程觉得自己有很大的独立地址空间
- 如果 n 是某物理设备对应的虚拟设备数，用时分复用则每台虚拟设备的平均速度 ≤ 1/n 物理速度；用空分复用则每台虚拟设备占用的空间 ≤ 1/n

### 📐 4. 异步（Asynchronism）
多道程序环境下，进程的执行**不是一贯到底**的，而是**走走停停**，以**不可预知的速度**向前推进。
- 例：进程 A 正在运行，需要读磁盘，它就要**等待**；与此同时 CPU 去执行进程 B……A 什么时候能继续、要多久完成，事先无法预知
- 只要运行环境相同，OS 必须保证**多次运行同一程序，都能得到相同的结果**（这就是后面“进程同步”要解决的问题）

🧒 **一句话总结**：并发（一起跑）→ 共享（一起用）→ 虚拟（看起来每人都有一份）→ 异步（走走停停，速度不可预知）。

## 三、操作系统的功能（⭐⭐）

### 📐 作为资源管理者：四大管理功能
| 功能 | 管理的资源 | 主要任务 | 本书对应章节 |
|---|---|---|---|
| **处理机管理** | CPU | 进程控制、进程同步、进程通信、**死锁处理**、**处理机调度** | 第 3~8 课 |
| **存储器管理** | 内存 | **内存分配与回收**、地址映射、内存保护与共享、**内存扩充（虚拟内存）** | 第 9~12 课 |
| **文件管理** | 文件（软件资源） | 文件存储空间管理、目录管理、文件读写管理与保护 | 第 13~15 课 |
| **设备管理** | I/O 设备 | 缓冲管理、设备分配、设备处理、虚拟设备 | 第 16~18 课 |

🧒 在多道程序环境下，**处理机的分配和运行都以进程（或线程）为基本单位**，所以处理机管理也叫**进程管理**。

### 📐 作为用户与硬件之间的接口
**1. 命令接口**：用户**直接**使用，通过命令控制作业运行
- **联机命令接口（交互式命令接口）**：用户**说一句，系统做一句**。如 Windows 的 cmd、Linux 的 Shell（终端里敲 `ls`、`cd`）
- **脱机命令接口（批处理命令接口）**：用户**一次性写好一堆命令**（作业控制说明书），交给系统**自动**一条条执行，中间用户不能干预。如 Windows 的 .bat 批处理文件、Linux 的 shell 脚本

**2. 程序接口**：由一组**系统调用**（广义指令）组成，用户**只能在程序中**使用，通过程序**间接**使用
- 例：C 语言的 `printf()` 最终会调用 `write` 系统调用；`fopen()` 最终调用 `open` 系统调用
- **系统调用是应用程序请求操作系统服务的唯一方式**（下一课详讲）

**3. 图形用户界面（GUI）**：窗口、图标、菜单、鼠标。本质上 GUI 也是**调用系统调用**实现的，考试中一般把 GUI 归为**命令接口**的一种形式

📌 **记忆**：“**命令接口给人用，程序接口给程序用**”。

### 📐 作为扩充机器
没有软件的机器叫**裸机**；覆盖了软件的机器叫**扩充机器**或**虚拟机**。OS 把硬件的复杂细节隐藏起来，让用户面对的是一台“更好用”的机器。

## 四、操作系统的发展与分类（⭐⭐）

### 📐 1. 手工操作阶段（无操作系统）
- 程序员把程序穿孔在纸带/卡片上，装入输入机，启动运行，取走结果
- 缺点：**用户独占全机**；**CPU 等待手工操作**，利用率极低
- 矛盾：**人机矛盾**（人慢机快）、**CPU 与 I/O 设备速度不匹配**

### 📐 2. 批处理阶段
#### (1) 单道批处理系统
引入**脱机输入/输出**技术（用外围机+磁带），由**监督程序**负责控制作业一个接一个地**自动**执行。
- 特点：**自动性**、**顺序性**、**单道性**（内存中只有一道程序）
- 优点：减少了人工操作的时间
- 缺点：内存中仅一道程序，**CPU 在等待 I/O 时空闲**，资源利用率仍然低

#### (2) 多道批处理系统（⭐⭐⭐ 真正的操作系统诞生）
允许**多个程序同时进入内存**，并允许它们在 CPU 中**交替运行**。当一道程序因 I/O 暂停时，CPU 立即转去运行另一道程序。
- 特点：
  - **多道**：内存中同时存放多道相互独立的程序
  - **宏观上并行**：同时进入系统的多道程序都处于运行过程中
  - **微观上串行**：各道程序轮流使用 CPU，交替执行
- 优点：**资源利用率高**（CPU 与 I/O 设备并行工作）、**系统吞吐量大**
- 缺点：
  - **用户响应时间长**
  - **不提供人机交互能力**：用户提交作业后就不能干预了，程序出错也不能即时修改
- 为了实现多道程序，OS 必须解决：**处理机的分配、内存的分配与保护、I/O 设备的分配、文件的组织与管理、作业的组织与管理、用户与系统的接口**——这就是 OS 的各大功能的由来

📝 **真题（2022 年第 23 题）**：下列关于多道程序系统的叙述中，**不正确**的是：
A. 支持进程的并发执行　B. 不必支持虚拟存储管理　C. 需要实现对共享资源的管理　D. 进程数越多 CPU 利用率越高
→ **D**
- A：多道程序就是为了并发，对
- B：多道程序只要求多个程序同时在内存，**不要求**虚拟内存（早期多道批处理系统就没有虚拟内存），对
- C：多个进程共享 CPU、内存、设备，必须管理，对
- D：进程数过多时，内存不够，会频繁换入换出（甚至**抖动**），CPU 利用率反而**下降**，错

### 📐 3. 分时操作系统（⭐⭐）
把处理器的运行时间分成很短的**时间片**，按时间片**轮流**把处理器分配给各联机作业使用。
- 🧒 一台主机连着很多终端，每个用户觉得自己**独占**一台计算机
- 特点：
  - **同时性（多路性）**：允许多个终端用户同时使用一台计算机
  - **交互性**：用户可以通过终端与系统进行人机对话
  - **独立性**：各用户独立操作，互不干扰
  - **及时性**：用户请求能在很短时间内获得响应
- 解决了**人机交互**问题
- 缺点：**不能优先处理紧急任务**（对所有作业一视同仁，按时间片轮流）

### 📐 4. 实时操作系统
在**规定的时间（截止时间）内**必须完成对事件的处理，并及时响应。
- **硬实时系统**：某个动作**必须绝对**在规定时刻或时间范围内完成，如导弹控制、飞行控制、自动驾驶
- **软实时系统**：偶尔违反时间规定是可以接受的，如订票系统、视频播放
- 特点：**及时性**、**可靠性**，主要特点是能**优先响应紧急任务**
- 与分时系统比较：实时系统更强调**及时性、可靠性**；分时系统更强调**交互性**

### 📐 5. 网络操作系统和分布式操作系统
- **网络操作系统**：把网络中的各台计算机有机地结合起来，实现**资源共享**和**数据通信**。如 Windows Server
- **分布式操作系统**：系统中任意两台计算机通过通信交换信息；各计算机**地位平等**、无主从之分；**资源共享**；系统中的若干台计算机可以**互相协作**完成同一个任务（**分布性、并行性**）。用户感觉不到是多台机器

### 📐 6. 个人计算机操作系统
目前使用最广泛：Windows、Linux、macOS。

### 📐 7. 其他
- **嵌入式操作系统**：运行在嵌入式设备中（路由器、智能手表），资源受限
- **服务器操作系统**、**智能手机操作系统**（Android、iOS）

### 📐 总结：几种系统的对比
| 系统 | 核心特点 | 解决的问题 | 缺点 |
|---|---|---|---|
| 单道批处理 | 自动、顺序、单道 | 人机矛盾 | CPU 仍常等待 I/O |
| **多道批处理** | 多道、宏观并行、微观串行 | **资源利用率低** | **无交互**、响应时间长 |
| **分时** | 时间片轮转，多路、交互、独立、及时 | **人机交互** | 不能优先处理紧急任务 |
| **实时** | 及时性、可靠性 | **紧急任务优先** | 资源利用率不一定高 |

## 五、多道程序设计的效果计算（⭐⭐）

### ✏️ 例：单道 vs 多道
两个程序 A、B，按下列顺序使用资源：
- A：计算 10ms → I/O 20ms → 计算 10ms
- B：计算 20ms → I/O 10ms → 计算 10ms
（假设 A 先运行，CPU 和 I/O 设备可并行，A、B 使用同一台 I/O 设备时要排队）

**单道**（A 全部完成后 B 才开始）：
- 总时间 = (10 + 20 + 10) + (20 + 10 + 10) = **80ms**
- CPU 工作时间 = 10 + 10 + 20 + 10 = 50ms，CPU 利用率 = 50 / 80 = **62.5%**

**多道**：
```
时间(ms)   0    10    20    30    40    50    60
CPU        A    B     B     A     B     
I/O             A     A     B
```
逐步分析：
- 0~10：A 计算
- 10~30：A 做 I/O；CPU 空出来给 B，B 计算 10~30（20ms）
- 30~40：A 的 I/O 已完成，A 计算 30~40；B 开始 I/O 30~40
- 40~50：A 已结束；B 的 I/O 已完成，B 计算 40~50
- 总时间 = **50ms**，CPU 工作 50ms，利用率 = 50 / 50 = **100%**

🧒 同样两个程序，多道比单道快了 30ms，CPU 一直没闲着！

⚠️ 做这类题的步骤：
1. 画时间轴，分别画出 **CPU 行** 和 **每种 I/O 设备行**
2. 同一时刻 CPU 只能给一个程序；同一台 I/O 设备同一时刻也只能给一个程序
3. 按题目给出的优先级（或先来先服务）安排

## ⚠️ 易错点

1. OS 是**最基本的系统软件**，直接运行在**裸机**上
2. **并发**是一段时间内；**并行**是同一时刻。单核 CPU 只能并发，不能并行（指 CPU 执行）
3. **并发和共享是最基本的特征**，互为存在条件
4. 互斥共享的资源叫**临界资源**（如打印机）；磁盘是可以“同时访问”的
5. **系统调用（程序接口）是程序请求 OS 服务的唯一方式**；命令接口是给用户用的
6. 多道批处理：**资源利用率高、吞吐量大**，但**无交互能力**
7. 分时系统：**交互性**；实时系统：**及时性、可靠性**
8. 多道程序中，**进程数不是越多越好**（2022 年第 23 题）
9. 多道程序系统**不必**支持虚拟存储管理

## 🏋️ 课后练习

1. 判断：(a) 并发的程序一定是并行的；(b) 单处理器系统中，任一时刻只有一个程序在 CPU 上运行；(c) 分时系统的主要目标是提高资源利用率。
2. 下列哪些属于操作系统的功能：(a) 编译 C 程序；(b) 分配内存；(c) 管理文件目录；(d) 进程调度；(e) 编辑文档。
3. 用户在 C 程序中调用 `fopen()` 打开文件，最终使用的是操作系统的哪种接口？在 Linux 终端输入 `ls` 使用的是哪种接口？
4. 为什么说并发和共享互为存在条件？
5. 程序 A：计算 20ms → 打印 30ms → 计算 10ms；程序 B：计算 10ms → 打印 20ms → 计算 20ms。两程序同时进入内存，A 先运行，只有一台打印机，CPU 和打印机可并行工作。求多道运行时完成两程序的总时间和 CPU 利用率。
6. 飞机的飞行控制系统应该选择哪种操作系统？火车票订票系统呢？

<details>
<summary>📖 答案</summary>

1. (a) **错**，并发不一定并行；(b) **对**；(c) **错**，分时系统的主要目标是**交互性/及时响应**，提高资源利用率是多道批处理的目标
2. **(b)、(c)、(d)**；编译器和文字编辑器是应用程序/系统程序，不属于 OS 功能
3. `fopen()` 最终使用**程序接口（系统调用）**；终端输入 `ls` 使用的是**命令接口（联机命令接口）**
4. 若没有并发（任一时刻只有一个程序），资源独占即可，不存在共享问题；若资源不能共享（每个程序独占全部资源），多个程序就无法同时存在和运行，也就无法并发
5. 0~20 A 计算；20~50 A 打印，B 在 20~30 计算；B 在 30 要打印但打印机忙，等到 50；50~60 A 计算，同时 50~70 B 打印；70~90 B 计算。总时间 **90ms**；CPU 工作 20 + 10 + 10 + 20 = 60ms，利用率 = 60 / 90 ≈ **66.7%**
6. 飞行控制：**硬实时系统**；订票系统：**软实时系统**
</details>
