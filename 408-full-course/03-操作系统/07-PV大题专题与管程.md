## 🚪 课前引入

PV 大题每年必考，通常 **7~8 分**。很多同学觉得它“玄”，其实它有非常固定的套路。

🧒 解 PV 题就像**安排一场派对的规矩**：
1. 先搞清楚**有哪些人**（进程）、**每人干什么**（操作）
2. 找出**谁必须等谁**（同步）、**什么东西不能同时用**（互斥）
3. 为每种“等待理由”和每个“不能同时用的东西”设一个**信号量**
4. 在合适的位置加上 P（等）和 V（通知）

## 一、PV 大题的通用解题步骤（⭐⭐⭐）

### 📐 第一步：关系分析
找出题目中有几类进程，分析它们之间的关系：
- **互斥关系**：哪些资源（缓冲区、设备、变量、门……）一次只能一个进程使用？
- **同步关系**：哪些操作之间有**先后顺序**？（“A 做完 B 才能做”“有 X 时才能 Y”“不满时才能放”“不空时才能取”）

### 📐 第二步：整理思路
- 写出每类进程的**操作流程**（伪代码框架）
- 确定 **P、V 操作的大致位置**：
  - 互斥：临界区**前 P 后 V**
  - 同步：**前 V 后 P**
  - 资源：用之前 P，释放后 V

### 📐 第三步：设置信号量
- 每个互斥资源一个互斥信号量（初值 **1**）
- 每种同步关系/资源一个信号量（初值 = **初始可用资源数**，一般为 0 或 n）
- **说明每个信号量的含义和初值**（题目通常明确要求，不写会扣分！）

### 📐 常用技巧总结
| 情形 | 技巧 |
|---|---|
| 缓冲区有容量限制 | empty = n（空位）、full = 0（产品） |
| 某处最多容纳 k 个进程 | 设资源信号量 = k |
| 需要“连续”执行多次 | 在循环外面加一个互斥信号量把整个循环包起来 |
| 需要“第一个/最后一个”做特殊事 | 用计数器 count + 保护它的 mutex |
| 多种产品、各取所需 | 为每种产品设一个信号量 |
| 同一进程需要多个资源 | 注意 P 的顺序，防止死锁；或限制并发数 |
| 同一进程内的顺序 | 不需要信号量 |

⚠️ **书写规范**：
- 用 `semaphore x = 初值;` 声明，并用注释说明含义
- 用 `P(x)`/`V(x)` 或 `wait(x)`/`signal(x)`，两者都可以（近年题目多用 wait/signal）
- 进程用 `process 名字() { while(1) { ... } }` 或 `cobegin ... coend` 描述

## 二、真题精讲

### 📝 真题 1（2025 年第 45 题，8 分）⭐⭐⭐ 植树问题
> 三个人一起植树，甲挖坑，乙放树苗入坑并填土，丙负责为新种树苗浇水。步骤依次为：挖树坑，放树苗，填土和浇水。现在有铁锹和水桶各一个，铁锹用于挖树坑，填土。水桶用于浇水。当树坑数量小于 3 时，甲才可以挖树坑。设初始坑 = 0，铁锹水桶均可用，定义尽可能少的信号量，用 wait()、signal() 操作描述植树过程中三人的同步互斥关系，并说明所用信号量的作用及其初值。

**第一步：关系分析**
- **互斥**：
  - **铁锹**：甲（挖坑）和乙（填土）都要用 → 互斥
  - **水桶**：只有丙用 → **不需要**信号量（“尽可能少”）
- **同步**：
  - 甲挖好坑 → 乙才能放树苗（“有坑”才能种）
  - 乙填好土 → 丙才能浇水
  - 树坑数量 < 3 时甲才能挖：已挖好但**还没种好**的坑最多 3 个，乙种好一个（填完土）坑数减 1，甲才能再挖

**第二步：设置信号量**
```c
semaphore shovel = 1;   // 铁锹，互斥使用，初值 1
semaphore empty  = 3;   // 还可以再挖的坑的数量（坑数 < 3 的限制），初值 3
semaphore pit    = 0;   // 已挖好、等待放树苗的坑的数量，初值 0
semaphore filled = 0;   // 已填好土、等待浇水的树的数量，初值 0
```

**第三步：写代码**
```c
甲() {
    while (1) {
        wait(empty);        // 坑数 < 3 才能挖
        wait(shovel);       // 取铁锹
        挖树坑;
        signal(shovel);     // 放回铁锹
        signal(pit);        // 多了一个可以种树的坑
    }
}

乙() {
    while (1) {
        wait(pit);          // 等有坑
        放树苗;
        wait(shovel);       // 取铁锹
        填土;
        signal(shovel);     // 放回铁锹
        signal(empty);      // 这个坑已经种好，坑数 −1，甲可以再挖
        signal(filled);     // 通知丙浇水
    }
}

丙() {
    while (1) {
        wait(filled);       // 等有填好土的树
        浇水;               // 水桶只有丙用，不需要互斥
    }
}
```

🧒 **易错点分析**：
- 水桶只被丙一个人使用，设置信号量反而**多余**（题目要求“尽可能少的信号量”）
- 乙在“放树苗”时不需要铁锹，所以 wait(shovel) 应放在填土之前，而不是放树苗之前（这样甲可以在乙放树苗时继续用铁锹挖坑，并发度更高）
- signal(empty) 的位置：坑“消失”是在乙填完土之后（也有答案放在乙取到坑、放树苗之后，只要说明“树坑”的含义一致即可）

### 📝 真题 2（2009 年第 45 题）生产者-消费者变形：分奇偶
> 三个进程 P1、P2、P3 互斥使用一个包含 N（N > 0）个单元的缓冲区。P1 每次用 produce() 生成一个正整数并用 put() 送入缓冲区某一空单元中；P2 每次用 getodd() 从该缓冲区中取出一个奇数并用 countodd() 统计奇数个数；P3 每次用 geteven() 从该缓冲区中取出一个偶数并用 counteven() 统计偶数个数。请用信号量机制实现这三个进程的同步与互斥活动，并说明所定义信号量的含义。

```c
semaphore mutex = 1;    // 缓冲区互斥访问
semaphore empty = N;    // 空单元数
semaphore odd = 0;      // 缓冲区中奇数的个数
semaphore even = 0;     // 缓冲区中偶数的个数

P1() {
    while (1) {
        x = produce();
        P(empty);
        P(mutex);
        put(x);
        V(mutex);
        if (x % 2 == 0) V(even);
        else            V(odd);
    }
}

P2() {                          P3() {
    while (1) {                     while (1) {
        P(odd);                         P(even);
        P(mutex);                       P(mutex);
        getodd();                       geteven();
        V(mutex);                       V(mutex);
        V(empty);                       V(empty);
        countodd();                     counteven();
    }                               }
}                               }
```
📌 本质就是水果盘问题：一个生产者生产两种产品，两个消费者各取所需。

### 📝 真题 3（2011 年第 45 题）银行叫号
> 某银行提供 1 个服务窗口和 10 个供顾客等待的座位。顾客到达银行时，若有空座位，则到取号机上领取一个号，等待叫号。取号机每次仅允许一位顾客使用。当营业员空闲时，通过叫号选取一位顾客，并为其服务。顾客和营业员的活动过程描述如下：
> ```
> cobegin {
>     process 顾客i {
>         从取号机获取一个号码;
>         等待叫号;
>         获取服务;
>     }
>     process 营业员 {
>         while (TRUE) {
>             叫号;
>             为客户服务;
>         }
>     }
> } coend
> ```
> 请添加必要的信号量和 P、V（或 wait()、signal()）操作，实现上述过程中的互斥与同步。要求写出完整的过程，说明信号量的含义并赋初值。

```c
semaphore empty = 10;   // 空座位数
semaphore mutex = 1;    // 互斥使用取号机
semaphore full = 0;     // 已占座位（等待服务的顾客）数
semaphore service = 0;  // 营业员叫号（提供服务）

cobegin {
    process 顾客i {
        P(empty);               // 等空座位
        P(mutex);
        从取号机获取一个号码;
        V(mutex);
        V(full);                // 通知营业员：有顾客在等
        P(service);             // 等待叫号
        获取服务;
    }
    process 营业员 {
        while (TRUE) {
            P(full);            // 没有顾客则休息
            V(empty);           // 被叫到的顾客离开座位
            V(service);         // 叫号
            为客户服务;
        }
    }
} coend
```

### 📝 真题 4（2013 年第 45 题）博物馆
> 某博物馆最多可容纳 500 人同时参观，有一个出入口，该出入口一次仅允许一个人通过。参观者的活动描述如下：
> ```
> cobegin
>     参观者进程i: {
>         ...
>         进门;
>         ...
>         参观;
>         ...
>         出门;
>         ...
>     }
> coend
> ```
> 请添加必要的信号量和 P、V（或 wait()、signal()）操作，以实现上述过程中的互斥与同步。要求写出完整的过程，说明信号量的含义并赋初值。

```c
semaphore empty = 500;  // 博物馆还可容纳的人数
semaphore mutex = 1;    // 出入口一次只允许一人通过

参观者进程i: {
    P(empty);           // 博物馆满了就在外面等
    P(mutex);
    进门;
    V(mutex);
    参观;
    P(mutex);
    出门;
    V(mutex);
    V(empty);           // 腾出一个名额
}
```
⚠️ P(empty) 必须在 P(mutex) 之前：若先占住出入口再发现馆内已满，里面的人出不来（出门也要 mutex）→ 死锁。

### 📝 真题 5（2014 年第 47 题）连续取 10 件
> 系统中有多个生产者进程和多个消费者进程，共享一个能存放 1000 件产品的环形缓冲区（初始为空）。当缓冲区未满时，生产者进程可以放入其生产的一件产品，否则等待；当缓冲区未空时，消费者进程可以从缓冲区取走一件产品，否则等待。要求一个消费者进程从缓冲区连续取出 10 件产品后，其他消费者进程才可以取产品。请使用信号量 P、V（wait()、signal()）操作实现进程间的互斥与同步，要求写出完整的过程，并说明所用信号量的含义和初值。

```c
semaphore mutex1 = 1;   // 消费者之间互斥：保证一个消费者连续取 10 件
semaphore mutex2 = 1;   // 缓冲区互斥访问
semaphore empty = 1000; // 空位数
semaphore full = 0;     // 产品数

producer() {
    while (1) {
        生产一个产品;
        P(empty);
        P(mutex2);
        把产品放入缓冲区;
        V(mutex2);
        V(full);
    }
}

consumer() {
    while (1) {
        P(mutex1);                      // 抢到“连续取 10 件”的权利
        for (int i = 0; i < 10; i++) {
            P(full);
            P(mutex2);
            从缓冲区取出一件产品;
            V(mutex2);
            V(empty);
            消费这件产品;
        }
        V(mutex1);                      // 取满 10 件，让出权利
    }
}
```
📌 技巧：“**连续做 k 次**”→ 用一个互斥信号量把整个循环**包起来**。

### 📝 真题 6（2015 年第 45 题）信箱辩论（双缓冲区）
> 有 A、B 两人通过信箱进行辩论，每个人都从自己的信箱中取得对方的问题。将答案和向对方提出的新问题组成一个邮件放入对方的信箱中。假设 A 的信箱最多放 M 个邮件，B 的信箱最多放 N 个邮件。初始时 A 的信箱中有 x 个邮件（0 < x < M），B 的信箱中有 y 个（0 < y < N）。辩论者每取出一个邮件，邮件数减 1。A 和 B 两人的操作过程描述如下：
> ```
> A {                                        B {
>     while (TRUE) {                             while (TRUE) {
>         从 A 的信箱中取出一个邮件;                  从 B 的信箱中取出一个邮件;
>         回答问题并提出一个新问题;                   回答问题并提出一个新问题;
>         将新邮件放入 B 的信箱;                      将新邮件放入 A 的信箱;
>     }                                          }
> }                                          }
> ```
> 当信箱不为空时，辩论者才能从信箱中取邮件，否则等待。当信箱不满时，辩论者才能将新邮件放入信箱，否则等待。请添加必要的信号量和 P、V（或 wait、signal）操作，以实现上述过程的同步。要求写出完整过程，并说明信号量的含义和初值。

```c
semaphore Full_A = x;       // A 信箱中的邮件数
semaphore Empty_A = M - x;  // A 信箱中的空位数
semaphore Full_B = y;       // B 信箱中的邮件数
semaphore Empty_B = N - y;  // B 信箱中的空位数
semaphore mutex_A = 1;      // 互斥访问 A 的信箱
semaphore mutex_B = 1;      // 互斥访问 B 的信箱

A {
    while (TRUE) {
        P(Full_A);
        P(mutex_A);
        从 A 的信箱中取出一个邮件;
        V(mutex_A);
        V(Empty_A);
        回答问题并提出一个新问题;
        P(Empty_B);
        P(mutex_B);
        将新邮件放入 B 的信箱;
        V(mutex_B);
        V(Full_B);
    }
}
// B 与 A 对称：把 A、B 互换
```
📌 两个缓冲区 → 两套 full/empty/mutex，每个进程既是一个缓冲区的消费者，又是另一个的生产者。
⚠️ **初值不一定是 0 或 n**：本题 Full_A = x，Empty_A = M − x。

### 📝 真题 7（2017 年第 46 题）最大并发的读写互斥
> 某进程中有 3 个并发执行的线程 thread1、thread2 和 thread3，其伪代码如下所示：
> ```c
> // 复数的结构类型定义
> typedef struct { float a; float b; } cnum;
> cnum x, y, z;   // 全局变量
>
> // 计算两个复数之和
> cnum add(cnum p, cnum q) {
>     cnum s;
>     s.a = p.a + q.a;
>     s.b = p.b + q.b;
>     return s;
> }
>
> thread1 {             thread2 {             thread3 {
>     cnum w;               cnum w;               cnum w;
>     w = add(x, y);        w = add(y, z);        w.a = 1; w.b = 1;
>     ...                   ...                   z = add(z, w);
> }                     }                         y = add(y, w);
>                                                 ...
>                                             }
> ```
> 请添加必要的信号量和 P、V（或 wait()、signal()）操作，要求确保线程互斥访问临界资源，并且最大程度地并发执行。

**分析**（读-读不互斥，读-写互斥）：
- x：只被 thread1 **读** → 无需互斥
- y：thread1 读、thread2 读、**thread3 写** → thread1 与 thread3 互斥，thread2 与 thread3 互斥，但 **thread1 与 thread2 可以同时读**
- z：thread2 读、**thread3 写** → 互斥
- w 是各线程的局部变量，不共享

为了让 thread1 和 thread2 能同时读 y，**不能**只用一个 mutex_y，而要分别设：
```c
semaphore mutex_y1 = 1;   // thread1 与 thread3 对 y 的互斥
semaphore mutex_y2 = 1;   // thread2 与 thread3 对 y 的互斥
semaphore mutex_z = 1;    // thread2 与 thread3 对 z 的互斥

thread1 {
    cnum w;
    P(mutex_y1);
    w = add(x, y);
    V(mutex_y1);
    ...
}

thread2 {
    cnum w;
    P(mutex_y2);
    P(mutex_z);
    w = add(y, z);
    V(mutex_z);
    V(mutex_y2);
    ...
}

thread3 {
    cnum w;
    w.a = 1; w.b = 1;
    P(mutex_z);
    z = add(z, w);
    V(mutex_z);
    P(mutex_y1);
    P(mutex_y2);
    y = add(y, w);
    V(mutex_y1);
    V(mutex_y2);
    ...
}
```
- 检查死锁：thread2 先占 y2 再占 z；thread3 占 z 后**先释放**再去占 y1、y2 → 不会形成循环等待 ✓
📌 技巧：“**最大程度并发**” → 只对真正冲突的线程对设互斥，**读-读不设互斥**。

### 📝 真题 8（2019 年第 43 题）哲学家与碗
> 有 n（n ≥ 3）名哲学家围坐在一张圆桌边，每名哲学家交替地就餐和思考。在圆桌中心有 m（m ≥ 1）个碗，每两名哲学家之间有一根筷子。每名哲学家必须取到一个碗和两侧的筷子后，才能就餐，进餐完毕，将碗和筷子放回原位，并继续思考。为使尽可能多的哲学家同时就餐，且防止出现死锁现象，请使用信号量的 P、V 操作（wait()、signal() 操作）描述上述过程中的互斥与同步，并说明所用信号量及初值的含义。

**分析**：碗的数量限制了同时尝试就餐的人数。若同时尝试拿筷子的人数 ≤ n − 1，就不会死锁（与“最多 4 人”同理）。
```c
semaphore bowl = min(n - 1, m);     // 同时允许拿筷子的人数：不超过碗数，且 ≤ n−1 防死锁
semaphore chopsticks[n];            // 每根筷子，初值均为 1
for (int i = 0; i < n; i++) chopsticks[i] = 1;

哲学家i() {
    while (1) {
        思考;
        P(bowl);                        // 先拿碗
        P(chopsticks[i]);               // 拿左边筷子
        P(chopsticks[(i + 1) % n]);     // 拿右边筷子
        就餐;
        V(chopsticks[i]);
        V(chopsticks[(i + 1) % n]);
        V(bowl);
    }
}
```
- 若 m < n，碗数本身就限制了人数 ≤ m ≤ n − 1，不会死锁
- 若 m ≥ n，要人为限制为 n − 1

## 三、管程（⭐⭐）

### 📐 为什么引入管程
信号量机制的问题：大量的 P、V 操作**分散在各个进程中**，编写程序困难、**易出错**（如 P 的顺序写反导致死锁）。

**管程（Monitor）**：把**共享资源**以及对它的**操作**封装起来，由编译器保证**互斥**，程序员只需关注**同步**。
- 🧒 比喻：信号量像“每个人自带钥匙开门”，容易有人忘记还钥匙；管程像“请一个**管家**”，所有人要用资源都找管家，管家保证**同一时间只放一个人进屋**

### 📐 管程的定义与组成
管程是一种特殊的软件模块，由以下部分组成：
1. 管程的**名称**
2. **局部于管程内部的共享数据结构**说明
3. 对该数据结构进行操作的**一组过程（函数）**
4. 对局部于管程内部的共享数据**设置初始值**的语句

🧒 很像面向对象中的“**类**”：数据是私有成员，过程是公有方法。

### 📐 管程的特征
1. 管程内部的数据结构**只能被管程内部的过程访问**
2. 一个进程只有通过**调用管程内的过程**才能进入管程访问共享数据
3. **每次只允许一个进程在管程内执行**某个内部过程（**互斥由编译器自动实现**）

### 📐 条件变量（⭐⭐）
管程保证了互斥，但同步怎么办？比如生产者进入管程后发现缓冲区满了，它得**等待**，但它还在管程里，别的进程都进不来——所以需要**条件变量**。
- 每个条件变量对应一种**等待原因**，维护一个等待队列
- **x.wait()**：当 x 对应的条件不满足时，调用 wait 的进程**阻塞**，插入 x 的等待队列，并**释放管程**（让其他进程进入）
- **x.signal()**：x 对应的条件发生变化，**唤醒**一个因 x 阻塞的进程（若没有进程在等，则**什么也不做**）

### 📐 条件变量 vs 信号量（⭐⭐）
| | 信号量 | 条件变量 |
|---|---|---|
| 是否有值 | **有值**（value 记录资源数） | **没有值**，只有等待队列 |
| wait/P | value 减 1，**不够时**才阻塞 | **一定阻塞** |
| signal/V | value 加 1，有等待者就唤醒；**无等待者时 V 操作的效果被“记住”**（value 增加） | 有等待者就唤醒；**无等待者时什么也不做**（signal 的效果丢失） |
| 资源计数 | 信号量自己记录 | 由管程中的**共享数据**记录（如 count） |

### 📐 用管程解决生产者-消费者问题
```c
monitor ProducerConsumer {
    condition full, empty;     // 条件变量
    int count = 0;             // 缓冲区中产品数

    void insert(Item item) {   // 由生产者调用
        if (count == N)
            full.wait();       // 缓冲区满，等待
        count++;
        把 item 放入缓冲区;
        if (count == 1)
            empty.signal();    // 原来是空的，唤醒等待的消费者
    }

    Item remove() {            // 由消费者调用
        if (count == 0)
            empty.wait();      // 缓冲区空，等待
        count--;
        从缓冲区取出 item;
        if (count == N - 1)
            full.signal();     // 原来是满的，唤醒等待的生产者
        return item;
    }
}

producer() {                   consumer() {
    while (1) {                    while (1) {
        item = 生产一个产品;            item = ProducerConsumer.remove();
        ProducerConsumer.insert(item);  消费 item;
    }                              }
}                              }
```
- 互斥（同一时刻只有一个进程在 insert 或 remove 中）由**编译器**保证
- 程序员只需要写同步逻辑（何时 wait、何时 signal）
- Java 的 `synchronized` 关键字就是类似管程的机制

## ⚠️ 易错点

1. 一定要**说明信号量的含义和初值**，否则扣分
2. 信号量初值**不一定是 0、1、n**，要按题目的初始状态设（信箱题 Full_A = x）
3. **同步的 P 在前，互斥的 P 在后**
4. 只有一个进程使用的资源**不需要**信号量（植树题的水桶）
5. “连续取 k 件” → 用互斥信号量**包住整个循环**
6. “最大并发” → **读-读不互斥**，只对真正冲突的线程设互斥（2017 年）
7. 多资源（碗 + 筷子）→ 限制同时竞争的进程数 ≤ n − 1 防死锁
8. 管程的**互斥由编译器实现**；**条件变量没有值**，signal 在无人等待时不起作用
9. 条件变量的 wait **一定阻塞**；信号量的 P 不一定阻塞

## 🏋️ 课后练习

1. 某寺庙有小和尚、老和尚若干。有一个水缸，由小和尚提水入缸供老和尚饮用。水缸可容 10 桶水，水取自同一井中，水井很窄，每次只能容一个桶取水。水桶总数为 3 个。每次入缸取水仅为 1 桶，且不可同时进行。试给出有关从缸中取水和向缸中倒水的算法描述。
2. 理发店有 1 位理发师、1 把理发椅和 n 把供等候理发的顾客坐的椅子。若没有顾客，理发师便在理发椅上睡觉；顾客到来时，若理发师在睡觉则唤醒他；若理发师正在理发，有空椅子就坐下等，没有空椅子就离开。用信号量描述。（提示：用计数器 waiting 记录等待人数）
3. 管程中条件变量的 signal 操作与信号量的 V 操作有什么区别？

<details>
<summary>📖 答案</summary>

1. 信号量：`well = 1`（水井互斥）、`vat = 1`（水缸互斥）、`empty = 10`（缸中还能装几桶）、`full = 0`（缸中有几桶水）、`pail = 3`（水桶数）。
   ```c
   小和尚() { while (1) {
       P(empty); P(pail);
       P(well); 从井中打水; V(well);
       P(vat); 倒入水缸; V(vat);
       V(full); V(pail);
   } }
   老和尚() { while (1) {
       P(full); P(pail);
       P(vat); 从缸中取水; V(vat);
       V(empty); 喝水; V(pail);
   } }
   ```
   注意：必须先 P(empty)/P(full) 再 P(pail)，否则 3 个桶都被小和尚拿走而缸满时，老和尚拿不到桶取水 → 死锁
2. ```c
   int waiting = 0;              // 等待理发的顾客数
   semaphore mutex = 1;          // 保护 waiting
   semaphore customers = 0;      // 等待理发的顾客（理发师据此睡觉）
   semaphore barber = 0;         // 理发师是否准备好
   理发师() { while (1) {
       P(customers);             // 没顾客就睡觉
       P(mutex); waiting--; V(mutex);
       V(barber);                // 理发师准备好了
       理发;
   } }
   顾客() {
       P(mutex);
       if (waiting < n) {
           waiting++;
           V(customers);         // 唤醒理发师（若在睡）
           V(mutex);
           P(barber);            // 等理发师
           坐下理发;
       } else {
           V(mutex);             // 没位子，离开
       }
   }
   ```
3. 信号量有值，V 操作使 value 加 1，即使没有进程等待，这次 V 的效果也会被“记住”；条件变量没有值，signal 只在有进程等待时唤醒一个，**没有进程等待时 signal 不起任何作用**
</details>
