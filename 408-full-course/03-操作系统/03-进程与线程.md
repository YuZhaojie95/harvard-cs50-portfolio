## 🚪 课前引入

你在电脑上**同时**打开了：网易云音乐（放歌）、微信（聊天）、浏览器（查资料）。你的电脑可能只有 4 个 CPU 核心，却同时“运行”着上百个程序。

这是怎么做到的？操作系统让这些程序**轮流**使用 CPU，每个程序用一小会儿就换下一个。但问题来了：
- 音乐播放器被换下时，播放到第几秒了？下一次换回来从哪继续？
- 它的变量值、打开的文件、用到的内存都要**记住**

所以，OS 需要一个概念来描述“**一个正在运行的程序，以及它运行到哪儿了、拥有哪些资源**”——这就是**进程**。

🧒 **比喻**：
- **程序** = 一本**菜谱**（静态的，放在书架上，不会自己动）
- **进程** = **一次做菜的过程**（动态的：正在用哪口锅、做到第几步、用了哪些食材）
- 同一本菜谱，可以同时被两个厨师拿去做——**一个程序可以对应多个进程**（比如同时打开两个记事本窗口）
- **PCB** = 厨师旁边的**便签**：“做到第 5 步了，用的是 3 号锅，盐已放”。换人时看便签就能接着做

## 一、进程的概念（⭐⭐）

### 📐 为什么要引入进程
在多道程序环境下，多个程序**并发执行**，失去了**封闭性**，具有**间断性**和**不可再现性**。为了**描述和控制程序的并发执行**，实现 OS 的**并发性和共享性**，引入了进程。

### 📐 进程的定义
- 进程是**程序的一次执行过程**
- 进程是一个程序及其数据在处理机上**顺序执行时所发生的活动**
- 进程是具有独立功能的程序在一个数据集合上运行的过程，它是**系统进行资源分配和调度的一个独立单位**（引入线程后，**调度的基本单位变为线程**，进程仍是**资源分配的基本单位**）

### 📐 进程实体（进程映像）
进程实体由三部分组成：
1. **PCB（进程控制块）**：描述进程的基本情况和运行状态，**是进程存在的唯一标志**
2. **程序段**：能被进程调度程序调度到 CPU 执行的程序代码（可被多个进程共享）
3. **数据段**：原始数据，或程序执行时产生的中间/最终结果

⚠️ 严格地说，**进程实体是静态的，进程是动态的**。进程是进程实体的**运行过程**。但一般不严格区分。

### 📐 进程的特征
1. **动态性**：进程是程序的一次执行，有创建、活动、暂停、终止的过程，具有**生命周期**。**动态性是进程最基本的特征**
2. **并发性**：多个进程实体同时存在于内存中，能在一段时间内同时运行
3. **独立性**：进程是一个能**独立运行、独立获得资源、独立接受调度**的基本单位
4. **异步性**：进程按各自独立的、不可预知的速度向前推进（需要**同步机制**来保证结果正确）
5. **结构性**：每个进程都有一个 PCB，由程序段、数据段、PCB 组成

### 📐 程序与进程的区别
| | 程序 | 进程 |
|---|---|---|
| 性质 | **静态**的指令集合 | **动态**的执行过程 |
| 生命期 | 永久（存在磁盘上） | 暂时（有创建和撤销） |
| 组成 | 代码和数据 | 程序段 + 数据段 + **PCB** |
| 对应关系 | 一个程序可对应多个进程 | 一个进程可执行多个程序（如 exec） |

## 二、进程控制块 PCB（⭐⭐⭐）

### 📐 PCB 的作用
- **PCB 是进程存在的唯一标志**：创建进程 = 创建 PCB；撤销进程 = 回收 PCB
- OS 通过 PCB **感知**和**管理**进程
- PCB 常驻**内存**，位于**内核空间**（用户程序不能直接访问）

### 📐 PCB 的内容
| 类别 | 内容 |
|---|---|
| **进程描述信息** | **进程标识符 PID**、用户标识符 UID |
| **进程控制和管理信息** | **进程当前状态**、**进程优先级**、代码运行入口地址、程序的外存地址、进入内存时间、CPU 占用时间、信号量使用…… |
| **资源分配清单** | 代码段指针、数据段指针、堆栈段指针、**打开的文件描述符**、键盘、鼠标…… |
| **处理机相关信息（CPU 上下文）** | **通用寄存器值**、地址寄存器值、控制寄存器值、**标志寄存器（PSW）**、**程序计数器 PC**…… |

🧒 进程切换时，把 CPU 中各寄存器的值保存到当前进程的 PCB 里；换回来时再从 PCB 恢复——就像厨师换班时看便签。

### 📐 PCB 的组织方式
- **链接方式**：把同一状态的 PCB 链接成一个**队列**（就绪队列、阻塞队列……）。阻塞队列还可以按**阻塞原因**分成多个队列
- **索引方式**：把同一状态的 PCB 组织在一个**索引表**中（就绪索引表、阻塞索引表）

## 三、进程的状态与转换（⭐⭐⭐）

### 📐 五种状态
| 状态 | 含义 |
|---|---|
| **创建态（新建态）** | 进程**正在被创建**：申请空白 PCB、填写控制和管理信息、分配资源……尚未进入就绪态 |
| **就绪态** | 进程获得了**除 CPU 之外的一切所需资源**，一旦得到 CPU 就能立即运行 |
| **运行态（执行态）** | 进程**正在 CPU 上运行**。单 CPU 时，任一时刻**最多一个**进程处于运行态 |
| **阻塞态（等待态）** | 进程**正在等待某一事件**而暂停运行（如等待 I/O 完成、等待某资源、等待信号量），**即使 CPU 空闲也不能运行** |
| **终止态（结束态）** | 进程**正在从系统中消失**：正常结束或因其他原因退出，OS 回收资源、撤销 PCB |

🧒 **比喻：银行排队办业务**
- 创建态：刚进门，**正在取号**
- 就绪态：取了号，**坐着等叫号**（什么都准备好了，就差柜台）
- 运行态：**正在柜台办理**
- 阻塞态：办到一半，柜员说“**您的身份证复印件还没带，回去拿**”——你离开柜台去拿，即使柜台空了也轮不到你，拿回来后要**重新排队（回到就绪态）**
- 终止态：**办完了，离开**

### 📐 状态转换图（⭐⭐⭐）
```
                    进程调度（分配 CPU）
  ┌──────┐ 创建完成 ┌──────┐ ─────────────────► ┌──────┐ 运行结束/出错 ┌──────┐
  │ 创建 │ ───────► │ 就绪 │                    │ 运行 │ ────────────► │ 终止 │
  └──────┘          └──────┘ ◄───────────────── └──────┘               └──────┘
                       ▲      时间片用完/被抢占       │
                       │                             │ 请求资源/等待事件
                       │     事件发生（被唤醒）        ▼  （主动行为）
                       └──────────────────────── ┌──────┐
                                                  │ 阻塞 │
                                                  └──────┘
```

### 📐 四个关键转换
1. **就绪 → 运行**：进程被**调度**，获得 CPU
2. **运行 → 就绪**：**时间片用完**，或被**更高优先级进程抢占**，或进程**主动让出 CPU**（如 yield）
3. **运行 → 阻塞**：进程**请求某资源**（如外设）、**等待某事件**（如 I/O 完成、读文件）、执行 **wait/P 操作**且资源不足。这是进程的**主动行为**（自己调用系统调用请求）
4. **阻塞 → 就绪**：等待的**事件发生**（如 I/O 完成、资源被释放）。这是**被动行为**（由别的进程或中断处理程序唤醒）

⚠️ **不可能的转换**：
- **阻塞 → 运行**：阻塞的进程被唤醒后要先回到**就绪**，等待调度
- **就绪 → 阻塞**：就绪进程没有在运行，不可能发出请求去等待

📝 **真题（2022 年第 28 题）**：下列事件或操作中，可能导致进程 P 由执行态变为阻塞态的是：I. 进程 P 读文件　II. 进程 P 的时间片用完　III. 进程 P 申请外设　IV. 进程 P 执行信号量的 wait() 操作
A. 仅 I、IV　B. 仅 II、III　C. 仅 III、IV　D. 仅 I、III、IV
→ **D**（时间片用完是**执行 → 就绪**）

📝 **真题（2023 年第 27 题）**：下列由当前线程引起的事件或执行的操作中，可能导致该线程由执行态变为就绪态的是：A. 键盘输入　B. 缺页异常　C. 主动出让 CPU　D. 执行信号量的 wait() 操作
→ **C**（A 键盘输入若是线程读键盘则等待 → 阻塞；B 缺页 → 等待调页 → 阻塞；D wait 可能 → 阻塞；C 主动出让 CPU（yield）→ 就绪）

### 📐 挂起态（七状态模型，了解）
内存不够时，把某些进程**换出到外存**，称为**挂起**：
- **就绪挂起（静止就绪）**：在外存，只要调入内存就能执行
- **阻塞挂起（静止阻塞）**：在外存，且在等待事件
- 与“阻塞”的区别：**阻塞**时进程映像**还在内存**；**挂起**时进程映像**在外存**

## 四、进程控制（⭐⭐）

进程控制就是对系统中所有进程实施有效管理，**实现进程状态转换**。进程控制用**原语**实现（原子操作，不可中断）。

### 📐 1. 进程的创建
**引起创建的事件**：**用户登录**（分时系统中）、**作业调度**（批处理系统中）、**提供服务**（如打印请求）、**应用请求**（用户程序调用 fork 创建子进程）

**创建原语的过程**：
1. 为新进程分配一个唯一的**进程标识号 PID**，并**申请一个空白的 PCB**（PCB 数量有限，若申请失败则创建失败）
2. 为进程**分配所需资源**：内存、文件、I/O 设备、CPU 时间等（从 OS 或父进程获得）。若资源不足（如内存），**并不是创建失败**，而是处于**创建态**，等待内存资源
3. **初始化 PCB**：标志信息、处理机状态信息、处理机控制信息、进程优先级等
4. 若就绪队列能接纳新进程，就把新进程**插入就绪队列**，等待被调度

📝 **真题（2021 年第 24 题）**：下列操作中，操作系统在创建新进程时，必须完成的是：I. 申请空白的进程控制块　II. 初始化进程控制块　III. 设置进程状态为执行态
A. 仅 I　B. 仅 I、II　C. 仅 I、III　D. 仅 II、III
→ **B**（新创建的进程进入**就绪态**，不是执行态）

### 📐 2. 进程的终止
**引起终止的事件**：**正常结束**；**异常结束**（越界、非法指令、运行超时、I/O 故障……）；**外界干预**（操作员或 OS 干预、父进程请求、父进程终止）

**终止原语的过程**：
1. 根据被终止进程的标识符，**检索 PCB**，读出该进程的状态
2. 若处于**执行态**，立即**终止执行**，把 CPU 分配给其他进程
3. 若有**子孙进程**，通常把子孙进程也终止（或者交给其他进程收养）
4. 把该进程拥有的**全部资源归还**给父进程或 OS
5. 把该 PCB 从所在队列中**删除**

### 📐 3. 进程的阻塞与唤醒
**阻塞原语（Block）**——进程**自己**调用（主动）：
1. 找到将要被阻塞进程的 PCB
2. 若为运行态，**保护其现场**，将其状态转为**阻塞态**，停止运行
3. 把 PCB 插入相应事件的**等待队列**，将 CPU 调度给其他就绪进程

**唤醒原语（Wakeup）**——由**释放资源的进程或中断处理程序**调用（被动）：
1. 在该事件的等待队列中找到相应进程的 PCB
2. 将其从等待队列中移出，并置其状态为**就绪态**
3. 把 PCB 插入**就绪队列**，等待调度

⚠️ **Block 和 Wakeup 必须成对使用**：一个进程因某事件阻塞，就必须有另一个相关进程在事件发生时唤醒它，否则它将永远阻塞。

### 📐 4. 进程切换（⭐⭐）
进程切换是指 CPU 从一个进程的运行转到另一个进程上运行，**在内核态**完成：
1. **保存 CPU 上下文**（包括 PC 和其他寄存器）到当前进程的 PCB
2. **更新当前进程的 PCB**（状态改为就绪或阻塞……）
3. 把当前进程的 PCB 移入相应的队列（就绪、阻塞……）
4. **选择另一个进程执行**，更新其 PCB（状态改为运行）
5. **更新内存管理的数据结构**（如切换页表基址寄存器、刷新 TLB）
6. **恢复新进程的 CPU 上下文**

⚠️ **进程切换 vs 模式切换**：
- **模式切换**（用户态 ↔ 内核态）：CPU 逻辑上可能**还在执行同一进程**（如系统调用），不一定发生进程切换
- **进程切换**：一定在**内核态**完成，要更换进程上下文
- 进程切换一定伴随模式切换（先进入内核态），但模式切换不一定导致进程切换
- 🧒 调度（选进程）和切换（换进程）是两个步骤：先调度选出下一个进程，再进行切换

## 五、进程的地址空间与父子进程（⭐⭐）

### 📐 进程的虚拟地址空间（以 Linux 32 位为例）
```
高地址  ┌──────────────────┐
        │    内核区         │ ← 所有进程共享，用户态不可访问（PCB、内核代码/数据、内核栈）
        ├──────────────────┤
        │    用户栈 ↓       │ ← 局部变量、函数参数、返回地址，向低地址增长
        │                  │
        │  (共享库映射区)    │
        │                  │
        │    运行时堆 ↑     │ ← malloc/new 动态分配，向高地址增长
        ├──────────────────┤
        │  可读写数据区      │ ← 全局变量、静态变量（.data 已初始化，.bss 未初始化）
        ├──────────────────┤
        │  只读代码区        │ ← 程序代码（.text）、只读常量（.rodata，如字符串字面量）
低地址  └──────────────────┘
```

📝 **真题（2025 年第 46 题，9 分）**：某进程的虚拟地址空间如下图所示（自上而下：内核区、[未占用区域]、用户栈、运行时堆、可读写数据区、只读代码区），另有 C 程序代码：
```c
char *ptr;
void main()
{
    int length;
    ptr = (char*)malloc(sizeof(char));
    scanf("%s", ptr);
    length = strlen(ptr);
    printf("length=%d\n", length);
    free(ptr);
}
```
(1) 上述程序执行时，PCB 位于哪个区域？执行 scanf() 等待键盘输入时，该进程处于什么状态？（3 分）
(2) main() 函数的代码位于哪个区域？其直接调用的哪些函数的功能需要通过执行驱动程序实现？（3 分）
(3) 变量 ptr 被分配在哪个区域？若变量 length 没有被分配在寄存器中，则会被分配在哪个区域？ptr 指向的字符串位于哪个区域？（3 分）

**(1)**
- **PCB 位于内核区**（PCB 是 OS 管理进程的数据结构，属于内核数据，用户程序不能访问）
- 执行 scanf() 等待键盘输入时，进程处于**阻塞态**（等待 I/O 事件）

**(2)**
- main() 的代码位于**只读代码区**
- **scanf() 和 printf()** 需要执行驱动程序：scanf 从**键盘**读入数据（键盘驱动），printf 向**显示器**输出（显示器驱动）。malloc、strlen、free 不涉及 I/O 设备

**(3)**
- ptr 是**全局变量** → **可读写数据区**
- length 是 main 的**局部变量** → **用户栈**
- ptr 指向的字符串由 **malloc** 分配 → **运行时堆**

（附注：malloc(sizeof(char)) 只分配了 1 字节，而 scanf 会写入整个字符串，这在实际中会**越界**写堆，是有 bug 的代码，不过不影响本题回答。）

### 📐 父进程与子进程（fork）
- 允许一个进程创建另一个进程，创建者为**父进程**，被创建者为**子进程**
- 子进程可以**继承**父进程所拥有的资源（打开的文件等）
- 子进程被撤销时，要把从父进程获得的资源归还
- UNIX 中，`fork()` 创建一个与父进程**几乎完全相同的副本**：
  - 子进程有**自己独立的 PCB** 和**独立的虚拟地址空间**（内容最初是父进程的拷贝，通常用**写时复制 COW** 实现）
  - fork() 在父进程中返回子进程的 PID，在子进程中返回 0
- 父、子进程**可以并发执行**
- 父、子进程**不共享虚拟地址空间**（但可以共享某些资源，如打开的文件、共享内存段）

📝 **真题（2020 年第 29 题）**：下列关于父进程与子进程的叙述中，**错误**的是：
A. 父进程与子进程可以并发执行　B. 父进程与子进程共享虚拟地址空间　C. 父进程与子进程有不同的进程控制块　D. 父进程与子进程不能同时使用同一临界资源
→ **B**（各自有独立的虚拟地址空间；D 是对的，临界资源任何时候都只能被一个进程使用）

✏️ **fork 经典计算**：
```c
int main() {
    fork();
    fork();
    printf("hi\n");
}
```
- 第 1 个 fork 后有 2 个进程；每个进程再执行第 2 个 fork → 4 个进程
- 输出 **4 行** hi。一般地，n 个连续的 fork() 产生 **2ⁿ** 个进程

## 六、进程通信（⭐⭐）

进程之间**信息交换**。每个进程有独立的地址空间，一个进程**不能直接访问**另一个进程的地址空间，所以需要 OS 提供通信机制。

- **低级通信**：PV 操作（信号量），只能传递少量信息（第 6 课）
- **高级通信**：以较高效率传输大量数据

### 📐 1. 共享存储
在通信的进程之间存在一块**可直接访问的共享空间**，通过对这块空间的读写实现信息交换。
- 需要用**同步互斥工具**（如 PV 操作）对共享空间的读写进行控制
- 两种方式：
  - **基于数据结构的共享**（低级）：如共享一个固定大小的数组，速度慢、限制多
  - **基于存储区的共享**（高级）：OS 在内存中划出一块共享存储区，由进程控制数据形式和存放位置
- 操作系统只负责**提供**共享空间和同步互斥工具，数据交换由用户自己安排读写指令完成
- 实现：把同一块物理内存**映射到**多个进程各自的虚拟地址空间

### 📐 2. 消息传递
进程间的数据交换以**格式化的消息**为单位。进程通过 OS 提供的**发送消息（send）**和**接收消息（receive）**两个**原语**进行数据交换。
- **直接通信方式**：发送进程直接把消息发送给接收进程，挂在接收进程的**消息缓冲队列**上
  - `send(P, 消息)`、`receive(Q, &消息)`
- **间接通信方式**：发送进程把消息发送到某个**中间实体（信箱）**，接收进程从信箱中取得消息。也称**信箱通信方式**，广泛用于计算机网络（电子邮件系统）

### 📐 3. 管道通信
**管道**：用于连接一个读进程和一个写进程以实现它们之间通信的一个**共享文件**（pipe 文件）。
- 写进程以**字符流**形式把数据写入管道，读进程从管道中读取
- 管道是**半双工**通信：某一时刻只能单向传输。要实现双向，需要**两个管道**
- 实质上是一个**固定大小的内存缓冲区**（Linux 中 4KB）
  - 管道**满**时，写进程**阻塞**；管道**空**时，读进程**阻塞**
- **各进程要互斥地访问**管道
- 数据一旦被读出，就从管道中被抛弃，所以**读进程最多只能有一个**（这是考试中的常见表述；实际 Linux 允许多个读者但会竞争数据）

### 📐 4. 信号（了解）
**信号（Signal）**用于**通知**进程某个特定事件已经发生（如 Ctrl+C 发送 SIGINT）。进程收到信号后，执行相应的信号处理程序。

## 七、线程（⭐⭐⭐）

### 📐 为什么引入线程
- 引入**进程**：为了多道程序并发执行，提高资源利用率和系统吞吐量
- 引入**线程**：为了**减小程序在并发执行时所付出的时空开销**，提高 OS 的**并发性能**

🧒 **比喻**：一个进程像一家**公司**，拥有办公室、电脑、资金（资源）。
- 以前一家公司只有一个员工，这个员工出去跑业务时（I/O 阻塞），公司就停摆了
- 线程 = **公司里的多个员工**：共享公司的办公室和资源，但各自干各自的活
- 创建一个员工（线程）比开一家新公司（进程）便宜得多；员工之间交流（共享内存）也比公司之间交流（进程通信）方便得多

### 📐 线程的概念
- 线程是“**轻量级进程**”（LWP），是一个**基本的 CPU 执行单元**，也是**程序执行流的最小单元**
- 由**线程 ID、程序计数器 PC、寄存器集合、堆栈**组成
- 线程是进程中的一个实体，是**被系统独立调度和分派的基本单位**
- 线程**自己不拥有系统资源**（只拥有一点运行中必不可少的资源：PC、寄存器、栈），但它可与**同属一个进程的其他线程共享进程所拥有的全部资源**
- 引入线程后：**进程是资源分配的基本单位**，**线程是 CPU 调度的基本单位**

### 📐 线程控制块 TCB
- 线程标识符
- 一组寄存器（PC、状态寄存器、通用寄存器）
- 线程运行状态（运行、就绪、阻塞）
- 优先级
- 线程专有存储区（线程切换时保存现场）
- **堆栈指针**（每个线程有自己的栈）

### 📐 进程与线程的比较（⭐⭐⭐）
| 比较项 | 进程 | 线程 |
|---|---|---|
| **调度** | 传统 OS 中是调度的基本单位 | **引入线程后，线程是调度的基本单位** |
| **拥有资源** | **资源分配的基本单位**，拥有资源 | **不拥有系统资源**（仅有 PC、寄存器、栈），**共享所属进程的资源** |
| **并发性** | 进程之间可并发 | 一个进程中的**多个线程之间**也可并发，并发性更高 |
| **独立性** | 每个进程有**独立的地址空间**和资源 | 同一进程的线程**共享进程的地址空间和资源**，某线程的栈对其他线程也是可见的（但不应访问） |
| **系统开销** | 创建/撤销/切换进程开销**大**（要分配/回收资源、切换地址空间） | 线程切换只需保存和设置少量寄存器，**开销小**；同一进程内线程切换**不会引起进程切换** |
| **通信** | 需要**进程间通信（IPC）**机制 | 同一进程的线程可以**直接读写进程数据段**（如全局变量）通信，需要同步互斥 |
| **支持多处理器** | 单线程进程只能运行在一个 CPU 上 | 多线程进程可以把线程分配到**多个 CPU**上并行执行 |

⚠️ **同一进程的各线程共享**：代码段、数据段（全局变量）、堆、打开的文件、进程的地址空间
⚠️ **各线程私有**：**线程 ID、PC、寄存器、栈（局部变量）**、线程状态

✏️ **例**：同一进程中的线程 T1 和 T2，下列哪些是共享的？(a) 全局变量 x；(b) T1 中的局部变量 y；(c) 进程打开的文件；(d) T1 的 PC；(e) 用 malloc 分配的内存
→ 共享：**(a)、(c)、(e)**；私有：(b) 在 T1 的栈中、(d)

### 📐 线程的实现方式（⭐⭐）
#### 1. 用户级线程（ULT，User-Level Thread）
- 线程管理（创建、撤销、切换）**全部由应用程序**（用户空间的**线程库**）完成，**内核意识不到线程的存在**
- 内核仍以**进程**为单位调度
- ✅ **线程切换不需要切换到内核态**，开销小、效率高
- ✅ 调度算法可以是**进程专用**的，不同进程可以根据需要选择不同的调度算法
- ✅ 实现与 OS 平台无关
- ❌ **一个线程执行系统调用而阻塞，整个进程（所有线程）都被阻塞**
- ❌ **不能发挥多处理机的优势**：内核每次只分配一个 CPU 给进程，进程中只有一个线程能执行

#### 2. 内核级线程（KLT，Kernel-Level Thread）
- 线程管理**由内核完成**，内核为每个线程维护 TCB，**以线程为单位进行调度**
- ✅ 能发挥**多处理机**的优势，内核能同时调度同一进程中的多个线程**并行**执行
- ✅ 一个线程被阻塞，内核可以调度该进程的**其他线程**运行
- ✅ 内核本身也可以用多线程实现
- ❌ 同一进程中的线程切换需要**从用户态转到内核态**，**开销较大**

#### 3. 组合方式
内核支持多个内核级线程的建立、调度和管理，同时允许用户程序建立、调度和管理用户级线程。

### 📐 多线程模型（用户级线程与内核级线程的映射）（⭐⭐）
| 模型 | 映射 | 优点 | 缺点 |
|---|---|---|---|
| **多对一** | 多个用户级线程 → **1 个**内核级线程 | 线程管理在用户空间，效率高 | 一个线程阻塞，整个进程阻塞；多个线程不能并行运行在多处理机上 |
| **一对一** | 每个用户级线程 → **一个**内核级线程 | 一个线程阻塞，其他线程可继续执行，**并发能力强** | 每创建一个用户线程就要创建一个内核线程，**开销大** |
| **多对多** | n 个用户级线程 → m 个内核级线程（**m ≤ n**） | 兼顾两者优点：并发性好，开销可控 | 实现复杂 |

⚠️ **CPU 调度的单位是内核级线程**。在多对一模型中，即使有 100 个用户级线程，也只能在 1 个 CPU 上运行。

### 📐 线程的状态
与进程类似：**执行态、就绪态、阻塞态**，转换条件也类似。

## ⚠️ 易错点

1. **PCB 是进程存在的唯一标志**；PCB 在**内核区**
2. 进程是**资源分配**的基本单位；**线程是调度**的基本单位（引入线程后）
3. **阻塞 → 运行**、**就绪 → 阻塞**不可能
4. 运行 → 阻塞是**主动**的（请求资源），阻塞 → 就绪是**被动**的（被唤醒）
5. **时间片用完**：运行 → 就绪；**读文件、申请外设、wait**：可能运行 → 阻塞
6. 创建进程后进入**就绪态**，不是运行态
7. 资源不足时进程停留在**创建态**，不是创建失败（PCB 申请不到才失败）
8. 父子进程：**各自独立的 PCB 和虚拟地址空间**，可并发
9. **全局变量 → 数据区；局部变量 → 栈；malloc → 堆；代码 → 代码区；PCB → 内核区**
10. 用户级线程：**内核不知道**，一个阻塞全部阻塞，不能利用多核；内核级线程反之
11. 同一进程的线程**共享**代码、全局数据、堆、文件；**私有** PC、寄存器、栈

## 🏋️ 课后练习

1. 某单 CPU 系统中有 10 个进程，运行态、就绪态、阻塞态的进程最多各有几个？最少各有几个？
2. 进程从运行态进入阻塞态，一定是由于什么引起的？阻塞态进程被唤醒后进入什么状态？
3. 下列哪些事件会导致创建新进程：(a) 用户登录；(b) 作业调度；(c) 设备分配；(d) 用户程序调用 fork
4. 下列代码执行后，一共输出多少个 "A"？
   ```c
   int main() { fork(); fork(); fork(); printf("A"); }
   ```
5. 在多对一线程模型中，某进程有 5 个用户级线程，其中一个执行了阻塞的系统调用，其他线程能否继续运行？一对一模型呢？
6. 判断：(a) 线程拥有自己的栈；(b) 同一进程的线程共享全局变量；(c) 进程切换时一定要切换页表，同一进程的线程切换则不需要；(d) 管道通信是全双工的。

<details>
<summary>📖 答案</summary>

1. 运行态最多 **1** 个，最少 **0** 个（如全部阻塞）；就绪态最多 **9** 个（1 个在运行），最少 0 个；阻塞态最多 **10** 个，最少 0 个
2. 由进程**自身**请求某种资源或等待某事件（如 I/O、wait 操作）引起；被唤醒后进入**就绪态**
3. **(a)、(b)、(d)**；设备分配不会创建新进程
4. **8** 个（2³）
5. 多对一：**不能**，整个进程被阻塞；一对一：**能**，只阻塞对应的内核级线程
6. (a) **对**；(b) **对**；(c) **对**；(d) **错**，半双工
</details>
