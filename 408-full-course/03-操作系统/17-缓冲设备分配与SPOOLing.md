## 🚪 课前引入

你在饭店点了 10 道菜。厨师做菜很快，服务员上菜很慢：
- **没有备菜台**：厨师做好一道，只能端在手里等服务员来拿，这期间不能做下一道——大家互相等
- **有一个备菜台**（单缓冲）：厨师做好放台上就可以去做下一道；但台上只能放一道，服务员没拿走之前，厨师做好的下一道没地方放
- **有两个备菜台**（双缓冲）：厨师往一个台上放的同时，服务员可以从另一个台上拿，效率更高

**缓冲区**就是 CPU 和 I/O 设备之间的“**备菜台**”。

## 一、缓冲区管理（⭐⭐⭐）

### 📐 什么是缓冲区
**缓冲区**是一个存储区域，可以由专门的**硬件寄存器**组成，也可利用**内存**作为缓冲区。
- 使用硬件作为缓冲区的**成本较高，容量也较小**，一般仅用在对速度要求非常高的场合（如联想寄存器、I/O 控制器中的数据缓冲寄存器）
- 一般情况下，更多的是**利用内存**作为缓冲区，“设备独立性软件”的**缓冲区管理**就是要组织管理好这些缓冲区

### 📐 缓冲区的作用
1. **缓和 CPU 与 I/O 设备之间速度不匹配的矛盾**
2. **减少对 CPU 的中断频率**，放宽对 CPU 中断响应时间的限制（如：设备每输入一个字符就中断一次 → 攒满一个缓冲区再中断一次）
3. **解决数据粒度不匹配的问题**：如输出进程每次可以生成一块数据，但 I/O 设备每次只能输出一个字符
4. **提高 CPU 与 I/O 设备之间的并行性**

### 📐 缓冲区的特点
- **缓冲区非空时**，不能往缓冲区冲入数据，只能从缓冲区把数据传出
- **缓冲区为空时**，可以往缓冲区冲入数据，但必须把缓冲区**充满**以后，才能从缓冲区把数据传出

### 📐 计算约定（⭐⭐⭐ 必背）
- **T**：从磁盘把一块数据**输入到缓冲区**的时间
- **M**：OS 把缓冲区的数据**传送到用户区（工作区）**的时间
- **C**：CPU 对这一块数据进行**处理（计算）**的时间

### 📐 1. 无缓冲
数据直接从设备送到用户区，CPU 处理完才能读下一块：
```
每块处理时间 = T + C
```

### 📐 2. 单缓冲
OS 在主存中为一个设备分配**一个缓冲区**（若题目中没有特别说明，一个缓冲区的大小就是**一个块**）。

```
磁盘 ──T──► 缓冲区 ──M──► 用户区 ──C──► CPU 处理
```
分析：
- 缓冲区空时才能输入（T）；缓冲区满时才能传出（M）
- **T 与 C 可以并行**：CPU 在处理上一块（C）时，磁盘可以同时往缓冲区输入下一块（T），因为上一块已经 M 到用户区了
- **M 不能与 T 并行**（都要用缓冲区），**M 不能与 C 并行**（都要用用户区）

```
时间 →
T: |==T1==|        |==T2==|        |==T3==|
M:        |M1|            |M2|            |M3|
C:           |==C1==|        |==C2==|        |==C3==|
```
📐 **采用单缓冲时，处理一块数据平均耗时 = max(C, T) + M**

### 📐 3. 双缓冲
OS 在主存中为一个设备分配**两个缓冲区**。
- 磁盘往缓冲区 1 输入的同时，可以把缓冲区 2 中的数据传到用户区，然后 CPU 处理
- **T 可以与 (M + C) 并行**

📐 **采用双缓冲时，处理一块数据平均耗时 = max(T, M + C)**
- 若 T > M + C：CPU 处理完后要等磁盘，平均 = T（磁盘一直在忙，是瓶颈）
- 若 T < M + C：磁盘输入完后要等 CPU，平均 = M + C（CPU 一直在忙）

✏️ **例**：T = 100，M = 50，C = 50（单位 μs）
- 无缓冲：100 + 50 = **150**（这里其实 M 不存在，数据直接进用户区）
- 单缓冲：max(50, 100) + 50 = **150**
- 双缓冲：max(100, 50 + 50) = **100**

📝 **真题（2011 年真题）**：某文件占 **10 个磁盘块**，现要把该文件磁盘块逐个读入主存缓冲区，并送用户区进行分析。假设一个缓冲区与一个磁盘块大小相同，把一个磁盘块读入缓冲区的时间为 **100μs**，将缓冲区的数据传送到用户区的时间是 **50μs**，CPU 对一块数据进行分析的时间为 **50μs**。在单缓冲区和双缓冲区结构下，读入并分析完该文件的时间分别是：
A. 1500μs、1000μs　B. 1550μs、1100μs　C. 1550μs、1550μs　D. 2000μs、2000μs

**单缓冲**：
- 每块平均 max(C, T) + M = max(50, 100) + 50 = 150μs
- 前 10 块的“读入 + 传送”都做完用时 10 × 150 = 1500μs，最后一块还要被 CPU 分析 50μs
- 总时间 = 1500 + 50 = **1550μs**

**双缓冲**：
- 每块平均 max(T, M + C) = max(100, 100) = 100μs
- 10 块全部读入缓冲区用时 10 × 100 = 1000μs，最后一块还要传送 50 + 分析 50
- 总时间 = 1000 + 50 + 50 = **1100μs**
→ 选 **B**

📐 **计算总时间的通用方法**：**总时间 = n × 平均时间 + 最后一块“剩下的”操作时间**。
- 单缓冲：n × (max(C, T) + M) + C
- 双缓冲（T ≥ M + C 时）：n × T + M + C

⚠️ **最保险的方法是画甘特图**，尤其是题目条件不太常规时。

### 📐 双缓冲用于通信
两台机器之间通信时，若只设置**单缓冲**，任一时刻只能实现**单向**数据传输；若要实现**双向**传输，两台机器各设置**两个缓冲区**（一个发送缓冲区、一个接收缓冲区）。

### 📐 4. 循环缓冲区
将**多个大小相等的缓冲区**链接成一个**循环队列**。
- 橙色表示已充满数据的缓冲区，绿色表示空缓冲区
- **in 指针**指向下一个可以冲入数据的空缓冲区
- **out 指针**指向下一个可以取出数据的满缓冲区
- 本质就是**生产者-消费者问题**中的环形缓冲区

### 📐 5. 缓冲池
由系统中**共用的缓冲区**组成。这些缓冲区按使用状况可以分为：
- **空缓冲队列**（emq）
- 装满**输入数据**的缓冲队列（**输入队列** inq）
- 装满**输出数据**的缓冲队列（**输出队列** outq）

根据一个缓冲区在实际运算中扮演的功能不同，又设置了**四种工作缓冲区**：
| 工作缓冲区 | 作用 |
|---|---|
| **hin**（收容输入） | 用于收容输入数据：从空缓冲队列取一个空缓冲区，装入输入数据后挂到输入队列 |
| **sin**（提取输入） | 用于提取输入数据：从输入队列取一个缓冲区，把数据提取给进程后挂到空缓冲队列 |
| **hout**（收容输出） | 用于收容输出数据：从空缓冲队列取一个空缓冲区，装入进程的输出数据后挂到输出队列 |
| **sout**（提取输出） | 用于提取输出数据：从输出队列取一个缓冲区，把数据输出到设备后挂到空缓冲队列 |

### 📐 高速缓存 vs 缓冲区（⭐⭐）
| | 高速缓存（Cache） | 缓冲区 |
|---|---|---|
| 存放的数据 | 存放的是**低速设备上某些数据的复制**，即高速缓存上有的，低速设备上**必然有** | 存放的是**低速设备传递给高速设备的数据**（或相反），这些数据在低速设备（或高速设备）上**不一定有备份**，这些数据再从缓冲区传送到高速设备（或低速设备） |
| 目的 | 高速缓存存放的是**高速设备经常要访问的数据**，若高速设备要访问的数据不在高速缓存中，则高速设备**直接访问低速设备** | 高速设备和低速设备的通信**都要经过缓冲区**，高速设备永远不会直接去访问低速设备 |
| 共同点 | 都介于高速设备和低速设备之间 | |

## 二、设备分配与回收（⭐⭐）

### 📐 设备分配时应考虑的因素
**1. 设备的固有属性**：
- **独占设备**：一个时段只能分配给一个进程（如**打印机**）
- **共享设备**：可同时分配给多个进程使用（如**磁盘**），各进程往往是宏观上同时共享使用设备，而微观上交替使用
- **虚拟设备**：采用 **SPOOLing 技术**将独占设备改造成虚拟的共享设备，可同时分配给多个进程使用（如采用 SPOOLing 技术实现的共享打印机）

**2. 设备分配算法**：先来先服务、优先级高者优先、短任务优先……

**3. 设备分配中的安全性**：
- **安全分配方式**：为进程分配一个设备后就**将进程阻塞**，本次 I/O 完成后才将进程唤醒。一个时段内每个进程只能使用一个设备
  - ✅ 破坏了“请求和保持”条件，**不会死锁**
  - ❌ 对于一个进程来说，CPU 和 I/O 设备只能串行工作
- **不安全分配方式**：进程发出 I/O 请求后，系统为其分配 I/O 设备，**进程可继续执行**，之后还可以发出新的 I/O 请求。只有某个 I/O 请求得不到满足时才将进程阻塞。一个进程可以同时使用多个设备
  - ✅ 进程的计算任务和 I/O 任务可以并行处理，使进程迅速推进
  - ❌ **有可能发生死锁**（死锁避免、死锁的检测和解除）

📝 **真题（2023 年第 32 题）**：下列因素中，设备分配需要考虑的是：I. 设备类型　II. 设备的访问权限　III. 设备的占用状态　IV. 逻辑设备与物理设备的映射关系
A. 仅 I、II　B. 仅 II、III　C. 仅 III、IV　D. I、II、III、IV
→ **D**
- I：根据设备类型找到对应的设备控制表（系统设备表中按类型查找）
- II：用户是否有权限使用该设备（设备保护）
- III：设备是否空闲（忙则阻塞等待）
- IV：用户请求的是逻辑设备，要通过 LUT 映射到物理设备

### 📐 静态分配与动态分配
- **静态分配**：进程**运行前**为其分配**全部所需资源**，运行结束后归还资源（破坏了“请求和保持”条件，不会发生死锁）
- **动态分配**：进程运行过程中**动态申请**设备资源

### 📐 设备分配管理中的数据结构（⭐⭐）
“设备、控制器、通道”之间的关系：**一个通道可控制多个设备控制器，每个设备控制器可控制多个设备**。
```
        CPU
         │
   ┌─────┴─────┐
 通道 1       通道 2
   │           │
 ┌─┴──┐      ┌─┴──┐
控制器1 控制器2  控制器3
 │  │    │     │
设备 设备 设备   设备
```
对应四张表：
| 数据结构 | 作用 | 主要内容 |
|---|---|---|
| **设备控制表（DCT）** | 系统为**每个设备**配置一张 DCT，记录设备情况 | **设备类型**、设备标识符、**设备状态**（忙碌/空闲/故障……）、**指向控制器表的指针**（每个设备由一个控制器控制）、重复执行次数或时间、**设备队列的队首指针**（指向正在等待该设备的进程队列，由进程 PCB 组成） |
| **控制器控制表（COCT）** | **每个设备控制器**对应一张 COCT。OS 根据 COCT 的信息对控制器进行操作和管理 | 控制器标识符、控制器状态、**指向通道表的指针**、控制器队列的队首/队尾指针 |
| **通道控制表（CHCT）** | **每个通道**对应一张 CHCT | 通道标识符、通道状态、**与通道连接的控制器表首址**、通道队列的队首/队尾指针 |
| **系统设备表（SDT）** | 记录了系统中**全部设备**的情况，**整个系统一张** | 每个设备一个表项：**设备类型、设备标识符**、**DCT 指针**、驱动程序入口地址 |

### 📐 设备分配的步骤
1. **根据进程请求的物理设备名查找 SDT**（注：物理设备名是进程请求分配设备时提供的参数）
2. **根据 SDT 找到 DCT**，若设备忙碌则将进程 PCB 挂到**设备等待队列**中，不忙碌则将设备分配给进程
3. **根据 DCT 找到 COCT**，若控制器忙碌则将进程 PCB 挂到控制器等待队列中，不忙碌则将控制器分配给进程
4. **根据 COCT 找到 CHCT**，若通道忙碌则将进程 PCB 挂到通道等待队列中，不忙碌则将通道分配给进程
5. 只有**设备、控制器、通道三者都分配成功**时，这次设备分配才算成功，之后便可**启动 I/O 设备**进行数据传送

❌ 缺点：用户编程时必须使用“**物理设备名**”，底层细节对用户不透明，不方便编程；若换了一个物理设备，则程序无法运行；若进程请求的物理设备正在忙碌，则即使系统中还有同类型的设备，进程也必须阻塞等待

### 📐 改进：用逻辑设备名申请
建立**逻辑设备名与物理设备名的映射**（设备独立性）：
1. 用户编程时提供**逻辑设备名**，OS 根据逻辑设备名查找 SDT，找到**该类型**的、**空闲**的设备分配给进程，并在 **LUT** 中增加相应表项
2. 如果之后用户进程再次通过相同的逻辑设备名请求使用设备，则 OS 通过 LUT 表即可知道用户进程实际要使用的是哪个物理设备了，并且也能知道该设备的驱动程序入口地址
3. 之后的步骤同上（DCT → COCT → CHCT）

### 📐 设备回收
与分配相反：归还通道、控制器、设备，修改表格，唤醒等待队列中的进程。

## 三、SPOOLing 技术（假脱机技术）（⭐⭐⭐）

### 📐 脱机技术的由来
- 早期批处理阶段：用**外围控制机** + **高速磁带**，先把纸带上的数据输入到磁带（慢速设备 → 快速设备），CPU 直接从磁带读数据，输出也先输出到磁带，再由外围机输出到打印机
- “**脱机**”：**脱离主机的控制**进行的输入/输出操作
- 作用：**缓解了设备与 CPU 的速度矛盾**，实现预输入、缓输出

### 📐 SPOOLing（假脱机）
**假脱机技术**，又称 **SPOOLing 技术**（Simultaneous Peripheral Operations On-Line），是用**软件**的方式**模拟脱机技术**。
- 用**磁盘**模拟磁带，用**输入进程/输出进程**模拟外围控制机
- 在**多道程序**环境下实现
- 需要**多道程序技术**的支持

### 📐 SPOOLing 系统的组成（⭐⭐⭐）
```
               输入设备（如键盘）                      输出设备（如打印机）
                    │                                     ▲
                    ▼                                     │
               ┌─────────┐                           ┌─────────┐
     内存      │ 输入缓冲区 │                           │ 输出缓冲区 │
               └────┬────┘                           └────▲────┘
                    │ 输入进程                            │ 输出进程
                    ▼                                     │
               ┌─────────┐                           ┌─────────┐
     磁盘      │  输入井   │ ──► 用户进程 ──►           │  输出井   │
               └─────────┘                           └─────────┘
```
1. **输入井和输出井**：在**磁盘**上开辟的两个大存储空间
   - **输入井**：模拟脱机输入时的磁带，用于收容 I/O 设备输入的数据
   - **输出井**：模拟脱机输出时的磁带，用于收容用户进程输出的数据
2. **输入缓冲区和输出缓冲区**：在**内存**中开辟的两个缓冲区
   - **输入缓冲区**：暂存由输入设备送来的数据，之后再传送到输入井
   - **输出缓冲区**：暂存从输出井送来的数据，之后再传送到输出设备
3. **输入进程和输出进程**：
   - **输入进程**：模拟脱机输入时的外围控制机，将用户要求的数据从输入机通过输入缓冲区再送到输入井。当 CPU 需要输入数据时，直接从输入井读入内存
   - **输出进程**：模拟脱机输出时的外围控制机，把用户要求输出的数据先从内存送到输出井，待输出设备空闲时，再将输出井中的数据经过输出缓冲区送到输出设备
4. **井管理程序**：用于控制作业与磁盘井之间信息的交换

### 📐 共享打印机原理（⭐⭐）
打印机是一种“**独占式设备**”，但可以用 SPOOLing 技术改造成“**共享设备**”：
当多个用户进程提出输出打印的请求时，系统会答应它们的请求，但是**并不是真正把打印机分配给他们**，而是由**假脱机管理进程**为每个进程做两件事：
1. 在**磁盘输出井**中为进程申请一个**空闲缓冲区**（也就是说，这个缓冲区是在磁盘上的），并将要打印的数据送入其中
2. 为用户进程申请一张**空白的打印请求表**，并将用户的打印请求填入表中（其实就是用来说明用户的打印数据存放位置等信息的），再将该表挂到**假脱机文件队列**上
3. 当打印机空闲时，**输出进程**会从文件队列的队头取出一张打印请求表，并根据表中的要求将要打印的数据从输出井传送到输出缓冲区，再输出到打印机进行打印。用这种方式可依次处理完全部的打印任务

🧒 **比喻**：公司只有一台打印机，大家不用排队站在打印机前等，而是把要打印的文件交给**前台**（放在磁盘输出井里，登记一张单子），前台按顺序一份份打印。每个人交完就可以回去工作了，感觉“**打印机随时都可以用**”。

📐 **SPOOLing 技术的特点**：
- **提高了 I/O 的速度**：对数据执行的 I/O 操作，已从对低速 I/O 设备执行的 I/O 操作演变为对磁盘缓冲区中数据的存取，如同脱机输入/输出一样，缓和了 CPU 与低速 I/O 设备之间速度不匹配的矛盾
- **将独占设备改造为共享设备**：在假脱机打印机系统中，实际上**并没有为任何进程分配设备**，而只是在输入井或输出井中为进程分配一个存储区和创建一张 I/O 请求表
- **实现了虚拟设备功能**：多个进程同时使用一台独占设备，而对每个进程而言，都认为自己独占这个设备，从而实现了设备的虚拟化（**时分复用**的思想，把一个物理设备变为多个逻辑上的对应物）
- ⚠️ SPOOLing 破坏了死锁的“**互斥条件**”（把独占设备变为共享设备）

⚠️ **易混**：
- **输入井/输出井在磁盘上**；**输入缓冲区/输出缓冲区在内存中**
- SPOOLing 是一种**以空间换时间**的技术（用磁盘空间换取 I/O 速度）
- SPOOLing 属于 I/O 软件层次中的**用户层软件**

---

## ⚠️ 易错点

1. 单缓冲每块时间 = **max(C, T) + M**；双缓冲 = **max(T, M + C)**
2. 总时间别忘了**最后一块**剩下的 M、C
3. 若题目没说，**一个缓冲区大小 = 一个块**
4. **缓冲区中的数据不一定在低速设备上有备份**；Cache 中的数据一定是低速设备中数据的副本
5. 设备分配数据结构：**SDT（全系统一张）→ DCT（每设备）→ COCT（每控制器）→ CHCT（每通道）**
6. 分配成功要**设备、控制器、通道三者**都分配成功
7. **安全分配**：进程申请设备后阻塞，不会死锁；**不安全分配**：可以继续执行，可能死锁
8. SPOOLing：**输入井/输出井在磁盘**，**缓冲区在内存**；需要**多道程序**支持；把独占设备改造成**共享设备**；并没有把打印机真正分配给进程

## 📋 本课小结

| 知识点 | 要点 |
|---|---|
| 缓冲作用 | 缓和速度矛盾、减少中断、解决粒度不匹配、提高并行 |
| 单缓冲 | max(C, T) + M |
| 双缓冲 | max(T, M + C) |
| 循环缓冲/缓冲池 | 多个缓冲区；hin、sin、hout、sout |
| 设备分配 | 固有属性、算法、安全性；SDT → DCT → COCT → CHCT |
| SPOOLing | 输入井/输出井（磁盘）+ 缓冲区（内存）+ 输入/输出进程；独占变共享 |

## 🏋️ 课后练习

1. 某文件占 5 个磁盘块，读入一块到缓冲区需 80μs，从缓冲区传到用户区需 20μs，CPU 处理一块需 60μs。求单缓冲和双缓冲下的总时间。
2. 在 T = 50，M = 20，C = 100 时，单缓冲和双缓冲下处理一块数据的平均时间各是多少？双缓冲能否显著提高效率？为什么？
3. 判断：(a) SPOOLing 技术中的输入井在内存中；(b) SPOOLing 技术可以把打印机改造为共享设备；(c) 设备分配时只要设备空闲就一定能分配成功。
4. 解释为什么说 SPOOLing 系统中“并没有为任何进程分配打印机”。

<details>
<summary>📖 答案</summary>

1. 单缓冲：每块 max(60, 80) + 20 = 100，总时间 = 5 × 100 + 60 = **560μs**。双缓冲：每块 max(80, 20 + 60) = 80，总时间 = 5 × 80 + 20 + 60 = **480μs**
2. 单缓冲：max(100, 50) + 20 = **120**；双缓冲：max(50, 120) = **120**。**不能**显著提高效率，因为瓶颈在 CPU 处理（M + C = 120 > T），缓冲区再多，CPU 也来不及处理
3. (a) **错**，在磁盘上；(b) **对**；(c) **错**，还需要控制器和通道也空闲
4. 进程提出打印请求时，系统只是在**磁盘输出井**中为它申请一块存储区存放打印数据，并建立一张打印请求表挂到队列上，进程就可以继续执行；真正使用打印机的是**输出进程**，它按队列顺序逐个打印。所以用户进程从未独占过打印机
</details>
