# 数据结构 第 24 课 · 红黑树

> 🎯 **本课目标**
> 1. 理解为什么需要红黑树（AVL 的缺点）
> 2. **记住红黑树的 5 条性质**，理解“黑高”
> 3. 掌握红黑树的重要结论：**最长路径 ≤ 2 × 最短路径**、**高度 ≤ 2log₂(n+1)**
> 4. 掌握红黑树的**插入**（新结点为红、看叔叔颜色：变色或旋转）
> 5. 了解删除，能比较 AVL 与红黑树
>
> 红黑树是 2022 年大纲新增的考点，目前主要以**选择题**形式考查性质和插入。

---

## 🚪 课前引入：AVL 太“较真”了

AVL 树要求每个结点左右子树高度差 ≤ 1，非常平衡，查找很快。但是：
- 每插入、删除一个结点，都可能要**旋转**来恢复平衡
- 特别是**删除**，可能要一直旋转到根

如果一个应用**插入删除非常频繁**（比如操作系统的进程调度、数据库索引），频繁旋转开销很大。
**红黑树**：放宽一点要求，只要“**大致平衡**”（最长路径不超过最短路径的 2 倍），换来**插入删除时旋转次数少**（插入最多 2 次旋转，删除最多 3 次旋转）。

Linux 内核的进程调度、C++ 的 map/set、Java 的 TreeMap 都用红黑树。

---

## 一、红黑树的定义（⭐⭐⭐）

红黑树是一棵**二叉排序树**，并满足：
1. 每个结点或是**红色**，或是**黑色**
2. **根结点是黑色**
3. **叶结点（虚构的外部结点、NULL 结点）都是黑色**
4. **不存在两个相邻的红结点**（红结点的父结点和孩子结点都是黑色）
5. 对每个结点，**从该结点到任一叶结点的简单路径上，所含黑结点的数量相同**

🧒 **口诀**：“**左根右，根叶黑，不红红，黑路同**”
- 左根右：它是二叉排序树（左 < 根 < 右）
- 根叶黑：根和叶（NULL）都是黑的
- 不红红：红结点不能连着
- 黑路同：每条路径上的黑结点数相同

⚠️ **这里的“叶结点”是指 NULL 外部结点**（就是二叉排序树中查找失败的位置），不是普通意义上的叶子。画图时常常省略，但计算黑高时要考虑。

一棵合法的红黑树（N 表示 NULL 黑色叶结点）：
```
                20(B)
             /                 10(B)         30(B)
        /    \         /         5(R)   15(R)   25(R)     N
     /  \   /  \    /      N    N N    N  N    N
```
检查“黑路同”：从 20 出发到任何一个 N，经过的黑结点（不含 20 本身）都是 2 个（10 或 30，再加上 N）。

### 📐 黑高（bh）
**从某结点出发（不含该结点本身）到达一个叶结点的任一简单路径上的黑结点总数**，称为该结点的**黑高**，记为 bh(x)。
- 由性质 5，黑高是**确定**的
- **根的黑高称为红黑树的黑高**

---

## 二、红黑树的重要结论（⭐⭐⭐ 选择题核心）

### 结论 1：从根到叶结点的最长路径不大于最短路径的 2 倍
🧒 **理由**：
- 由性质 5，所有路径上**黑结点数相同**，设为 bh
- **最短路径**：全是黑结点，长度 bh
- **最长路径**：由性质 4（不能红红），最多是**红黑相间**，红结点数 ≤ 黑结点数，长度 ≤ 2bh
- 所以 最长 ≤ 2 × 最短

### 结论 2：有 n 个内部结点的红黑树，高度 h ≤ 2log₂(n + 1)
🧒 **推导**：
- 先证：以任一结点 x 为根的子树，至少有 **2^bh(x) − 1** 个内部结点（数学归纳法）
- 根的黑高 ≥ h/2（因为从根到叶的路径上至少一半是黑结点）
- 所以 n ≥ 2^(h/2) − 1 → h ≤ 2log₂(n + 1)
→ 红黑树的查找、插入、删除都是 **O(log n)**

### 结论 3：黑高为 bh 的红黑树，内部结点数至少为 2^bh − 1，至多为 2^(2bh) − 1
- 最少：全黑的满二叉树（高度 bh）→ 2^bh − 1
- 最多：红黑相间的满二叉树（高度 2bh）→ 2^(2bh) − 1

### 结论 4：其他性质
- 红结点的孩子**要么都是 NULL，要么都是黑色的内部结点**（不可能一个 NULL 一个黑色内部结点——那样两条路径的黑结点数不同）
- 若一个结点只有一个孩子（不算 NULL），那么这个孩子一定是**红色的叶子**，这个结点一定是**黑色**的
- 新插入的结点是**红色**的（见下）

## 三、红黑树的插入（⭐⭐）

### 📐 为什么新结点是红色？
- 若插入黑色结点，**这条路径上黑结点就多了一个**，必然破坏性质 5，而且很难修复
- 插入红色结点：只有当它的**父结点也是红色**时才破坏性质 4，修复相对容易

### 📐 插入步骤
1. 按**二叉排序树**的方法插入新结点 z，**染成红色**
2. 若 z 是**根** → 染成黑色，结束
3. 若 z 的**父结点是黑色** → 没有破坏任何性质，结束
4. 若 z 的**父结点是红色**（出现“红红”）→ 需要调整。设父结点为 p，祖父为 g（g 一定是黑色，因为 p 是红色），**叔叔**（父结点的兄弟）为 u，**看叔叔的颜色**：

### 📐 情况一：叔叔是红色 → 变色
- 把**父结点 p 和叔叔 u 染黑**，**祖父 g 染红**
- 然后**把 g 当作新插入的结点**，继续向上检查（g 的父结点可能也是红色）
- 若 g 是根，最后把根染回黑色

```
         g(B)                    g(R) ← 继续向上检查
        /    \                  /    \
     p(R)    u(R)     →      p(B)    u(B)
     /                       /
   z(R)                    z(R)
```
🧒 “**叔红：父叔变黑，爷爷变红，爷爷当新人**”

### 📐 情况二：叔叔是黑色（包括 NULL）→ 旋转 + 变色
按 z 相对于 g 的位置分四种（和 AVL 一样）：

**LL 型**（p 是 g 的左孩子，z 是 p 的左孩子）：
- 以 g 为轴**右旋**（p 上位）
- **p 染黑，g 染红**（父爷换色）
```
         g(B)                     p(B)
        /    \                   /    \
     p(R)    u(B)     →       z(R)    g(R)
     /                                   \
   z(R)                                  u(B)
```
**RR 型**：对称，**左旋** + p、g 换色

**LR 型**（p 是 g 的左孩子，z 是 p 的右孩子）：
- 先以 p 为轴**左旋**（变成 LL 型，此时 z 在原 p 的位置）
- 再以 g 为轴**右旋**
- **z 染黑，g 染红**（儿爷换色）
```
       g(B)              g(B)               z(B)
      /    \            /    \             /    \
   p(R)   u(B)  →    z(R)   u(B)   →    p(R)    g(R)
      \              /                             \
      z(R)         p(R)                            u(B)
```
**RL 型**：对称，先右旋再左旋，z、g 换色

🧒 **口诀**：“**叔黑旋转：LL/RR 父爷换色；LR/RL 儿爷换色**”（本质是：旋转后**新的子树根染黑**，它的两个孩子为红）

### ✏️ 例题：依次插入 10, 20, 30, 15, 25, 5
**插入 10**：根 → 黑。`10(B)`

**插入 20**：20 > 10 → 右孩子，红。父黑，结束。
```
10(B)
   \
   20(R)
```
**插入 30**：30 → 20 的右孩子，红。父 20 红 → 调整。叔叔（10 的左孩子）是 NULL（黑）→ **RR 型**：以 10 为轴左旋，20 与 10 换色。
```
      20(B)
     /    \
  10(R)   30(R)
```
**插入 15**：15 < 20 → 10 → 15 > 10 → 10 的右孩子，红。父 10 红，叔叔 30 **红** → **变色**：10、30 染黑，20 染红；20 是根 → 染回黑。
```
       20(B)
      /     \
   10(B)    30(B)
      \
      15(R)
```
**插入 25**：25 → 30 的左孩子，红。父 30 黑，结束。
**插入 5**：5 → 10 的左孩子，红。父 10 黑，结束。
```
          20(B)
        /       \
     10(B)      30(B)
     /   \      /
   5(R) 15(R) 25(R)
```
检查：根黑 ✓；无红红 ✓；各路径黑结点数（不含根）都是 2（含 NULL 叶子）✓

### ✏️ LR 型的例子：依次插入 10, 5, 7
- 10 根，黑；5 左孩子，红
- 7 → 5 的右孩子，红。父 5 红，叔叔 NULL 黑，**LR 型**：先左旋 5，再右旋 10，7 染黑、10 染红
```
   10(B)                7(B)
   /          →        /   \
 5(R)               5(R)   10(R)
    \
    7(R)
```

### 📐 插入的复杂度
- 查找插入位置 O(log n)
- 情况一（变色）最多向上 O(log n) 次
- 情况二（旋转）**最多 2 次旋转**，旋转后调整就结束了
- 总 **O(log n)**

## 四、红黑树的删除（了解）
- 先按二叉排序树的方法删除（有两个孩子时用前驱或后继替代）
- 若删除的是**红色**结点，不影响性质
- 若删除的是**黑色**结点，某些路径黑结点少了一个，需要通过变色和旋转修复（情况较多，考试一般不深究）
- **删除最多 3 次旋转**，时间 O(log n)

---

## 五、红黑树 vs AVL 树（⭐⭐）

| | AVL 树 | 红黑树 |
|---|---|---|
| 平衡条件 | 左右子树高度差 ≤ 1（**严格**平衡） | 最长路径 ≤ 2 × 最短路径（**大致**平衡） |
| 树高 | ≈ 1.44 log₂n | ≤ 2log₂(n+1) |
| 查找 | 略快 | 略慢（但同为 O(log n)） |
| 插入旋转次数 | 最多 1 次调整（单旋或双旋） | 最多 2 次 |
| 删除旋转次数 | 可能要一直调整到根，O(log n) 次 | **最多 3 次** |
| 适用 | **查找多、修改少** | **插入删除频繁** |

⚠️ **红黑树不一定是 AVL 树**：红黑树允许左右子树高度差超过 1。
例如下面这棵树是合法的红黑树（每条路径黑结点数都是 2，含 NULL），但根的左子树高 1、右子树高 3，高度差为 2，不是 AVL 树：
```
        20(B)
       /         10(B)    25(R)
            /              22(B)    28(B)
         /
      21(R)
```

## 六、常见选择题（⭐）

📝 **题 1**：下列关于红黑树的说法中，正确的是：
- 红黑树是一棵二叉排序树 ✓
- 红黑树中红结点的孩子一定是黑色（包括 NULL）✓
- 从根到叶的最长路径不超过最短路径的 2 倍 ✓
- 红黑树一定是平衡二叉树（AVL）✗
- 新插入的结点一定是红色 ✓（插入时染红，但调整后可能变色）

📝 **题 2**：一棵黑高为 3 的红黑树，内部结点最少有几个？最多有几个？
→ 最少 2³ − 1 = **7**；最多 2⁶ − 1 = **63**

📝 **题 3**：含有 n 个内部结点的红黑树，高度最大是？
→ **2log₂(n + 1)**

📝 **题 4**：在红黑树中插入一个结点，若其父结点为红色、叔叔结点为红色，应该怎么做？
→ 父、叔染黑，祖父染红，以祖父为新结点继续向上调整

---

## ⚠️ 易错点
1. 红黑树的“叶结点”是 **NULL 外部结点**
2. 黑高**不含**出发结点本身
3. 新插入的结点**染红**
4. 叔叔红 → 变色（不旋转）；叔叔黑 → 旋转 + 变色
5. LL/RR：父、爷换色；LR/RL：儿、爷换色
6. 红黑树**不一定**是 AVL 树

## 📋 本课小结

| 知识点 | 要点 |
|---|---|
| 5 条性质 | 左根右，根叶黑，不红红，黑路同 |
| 黑高 bh | 到叶结点路径上黑结点数（不含自身） |
| 最长 vs 最短 | 最长 ≤ 2 × 最短 |
| 树高 | h ≤ 2log₂(n+1) |
| 结点数 | 黑高 bh：至少 2^bh − 1，至多 2^(2bh) − 1 |
| 插入 | 新结点红；父黑结束；父红看叔叔 |
| 叔红 | 父叔变黑，爷变红，爷当新结点 |
| 叔黑 | 旋转（LL/RR/LR/RL）+ 换色 |
| 旋转次数 | 插入 ≤ 2，删除 ≤ 3 |
