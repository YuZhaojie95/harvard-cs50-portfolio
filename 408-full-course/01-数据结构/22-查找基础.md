## 一、查找的基本概念

| 术语 | 含义 |
|---|---|
| **查找** | 在数据集合中寻找满足某种条件的数据元素 |
| **查找表** | 用于查找的数据集合 |
| **静态查找表** | 只做查找操作（不插入删除） |
| **动态查找表** | 查找的同时还要插入、删除 |
| **关键字** | 数据元素中**唯一标识**该元素的某个数据项的值（如学号） |
| **平均查找长度 ASL** | 查找过程中**关键字比较次数**的平均值 |

$$\text{ASL} = \sum_{i=1}^{n} P_i C_i$$
- Pᵢ：查找第 i 个元素的概率（一般假设相等，Pᵢ = 1/n）
- Cᵢ：找到第 i 个元素需要的比较次数

**ASL 分为**：
- **查找成功**的 ASL：要找的元素在表中
- **查找失败**的 ASL：要找的元素不在表中

**ASL 是衡量查找算法效率的主要指标。**

## 二、顺序查找（线性查找）

### 📐 一般线性表的顺序查找
从一端开始，逐个比较，直到找到或到另一端。
```c
typedef struct {
    ElemType *elem;          // elem[0] 留作“哨兵”
    int TableLen;
} SSTable;

int Search_Seq(SSTable ST, ElemType key) {
    ST.elem[0] = key;                                  // 哨兵
    int i;
    for (i = ST.TableLen; ST.elem[i] != key; i--);     // 从后往前找
    return i;                                          // 返回 0 表示失败
}
```
🧒 **哨兵的作用**：把 key 放在 elem[0]，循环时**不用每次判断 i 是否越界**（到 0 时一定会相等而停下），提高效率。

**ASL**（n 个元素，等概率）：
- **成功**：找第 i 个（从后往前第 i 个）要比较 i 次 → ASL = (1 + 2 + … + n)/n = **(n + 1)/2**
- **失败**：要比较到哨兵，共 **n + 1** 次（不用哨兵是 n 次）

**特点**：
- ✅ 对表**没有任何要求**：无序可以、链表也可以
- ❌ n 大时效率低，**O(n)**

### 📐 有序表的顺序查找
表中元素**有序**（比如递增），查找失败时**不用比到最后**：一旦发现当前元素已经**大于** key，就可以停止了。

**判定树**表示：
```
          10
         /  \
     (<10)   20
            /  \
        (10~20)  30
                /  \
          (20~30)  (>30)
```
- **成功** ASL 不变：**(n + 1)/2**
- **失败**：n 个元素把数轴分成 **n + 1** 个失败区间，落到第 j 个区间需要比较 j 次（最后一个区间比较 n 次）：
$$\text{ASL}_{失败} = \frac{1 + 2 + \cdots + n + n}{n + 1} = \frac{n}{2} + \frac{n}{n+1}$$

## 三、折半查找（二分查找，⭐⭐⭐）

### 📐 前提
**只适用于有序的顺序表**（必须能随机存取，链表不行）。

### 📐 算法
1. low = 1，high = n
2. mid = ⌊(low + high)/2⌋
3. 比较 key 和 elem[mid]：
   - 相等 → 成功
   - key < elem[mid] → 去左半边：high = mid − 1
   - key > elem[mid] → 去右半边：low = mid + 1
4. 重复直到 low > high（失败）

```c
int Binary_Search(SSTable L, ElemType key) {
    int low = 1, high = L.TableLen, mid;
    while (low <= high) {
        mid = (low + high) / 2;           // 向下取整
        if (L.elem[mid] == key) return mid;
        else if (L.elem[mid] > key) high = mid - 1;
        else low = mid + 1;
    }
    return 0;                             // 失败
}
```

### ✏️ 过程演示
表：{7, 10, 13, 16, 19, 29, 32, 33, 37, 41, 43}（下标 1~11），查找 **11**（不存在）：
| 轮次 | low | high | mid | elem[mid] | 比较 |
|---|---|---|---|---|---|
| 1 | 1 | 11 | 6 | 29 | 11 < 29，high = 5 |
| 2 | 1 | 5 | 3 | 13 | 11 < 13，high = 2 |
| 3 | 1 | 2 | 1 | 7 | 11 > 7，low = 2 |
| 4 | 2 | 2 | 2 | 10 | 11 > 10，low = 3 |
| — | 3 | 2 | | | low > high，**失败**，共比较 4 次 |

### 📐 判定树（⭐⭐⭐）
把折半查找的过程画成一棵二叉树：第一次比较的 mid 作为根，左半部分的 mid 作为左孩子，右半部分的作为右孩子……再把**查找失败的位置**画成方形的**失败结点**。

**11 个元素**（用下标表示）的判定树：
```
                    6
              /           \
            3               9
          /   \           /   \
         1     4         7     10
        / \   / \       / \   /  \
       □   2 □   5     □   8 □    11
          / \   / \       / \    /  \
         □   □ □   □     □   □  □    □
（□ 表示失败结点）
```
**判定树的性质**：
1. 查找某元素的比较次数 = 它在判定树中的**层数**
2. 查找失败的比较次数 = 失败结点**父结点的层数**（到达失败结点前比较过的次数）
3. n 个元素的判定树有 **n 个圆形结点**、**n + 1 个方形（失败）结点**
4. 判定树是一棵**平衡二叉树**（左右子树高度差 ≤ 1），也是一棵**二叉排序树**
5. 用 mid = ⌊(low+high)/2⌋ 时，对任一结点，**右子树结点数 − 左子树结点数 = 0 或 1**（右边可能多一个）
   用 mid = ⌈(low+high)/2⌉ 时，左子树可能多一个
6. **树高 h = ⌈log₂(n + 1)⌉**（不含失败结点）
7. **查找成功和失败时，比较次数最多都不超过树高 ⌈log₂(n + 1)⌉**

**ASL 计算（上例 n = 11）**：
- 成功：第 1 层 1 个、第 2 层 2 个、第 3 层 4 个、第 4 层 4 个
  ASL成功 = (1×1 + 2×2 + 3×4 + 4×4)/11 = 33/11 = **3**
- 失败：12 个失败结点，其中 4 个的父结点在第 3 层（1、4、7、10 的左孩子位置），8 个的父结点在第 4 层
  ASL失败 = (3×4 + 4×8)/12 = 44/12 ≈ **3.67**

**近似公式**：ASL ≈ log₂(n + 1) − 1，时间复杂度 **O(log n)**

📝 **经典真题（2010 年真题）**：已知一个长度为 16 的顺序表 L，其元素按关键字有序排列。若采用折半查找法查找一个 L 中**不存在**的元素，则关键字的比较次数**最多**是？
→ 树高 ⌈log₂(16 + 1)⌉ = ⌈4.09⌉ = **5**

### 📐 判断一棵树能否是折半查找判定树（⭐）
检查每个结点：若都是“**右子树比左子树多 0 或 1 个结点**”（向下取整），或都是“**左子树比右子树多 0 或 1 个**”（向上取整），就可能是。**同一棵树中不能混用两种**。

### 📐 判断比较序列是否合法（⭐）
折半查找的比较序列，是判定树（BST）中**从根往下的一条路径**。所以要满足 BST 性质：每次比较后，后续比较的值都要落在“当前允许的区间”内。
📝 **经典题（2015 年真题）**：下列选项中，**不能**构成折半查找中关键字比较序列的是：
A. 500, 200, 450, 180 &nbsp; B. 500, 450, 200, 180 &nbsp; C. 180, 500, 200, 450 &nbsp; D. 180, 200, 500, 450
**分析 A**：比较 500 → 去左边（< 500）；比较 200 → 下一个 450 > 200，去右边，区间 (200, 500)；比较 450 → 下一个 180 < 450，区间应是 (200, 450)，但 **180 < 200**，不在区间内 ✗
（B：500 → (−∞,500)；450 → 200 在左 (−∞,450)；200 → 180 在左 ✓；C：180 → (180,∞)；500 → 200 在 (180,500) ✓；200 → 450 在 (200,500) ✓；D：180 → 200 → 500 → 450 在 (200,500) ✓）
答案 **A**。

### 📐 折半查找 vs 顺序查找
📝 **经典题（2016 年真题）**：在 n（n > 1000）个元素的升序数组 A 中查找 x，算法是：k 从 0 开始，每次 **k += 3**，直到 A[k] ≥ x，然后检查 A[k]、A[k−1]、A[k−2]。本算法与折半查找相比，**有可能具有更少比较次数**的情形是？
→ **当 x 接近数组开头处**（只比较几次就停了，而折半查找总要比较约 log₂n 次）

## 四、分块查找（索引顺序查找，⭐⭐）

### 📐 思想
- 把表分成若干**块**，**块内无序，块间有序**（第一块中所有元素 < 第二块中所有元素 < …）
- 建一个**索引表**，每个索引项记录**该块的最大关键字**和**块的起始地址**，索引表**按关键字有序**

```
索引表:   [ 22 | 48 | 86 ]      （各块的最大关键字）
            ↓    ↓    ↓
查找表:   22 12 13 8 9 20 | 33 42 44 38 24 48 | 60 58 74 49 86 53
            第 1 块              第 2 块                第 3 块
```
**查找步骤**：
1. 在**索引表**中确定 key 所在的块（顺序或折半查找）
2. 在**块内**顺序查找

### 📐 ASL（⭐⭐）
设 n 个元素均匀分成 **b 块**，每块 **s 个**（n = bs），等概率：
$$\text{ASL} = L_I + L_S$$
（L_I：索引查找 ASL；L_S：块内查找 ASL）

**索引表和块内都用顺序查找**：
$$\text{ASL} = \frac{b + 1}{2} + \frac{s + 1}{2} = \frac{s^2 + 2s + n}{2s}$$
当 **s = √n** 时 ASL 取最小值 **√n + 1**。

🧒 **推导**：ASL = (n/s + s)/2 + 1，由均值不等式 n/s + s ≥ 2√n，当 n/s = s，即 s = √n 时取等号。

**索引表用折半查找、块内顺序查找**：
$$\text{ASL} = \lceil \log_2(b + 1) \rceil + \frac{s + 1}{2}$$

📝 **真题（2025 年第 7 题）**：已知查找表中有 400 个元素，查找元素概率相同。采用分块查找法且均匀分块，若采用顺序查找法确定元素所在块，且块内也用顺序查找法，为效率最高，每块包含元素应为？
→ s = √400 = **20**，选 C（此时 ASL = 21）

📝 **变形**：n = 10000，索引和块内都顺序查找，最优时 ASL = √10000 + 1 = **101**

## 五、三种查找方法比较

| | 顺序查找 | 折半查找 | 分块查找 |
|---|---|---|---|
| 表的要求 | 无 | **有序 + 顺序存储** | 块间有序 |
| 存储结构 | 顺序、链式都可 | **只能顺序** | 顺序或链式 |
| ASL（成功） | (n+1)/2 | ≈ log₂(n+1) − 1 | (b+1)/2 + (s+1)/2 |
| 时间复杂度 | O(n) | O(log n) | 介于两者之间，最优 O(√n) |
| 插入删除 | 方便 | 需要移动元素保持有序 | 较方便（块内无序） |

## 📌 补充真题

📝 **补充真题（2023 年第 8 题）**：对含有 600 个元素的有序顺序表进行折半查找，关键字间的比较次数最多是：A. 9　B. 10　C. 30　D. 300
- 最多比较次数 = 判定树高度 = ⌊log₂n⌋ + 1 = ⌊log₂600⌋ + 1 = 9 + 1 = **10** → 选 **B**（2⁹ = 512 ≤ 600 < 1024 = 2¹⁰）

## ⚠️ 易错点
1. 折半查找**不能用于链表**
2. 判定树高 ⌈log₂(n+1)⌉；**成功和失败最多比较次数都是它**
3. 失败 ASL 的分母是**失败结点个数 n + 1**
4. 失败结点的比较次数 = **父结点所在层数**
5. 用向下取整时右子树可能多一个结点
6. 分块查找最优块长 s = √n（索引和块内都顺序查找时）

## 📋 本课小结

| 方法 | 成功 ASL | 失败 ASL / 要点 |
|---|---|---|
| 顺序（无序） | (n+1)/2 | n+1（有哨兵） |
| 顺序（有序） | (n+1)/2 | n/2 + n/(n+1) |
| 折半 | ≈ log₂(n+1) − 1 | 最多比较 ⌈log₂(n+1)⌉ 次 |
| 分块（顺序+顺序） | (b+1)/2 + (s+1)/2 | 最优 s = √n，ASL = √n + 1 |
