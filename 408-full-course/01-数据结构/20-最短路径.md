## 🚪 课前引入：手机导航

打开导航软件，从家到学校，它会告诉你“最短路线”。
- 如果只关心“换乘几次”（每段路都算 1），用 **BFS** 就行
- 如果每段路长度不同（有的 2 公里，有的 5 公里），就要用 **Dijkstra**
- 如果要做一张“**任意两地之间的距离表**”，用 **Floyd**

## 一、问题分类

| 问题 | 含义 | 算法 |
|---|---|---|
| **单源最短路径** | 从**一个**顶点到**其他所有**顶点的最短路径 | BFS（无权图）、**Dijkstra**（带权图） |
| **各顶点间最短路径** | **每一对**顶点之间的最短路径 | **Floyd**（或对每个顶点跑一次 Dijkstra） |

带权图中，**路径长度 = 路径上所有边的权值之和**。

---

## 二、BFS 求无权图的单源最短路径
上一课讲过：BFS 按“距离”由近到远访问，第一次访问某顶点时的层数就是最短路径长度。
⚠️ **只能用于无权图（或所有边权值相同）**。带权图中，边数少的路径不一定权值和小。
📝 **2025 年第 6 题 D**：“可用 BFS 算法求出带权图中每一对顶点间的最短路径” ✗。

## 三、Dijkstra 算法（迪杰斯特拉，⭐⭐⭐）

### 📐 思想（贪心）
🧒 **大白话**：从家出发，你想知道到每个地方的最短距离。
1. 先看从家**直接**能到的地方，其中**最近**的那个地方 X，它的最短距离**一定已经确定**了——因为如果绕别的地方去 X，第一段就已经比直接去 X 远了（前提：没有负权边）
2. 然后看看“**经过 X 中转**”，能不能让去其他地方的距离变短，能就更新
3. 在还没确定的地方里，再选最近的，它的最短距离又确定了……
4. 重复，直到所有地方都确定

### 📐 三个辅助数组
| 数组 | 含义 |
|---|---|
| **final[v]** | 顶点 v 的最短路径是否**已经确定**（已加入集合 S） |
| **dist[v]** | 当前找到的从源点到 v 的最短路径长度 |
| **path[v]** | 当前最短路径上 v 的**前驱**（用于还原路径） |

### 📐 算法步骤
1. **初始化**：final[源点] = true；dist[v] = 源点到 v 的弧的权值（没有弧则 ∞）；path[v] = 源点（有弧时）或 −1
2. **重复 n − 1 次**：
   - 在 final[v] = false 的顶点中，选 **dist 最小**的顶点 k，令 final[k] = true（k 的最短路径确定）
   - **松弛（更新）**：对每个 final[v] = false 的顶点 v，若 dist[k] + w(k, v) < dist[v]，则 dist[v] = dist[k] + w(k, v)，path[v] = k

### ✏️ 例题（⭐ 一定要自己画表跟一遍）
有向带权图，源点 1：
```
1→2 (10)   1→4 (5)
2→3 (1)    2→4 (2)
4→2 (3)    4→3 (9)    4→5 (2)
3→5 (4)    5→3 (6)    5→1 (7)
```
| 轮次 | 确定的顶点 | dist[2] | dist[3] | dist[4] | dist[5] | 说明 |
|---|---|---|---|---|---|---|
| 初始 | 1 | 10 | ∞ | 5 | ∞ | 1 直达 2、4 |
| 第 1 轮 | **4**（dist=5 最小） | 5+3=**8** | 5+9=14 | ✓5 | 5+2=**7** | 经 4 到 2 更近 |
| 第 2 轮 | **5**（dist=7） | 8 | 7+6=**13** | ✓ | ✓7 | 经 5 到 3 更近 |
| 第 3 轮 | **2**（dist=8） | ✓8 | 8+1=**9** | ✓ | ✓ | 经 2 到 3 更近 |
| 第 4 轮 | **3**（dist=9） | ✓ | ✓9 | ✓ | ✓ | 3 的出边只到 5，已确定 |

**最终结果**：
| 顶点 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|
| dist | 8 | 9 | 5 | 7 |
| path | 4 | 2 | 1 | 4 |

**还原路径**（顺着 path 往回找）：
- 到 3：path[3] = 2，path[2] = 4，path[4] = 1 → **1 → 4 → 2 → 3**，长度 5 + 3 + 1 = 9 ✓
- 到 5：path[5] = 4，path[4] = 1 → **1 → 4 → 5**，长度 7 ✓

**依次得到最短路径的顶点顺序**：4, 5, 2, 3（最短路径长度依次递增：5, 7, 8, 9）

📝 **真题（2021 年第 8 题）**：使用 Dijkstra 算法求下图中从顶点 1 到其余各顶点的最短路径，将当前找到的从顶点 1 到顶点 2, 3, 4, 5 的最短路径长度保存在数组 dist 中，**求出第二条最短路径后**，dist 中的内容更新为？
A. 26, 3, 14, 6 &nbsp; B. 25, 3, 14, 6 &nbsp; C. 21, 3, 14, 6 &nbsp; D. 15, 3, 14, 6
图中的弧（据原卷图）：1→2 (26)、1→3 (3)、1→5 (6)、5→2 (15)、5→3 (6)、5→4 (8)、4→2 (1)、4→3 (6)、3→2 (22)

| 阶段 | 确定的顶点 | dist[2] | dist[3] | dist[4] | dist[5] |
|---|---|---|---|---|---|
| 初始 | 1 | 26 | 3 | ∞ | 6 |
| 第一条最短路径 | **3**（3） | 3+22 = **25** | ✓3 | ∞ | 6 |
| 第二条最短路径 | **5**（6） | 6+15 = **21** | ✓ | 6+8 = **14** | ✓6 |

求出第二条最短路径（到 5）并更新后：dist = **21, 3, 14, 6**，选 **C**。
⚠️ 陷阱：选 B（25, 3, 14, 6）的同学是忘了用顶点 5 去更新 dist[2]；选 A 的同学是连第一次更新都忘了。

### 📐 代码
```c
void Dijkstra(MGraph G, int v0, int dist[], int path[]) {
    bool final[MAX];
    for (int v = 0; v < G.vexnum; v++) {
        final[v] = false;
        dist[v] = G.Edge[v0][v];                     // 无边为 INF
        path[v] = (G.Edge[v0][v] < INF) ? v0 : -1;
    }
    final[v0] = true; dist[v0] = 0;
    for (int i = 1; i < G.vexnum; i++) {             // 再确定 n-1 个顶点
        int min = INF, k = -1;
        for (int v = 0; v < G.vexnum; v++)           // 选未确定顶点中 dist 最小的
            if (!final[v] && dist[v] < min) { min = dist[v]; k = v; }
        if (k == -1) break;                          // 剩下的都不可达
        final[k] = true;
        for (int v = 0; v < G.vexnum; v++)           // 松弛
            if (!final[v] && G.Edge[k][v] < INF && dist[k] + G.Edge[k][v] < dist[v]) {
                dist[v] = dist[k] + G.Edge[k][v];
                path[v] = k;
            }
    }
}
```

### 📐 复杂度
- 外层 n − 1 次，每次选最小 O(n) + 松弛 O(n) → **O(|V|²)**
- 用邻接表也是 O(|V|²)（瓶颈在“选最小”）；用堆优化可以到 O(|E| log |V|)（了解）

### 📐 Dijkstra 不能处理负权边（⭐⭐）
**反例**：
```
A → B (5)
A → C (6)
C → B (−3)
```
- 初始 dist[B] = 5，dist[C] = 6
- 第 1 轮选 B（5 最小），**final[B] = true**，认为 A→B 最短是 5
- 第 2 轮选 C，想用 C 更新 B：6 + (−3) = 3 < 5，但 B 已经 final 了，**不会再更新**
- 实际最短路径 A→C→B 长度 3，Dijkstra 给出 5 ✗

🧒 原因：Dijkstra 的前提是“**绕远路只会更远**”，负权边打破了这个前提。

### 📐 Dijkstra 与 Prim 的异同（⭐ 选择题）
代码结构几乎一样，区别在更新规则：
- **Prim**：lowcost[v] = min(lowcost[v], **w(k, v)**)——到“树”的距离
- **Dijkstra**：dist[v] = min(dist[v], **dist[k] + w(k, v)**)——到“源点”的距离

## 四、Floyd 算法（弗洛伊德，⭐⭐）

### 📐 思想（动态规划）
🧒 **大白话**：一开始，只允许“直达”；然后允许“**经过顶点 0 中转**”，看看有没有哪两点之间因此变近了；再允许“经过 0 和 1 中转”……直到允许经过所有顶点中转。

定义 **A⁽ᵏ⁾[i][j]**：从 i 到 j、**中间只允许经过编号 ≤ k 的顶点**的最短路径长度。
- **A⁽⁻¹⁾ = 邻接矩阵**（不允许任何中转）
- 递推：
$$A^{(k)}[i][j] = \min\{A^{(k-1)}[i][j],\; A^{(k-1)}[i][k] + A^{(k-1)}[k][j]\}$$
（要么不经过 k，要么经过 k：i → k → j）
- **A⁽ⁿ⁻¹⁾** 就是最终答案

### 📐 代码（三重循环，**k 在最外层**）
```c
void Floyd(MGraph G, int A[][MAX], int path[][MAX]) {
    int n = G.vexnum;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++) {
            A[i][j] = G.Edge[i][j];              // 初始化为邻接矩阵
            path[i][j] = -1;                     // -1 表示直达（没有中转点）
        }
    for (int k = 0; k < n; k++)                  // 考虑以 k 为中转点
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                if (A[i][k] + A[k][j] < A[i][j]) {
                    A[i][j] = A[i][k] + A[k][j];
                    path[i][j] = k;              // 记录中转点
                }
}
```
⚠️ **k 必须在最外层**！否则就不是“逐步允许更多中转点”了，结果会错。

### ✏️ 例题
有向图：0→1 (4)，0→2 (11)，1→0 (6)，1→2 (2)，2→0 (3)
```
A⁽⁻¹⁾（邻接矩阵）：        A⁽⁰⁾（允许经过 0）：
     0   1   2                 0   1   2
0 [  0   4  11 ]          0 [  0   4  11 ]
1 [  6   0   2 ]          1 [  6   0   2 ]
2 [  3   ∞   0 ]          2 [  3  [7]  0 ]    ← 2→0→1 = 3+4 = 7 < ∞

A⁽¹⁾（允许经过 0、1）：     A⁽²⁾（允许经过 0、1、2）：
     0   1   2                 0   1   2
0 [  0   4  [6] ]         0 [  0   4   6 ]
1 [  6   0   2 ]          1 [ [5]  0   2 ]    ← 1→2→0 = 2+3 = 5 < 6
2 [  3   7   0 ]          2 [  3   7   0 ]
     ↑ 0→1→2 = 4+2 = 6 < 11
```
**最终 path 矩阵**（记录中转点）：path[2][1] = 0，path[0][2] = 1，path[1][0] = 2，其余 −1。
还原 0 到 2 的路径：path[0][2] = 1 → 0 → 1 → 2（再分别看 path[0][1]、path[1][2] 都是 −1，直达）。

### 📐 复杂度与适用条件
- 时间 **O(|V|³)**，空间 O(|V|²)
- **允许有负权边**，但**不允许有负权回路**（绕着负环转一圈路径就更短，无限转下去，最短路径不存在）
- 也适用于**无向图**（无向边看成两条方向相反的有向边）
- 对每个顶点跑一次 Dijkstra 也能求所有顶点对，时间同样 O(|V|³)

## 五、三种算法比较（⭐⭐⭐）

| | BFS | Dijkstra | Floyd |
|---|---|---|---|
| 问题 | 单源 | 单源 | 各顶点间 |
| 无权图 | ✓ | ✓ | ✓ |
| 带权图 | ✗ | ✓ | ✓ |
| 负权边 | ✗ | **✗** | **✓** |
| 负权回路 | ✗ | ✗ | ✗ |
| 时间复杂度 | O(\|V\|²) 或 O(\|V\|+\|E\|) | **O(\|V\|²)** | **O(\|V\|³)** |
| 思想 | 层次扩展 | 贪心 | 动态规划 |

---

## ⚠️ 易错点
1. BFS 只能用于**无权图**
2. Dijkstra 选的是 dist 最小的**未确定**顶点；松弛时用 **dist[k] + w(k,v)**
3. Dijkstra 不能有负权边；Floyd 可以有负权边但不能有负权回路
4. Floyd 的 **k 在最外层**
5. “求出第 k 条最短路径后的 dist”——要包括这一轮的松弛更新
6. Dijkstra 得到最短路径的顺序是按**路径长度递增**的

---

## 📋 本课小结

| 算法 | 关键公式 | 复杂度 | 负权边 |
|---|---|---|---|
| BFS | d[w] = d[u] + 1 | O(V+E) | — |
| Dijkstra | dist[v] = min(dist[v], dist[k] + w(k,v)) | O(V²) | ✗ |
| Floyd | A[i][j] = min(A[i][j], A[i][k] + A[k][j]) | O(V³) | ✓（无负环） |

## 🏋️ 课后练习

1. 有向图：a→b (2)，a→c (5)，b→c (1)，b→d (6)，c→d (3)，c→e (8)，d→e (1)。用 Dijkstra 求 a 到各顶点的最短路径，写出每一轮的 dist 表和依次确定的顶点。
2. 对上题的图，求出第二条最短路径后，dist 数组（b, c, d, e）的内容是什么？
3. 无向图：A-B 1，B-C 2，A-C 4，用 Floyd 求所有顶点对的最短路径（写出 A⁽⁻¹⁾ 到最终矩阵）。
4. 为什么 Floyd 算法中 k 要放在最外层循环？

<details>
<summary>📖 答案</summary>

1. 初始：b 2，c 5，d ∞，e ∞
   - 确定 b(2)：c = min(5, 2+1) = 3，d = 2+6 = 8
   - 确定 c(3)：d = min(8, 3+3) = 6，e = 3+8 = 11
   - 确定 d(6)：e = min(11, 6+1) = 7
   - 确定 e(7)
   依次确定：**b, c, d, e**；最终 dist：b 2，c 3，d 6，e 7
2. 第二条最短路径是到 c（3），更新后：**b 2，c 3，d 6，e 11**
3. A⁽⁻¹⁾：A-B 1，B-C 2，A-C 4（对称）；经过 A：无改进；经过 B：A-C = min(4, 1+2) = **3**；经过 C：无改进。最终：A-B 1，A-C 3，B-C 2
4. A⁽ᵏ⁾ 的含义是“只允许经过编号 ≤ k 的顶点中转”。必须先把“只经过 0 号”的所有顶点对都算完，才能在此基础上考虑“经过 0、1 号”……如果 k 在内层，计算某对 (i, j) 时，用到的 A[i][k]、A[k][j] 可能还没有考虑完所有允许的中转点，结果不正确
</details>
