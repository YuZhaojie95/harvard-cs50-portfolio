## 🚪 课前引入

你（CPU）要从快递员（外设）那里收 100 个包裹，有几种办法：
1. **程序查询**：你**一直站在门口等**，每隔几秒问一句“到了吗？”——你什么别的事都干不了
2. **中断**：你在屋里干自己的事，**快递员每送来一个包裹就按一次门铃**，你出去签收一个——每个包裹都要你亲自去一趟
3. **DMA**：你雇了一个**管家（DMA 控制器）**，告诉他“收 100 个包裹，放到仓库第 3 排”。管家自己去收，**全部收完才告诉你一声**——你只在开始和结束时操心
4. **通道**：你雇了一个**物流经理（通道/I/O 处理器）**，他能按你给的“任务清单”（通道程序）管理好几个管家——你只需要下达任务清单

CPU 的速度远远快于外设，这 4 种方式就是让 CPU **越来越少地参与 I/O**、越来越多地去干别的事。

## 一、I/O 系统的基本概念（⭐）

### 📐 I/O 系统的组成
- **I/O 硬件**：外部设备、**I/O 接口（I/O 控制器）**、I/O 总线等
- **I/O 软件**：驱动程序、用户程序、管理程序等
  - 通过 **I/O 指令**（或访存指令）与接口交互；I/O 指令通常是**特权指令**，只能在**内核态**执行

### 📐 外部设备
- **输入设备**：键盘、鼠标
- **输出设备**：显示器、打印机
- **外存设备**：磁盘、SSD、光盘（既是输入也是输出）
- **网络设备**：网卡

## 二、I/O 接口（⭐⭐）

### 📐 为什么需要接口
外设种类多、速度差异大、信号格式各异，不能直接挂到系统总线上。**I/O 接口（I/O 控制器、设备控制器）**是主机和外设之间的“**翻译官 + 缓冲区**”。

### 📐 I/O 接口的功能
1. **地址译码和设备选择**：CPU 送来的地址是否选中本接口的某个寄存器
2. **数据缓冲**：解决主机和外设的**速度差异**
3. **信号格式转换**：如串-并转换、电平转换
4. **传送控制命令和状态信息**：CPU 发命令给外设；把外设的状态（“就绪”“忙”“出错”）报告给 CPU
5. 中断、DMA 等控制逻辑

### 📐 I/O 接口的结构
```
  系统总线侧                                    外设侧
  ┌──────────────────── I/O 接口 ────────────────────┐
  │  数据缓冲寄存器（DBR）  ◄──────────────────────►  │ ◄──► 外设
  │  状态寄存器            ◄───────────────────────  │
  │  控制寄存器            ───────────────────────►  │
  │  地址译码、I/O 控制逻辑、中断/DMA 控制逻辑        │
  └──────────────────────────────────────────────────┘
```
- **数据缓冲寄存器**：暂存要传送的数据
- **状态寄存器**：记录设备状态（就绪、忙、错误）
- **控制寄存器**：存放 CPU 发来的控制命令
- 状态寄存器和控制寄存器传送方向相反，**常合并为一个“控制/状态寄存器”**

### 📐 I/O 端口
- **端口**：接口中**可以被 CPU 直接访问的寄存器**（数据端口、状态端口、控制端口）
- 接口 = 端口 + 控制逻辑

⚠️ **区分：接口 ≠ 设备**。
📝 **真题（2021 年第 20 题）**：下列选项中，**不属于** I/O 接口的是：A. 磁盘驱动器　B. 打印机适配器　C. 网络控制器　D. 可编程中断控制器
→ **A**（磁盘驱动器是**外设本身**的一部分；适配器、控制器才是接口）

### 📐 I/O 端口的编址（⭐⭐）
| | 统一编址（存储器映射 I/O） | 独立编址（I/O 映射） |
|---|---|---|
| 做法 | I/O 端口占用**主存地址空间**的一部分 | I/O 端口有**单独的地址空间** |
| 访问方式 | 用**访存指令**（load/store、mov）访问 | 用**专门的 I/O 指令**（IN、OUT）访问 |
| 优点 | 不需要专门的 I/O 指令，访存指令功能强，编程灵活 | 主存空间不被占用；I/O 指令易于识别，程序清晰 |
| 缺点 | 占用主存地址空间；I/O 和访存指令外表相同，不易区分 | 需要专门的 I/O 指令，功能较弱 |
| 例子 | ARM、MIPS 等 RISC | x86（也支持统一编址） |

## 三、程序查询方式（⭐）

### 📐 过程
CPU 执行 I/O 程序：
1. 向接口发出启动命令
2. **反复读取状态寄存器，检查“就绪”位**（**忙等待**）
3. 就绪后，传送一个数据（读数据寄存器或写数据寄存器）
4. 若还没传完，回到 2

### 📐 特点
- ✅ 简单，硬件少
- ❌ **CPU 与外设串行工作**，CPU 大量时间浪费在查询上
- 数据传送完全由 **CPU 执行程序**完成

### ✏️ 例：查询方式的 CPU 占用率
某 CPU 主频 500MHz，外设数据传输率 1MB/s，每次传送 1B。每次查询（含传送）需 100 个时钟周期。**即使设备没准备好，CPU 也必须不断查询**，CPU 全部时间都用在 I/O 上（100%）。

若改为**定时查询**：外设每秒传 1M 个字节，**至少每秒查询 1M 次**（保证不丢数据），每次 100 周期：
- CPU 用于 I/O 的周期 = 1M × 100 = 100M 周期/秒
- 占比 = 100M / 500M = **20%**

## 四、程序中断方式（⭐⭐⭐）

### 📐 基本思想
CPU 启动外设后**继续执行原来的程序**；外设准备好数据后，向 CPU 发**中断请求**；CPU 暂停当前程序，执行**中断服务程序**完成一次数据传送，然后返回。
- **CPU 与外设并行工作**（外设准备数据时，CPU 可以做别的事）
- 但**每次数据传送仍然由 CPU 执行程序完成**（中断服务程序中的 I/O 指令）

📝 **真题（2022 年第 21 题）**：下列关于中断 I/O 方式的叙述中，**不正确**的是：
A. 适用于键盘、针式打印机等字符型设备　B. 外设和主机之间的数据传送通过软件完成　C. 外设准备数据的时间应小于中断处理时间　D. 外设为某进程准备数据时 CPU 可运行其他进程
→ **C**（恰恰相反：外设准备数据的时间应**大于**中断处理时间，否则上一个中断还没处理完，下一个数据又到了，会**丢失数据**；而且中断方式的意义就在于外设慢，CPU 可以在等待时干别的）

### 📐 中断系统的工作流程
1. **中断请求**：外设准备好后，接口中的**中断请求触发器**置 1，向 CPU 发请求
2. **中断判优**：多个中断同时请求时，按**优先级**选一个（硬件排队器或软件查询）
3. **中断响应**：满足条件时（指令结束、开中断、请求未被屏蔽），执行**中断隐指令**（关中断、保存断点、找入口）
4. **中断处理**：执行中断服务程序
5. **中断返回**

### 📐 中断请求标记与判优
- 每个中断源有一个**中断请求标记触发器**，多个触发器构成**中断请求标记寄存器**
- **中断判优**的一般优先顺序：
  1. **硬件故障**中断（最高）
  2. 软件中断（如除 0）
  3. **不可屏蔽中断** > 可屏蔽中断
  4. **DMA 请求 > I/O 设备中断**（DMA 数据若不及时处理会丢失）
  5. 高速设备 > 低速设备；输入设备 > 输出设备；实时设备 > 普通设备

### 📐 中断屏蔽技术（⭐⭐⭐）
- 每个中断源对应一个**屏蔽触发器**，所有屏蔽触发器组成**屏蔽字寄存器**，其内容叫**屏蔽字**
- **屏蔽字某位为 1**：屏蔽该中断源（该请求**不能**送到 CPU）；为 **0**：开放
- **每个中断源都有自己的屏蔽字**，在执行它的中断服务程序时装入屏蔽字寄存器
- 通过屏蔽字，可以**改变中断的处理优先级**（不改变硬件的**响应优先级**）

⚠️ 两种优先级：
- **响应优先级**：多个中断**同时请求**时 CPU 先响应谁，由**硬件排队电路**决定，**不能改变**
- **处理优先级**：中断处理**完成的先后顺序**，谁能打断谁，由**屏蔽字**决定，**可以改变**

📐 **设置屏蔽字的原则**：Lᵢ 的屏蔽字中，**处理优先级 ≤ Lᵢ 的中断源（包括自己）对应位为 1**，比 Lᵢ 高的为 0。

📝 **真题（2020 年第 21 题）**：外部中断包括不可屏蔽中断（NMI）和可屏蔽中断，下列关于外部中断的叙述中，**错误**的是：
A. CPU 处于关中断状态时，也能响应 NMI 请求　B. 一旦可屏蔽中断请求信号有效，CPU 将立即响应　C. 不可屏蔽中断的优先级比可屏蔽中断的优先级高　D. 可通过中断屏蔽字改变可屏蔽中断的处理优先级
→ **B**（要等**当前指令执行结束**，且 CPU **开中断**、该中断**未被屏蔽**时才响应）

### 📐 多重中断（中断嵌套）
- **单重中断**：执行中断服务程序时**不响应**新的中断
- **多重中断**：执行中断服务程序时，可以响应**更高优先级**的中断，打断当前的中断服务程序
- 实现多重中断的条件：
  1. 在中断服务程序中**提前开中断**（保存现场、设置屏蔽字之后）
  2. 优先级别高的中断源有权中断优先级别低的中断源

### 📐 中断服务程序的流程（多重中断）
```
① 关中断（硬件，中断隐指令）
② 保存断点、PSW（硬件）
③ 送中断服务程序入口（硬件）
—————— 以下为中断服务程序（软件） ——————
④ 保存现场和屏蔽字
⑤ 设置新的屏蔽字
⑥ 开中断                  ← 从这里起可以响应更高级的中断
⑦ 执行中断服务（设备服务）
⑧ 关中断
⑨ 恢复现场和屏蔽字
⑩ 开中断
⑪ 中断返回
```
（单重中断：没有 ⑤⑥⑧，服务完毕后才开中断返回。）

📝 **真题（2020 年第 25 题）**：下列与中断相关的操作中，由**操作系统**完成的是：I. 保存被中断程序的中断点　II. 提供中断服务　III. 初始化中断向量表　IV. 保存中断屏蔽字
A. 仅 I、II　B. 仅 I、II、IV　C. 仅 III、IV　D. 仅 II、III、IV
→ **D**（保存断点由**硬件**（中断隐指令）完成；中断服务、初始化中断向量表、保存屏蔽字都由操作系统的程序完成）

### ✏️ 例：用屏蔽字改变处理优先级，画 CPU 运行轨迹（⭐⭐⭐）
某系统有 4 个中断源 L0、L1、L2、L3，**硬件响应优先级 L0 > L1 > L2 > L3**。现要求**处理优先级**改为 **L1 > L3 > L0 > L2**。
**(1) 写出各中断源的屏蔽字**（顺序 L0 L1 L2 L3，1 表示屏蔽）：
| 中断源 | 比它低或相等的（要屏蔽） | 屏蔽字 L0 L1 L2 L3 |
|---|---|---|
| L0 | L0、L2 | **1 0 1 0** |
| L1 | 全部 | **1 1 1 1** |
| L2 | 只有自己 | **0 0 1 0** |
| L3 | L3、L0、L2 | **1 0 1 1** |

**(2)** 设每个中断服务程序需要 **10 个时间单位**（忽略中断响应开销）。在 t = 0 时 **L0、L2 同时**发出请求，t = 15 时 **L3** 发出请求，t = 20 时 **L1** 发出请求。画出 CPU 执行轨迹。

- **t = 0**：L0、L2 同时请求，按**响应优先级**先响应 **L0**。L0 服务程序装入屏蔽字 1010，L2 被屏蔽
- **t = 10**：L0 完成返回；L2 请求仍在，响应 **L2**（屏蔽字 0010）
- **t = 15**：L3 请求，L2 的屏蔽字对 L3 为 0（不屏蔽）→ **L3 打断 L2**（L3 屏蔽字 1011）
- **t = 20**：L1 请求，L3 的屏蔽字对 L1 为 0 → **L1 打断 L3**
- **t = 30**：L1 完成，返回 L3（还剩 5）
- **t = 35**：L3 完成，返回 L2（还剩 5）
- **t = 40**：L2 完成，返回用户程序

```
时间      0    5    10   15   20   25   30   35   40
用户程序  ┐                                        ┌──
L0        └────────┐
L2                 └────┐                   ┌────┘
L3                      └────┐         ┌────┘
L1                           └─────────┘
```
**完成顺序：L0 → L1 → L3 → L2**

🧒 注意 L0：虽然处理优先级 L0 > L2，但低于 L1、L3。本例中 L0 在 t = 0~10 期间没有更高级的请求到来，所以它先完成。

### 📐 中断方式的 CPU 时间计算（⭐⭐⭐）
```
CPU 用于 I/O 的时间占比 = 每秒中断次数 × 每次中断的开销（时钟周期） / 主频
每秒中断次数 = 数据传输率 / 每次中断传送的数据量
```

📝 **真题（2009 年第 43 题）**：某计算机的 CPU 主频为 500MHz，CPI 为 5（即执行每条指令平均需 5 个时钟周期）。假定某外设的数据传输率为 0.5MB/s，采用中断方式与主机进行数据传送，以 32 位为传输单位，对应的中断服务程序包含 18 条指令，中断服务的其他开销相当于 2 条指令的执行时间。请回答下列问题，要求给出计算过程。
(1) 在中断方式下，CPU 用于该外设 I/O 的时间占整个 CPU 时间的百分比是多少？
(2) 当该外设的数据传输率达到 5MB/s 时，改用 DMA 方式传送数据。假定每次 DMA 传送块大小为 5000B，且 DMA 预处理和后处理的总开销为 500 个时钟周期，则 CPU 用于该外设 I/O 的时间占整个 CPU 时间的百分比是多少？（假设 DMA 与 CPU 之间没有访存冲突）

**(1)**
- 每次中断传送 32 位 = 4B，每秒中断次数 = 0.5MB / 4B = **125K 次**（按 1M = 10⁶ 计：0.5 × 10⁶ / 4 = 1.25 × 10⁵）
- 每次中断 = (18 + 2) 条 × 5 周期 = **100 个时钟周期**
- 每秒用于 I/O 的周期 = 1.25 × 10⁵ × 100 = 1.25 × 10⁷
- 占比 = 1.25 × 10⁷ / (5 × 10⁸) = **2.5%**

**(2)**
- 每秒 DMA 次数 = 5MB / 5000B = **1000 次**
- 每次开销 500 个周期，每秒 = 5 × 10⁵ 周期
- 占比 = 5 × 10⁵ / (5 × 10⁸) = **0.1%**

🧒 对比：传输率提高了 10 倍，但用 DMA 后 CPU 占用反而从 2.5% 降到 0.1%！

⚠️ **计算时单位要统一**：题目中 MB/s 一般按 **10⁶**（数据传输率常用十进制），块大小 5000B 也是十进制，正好整除。

## 五、DMA 方式（⭐⭐⭐）

### 📐 基本思想
**DMA（Direct Memory Access，直接存储器存取）**：在**主存和 I/O 设备之间**开辟一条**直接数据通路**，数据传送由 **DMA 控制器**控制，**不需要 CPU 执行程序**。
- CPU 只在**开始**（初始化 DMA 控制器）和**结束**（处理 DMA 结束中断）时参与
- 以**数据块**为单位传送
- 适用于**高速、成块**传送的设备：**磁盘、SSD、网卡**、显卡

📝 **真题（2025 年第 21 题）**：下列设备中，适合采用 DMA 输入输出的设备是：I. 键盘　II. 网卡　III. 固态硬盘　IV. 针式打印机
A. I、II　B. II、III　C. II、IV　D. III、IV
→ **B**（键盘、针式打印机是慢速字符设备，用中断方式）

### 📐 DMA 控制器的组成
| 部件 | 作用 |
|---|---|
| **主存地址计数器（AR）** | 存放要交换数据的**主存地址**，每传送一个字后自动 +1 |
| **传送长度计数器（WC）** | 记录**还要传送的字数**，每传一个字后 −1（或 +1），为 0 表示传完 |
| **数据缓冲寄存器（BR）** | 暂存每次传送的数据 |
| **DMA 请求触发器** | 设备准备好一个数据后置 1 |
| **控制/状态逻辑** | 发出总线请求（HRQ）、接收总线允许（HLDA）等 |
| **中断机构** | 数据块**传送结束**后，向 CPU 发 **DMA 结束中断** |

### 📐 DMA 传送过程（⭐⭐）
1. **预处理**（CPU 执行程序完成）：CPU 执行 I/O 指令，向 DMA 控制器送**主存起始地址、传送字数、传送方向**，并**启动设备**。然后 CPU 继续执行原程序
2. **数据传送**（DMA 控制器控制，**硬件**完成）：设备每准备好一个数据，DMA 控制器**申请总线**，获得总线后在**主存与设备之间直接传送**，修改 AR 和 WC；重复直到 WC = 0
3. **后处理**（CPU 执行中断服务程序）：DMA 控制器发出 **DMA 结束中断**，CPU 响应后做校验、判断是否继续等

### 📐 DMA 的三种传送方式（⭐⭐⭐）
主存是 CPU 和 DMA 控制器共享的，两者可能同时要访存，怎么协调？

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **停止 CPU 访存** | DMA 传送**整个数据块期间**，CPU **放弃总线**、不能访存 | 控制简单 | CPU 基本处于不工作状态；外设准备数据时主存也空闲，**利用率低** |
| **周期挪用（周期窃取）** | 设备**每准备好一个数据**，DMA 控制器就**申请一次总线**，**挪用一个存取周期**传送，然后**归还**总线 | 既实现 I/O 传送，又较好发挥了主存和 CPU 的效率 | 每次都要申请、建立、归还总线 |
| **DMA 与 CPU 交替访存** | 把一个 CPU 周期分成两半，一半给 DMA、一半给 CPU，**分时**使用 | 不需要申请/归还总线，效率高 | 硬件复杂；适用于 CPU 周期比主存周期长很多的情况 |

📐 **周期挪用时，DMA 与 CPU 同时要访存**：
- CPU 此时不访存（在执行内部操作）→ DMA 直接用，不冲突
- CPU 正在访存 → 等 CPU 这个存取周期结束，**DMA 再用**
- **CPU 与 DMA 同时请求** → **DMA 优先**（数据在接口缓冲中，不及时取走会被下一个数据覆盖而**丢失**；而 CPU 晚一点访存没关系）

📝 **真题（2020 年第 22 题）**：若设备采用周期挪用 DMA 方式进行输入和输出，每次 DMA 传送的数据块大小为 512 字节，相应的 I/O 接口中有一个 32 位数据缓冲寄存器。对于数据输入过程，下列叙述中，**错误**的是：
A. 每准备好 32 位数据，DMA 控制器就发出一次总线请求　B. 相对于 CPU，DMA 控制器的总线使用权的优先级更高　C. 在整个数据块的传送过程中，CPU 不可以访问主存储器　D. 数据块传送结束时，会产生“DMA 传送结束”中断请求
→ **C**（周期挪用只挪用某些存取周期，其余时间 CPU **可以**访存；“整个数据块期间 CPU 不能访存”是**停止 CPU 访存**方式）

📝 **真题（2022 年第 44 题第 3 问）**（第 9 课已完整讲解）：一个扇区 512B，DMA 数据缓冲区 64 位（8B）→ 一个扇区需要 512 / 8 = **64 次**总线请求；CPU 同时要访存时，**DMA 控制器可以获得总线使用权**（DMA 优先级更高，否则数据会丢失）。

### 📐 DMA 与中断的比较（⭐⭐⭐）
| | 中断方式 | DMA 方式 |
|---|---|---|
| 数据传送 | **CPU 执行程序**完成（软件） | **DMA 控制器硬件**完成 |
| 传送单位 | 通常一个字/字节 | 数据块 |
| CPU 参与 | 每次传送都要 | 只在开始和结束 |
| 响应时机 | 一条**指令执行结束**后 | **每个机器周期（存取周期）结束**后均可响应总线请求 |
| 是否需要保护现场 | **需要**（执行中断服务程序） | **不需要**（CPU 只是让出总线，不执行程序） |
| 优先级 | 低 | **高**（DMA 请求优先于中断请求） |
| 能否处理异常 | 能 | 不能（只能传数据） |
| 适用 | 慢速字符设备（键盘、打印机） | 高速块设备（磁盘、网卡） |

📝 **真题（2023 年第 22 题）**：下列关于 I/O 控制方式的叙述中，**错误**的是：
A. 查询方式下，通过 CPU 执行查询程序进行 I/O 操作　B. 中断方式下，通过 CPU 执行中断服务程序进行 I/O 操作　C. DMA 方式下，通过 CPU 执行 DMA 传送程序进行 I/O 操作　D. 对于 SSD、网络适配器等高速设备，采用 DMA 方式输入/输出
→ **C**（DMA 方式的数据传送由 **DMA 控制器硬件**完成，CPU 不执行传送程序）

### ✏️ 例：DMA 周期挪用的 CPU 时间占用
某磁盘数据传输率 4 × 10⁶ B/s，每次 DMA 传送一个 4000B 的数据块，DMA 预处理 + 后处理共 1000 个时钟周期，CPU 主频 400MHz。采用周期挪用，每次挪用传送 4B，每挪用一次使 CPU 损失 1 个时钟周期。求 CPU 用于该磁盘 I/O 的时间占比。
- 每秒 DMA 块数 = 4 × 10⁶ / 4000 = **1000 块**
- 预/后处理：1000 × 1000 = 10⁶ 周期
- 每块挪用次数 = 4000 / 4 = 1000 次，每秒 1000 × 1000 = 10⁶ 周期
- 共 2 × 10⁶ 周期，占比 = 2 × 10⁶ / (4 × 10⁸) = **0.5%**

## 六、通道方式（了解）

- **通道**：一种**专门负责 I/O** 的**处理器**，有自己的**通道指令**，执行**通道程序**
- CPU 只需发出 I/O 指令启动通道，通道就能独立管理**多台**外设的 I/O
- 比 DMA 更进一步：DMA 只能控制**一台**设备进行简单的块传送，通道能执行程序、控制多台设备
- 多用于大型机
- 通道类型：**字节多路通道**（多台低速设备，按字节交叉）、**选择通道**（一次选一台高速设备，成块传送）、**数组多路通道**（多台高速设备，按块交叉）

---

## 七、四种方式总结（⭐⭐⭐）

| 方式 | CPU 与外设 | 数据传送由谁完成 | CPU 干预程度 | 适用 |
|---|---|---|---|---|
| 程序查询 | **串行** | CPU（程序） | 全程 | 简单、低速 |
| 程序中断 | 并行 | CPU（中断服务程序） | 每个数据 | 慢速字符设备 |
| DMA | 并行 | DMA 控制器（硬件） | 每个数据块（开始+结束） | 高速块设备 |
| 通道 | 并行 | 通道（执行通道程序） | 一组数据块 | 大型机、多设备 |

---

## ⚠️ 易错点

1. **磁盘驱动器不是 I/O 接口**，适配器、控制器才是
2. 统一编址用**访存指令**；独立编址用 **IN/OUT 指令**
3. 中断方式中外设准备数据的时间要**大于**中断处理时间
4. 中断**响应优先级**由硬件决定，**处理优先级**由屏蔽字改变
5. 屏蔽字 **1 表示屏蔽**；Lᵢ 的屏蔽字对**不高于自己**的中断源置 1
6. **保存断点是硬件做的**；保存现场、屏蔽字是 OS（软件）做的
7. **DMA 传送由硬件完成**；预处理和后处理需要 CPU
8. DMA **周期挪用**：每个数据申请一次总线；CPU 其余时间可访存
9. CPU 与 DMA 同时访存 → **DMA 优先**
10. DMA 请求在**存取周期**结束时响应；中断在**指令**结束时响应
11. 算 CPU 占比：每秒次数 × 每次周期数 / 主频

## 🏋️ 课后练习

1. 某中断系统有 L0~L3 四级中断，响应优先级 L0 > L1 > L2 > L3。要求处理优先级为 L2 > L0 > L3 > L1，写出各级的屏蔽字（L0 L1 L2 L3 顺序，1 表示屏蔽）。
2. 某外设以中断方式传送，数据传输率 200KB/s，每次中断传送 2B，中断服务程序（含其他开销）共执行 50 条指令，CPI = 4，主频 800MHz。求 CPU 用于该外设的时间占比。若传输率提高到 4MB/s，还能用中断方式吗？（按每次中断必须在下一个数据到来前完成计算）
3. 判断：(a) DMA 方式下，CPU 响应 DMA 请求时要保护现场；(b) 周期挪用方式下，在 DMA 传送一个数据块期间，CPU 仍可以访问主存；(c) 中断方式中，数据的传送由硬件完成。
4. 为什么 DMA 请求的优先级高于 CPU 访存？
5. 独立编址方式下，CPU 如何区分访问的是主存还是 I/O 端口？

<details>
<summary>📖 答案</summary>

1. 处理优先级 L2 > L0 > L3 > L1：
   - L0：屏蔽 L0、L3、L1 → **1 1 0 1**
   - L1：只屏蔽自己 → **0 1 0 0**
   - L2：全部屏蔽 → **1 1 1 1**
   - L3：屏蔽 L3、L1 → **0 1 0 1**
2. 每秒中断 200K / 2 = 10⁵ 次；每次 50 × 4 = 200 周期；占比 = 2 × 10⁷ / 8 × 10⁸ = **2.5%**。传输率 4MB/s：每秒 2 × 10⁶ 次中断，每次数据间隔 0.5μs；每次中断处理 200 周期 = 0.25μs < 0.5μs，理论上来得及，但 CPU 占比 = 4 × 10⁸ / 8 × 10⁸ = **50%**，开销太大，**应改用 DMA**
3. (a) **错**，DMA 只让出总线，不执行程序，不需保护现场；(b) **对**；(c) **错**，由 CPU 执行中断服务程序完成
4. 外设的数据准备好后暂存在接口的缓冲寄存器中，若 DMA 不能及时把它写入主存，下一个数据到来时就会把它覆盖，造成**数据丢失**；而 CPU 访存推迟一下只是稍慢，不会出错
5. 通过**不同的指令**：访存用 mov/load/store，访问 I/O 端口用专门的 **IN/OUT** 指令，CPU 执行 I/O 指令时发出 I/O 读/写控制信号（而不是存储器读/写信号）
</details>
