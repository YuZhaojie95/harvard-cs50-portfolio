## 🚪 课前引入：计算机里没有“负号”

我们写 −5 很自然，但计算机只有 0 和 1，**没有“−”这个符号**。怎么表示负数？
人们想到的办法是：**拿出一位来专门表示正负**（0 正、1 负）。但具体怎么表示，有好几种方案——原码、反码、补码、移码。每种方案都有各自的优缺点。

---

## 一、基本概念

### 📐 真值与机器数
- **真值**：带 “+”“−” 号的数，我们日常写的数（如 +1011、−0.101、−13）
- **机器数**：把符号“数字化”后的二进制数（如 0,1011、1,1011）

### 📐 无符号数
所有位都表示数值，没有符号位。n 位无符号数范围：**0 ~ 2ⁿ − 1**。
例：8 位 0 ~ 255；16 位 0 ~ 65535；32 位 0 ~ 4294967295（约 43 亿）

### 📐 定点数
小数点位置**固定不变**的数：
- **定点整数**：小数点固定在最低位之后 → **纯整数**。格式：`符号位 | 数值位 .`
- **定点小数**：小数点固定在符号位之后 → **纯小数**（绝对值 < 1）。格式：`符号位 . 数值位`

以下设机器数共 **n + 1 位**：1 位符号 + n 位数值。

---

## 二、原码（⭐）

### 📐 定义
**符号位 + 数值的绝对值**：符号位 0 正 1 负，数值部分就是真值的绝对值。

✏️ 例（8 位）：
- +13 = +1101 → [+13]原 = **0**000 1101
- −13 = −1101 → [−13]原 = **1**000 1101
- +0.75 = +0.11 → [+0.75]原 = 0.1100000
- −0.75 → [−0.75]原 = 1.1100000

### 📐 表示范围
| | 整数（n+1 位） | 小数（n+1 位） |
|---|---|---|
| 范围 | −(2ⁿ − 1) ~ 2ⁿ − 1 | −(1 − 2⁻ⁿ) ~ 1 − 2⁻ⁿ |
| 8 位 | −127 ~ +127 | −(1 − 2⁻⁷) ~ 1 − 2⁻⁷ |
范围**关于 0 对称**。

### 📐 特点
- ✅ 直观，与真值对应关系简单；**乘除运算方便**（符号单独处理，数值部分直接乘除）
- ❌ **0 有两种表示**：[+0]原 = 0000 0000，[−0]原 = 1000 0000
- ❌ **加减运算复杂**：要先判断符号，同号相加、异号相减，还要比较绝对值大小决定结果的符号

---

## 三、反码

### 📐 定义
- 正数：反码 = 原码
- 负数：**符号位不变，数值位按位取反**

✏️ 例：[−13]原 = 1000 1101 → [−13]反 = **1111 0010**

### 📐 特点
- 范围同原码：−(2ⁿ − 1) ~ 2ⁿ − 1
- **0 仍有两种表示**：[+0]反 = 0000 0000，[−0]反 = 1111 1111
- 反码主要作为**求补码的中间过渡**，很少直接使用

---

## 四、补码（⭐⭐⭐）

### 🧒 为什么要用补码：钟表的启发
钟表只有 12 个刻度（**模 12**）。现在是 3 点，要调到 1 点：
- 往回拨 2 格：3 − 2 = 1
- 往前拨 10 格：3 + 10 = 13，而 13 在钟表上就是 1（超过 12 的部分自动“溢出”丢掉了）

所以**在模 12 的系统里，“−2”和“+10”效果完全一样**！10 就叫做 −2 的“**补数**”（10 + 2 = 12 = 模）。
这意味着：**减法可以变成加法**！

计算机里 n+1 位的寄存器也是一个“钟表”：8 位寄存器能表示 0~255，超过 255 的部分溢出丢掉，**模是 2⁸ = 256**。
- −5 的补数 = 256 − 5 = 251 = 1111 1011
- 计算 7 − 5：7 + 251 = 258，丢掉超出 256 的部分 → 2 ✓

**好处**：只需要一个**加法器**，就能做加法和减法，电路简单！

### 📐 定义
**整数**：
$$[x]_补 = \begin{cases} x, & 0 \le x < 2^n \\ 2^{n+1} + x = 2^{n+1} - |x|, & -2^n \le x < 0 \end{cases} \pmod{2^{n+1}}$$
**小数**：
$$[x]_补 = \begin{cases} x, & 0 \le x < 1 \\ 2 + x, & -1 \le x < 0 \end{cases} \pmod 2$$

### 📐 求补码的方法（⭐⭐⭐）
**正数**：补码 = 原码 = 真值本身（符号位为 0）

**负数**（三种方法，结果一样）：
1. **定义法**：[x]补 = 2ⁿ⁺¹ − |x|
   - 例（8 位）：[−13]补 = 256 − 13 = 243 = **1111 0011**
2. **反码加 1**：原码的符号位不变、数值位取反，末位加 1
   - [−13]原 = 1000 1101 → 反码 1111 0010 → +1 → **1111 0011**
3. **快速法（⭐ 推荐）**：从 |x| 的二进制出发，**从右往左找到第一个 1，这个 1 及其右边的 0 保持不变，左边所有位全部取反**
   - 13 = 0000 1101，从右往左第一个 1 是最低位 → 最低位 1 不变，左边 0000 110 全部取反成 1111 001 → **1111 0011** ✓
   - 再例：−20：20 = 0001 0100，从右往左第一个 1 在倒数第 3 位（`100`），保持不变；左边 00010 取反 → 11101 → **1110 1100**

### 📐 补码 → 真值（⭐⭐⭐）
1. **符号位为 0**：直接按二进制求值
2. **符号位为 1**（负数），两种方法：
   - **方法一：再求一次补码得到绝对值**：[[x]补]补 = [x]原。
     例：1110 1100 → 按快速法（右边第一个 1 及其右不变，左边取反）→ 0001 0100 = 20 → 真值 **−20**
   - **方法二（⭐ 推荐）：最高位的权值是负的**：
     $$x = -b_n \cdot 2^n + \sum_{i=0}^{n-1} b_i 2^i$$
     例：1110 1100 = −128 + 64 + 32 + 8 + 4 = **−20** ✓

**十六进制补码快速求真值**：
- 负数 = 该数 − 2ⁿ⁺¹（位数为 n+1）
- 例（16 位）：FFFDH = 65533 − 65536 = **−3**；FFDFH = 65503 − 65536 = **−33**；E002H = 57346 − 65536 = **−8190**

### 📐 [−x]补 与 [x]补 的关系（⭐）
已知 [x]补，求 [−x]补：**连同符号位一起，全部取反，末位加 1**（即“求补”操作）。
例：[x]补 = 0000 1101（13）→ [−x]补 = 1111 0010 + 1 = **1111 0011**（−13）✓
例：[x]补 = 1111 0011（−13）→ [−x]补 = 0000 1100 + 1 = **0000 1101**（13）✓
⚠️ 注意与“负数的补码 → 原码”区分：那个是**符号位不变**，数值位取反加 1。

### 📐 表示范围（⭐⭐⭐ 必背）
| | 整数（n+1 位） | 小数（n+1 位） |
|---|---|---|
| 范围 | **−2ⁿ ~ 2ⁿ − 1** | **−1 ~ 1 − 2⁻ⁿ** |
| 8 位 | **−128 ~ +127** | −1 ~ 1 − 2⁻⁷ |
| 16 位 | −32768 ~ +32767 | |
| 32 位 | −2³¹ ~ 2³¹ − 1 | |

- 补码的范围**比原码多一个负数**：整数多了 **−2ⁿ**（8 位时为 1000 0000 = −128），小数多了 **−1**（1.0000000）
- **0 的补码唯一**：[+0]补 = [−0]补 = 0000 0000
- ⚠️ 1000 0000 在**原码**中是 −0，在**补码**中是 −128，在**移码**中是 0

📝 **真题（2022 年第 13 题）**：32 位补码所能表示的整数范围是：A. −2³² ~ 2³¹ − 1 **B. −2³¹ ~ 2³¹ − 1** C. −2³² ~ 2³² − 1 D. −2³¹ ~ 2³² − 1 → **B**

### 📐 几个特殊的补码（⭐ 秒答）
| 8 位补码 | 真值 | 16 位补码 | 真值 |
|---|---|---|---|
| 0111 1111 (7FH) | +127（最大） | 7FFFH | +32767 |
| 0000 0001 (01H) | +1 | 0001H | +1 |
| 0000 0000 (00H) | 0 | 0000H | 0 |
| 1111 1111 (FFH) | **−1** | FFFFH | **−1** |
| 1000 0001 (81H) | −127 | 8001H | −32767 |
| 1000 0000 (80H) | **−128（最小）** | 8000H | −32768 |

🧒 **记住：全 1 是 −1；符号位 1 后面全 0 是最小负数。**

📝 **真题（2023 年第 13 题）**：若 short 型变量 x = −8190，则 x 的机器数是：A. E002H B. E001H C. 9FFFH D. 9FFEH
- 8190 = 8192 − 2 = 2¹³ − 2 = 0001 1111 1111 1110 = 1FFEH
- −8190 的 16 位补码 = 2¹⁶ − 8190 = 65536 − 8190 = 57346 = **E002H**
- 快速法验证：1FFEH = 0001 1111 1111 1110，右边第一个 1 在倒数第 2 位（`10` 不变），左边全部取反 → 1110 0000 0000 0010 = E002H ✓
→ 选 **A**

### 📐 变形补码（模 4 补码，双符号位）
用**两个符号位**：正数 00，负数 11。用于**判断溢出**（下一课）。
例：[+13]变补 = 00 000 1101（数值部分同补码）

## 五、移码（⭐）

### 📐 定义
**移码 = 真值 + 偏置值**。通常偏置值取 **2ⁿ**（n+1 位时）：
$$[x]_移 = 2^n + x \quad (-2^n \le x < 2^n)$$

### 📐 与补码的关系（⭐ 快速求法）
**偏置值为 2ⁿ 时：移码 = 补码的符号位取反**
- [+13]补 = 0000 1101 → [+13]移 = **1**000 1101
- [−13]补 = 1111 0011 → [−13]移 = **0**111 0011

### 📐 特点
- 范围同补码：−2ⁿ ~ 2ⁿ − 1
- **0 的移码唯一**：1000 0000
- **移码全 0 表示最小的数，全 1 表示最大的数**
- ⭐ **移码的大小关系与真值的大小关系一致**：移码大，真值就大 → 可以直接按无符号数比较大小
- **移码只用于表示整数**，主要用于浮点数的**阶码**
- ⚠️ IEEE 754 的阶码用的是**偏置值 127**（而不是 128）的移码，下下课讲

## 六、四种码制对比（⭐⭐）

以 8 位整数为例：
| 真值 | 原码 | 反码 | 补码 | 移码 |
|---|---|---|---|---|
| +127 | 0111 1111 | 0111 1111 | 0111 1111 | 1111 1111 |
| +1 | 0000 0001 | 0000 0001 | 0000 0001 | 1000 0001 |
| +0 | 0000 0000 | 0000 0000 | 0000 0000 | 1000 0000 |
| −0 | 1000 0000 | 1111 1111 | 0000 0000 | 1000 0000 |
| −1 | 1000 0001 | 1111 1110 | 1111 1111 | 0111 1111 |
| −127 | 1111 1111 | 1000 0000 | 1000 0001 | 0000 0001 |
| −128 | 无法表示 | 无法表示 | 1000 0000 | 0000 0000 |

| | 原码 | 反码 | 补码 | 移码 |
|---|---|---|---|---|
| 正数的表示 | 相同 | 相同 | 相同 | 符号位为 1 |
| 0 的表示 | 两种 | 两种 | **唯一** | **唯一** |
| 整数范围 | −(2ⁿ−1)~2ⁿ−1 | 同原码 | **−2ⁿ~2ⁿ−1** | 同补码 |
| 主要用途 | 浮点数尾数（IEEE 754）、乘除 | 过渡 | **定点整数加减运算** | 浮点数阶码 |

## 七、C 语言中的整数与类型转换（⭐⭐⭐ 近年高频）

### 📐 C 语言中的整数类型
- `int`、`short`、`char`、`long` 等**有符号整数**用**补码**表示
- `unsigned int` 等**无符号整数**直接用二进制表示

### 📐 核心原则：**转换时，机器数（位模式）怎么变？**

**① 相同位数的有符号 ↔ 无符号：位模式不变，只是换一种“眼光”解释**
```c
short si = -1;               // 机器数 FFFFH
unsigned short usi = si;     // 机器数仍是 FFFFH，解释为 65535
int i = -32768;
unsigned int ui = i;         // 机器数 FFFF8000H，解释为 2^32 − 32768 = 4294934528
```
规律：负数 x 转成 n 位无符号数，值为 **x + 2ⁿ**；无符号数 ≥ 2ⁿ⁻¹ 的转成有符号数，值为 **x − 2ⁿ**。

**② 短 → 长（扩展）**
- **有符号数：符号扩展**——高位补**符号位**（正数补 0，负数补 1），真值不变
- **无符号数：零扩展**——高位补 **0**，真值不变
```c
short si = -3;               // FFFDH
int i = si;                  // 符号扩展：FFFF FFFDH，仍是 -3
unsigned short us = 65533;   // FFFDH
unsigned int ui = us;        // 零扩展：0000 FFFDH，仍是 65533
```
⚠️ **扩展方式由“源类型”决定**：先看被扩展的数是有符号还是无符号。

**③ 长 → 短（截断）**
**直接丢掉高位**，保留低位。可能改变真值！
```c
int i = 32768;               // 0000 8000H
short si = (short)i;         // 截断为 8000H，解释为 -32768 ✗（数变了）
int j = 65537;               // 0001 0001H
short sj = (short)j;         // 截断为 0001H = 1
```

**④ 既变长又变符号**（先扩展、后解释）
```c
short si = -32767;
unsigned int ui = si;        // 先按 short（有符号）符号扩展成 32 位，再按无符号解释
```

📝 **真题（2025 年第 12 题）**：在 32 位计算机上执行下列 C 语言代码，则 ui 的真值为：
```c
short si = -32767;
unsigned int ui = si;
```
A. 2¹³ − 1 &nbsp; B. 2¹⁵ + 1 &nbsp; C. 2³² − 2¹⁵ − 1 &nbsp; D. 2³² − 2¹⁵ + 1
1. si = −32767 的 16 位补码：32767 = 7FFFH → 快速法 → **8001H**
2. short 是**有符号**的，扩展到 32 位用**符号扩展** → **FFFF 8001H**
3. 按 unsigned 解释：FFFF 8001H = 2³² − 2¹⁶ + 2¹⁵ + 1 = 2³² − 2¹⁵ + 1
   （或者：它作为补码的真值是 −32767，转无符号 = 2³² − 32767 = 2³² − 2¹⁵ + 1）
→ 选 **D**

📝 **真题（2021 年第 13 题）**：已知带符号整数用补码表示，变量 x、y、z 的机器数分别为 FFFDH、FFDFH、7FFCH，下列结论中正确的是：
A. 若 x、y、z 为无符号整数，则 z < x < y
B. 若 x、y、z 为无符号整数，则 x < y < z
C. 若 x、y、z 为带符号整数，则 x < y < z
D. 若 x、y、z 为带符号整数，则 y < x < z
- 无符号：FFFDH = 65533，FFDFH = 65503，7FFCH = 32764 → **z < y < x**（A、B 都错）
- 有符号：FFFDH = **−3**，FFDFH = **−33**，7FFCH = **32764** → **y < x < z**
→ 选 **D**

📝 **真题（2020 年第 13 题，部分）**：已知带符号整数用补码表示，float 型数据用 IEEE 754 标准表示，假定变量 x 的类型只可能是 int 或 float，当 x 的机器数为 C800 0000H 时，x 的值可能是：A. −7 × 2²⁷ B. −2¹⁶ C. 2¹⁷ D. 25 × 2²⁷
- 当 **int**（补码）：C800 0000H 符号位为 1，是负数。真值 = C800 0000H − 2³² = −(2³² − C800 0000H) = −3800 0000H。3800 0000H = 0011 1000 0000 … = 111₂ × 2²⁷ = 7 × 2²⁷ → **−7 × 2²⁷** ✓（选项 A）
- 当 float：见第 5 课（结果是 −2¹⁷，不在选项中）
→ 选 **A**

### 📐 比较运算中的“隐式转换”陷阱（了解）
C 语言中，**有符号数和无符号数比较时，有符号数会被转换为无符号数**：
```c
int a = -1;
unsigned int b = 1;
if (a < b) ...    // -1 被转成 4294967295，所以 a < b 为假！
```

---

## ⚠️ 易错点
1. 补码范围：**−2ⁿ ~ 2ⁿ − 1**，比原码多一个负数
2. 补码中 **1000…0 是最小负数**，**全 1 是 −1**
3. 补码 0 唯一；原码、反码 0 有两种
4. 求 [−x]补 要**连同符号位**取反加 1；求负数原码时符号位不变
5. 移码 = 补码符号位取反（偏置 2ⁿ 时）；移码大小关系与真值一致
6. 有符号 ↔ 无符号：**位模式不变**
7. 短变长：有符号**符号扩展**，无符号**零扩展**（看源类型）
8. 长变短：**截断高位**

## 📋 本课小结

| 码制 | 负数怎么求 | 整数范围 | 0 |
|---|---|---|---|
| 原码 | 符号位 1 + 绝对值 | −(2ⁿ−1) ~ 2ⁿ−1 | ±0 |
| 反码 | 原码数值位取反 | 同原码 | ±0 |
| 补码 | 反码 + 1；快速法；2ⁿ⁺¹ − \|x\| | −2ⁿ ~ 2ⁿ−1 | 唯一 |
| 移码 | 补码符号位取反 | −2ⁿ ~ 2ⁿ−1 | 唯一 |

| 类型转换 | 规则 |
|---|---|
| 同长度有符号 ↔ 无符号 | 位不变，解释变 |
| 短 → 长 | 有符号符号扩展，无符号零扩展 |
| 长 → 短 | 截断高位 |

## 🏋️ 课后练习

1. 写出 −57 的 8 位原码、反码、补码、移码。
2. 8 位补码 1011 0110 的真值是多少？若是原码呢？若是无符号数呢？
3. 16 位补码 8005H 的真值是多少？
4. 定点小数 x = −0.1011（8 位，1 位符号 7 位数值），求 [x]原、[x]补。
5. 执行以下 C 代码后，各变量的值（十进制）是多少？
   ```c
   char c = -128;
   unsigned char uc = c;
   int i = c;
   unsigned int ui = uc;
   short s = (short)70000;
   ```
6. 已知 [x]补 = 1100 1010，求 [−x]补 和 [x/2]补（算术右移一位）。

<details>
<summary>📖 答案</summary>

1. 57 = 0011 1001。原码 **1011 1001**；反码 **1100 0110**；补码 **1100 0111**；移码 **0100 0111**
2. 补码：−128 + 32 + 16 + 4 + 2 = **−74**；原码：−(011 0110) = **−54**；无符号：128 + 32 + 16 + 4 + 2 = **182**
3. 8005H − 65536 = 32773 − 65536 = **−32763**
4. [x]原 = **1.1011000**；[x]补 = **1.0101000**（数值位取反 0100111 加 1 → 0101000）
5. c = −128（80H）；uc = **128**（80H 按无符号）；i = **−128**（符号扩展 FFFFFF80H）；ui = **128**（uc 是无符号，零扩展）；s：70000 = 0001 1170H → 截断为 1170H = **4464**
6. [−x]补：全部取反加 1 → 0011 0101 + 1 = **0011 0110**（x = −54，−x = 54 ✓）；[x/2]补 = **1110 0101**（算术右移，高位补符号位 1，= −27）
</details>
