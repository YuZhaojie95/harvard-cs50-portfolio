## 🚪 课前引入

想象你在图书馆写论文：
- **书架（主存）**：书很多，但每次去拿都要走一大段路（**慢**）
- **书桌（Cache）**：只能放十几本书，但伸手就拿到（**快**）

聪明的做法是：把**最近要用的书**搬到书桌上。只要大部分时间要找的书都在书桌上，你写论文的速度就接近“书全在手边”的速度，而书的数量却和“整个书架”一样多。

**Cache（高速缓冲存储器）** 就是 CPU 的“书桌”：
- 用 **SRAM** 做成，速度接近 CPU，但容量小、价格贵
- 位于 **CPU 和主存之间**（现代 CPU 里，Cache 就做在 CPU 芯片内部）
- 存放**主存中一部分内容的副本**

上一课我们学过：CPU 每纳秒能执行好几条指令，但访问 DRAM 主存要几十纳秒。如果每条指令都去主存取，CPU 大部分时间都在“等”。Cache 就是为了解决这个 **“CPU 太快、主存太慢”** 的矛盾。

## 一、程序局部性原理（⭐⭐）

### 🧒 大白话
为什么小小的书桌能满足大部分需要？因为你写论文时，**翻来覆去用的就是那几本书**，而且**常常看完第 5 页接着看第 6 页**。

程序也是这样，这就是**局部性原理**：

### 📐 两种局部性
1. **时间局部性**：**最近被访问过的**信息，**很快还会被再次访问**
   - 例：循环体里的指令被反复执行；循环变量 i、累加变量 sum 被反复读写
2. **空间局部性**：**最近被访问过的信息的附近**的信息，很快也会被访问
   - 例：指令顺序执行；数组元素按顺序访问 a[0]、a[1]、a[2]……

### ✏️ 例：分析局部性
```c
int sum = 0;
for (int i = 0; i < n; i++)
    sum += a[i];
```
- **sum、i**：每次循环都访问 → **时间局部性好**
- **数组 a**：按顺序访问，a[i] 旁边的 a[i+1] 马上被访问 → **空间局部性好**；但每个 a[i] 只访问一次 → **没有时间局部性**
- **循环体的指令**：反复执行 → 时间局部性好；顺序执行 → 空间局部性好

### ✏️ 例：按行访问 vs 按列访问
C 语言二维数组**按行优先存放**：a[0][0]、a[0][1]、……a[0][n-1]、a[1][0]……
```c
// 程序 A：按行访问（内层循环变 j）
for (i = 0; i < M; i++)
    for (j = 0; j < N; j++)
        sum += a[i][j];      // 地址连续 → 空间局部性好

// 程序 B：按列访问（内层循环变 i）
for (j = 0; j < N; j++)
    for (i = 0; i < M; i++)
        sum += a[i][j];      // 每次跳过一整行 → 空间局部性差
```
**程序 A 的空间局部性比程序 B 好**，通常 A 更快（Cache 命中率更高）。

### 🔗 Cache 如何利用局部性
- 利用**时间局部性**：把刚访问的数据**留在** Cache 里，下次再用就命中
- 利用**空间局部性**：缺失时不是只调入一个字节，而是**把它所在的整个“块”（如 64 字节）一起调入**，这样附近的数据下次也能命中

## 二、Cache 的基本工作原理

### 📐 块（Block）与行（Line）
- 主存和 Cache 都被划分成**大小相同的块**，块大小如 32B、64B
  - 主存中的叫 **主存块**（block）
  - Cache 中存放一个块的位置叫 **Cache 行**（line，也叫槽 slot）
- **Cache 与主存之间以“块”为单位交换数据**
- **CPU 与 Cache 之间以“字”（或字节）为单位交换数据**

```
     字/字节                块
CPU ◄─────────► Cache ◄─────────► 主存
```

### 📐 CPU 访存过程
CPU 给出一个主存地址 → 先查 Cache：
1. **命中（hit）**：要访问的内容在 Cache 里 → 直接从 Cache 读/写，很快
2. **缺失（miss，也叫不命中）**：不在 Cache 里 → 从主存把**包含该地址的整个块**调入 Cache（Cache 满了就要**替换**掉某一块），同时把需要的字送给 CPU

⚠️ **Cache 的全部功能都由硬件实现**，对程序员（包括汇编程序员和操作系统）**透明**。程序员写程序时根本看不见 Cache。
- 对比：后面要学的虚拟存储器，缺页时由**操作系统（软件）**处理
- 2020 年第 15 题就考了这一点：“TLB 和 Cache 的缺失处理都可以由硬件实现”是**对**的；“都由 DRAM 组成”是**错**的（它们都用 SRAM），选 D

### 📐 命中率与平均访问时间（⭐⭐⭐）
设：
- **命中率 H** = 命中次数 / 访问总次数
- **缺失率** = 1 − H
- **t_c**：Cache 访问时间，**t_m**：主存访问时间

**平均访问时间 T_a** 有两种模型，题目会说清楚是哪一种：

**① 先访问 Cache，缺失后再访问主存（“串行”，默认）**
```
T_a = H × t_c + (1 − H) × (t_c + t_m) = t_c + (1 − H) × t_m
```
🧒 不管命中与否都要先查一次 Cache（t_c），缺失时再多花一次主存时间。

**② 同时访问 Cache 和主存（“并行”），命中就中止主存访问**
```
T_a = H × t_c + (1 − H) × t_m
```

**效率 e** = t_c / T_a（越接近 1 越好）

### ✏️ 例 1
CPU 执行一段程序时，Cache 完成存取 **1900 次**，主存完成存取 **100 次**，Cache 存取周期 **50 ns**，主存 **250 ns**。求命中率、平均访问时间、效率（按同时访问计算）。
- H = 1900 / (1900 + 100) = **0.95**
- T_a = 0.95 × 50 + 0.05 × 250 = 47.5 + 12.5 = **60 ns**
- e = 50 / 60 ≈ **83.3%**
- 若按“先访问 Cache，缺失再访问主存”：T_a = 50 + 0.05 × 250 = **62.5 ns**

### ✏️ 例 2：以“时钟周期”为单位
某 CPU 访问 Cache 需 **1 个时钟周期**，缺失时从主存调入一个块需 **100 个时钟周期**（缺失损失）。命中率 **98%**。
- 平均访问时间 = 1 + 2% × 100 = **3 个时钟周期**
- 🧒 命中率只差 2%，平均时间却是 Cache 的 3 倍！所以**命中率哪怕提高一点点，性能提升都很明显**。

### 📐 缺失损失（miss penalty）
缺失时，除了访问 Cache 的时间，还要额外付出的时间：**从主存读一个块到 Cache 的时间**。块越大，读一个块越久。

## 三、映射方式总览：主存块放在 Cache 的哪一行？

主存有很多块，Cache 只有很少的行。**一个主存块被调入时，可以放在 Cache 的哪些行？** 这就是**映射方式**。

🧒 用**停车场**打比方。Cache 有 8 个车位，主存有几千辆车（块）：
| 方式 | 停车规则 | 找车时 |
|---|---|---|
| **直接映射** | 每辆车**只能停在 1 个固定车位**（车牌号 mod 8） | 只看 1 个车位，快 |
| **全相联映射** | 每辆车**可以停在任意车位** | 要把 8 个车位全看一遍，慢/贵 |
| **组相联映射** | 车位分成若干**组**，每辆车**只能停在固定的一组**，组内**任意车位** | 只看一组内的几个车位 |

每一行都要记住“**我现在装的是主存中的哪一块**”，这就是**标记（Tag）**。

## 四、直接映射（⭐⭐⭐）

### 📐 规则
设 Cache 共有 **2^c 行**，主存块号为 j：
```
Cache 行号 i = j mod 2^c
```
即：每个主存块**只能**放到唯一确定的一行。

### ✏️ 例
Cache 有 8 行（行号 0~7），主存块号 0~31：
- 主存块 0、8、16、24 → 都只能放 Cache 第 0 行
- 主存块 1、9、17、25 → 都只能放 Cache 第 1 行
- ……
- 主存块 13 → 13 mod 8 = **第 5 行**

```
主存块号     Cache 行
 0, 8,16,24 ──► 0
 1, 9,17,25 ──► 1
 2,10,18,26 ──► 2
    ...        ...
 7,15,23,31 ──► 7
```

### 📐 地址划分（⭐⭐⭐）
因为 Cache 行数 2^c 是 2 的幂，**“块号 mod 2^c”就是块号的低 c 位**！所以主存地址可以直接切成三段：

```
|<------------ 主存地址 ------------>|
|   标记 Tag   |  行号 Index  | 块内地址 Offset |
|  剩下的高位  |    c 位      |     b 位        |
|<----- 主存块号 ----->|
```
- **块内地址（offset）**：b 位，**2^b = 块大小**（按字节编址）
- **行号（index）**：c 位，**2^c = Cache 行数**
- **标记（tag）**：主存地址位数 − c − b

🧒 为什么这样就够了？块号 = tag 和 index 拼起来。index 已经“藏”在行的位置里了（第几行就是 index），所以行里只要再记住 tag，就能唯一确定是哪一块。

### 📐 直接映射的访问过程
1. 用地址的 **index** 找到唯一的那一行
2. 比较这一行的 **tag** 与地址的 **tag**，并检查**有效位 V = 1**
3. 相等且有效 → **命中**，用 offset 从这一行的数据中选出要的字节/字
4. 否则 → **缺失**，从主存调入该块，放在这一行（**直接替换，不需要替换算法**）

只需要 **1 个比较器**，比较器位数 = **tag 位数**。

### 📐 优缺点
- ✅ 电路简单，查找快
- ❌ **冲突多**：即使 Cache 其他行都空着，两个映射到同一行的块也只能互相“踢来踢去”（**抖动**），命中率低

### ✏️ 例：直接映射的冲突
Cache 8 行，直接映射，依次访问主存块 0、8、0、8、0、8：
- 0 → 行 0，缺失
- 8 → 行 0，缺失（把 0 替换掉）
- 0 → 缺失（把 8 替换掉）
- ……**全部缺失**，而其他 7 行一直空着！

## 五、全相联映射（⭐⭐）

### 📐 规则
主存的**任意一块**可以放到 Cache 的**任意一行**。

### 📐 地址划分
```
|        标记 Tag（= 主存块号）        | 块内地址 Offset |
|        主存地址位数 − b 位           |     b 位        |
```
没有 index，**tag 就是整个主存块号**。

### 📐 访问过程
要把地址的 tag 与 Cache **所有行**的 tag **同时比较**（用**相联存储器**/按内容访问）。
- 需要 **Cache 行数个比较器**，每个比较器位数 = tag 位数

### 📐 优缺点
- ✅ 最灵活，**冲突最少**，命中率最高（相同容量下）
- ❌ 比较电路多，**成本高、速度慢**，只适合小容量 Cache（如 TLB 常用全相联）

## 六、组相联映射（⭐⭐⭐ 最常考）

### 📐 规则
把 Cache 的行分成 **Q 组**，每组 **K 行**（叫 **K 路组相联**，K-way）：
```
Cache 组号 = 主存块号 mod Q
```
主存块**只能放到固定的那一组**，但可以放在**组内任意一行**。

### 📐 地址划分
```
|  标记 Tag  |  组号 Index  | 块内地址 Offset |
|  剩余高位  |  q 位，2^q=Q |     b 位        |
```
- **组数 Q = Cache 行数 / K**
- tag 位数 = 地址位数 − q − b

### 📐 访问过程
1. 用 **index（组号）** 找到对应的组
2. 把地址的 tag 与**该组内 K 行**的 tag **同时比较**（K 个比较器）
3. 有一行相等且有效 → 命中；否则缺失，从主存调入，放在该组的**某一个空行**，组满了就用**替换算法**选一行替换

需要 **K 个比较器**，每个比较器位数 = **tag 位数**。

### 📐 组相联是“折中”
| K（路数） | 等价于 |
|---|---|
| K = 1（1 路组相联） | **直接映射**（每组 1 行，组数 = 行数） |
| K = 行数（只有 1 组） | **全相联映射** |
| 中间 | 组相联 |

🧒 **路数越多**：冲突越少、命中率越高，但比较器越多、越贵、越慢；**tag 位数也越多**（因为组数变少，index 位变少，多出来的位归到 tag）。

### ✏️ 例：三种方式对比同一个 Cache
主存地址 **32 位**，按字节编址；Cache 数据区 **16 KB**，块大小 **32 B**。
- 块内地址 b：32 = 2⁵ → **5 位**
- Cache 行数：16 KB / 32 B = 2¹⁴ / 2⁵ = **512 = 2⁹ 行**

| 映射方式 | Tag | Index | Offset | 比较器 |
|---|---|---|---|---|
| 直接映射 | 32 − 9 − 5 = **18** | 9（行号） | 5 | 1 个 18 位 |
| 4 路组相联 | 512/4 = 128 = 2⁷ 组 → 32 − 7 − 5 = **20** | 7（组号） | 5 | 4 个 20 位 |
| 全相联 | 32 − 5 = **27** | 0 | 5 | 512 个 27 位 |

看到规律了吗？**路数每翻一倍，index 少 1 位，tag 多 1 位。**

### ✏️ 例：某地址映射到哪一组
接上例（4 路组相联，128 组），主存地址 **1234 5678H** 映射到哪一组？
- 写成二进制，取中间 7 位（第 11~5 位，最低位为第 0 位）
- 5678H 的低 12 位 = 678H = 0110 0111 1000
  - 位 4~0（offset）= 11000 = 24
  - 位 11~5（组号）= 0110011 = **51**
- 映射到**第 51 组**

🧒 **小技巧**：也可以先求块号 = 地址 ÷ 32，再 mod 128。1234 5678H ÷ 32 = 91A2B3H（右移 5 位），91A2B3H mod 128 = B3H mod 80H = 33H = **51** ✓

## 七、Cache 行的结构与“总容量”（⭐⭐⭐）

### 📐 一行里除了数据还有什么
```
| 有效位 V | 脏位 D | 替换控制位 | 标记 Tag | 数据（一个块）|
```
1. **有效位（Valid）**：1 位，表示这一行是否装了有效数据（开机时全为 0）——**一定有**
2. **标记（Tag）**：若干位——**一定有**
3. **数据**：块大小 × 8 位
4. **脏位 / 修改位（Dirty）**：1 位，**只有采用“写回法”才需要**（下一课讲）；写直达（全写）法不需要
5. **替换控制位**：采用 LRU 等替换算法时需要（下一课讲）。直接映射不需要替换算法 → 没有这一项

⚠️ 默认题目问“Cache 行的位数”时，要**看清楚题目说了哪些策略**，把需要的位都加上。

### 📐 Cache 的总容量
- **数据区容量**：通常说的“Cache 大小为 32KB”指的就是**数据区**
- **Cache 总容量**（实际存储位数）= 行数 × (数据位 + tag + 有效位 + 脏位 + 替换位)

### ✏️ 真题精讲 1
📝 **真题（2021 年第 16 题）**：若计算机主存地址为 32 位，按字节编址，Cache 数据区大小为 32KB，主存块大小为 32B，采用**直接映射**方式和**回写（Write Back）**策略，则 Cache 行的位数至少是：A. 275　B. 274　C. 258　D. 257

1. 块内地址：32B = 2⁵ → 5 位
2. 行数：32KB / 32B = 2¹⁵ / 2⁵ = 2¹⁰ = 1024 行 → 行号 10 位
3. Tag：32 − 10 − 5 = **17 位**
4. 一行的位数 = 数据 32 × 8 = **256** + Tag **17** + 有效位 **1** + 脏位 **1**（回写法需要）= **275**
5. 直接映射不需要替换控制位
→ 选 **A**

⚠️ 如果漏了脏位得 274（B），如果把 tag 算错也会错选。**有效位永远别忘**。

### ✏️ 真题精讲 2
📝 **真题（2022 年第 16 题）**：若计算机主存地址为 32 位，按字节编址，某 Cache 的数据区容量为 32KB，主存块大小为 64B，采用 **8 路组相联**映射方式，该 Cache 中比较器的个数和位数分别为：A. 8, 20　B. 8, 23　C. 64, 20　D. 64, 23

1. 块内地址：64B = 2⁶ → 6 位
2. 行数：32KB / 64B = 2¹⁵ / 2⁶ = 2⁹ = 512 行
3. 组数：512 / 8 = 64 = 2⁶ 组 → 组号 6 位
4. Tag：32 − 6 − 6 = **20 位**
5. 8 路组相联 → 每次在一组内的 8 行同时比较 → **8 个比较器**，每个 **20 位**
→ 选 **A**

⚠️ 比较器个数 = **路数 K**（不是组数 64！）。因为同一时刻只查一个组。

### ✏️ 真题精讲 3（大题第 1 问）
📝 **真题（2020 年第 44 题第 1 问）**：假定主存地址为 32 位，按字节编址，指令 Cache 和数据 Cache 与主存之间均采用 **8 路组相联**映射方式、**直写（Write Through）**写策略和 **LRU** 替换算法，主存块大小为 **64B**，数据区容量各为 **32KB**。Cache 每一行中标记（Tag）、LRU 位各占几位？是否有修改位？

1. 块内 6 位；512 行 / 8 路 = 64 组 → 组号 6 位；**Tag = 32 − 6 − 6 = 20 位**
2. **LRU 位**：8 路组相联，每组 8 行，要给组内每一行记录“第几久没用”（0~7）→ **log₂8 = 3 位**
3. **没有修改位**：直写法每次写 Cache 同时写主存，Cache 和主存始终一致，不需要脏位

（第 2、3 问见下一课“综合计算”。）

## 八、综合例题：给地址算映射（2023 年第 43 题第 3、4 问）

📝 **真题（2023 年第 43 题节选）**：已知计算机 M 字长 32 位，按字节编址，虚拟地址 32 位，页大小 4KB；**数据 Cache 采用 4 路组相联映射**，数据区大小 **8KB**，主存块大小 **32B**。有 C 语言程序段：
```c
int a[24][64];
......
for (i = 0; i < 24; i++)
    for (j = 0; j < 64; j++)
        a[i][j] = 10;
```
二维数组 a 按行优先存储，起始（虚拟）地址为 **0042 2000H**，sizeof(int) = 4。
（注：扫描版真题中数组声明印作 a[24][24]，与循环 j < 64 不符，原题为 **a[24][64]**，我们按 a[24][64] 讲解。）

**(2) 不考虑变量 i 和 j，该程序段的数据访问是否具有时间局部性？**
- **没有**。每个数组元素 a[i][j] 只被访问（写）**一次**，之后再也不访问。
- （但有**空间局部性**：按行顺序访问，地址连续。）

**(3) 虚拟地址 A31~A0 中哪几位用作块内地址？哪几位用作 Cache 组号？a[1][0] 的虚拟地址是多少？其所在主存块对应的 Cache 组号是多少？**
1. 块大小 32B = 2⁵ → **A4~A0** 为块内地址
2. 行数 = 8KB / 32B = 256；组数 = 256 / 4 = 64 = 2⁶ → **A10~A5** 为组号
3. a[1][0] 前面有 1 行共 64 个 int = 256B = 100H
   → 地址 = 0042 2000H + 100H = **0042 2100H**
4. 2100H 的二进制：0010 **0001 00**00 0000，A10~A5 = 001000 = **8** → **第 8 组**

（注意：题目中 Cache 用虚拟地址的这几位来索引，这是因为页大小 4KB，低 12 位的页内地址在虚实转换中不变，A10~A5 都在低 12 位内，所以用虚拟地址或物理地址算出的组号相同。第 12 课会详细讲。）

**(4) 数组 a 总共占多少主存块？假设程序段执行过程中数组 a 的访问不会和其他数据发生 Cache 访问冲突，则数组 a 的 Cache 命中率是多少？若将循环中 i 和 j 的次序调换（外层 j、内层 i），命中率又是多少？**
1. 数组大小 = 24 × 64 × 4 = 6144 B；主存块数 = 6144 / 32 = **192 块**
2. **按行访问**：每个块有 32/4 = **8 个 int**。访问一个块的第 1 个元素时缺失（调入整块），后 7 个都命中
   → 每块 1 次缺失，共 192 次缺失，访问总数 24 × 64 = 1536 次
   → 命中率 = (1536 − 192) / 1536 = **7/8 = 87.5%**
3. **交换循环（按列访问）**：先访问 a[0][0]、a[1][0]、……、a[23][0]，每次跨 256B，全部缺失（24 次），调入了 24 个块，每块包含 a[i][0]~a[i][7]；
   接下来 j = 1~7 时，访问的 a[i][j] 都在这 24 个块里——**它们还在 Cache 中吗？**
   - Cache 容量 8KB > 数组 6KB；192 个块依次映射到 64 个组，每组最多 192/64 = **3 块**，不超过 4 路 → **不会被替换**
   - 所以 j = 1~7 全部命中；j = 8 时又访问新的 24 个块……
   → 缺失次数仍然是 **192**，命中率仍是 **87.5%**

🧒 **本题的“陷阱”**：很多同学直觉认为按列访问命中率会很低。但这里数组整体比 Cache 小，且没有冲突，所以调入的块都能留住。**一定要结合 Cache 容量和映射冲突分析，而不是凭感觉。**
（如果 Cache 很小，按列访问时调入的块在用到之前就被替换出去，命中率就会暴跌。）

## 九、映射方式对比表（⭐⭐⭐ 背下来）

| | 直接映射 | 全相联映射 | K 路组相联 |
|---|---|---|---|
| 主存块可放位置 | 唯一 1 行 | 任意行 | 固定组内任意行 |
| 地址划分 | Tag \| 行号 \| 块内 | Tag \| 块内 | Tag \| 组号 \| 块内 |
| Tag 位数 | 最少 | 最多（= 块号位数） | 中间 |
| 比较器个数 | 1 | 行数 | K |
| 替换算法 | **不需要** | 需要 | 需要 |
| 冲突/命中率 | 冲突最多，命中率最低 | 冲突最少，命中率最高 | 折中 |
| 速度/成本 | 最快、最便宜 | 最慢、最贵 | 折中 |

## 十、多级 Cache 与分离 Cache（了解）

### 📐 多级 Cache
现代 CPU 有 **L1、L2、L3** 三级 Cache：
- **L1**：最靠近 CPU，最小（几十 KB）、最快，通常**分为指令 Cache（I-Cache）和数据 Cache（D-Cache）**
- **L2**：几百 KB~几 MB
- **L3**：几 MB~几十 MB，通常**多个核共享**

### 📐 分离 Cache（哈佛结构思想）
- 指令和数据分开放在 **I-Cache、D-Cache** 中，好处：**取指令和读写数据可以同时进行**，避免**流水线的结构冲突**（第 18 课）
- 统一 Cache（Unified Cache）：指令和数据放在一起，L2、L3 通常是统一 Cache

## ⚠️ 易错点

1. **Cache 由 SRAM 实现**；主存由 DRAM 实现
2. **Cache 对所有程序员透明**，全部由硬件管理
3. Cache 与主存按**块**交换，CPU 与 Cache 按**字**交换
4. 平均访问时间：先看题目是“先查 Cache 再查主存”还是“同时访问”
5. 组相联：**比较器个数 = 路数**，**比较器位数 = tag 位数**
6. 行数 = 数据区容量 / 块大小；组数 = 行数 / 路数
7. Cache 行位数 = **数据位 + tag + 有效位（1）** + 脏位（写回才有）+ 替换位（LRU 等才有）
8. 直接映射**不需要替换算法**，也就没有替换控制位
9. “有没有时间局部性”针对的是**同一个数据**是否被重复访问；数组只遍历一次 → 没有时间局部性
10. 地址划分时，按**字节编址**，块内地址位数 = log₂(块字节数)；若按字编址要换算

## 📋 本课小结

| 知识点 | 要点 |
|---|---|
| 为什么需要 Cache | CPU 快、主存慢；利用局部性，用少量 SRAM 缓存常用块 |
| 局部性 | 时间：刚用过的还会用；空间：附近的也会用 |
| 平均访问时间 | 串行：t_c + (1−H)t_m；并行：H·t_c + (1−H)t_m |
| 直接映射 | 行号 = 块号 mod 行数；Tag \| 行号 \| 块内 |
| 全相联 | 任意行；Tag \| 块内；比较器 = 行数 |
| 组相联 | 组号 = 块号 mod 组数；Tag \| 组号 \| 块内；比较器 = 路数 |
| 行结构 | V + (D) + (LRU) + Tag + 数据 |

## 🏋️ 课后练习

1. 下列程序段中，对数组 a 的访问具有怎样的局部性？对 sum 呢？
   ```c
   for (i = 0; i < 100; i++) sum += a[i] * a[i];
   ```
2. 某计算机 Cache 命中率 95%，Cache 访问时间 2ns，主存访问时间 80ns。采用“先访问 Cache，缺失后访问主存”的方式，求平均访问时间。若采用同时访问的方式呢？
3. 主存地址 24 位，按字节编址，Cache 数据区 8KB，块大小 16B。分别求直接映射、2 路组相联、全相联时 Tag、Index、Offset 的位数。
4. 接第 3 题，采用直接映射。主存地址 12 3456H 映射到 Cache 的哪一行？该行的 Tag 是多少？
5. 某 Cache 采用 4 路组相联，主存地址 32 位，按字节编址，块大小 64B，Cache 数据区 64KB，采用写回法和 LRU 替换算法。求：(1) Cache 共多少组？(2) 每行的位数（含有效位、脏位、LRU 位）？(3) Cache 的总容量是多少位？
6. 判断：直接映射 Cache 的命中率一定比全相联 Cache 低。
7. 主存块号为 100 的块，在 16 行的 Cache 中，采用直接映射时放在哪一行？采用 4 路组相联时放在哪一组？

<details>
<summary>📖 答案</summary>

1. a：每个元素 a[i] 在一次循环中被访问两次（a[i]*a[i]），紧接着重复访问 → 有一点时间局部性（第二次访问一定命中）；顺序访问 → **空间局部性好**。sum：每次循环都访问 → **时间局部性好**。
2. 串行：2 + 0.05 × 80 = **6 ns**；并行：0.95 × 2 + 0.05 × 80 = 1.9 + 4 = **5.9 ns**
3. 块内 4 位（16=2⁴）；行数 8KB/16B = 512 = 2⁹。
   - 直接映射：Tag 24−9−4 = **11**，Index **9**，Offset **4**
   - 2 路组相联：256 组 = 2⁸，Tag 24−8−4 = **12**，Index **8**，Offset **4**
   - 全相联：Tag 24−4 = **20**，Index **0**，Offset **4**
4. 12 3456H = 0001 0010 0011 0100 0101 0110。Offset = 低 4 位 = 0110；行号 = 接下来 9 位（位 12~4）= 1 0100 0101 = 145H = **325**；Tag = 高 11 位（位 23~13）= 0001 0010 001 = 000 1001 0001 = **091H**（= 145）。
   验证：块号 = 12 3456H >> 4 = 1 2345H，mod 512 = 1 2345H & 1FFH = 145H = 325 ✓；Tag = 1 2345H >> 9 = 91H ✓
5. (1) 行数 64KB/64B = 1024，组数 = 1024/4 = **256 组**
   (2) 块内 6 位，组号 8 位，Tag = 32−8−6 = 18 位；LRU 4 路 → 2 位；每行 = 512（数据）+ 18 + 1（V）+ 1（D）+ 2（LRU）= **534 位**
   (3) 总容量 = 1024 × 534 = **546 816 位**（≈ 66.75 KB）
6. **错**。一般情况下全相联冲突更少、命中率更高，但“一定”太绝对：替换算法选得不好时，特定访问序列下全相联也可能比直接映射命中率低。
7. 直接映射：100 mod 16 = **第 4 行**；4 路组相联：16/4 = 4 组，100 mod 4 = **第 0 组**
</details>
