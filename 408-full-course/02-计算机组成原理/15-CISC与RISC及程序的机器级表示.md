## 🚪 课前引入

同样是“做一道菜”：
- **CISC 的菜谱**：一条命令“做一份宫保鸡丁”——命令很强大，但厨师（CPU）要懂几百种复杂命令，每条命令执行时间长短不一
- **RISC 的菜谱**：拆成很多简单步骤“切肉、下锅、翻炒……”——每条命令都很简单、执行时间相同，厨师可以像流水线一样高效干活

现代计算机两种思路都有：你的电脑（Intel/AMD，x86）是 CISC，手机（ARM）是 RISC。

后半节课，我们要学会**读汇编代码**。408 大题常常把 C 程序和它的**x86 机器级代码**并排给出，让你分析指令地址、寻址方式、栈帧、条件转移、溢出……看不懂汇编就会失分。

## 一、CISC 与 RISC（⭐⭐⭐）

### 📐 CISC（复杂指令集计算机）
**Complex Instruction Set Computer**，代表：**x86**
- 指令系统**复杂庞大**，指令数目多（几百条）
- **指令长度不固定**，指令格式多，**寻址方式多**
- **可以访存的指令不受限制**（运算指令也可以直接访存）
- 各种指令执行时间相差很大，**大多数指令需要多个时钟周期**
- 控制器大多采用**微程序控制**
- **难以用优化编译器**生成高效代码
- 通用寄存器较少

### 📐 RISC（精简指令集计算机）
**Reduced Instruction Set Computer**，代表：**ARM、MIPS、RISC-V**
- 核心思想：**选取使用频率最高的一些简单指令**，复杂功能由简单指令组合实现
  - 统计发现：程序中 80% 的时间在执行 20% 的简单指令（“80-20 规律”）
- **指令长度固定**，指令格式种类少，**寻址方式种类少**
- **只有 Load/Store（取数/存数）指令访存**，其余指令的操作都在**寄存器**之间进行（**Load/Store 架构**）
- **通用寄存器数量多**（如 32 个）
- **一定采用指令流水线技术**，大部分指令在**一个时钟周期**内完成
- 控制器以**硬布线（组合逻辑）控制**为主，不用或少用微程序
- **重视编译优化**，减少程序执行时间
- 参数通常通过**寄存器**传递（寄存器多）

### 📐 对比表（⭐⭐⭐）

| | CISC | RISC |
|---|---|---|
| 指令数目 | 多 | 少 |
| 指令长度 | **变长** | **定长** |
| 寻址方式 | 多 | 少 |
| 访存指令 | 不限制 | **只有 Load/Store** |
| 通用寄存器 | 少 | **多** |
| 执行周期 | 多数需多个周期 | 多数**一个周期** |
| 流水线 | 较难 | **一定采用** |
| 控制器 | **微程序**为主 | **硬布线**为主 |
| 编译优化 | 难 | **重视** |
| 过程调用传参 | 多用栈 | 多用寄存器 |
| 代表 | x86 | ARM、MIPS、RISC-V |

📝 **真题（2025 年第 17 题）**：下列关于 RISC 的叙述中，**错误**的是：
A. 多采用硬连线方式实现控制器　B. 通常采用 Load/Store 型指令设计风格　C. 难以采用流水线数据通路实现微架构　D. 多采用寄存器传递过程调用时的参数
→ **C**（RISC 恰恰是**最适合**流水线的：指令定长、格式规整、只有 Load/Store 访存）

⚠️ 现代 CPU 是**融合**的：x86 处理器内部会把复杂 CISC 指令翻译成类似 RISC 的“微操作”再流水执行。

## 二、从源程序到可执行文件（⭐）

```
hello.c ──预处理──► hello.i ──编译──► hello.s ──汇编──► hello.o ──链接──► hello（可执行文件）
 源程序    (cpp)    预处理后源程序  (cc1)   汇编程序    (as)   可重定位目标文件  (ld)
```
1. **预处理**：处理 `#include`、`#define`、条件编译，展开宏，删注释
2. **编译**：把 C 语言翻译成**汇编语言**
3. **汇编**：把汇编语言翻译成**机器语言**（二进制的目标文件）
4. **链接**：把多个目标文件和库函数（如 printf）**合并**，确定所有符号的最终地址，生成可执行文件

📝 **真题（2022 年第 20 题）**：将高级语言源程序转换为可执行目标文件的主要过程是：
A. 预处理→编译→汇编→链接　B. 预处理→汇编→编译→链接　C. 预处理→编译→链接→汇编　D. 预处理→汇编→链接→编译
→ **A**

🧒 记忆：“**预编汇链**”——先把 C 变成汇编（编译），再把汇编变成机器码（汇编），最后拼起来（链接）。

## 三、x86 汇编基础（⭐⭐）

### 📐 寄存器（IA-32，32 位）
| 寄存器 | 常见用途 |
|---|---|
| **EAX** | 累加器；**函数返回值** |
| EBX | 基址 |
| ECX | 计数器（循环） |
| EDX | 数据；乘除法的高位 |
| ESI、EDI | 源变址、目的变址（数组、字符串） |
| **ESP** | **栈指针**（指向栈顶） |
| **EBP** | **基址指针**（指向当前栈帧的底部） |
| **EIP** | 指令指针，就是 **PC** |
| **EFLAGS** | 标志寄存器（CF、ZF、SF、OF……） |

- 16 位时叫 AX、BX……；8 位 AL、AH……；64 位时叫 RAX、RBX……
- 408 采用 **Intel 格式**：**`指令 目的, 源`**（如 `mov eax, ebx` 表示 eax ← ebx）
  - AT&T 格式（Linux 的 gcc 默认）相反：`movl %ebx, %eax`，考试一般不用

### 📐 主存操作数的写法
```
[基址寄存器 + 变址寄存器 × 比例因子 + 偏移量]
```
- `mov eax, [ebx]`：eax ← M[ebx]（寄存器间接）
- `mov eax, [ebp - 8]`：eax ← M[ebp − 8]（基址寻址，访问局部变量）
- `mov eax, [ebx + esi*4]`：eax ← M[ebx + esi × 4]（数组元素）
- 大小修饰：`dword ptr [..]`（4 字节）、`word ptr`（2 字节）、`byte ptr`（1 字节）

### 📐 常用指令
| 指令 | 功能 | 说明 |
|---|---|---|
| `mov d, s` | d ← s | **不能两个操作数都是主存** |
| `lea d, [addr]` | d ← addr（**地址本身**，不访存） | 常用来做加法：`lea eax, [ebx+ecx*2]` |
| `push s` | esp ← esp − 4；M[esp] ← s | |
| `pop d` | d ← M[esp]；esp ← esp + 4 | |
| `add d, s` / `sub d, s` | d ← d ± s | 设置标志位 |
| `inc d` / `dec d` | d ± 1 | |
| `imul d, s` | 带符号乘 | 乘积只保留低位 |
| `neg d` | d ← −d | |
| `and` / `or` / `xor` / `not` | 逻辑运算 | `xor eax, eax` 常用于清零 |
| `shl` / `sal` | 左移 | |
| `shr` | **逻辑**右移（补 0） | 无符号数 |
| `sar` | **算术**右移（补符号位） | 有符号数 |
| `cmp a, b` | 计算 a − b，**只设置标志，不保存结果** | 比较 |
| `test a, b` | 计算 a AND b，只设置标志 | `test eax, eax` 判断是否为 0 |
| `jmp L` | 无条件跳转 | |
| `jxx L` | 条件跳转 | 见下 |
| `call f` | 压入返回地址，跳到 f | |
| `ret` | 弹出返回地址到 EIP | |

### 📐 标志位（条件码）
| 标志 | 含义 | 何时为 1 |
|---|---|---|
| **ZF**（零标志） | 结果为 0 | 结果全 0 |
| **SF**（符号标志） | 结果为负 | 结果最高位为 1 |
| **CF**（进位/借位标志） | **无符号**运算溢出 | 加法最高位有进位；减法有借位（被减数 < 减数，按无符号比较） |
| **OF**（溢出标志） | **有符号**运算溢出 | 两个同号数相加得异号结果等 |

📝 **真题（2023 年第 16 题）**：已知 x、y 为 int 类型，当 x = 100，y = 200 时，执行 x − y 指令得到的溢出标志 OF 和借位标志 CF 分别为 0、1，那么当 x = 10，y = −20 时，执行该指令得到的 OF 和 CF 分别是：
A. OF=0, CF=0　B. OF=0, CF=1　C. OF=1, CF=0　D. OF=1, CF=1
- 有符号：10 − (−20) = 30，在 int 范围内 → **OF = 0**
- 无符号：y = −20 的补码当作无符号数是 2³² − 20，非常大；10 < 2³² − 20，**有借位** → **CF = 1**
→ 选 **B**

### 📐 条件转移指令（⭐⭐⭐）
**有符号数比较**用 greater/less，**无符号数比较**用 above/below：

| 含义 | 有符号 | 无符号 | 通用 |
|---|---|---|---|
| 大于 | **jg**（jnle） | **ja**（jnbe） | |
| 大于等于 | **jge**（jnl） | **jae**（jnb） | |
| 小于 | **jl**（jnge） | **jb**（jnae） | |
| 小于等于 | **jle**（jng） | **jbe**（jna） | |
| 等于 | | | **je**（jz） |
| 不等于 | | | **jne**（jnz） |

- 判断依据：
  - `jb`（无符号 <）：**CF = 1**
  - `ja`（无符号 >）：CF = 0 且 ZF = 0
  - `jl`（有符号 <）：**SF ≠ OF**
  - `jge`（有符号 ≥）：SF = OF
  - `jg`：ZF = 0 且 SF = OF
- 🧒 记忆：**g/l（great/less）比有符号，a/b（above/below）比无符号**

⚠️ **经典陷阱**：C 语言中 unsigned 和 int 比较时，int 会被转换成 unsigned，编译器会用 **ja/jb**。例如 `unsigned i; for (i = n - 1; i >= 0; i--)` 永远不会结束（i ≥ 0 恒成立）。

## 四、选择和循环结构的机器级表示（⭐⭐）

### 📐 if-else
```c
if (a > b) c = a;
else       c = b;
```
假设 a、b、c 是 int，分别在 [ebp-4]、[ebp-8]、[ebp-12]：
```asm
    mov  eax, [ebp-4]     ; eax = a
    cmp  eax, [ebp-8]     ; 计算 a - b，设置标志
    jle  ELSE             ; 若 a <= b（有符号），跳到 ELSE
    mov  [ebp-12], eax    ; c = a
    jmp  END
ELSE:
    mov  eax, [ebp-8]
    mov  [ebp-12], eax    ; c = b
END:
```
🧒 注意：编译器通常把条件**取反**再跳（C 里是 a > b，汇编里是 jle 跳到 else）。

### 📐 for 循环
```c
for (i = 0; i < 24; i++) { ... }
```
常见的编译方式（2023 年第 44 题就是这样）：
```asm
    mov  [ebp-8], 0       ; i = 0
    jmp  COND             ; 先跳去判断条件
BODY:
    ...                   ; 循环体
    mov  eax, [ebp-8]
    add  eax, 1
    mov  [ebp-8], eax     ; i++
COND:
    cmp  [ebp-8], 24      ; 计算 i - 24
    jl   BODY             ; i < 24 则继续（或写成 jge 跳出）
```
2023 年第 44 题中，第 2 条 `jmp 00401084h` 就是“初始化后先跳到条件判断”，第 7 条 `jge 004010bch` 就是“i ≥ 24 时跳出循环”。

## 五、过程调用的机器级表示（⭐⭐⭐）

### 📐 栈的基本知识
- x86 的栈在主存中，**从高地址向低地址增长**
- **ESP** 指向**栈顶**（最低的已用地址）；**EBP** 指向当前**栈帧的底部**（基准）
- 每个正在执行的函数有一个**栈帧（Stack Frame）**，存放它的局部变量、保存的寄存器、调用别的函数时的参数等

### 📐 call 与 ret
- **`call f`**：
  1. 把**返回地址**（call 的下一条指令的地址）**压栈**：esp ← esp − 4，M[esp] ← 返回地址
  2. 跳到 f：EIP ← f 的地址
- **`ret`**：
  1. 从栈顶**弹出**返回地址到 EIP：EIP ← M[esp]，esp ← esp + 4

🧒 就像你去隔壁帮忙前，在门口贴张纸条“干完回到第 12 行”（压栈）；干完活，撕下纸条，看一眼，回到第 12 行（弹栈）。

### 📐 一个完整的例子
```c
int add(int x, int y) {
    int sum = x + y;
    return sum;
}
int caller() {
    int r = add(3, 5);
    return r;
}
```
**调用者 caller 中**：
```asm
    push 5              ; 参数从右向左压栈：先压 y
    push 3              ; 再压 x
    call add            ; 压入返回地址，跳转
    add  esp, 8         ; 调用者清理参数（2 个 × 4 字节）
    mov  [ebp-4], eax   ; r = 返回值（在 eax 中）
```
**被调用者 add 中**：
```asm
add:
    push ebp            ; ① 保存调用者的 ebp
    mov  ebp, esp       ; ② ebp 指向本栈帧底部
    sub  esp, 4         ; ③ 为局部变量 sum 分配空间
    mov  eax, [ebp+8]   ; eax = x（第 1 个参数）
    add  eax, [ebp+12]  ; eax = x + y（第 2 个参数）
    mov  [ebp-4], eax   ; sum = eax
    mov  eax, [ebp-4]   ; 返回值放 eax
    mov  esp, ebp       ; ④ 释放局部变量（也可写 leave）
    pop  ebp            ; ⑤ 恢复调用者的 ebp
    ret                 ; ⑥ 返回
```

**进入 add、执行完 ③ 后的栈**（高地址在上）：
```
高地址
        ┌──────────────┐
        │ caller 的栈帧 │
        ├──────────────┤
ebp+12  │   y = 5      │  ← 参数 2
ebp+8   │   x = 3      │  ← 参数 1
ebp+4   │   返回地址    │  ← call 压入
ebp  →  │ 旧 ebp        │  ← push ebp
ebp-4   │   sum        │  ← 局部变量
esp  →  └──────────────┘
低地址
```

### 📐 规律（⭐⭐⭐ 背下来）
- **[ebp + 4]**：返回地址
- **[ebp + 8]**：第 1 个参数；**[ebp + 12]**：第 2 个参数……（参数在 ebp 的**上方**，正偏移）
- **[ebp − 4]、[ebp − 8]……**：局部变量（在 ebp 的**下方**，负偏移）
- **[ebp]**：保存的调用者的 ebp
- **返回值在 EAX 中**
- 参数**从右向左**压栈，所以第 1 个参数离 ebp 最近
- 函数开头的“**push ebp; mov ebp, esp**”叫**序言（prologue）**，结尾的“**mov esp, ebp; pop ebp; ret**”（或 **leave; ret**）叫**尾声（epilogue）**

### 📐 寄存器的保存
- **调用者保存寄存器**（EAX、ECX、EDX）：调用者若在调用后还要用，需要在 call 前自己保存
- **被调用者保存寄存器**（EBX、ESI、EDI）：被调用者若要使用，必须先保存、返回前恢复
- EBP、ESP 由序言/尾声维护

### 📐 递归调用
每次递归调用都会**新建一个栈帧**（返回地址、旧 ebp、局部变量……），递归深度越大，栈用得越多；太深会**栈溢出**。

## 六、真题精讲：2023 年第 44 题第 4 问

> 第 1 次执行第 19 条指令时，取指令过程中是否会发生缺页异常？为什么？

- 第 19 条指令虚拟地址 0040 10AEH，长 11 字节，占 0040 10AEH ~ 0040 10B8H
- 页大小 4KB，这些地址都在**虚页 00401H** 中（地址范围 0040 1000H ~ 0040 1FFFH）
- 第 1~18 条指令也都在这一页中，**在执行第 19 条之前已经执行过**（比如第 1 条 0040 1072H），这一页早已调入主存
- 所以**不会**发生缺页异常

⚠️ 答题要点：①指出指令所在的页；②指出该页在之前已被访问（调入）；③若一条指令**跨越两个页**，则要分别判断。

## 七、汇编代码分析的答题技巧

1. **数字节数**：变长指令的地址 = 上一条地址 + 上一条的机器码字节数
2. **找偏移量**：相对转移指令的偏移量在机器码最后 1 或 4 个字节，按**小端**读
3. **识别变量**：[ebp − k] 是局部变量，[ebp + 8]、[ebp + 12] 是参数
4. **识别循环**：向回跳的条件转移（目标地址 < 当前地址）是循环
5. **判断有/无符号**：看跳转指令是 jg/jl 还是 ja/jb；看移位是 sar 还是 shr；看乘法是 imul 还是 mul
6. **判断溢出**：imul 只保留低 32 位，结果超出范围就溢出（2020 年第 43 题）

## ⚠️ 易错点

1. RISC **一定用流水线**，控制器以**硬布线**为主，**只有 Load/Store 访存**
2. CISC 控制器多用**微程序**，指令**变长**
3. 顺序：**预处理 → 编译 → 汇编 → 链接**
4. Intel 格式：**目的在前**，源在后
5. **cmp a, b 计算 a − b**，不保存结果
6. **CF 反映无符号**溢出/借位，**OF 反映有符号**溢出
7. **jg/jl 有符号，ja/jb 无符号**
8. 栈**向低地址**增长；call 压入的是**下一条指令地址**
9. [ebp + 8] 是第 1 个参数，返回值在 **EAX**
10. `lea` 只计算地址，**不访存**

## 📋 本课小结

| 知识点 | 要点 |
|---|---|
| CISC | 复杂、变长、多寻址、微程序（x86） |
| RISC | 简单、定长、Load/Store、多寄存器、流水线、硬布线（ARM） |
| 编译过程 | 预处理 → 编译 → 汇编 → 链接 |
| 条件转移 | 有符号 jg/jl（看 SF、OF），无符号 ja/jb（看 CF） |
| 过程调用 | call 压返回地址；序言 push ebp / mov ebp, esp；ret 弹返回地址 |
| 栈帧 | [ebp+8] 参数 1，[ebp+4] 返回地址，[ebp−4] 局部变量，返回值 EAX |

## 🏋️ 课后练习

1. 判断：(a) RISC 的所有指令都在一个时钟周期内完成；(b) RISC 中运算指令的操作数只能来自寄存器或立即数；(c) CISC 更适合使用硬布线控制器。
2. 执行 `cmp eax, ebx` 后，eax = 0000 0001H，ebx = FFFF FFFFH。问：jg 和 ja 分别是否跳转？
3. 某函数 `int f(int a, int b, int c)`，按本课的调用约定，在 f 的序言执行后，参数 c 位于哪里？
4. 在调用 `call f` 之前 esp = 0000 8000H，call 指令本身位于地址 0040 1000H，长 5 字节。执行 call 后，esp 为多少？栈顶单元的内容是多少？
5. 下列汇编片段实现了什么 C 语句？（x 在 [ebp-4]，y 在 [ebp-8]）
   ```asm
       mov  eax, [ebp-4]
       test eax, eax
       jge  L1
       neg  eax
   L1: mov  [ebp-8], eax
   ```

<details>
<summary>📖 答案</summary>

1. (a) **错**，是“大多数”指令；(b) **对**（Load/Store 架构）；(c) **错**，CISC 多用微程序控制器
2. 有符号：1 > −1 → **jg 跳转**；无符号：1 < 4294967295 → **ja 不跳转**
3. **[ebp + 16]**（[ebp+8] 是 a，[ebp+12] 是 b，[ebp+16] 是 c）
4. esp = 8000H − 4 = **0000 7FFCH**；栈顶内容 = 返回地址 = 0040 1000H + 5 = **0040 1005H**
5. `y = (x >= 0) ? x : -x;` 即 **y = |x|**（test eax, eax 设置 SF；jge 在 x ≥ 0 时跳过取负）
</details>
