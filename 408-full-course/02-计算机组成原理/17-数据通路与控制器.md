🧒 **比喻：城市交通**
- **数据通路**是城市的**道路网**：数据（车）在寄存器、ALU、主存（各个地点）之间流动
- **控制信号**是**红绿灯和闸门**：`PCout` 打开 PC 的出口，`MARin` 打开 MAR 的入口，车就从 PC 开到了 MAR
- **控制器**是**交通指挥中心**：按照时间表（时序），在每个时刻打开正确的闸门

## 一、数据通路的基本概念（⭐⭐）

### 📐 定义
**数据通路**：数据在功能部件之间传送的**路径**，包括路径上的部件（ALU、寄存器、多路选择器、总线……）。
- 数据通路描述“**数据怎么流动**”
- **控制部件（控制器）**根据指令产生**控制信号**，控制数据通路中数据的流动方向

### 📐 两类元件（⭐⭐⭐）
| 类型 | 特点 | 例子 |
|---|---|---|
| **组合逻辑元件（操作元件）** | 输出**只取决于当前输入**，**没有存储功能**，不需要时钟 | **ALU、加法器、多路选择器 MUX、译码器**、三态门、符号扩展器 |
| **时序逻辑元件（状态元件）** | 有**存储功能**，输出取决于存储的内容，在**时钟**控制下写入 | **寄存器（PC、IR、通用寄存器组）**、触发器、存储器 |

📝 **真题（2023 年第 18 题）**：数据通路由组合逻辑元件（操作元件）和时序逻辑元件（状态元件）组成。下列给出的元件中，属于操作元件的是：I. 算术逻辑部件（ALU）　II. 程序计数器（PC）　III. 通用寄存器组（GPRs）　IV. 多路选择器（MUX）
A. 仅 I、II　B. 仅 I、IV　C. 仅 II、III　D. I、II、IV
→ **B**（PC、GPRs 是寄存器，能存储，属于状态元件）

📝 **真题（2021 年第 18 题）**：下列关于数据通路的叙述中，**错误**的是：
A. 数据通路包含 ALU 等组合逻辑（操作）元件　B. 数据通路包含寄存器等时序逻辑（状态）元件　C. 数据通路不包含用于异常事件检测及响应的电路　D. 数据通路中的数据流动路径由控制信号进行控制
→ **C**（异常检测电路，如溢出检测、非法地址检测、保存断点的通路，也是数据通路的一部分）

### 📐 寄存器的输入输出控制
- 寄存器的**输入**：由 `Rin`（写使能）信号控制，时钟边沿到来且 Rin = 1 时，把输入端的数据写入寄存器
- 寄存器的**输出**：接到总线上时，要通过**三态门**，由 `Rout` 控制。**同一时刻总线上只能有一个部件输出**（否则“撞车”）

## 二、数据通路的结构

### 📐 1. CPU 内部单总线
所有寄存器的输入端、输出端都连在**一条公共总线**上。
```
    ─────────────────── 内部总线 ───────────────────────
      │↑     │↑    │↑    │↑     │↑       ↓         ↑
      PC     IR    R0    R1    MAR     Y(暂存)     Z
                                │      │         ↑
                                ↓      └──►ALU◄──┘(另一个输入来自总线)
                               主存        │
                                │          └──► Z
                               MDR ◄──► 总线
```
- 结构简单，但**同一时刻只能传送一个数据**，数据传送冲突多，效率低
- ALU 有两个输入，而总线一次只能提供一个，所以要先把一个操作数存进**暂存寄存器 Y**（或 A），另一个再从总线来；ALU 的结果先放进**暂存寄存器 Z**（或 AC），下一个节拍再送到总线上

### 📐 2. CPU 内部多总线
两条或三条内部总线，**同一时刻可以传送多个数据**，效率高，但硬件多。

### 📐 3. 专用数据通路
根据指令执行过程的需要，在部件之间建立**专用的连接**（用多路选择器选择来源），没有公共总线冲突，性能高，但硬件量大。**单周期、流水线 CPU 通常用专用通路**。

## 三、单总线数据通路中的微操作（⭐⭐⭐）

### 📐 基本操作的写法
**寄存器之间传送**：`R1 → R2` 需要 1 个节拍，控制信号 **R1out、R2in**

**主存读**（地址在 MAR 中）：
```
M(MAR) → MDR          控制信号：MemR（读存储器）、MDRinE（MDR 从外部数据总线输入）
```
**主存写**：
```
MDR → M(MAR)          控制信号：MDRoutE（MDR 输出到外部数据总线）、MemW
```

**ALU 运算**（R1 + R2 → R3）：
```
① R1 → Y              R1out, Yin
② (Y) + (R2) → Z       R2out, ADD, Zin     ; 另一个操作数从总线来
③ Z → R3              Zout, R3in
```
（因为单总线一次只能传一个数，**一个加法要 3 个节拍**。）

### 📐 取指周期的节拍（⭐⭐⭐）
```
节拍  微操作                        有效控制信号
C1   MAR ← (PC)                    PCout, MARin
C2   MDR ← M(MAR)；PC ← (PC) + 1    MemR, MDRinE, PC+1
C3   IR ← (MDR)                    MDRout, IRin
C4   指令译码                       无
```
- C2 中，PC + 1 与读存储器**不冲突**（PC + 1 由 PC 自带的加法/计数功能完成，不占用内部总线），所以可以在同一个节拍完成

### 📝 真题（2009 年第 44 题）⭐⭐⭐
> 某计算机字长 16 位，采用 16 位定长指令字结构，部分数据通路结构如下图所示，图中所有控制信号为 1 时表示有效、为 0 时表示无效。例如控制信号 MDRinE 为 1 表示允许数据从 DB 打入 MDR，MDRin 为 1 表示允许数据从内总线打入 MDR。假设 MAR 的输出一直处于使能状态。加法指令“**ADD (R1), R0**”的功能为 **(R0) + ((R1)) → (R1)**，即将 R0 中的数据与 R1 的内容所指向的主存单元的数据相加，并将结果送入 R1 的内容所指主存单元中保存。
>
> 数据通路示意（单总线）：内总线上连接 PC、IR、R0~R3、MAR、MDR、暂存寄存器 A；ALU 的一个输入来自 A，另一个输入来自内总线，输出送暂存寄存器 AC；AC 的输出接到内总线；MAR 接地址总线 AB，MDR 接数据总线 DB（MDRinE/MDRoutE 控制）。
>
> 下表给出了上述指令取指和译码阶段每个节拍（时钟周期）的功能和有效控制信号，请按相同方式给出该指令执行阶段每个节拍的功能和有效控制信号。
>
> | 时钟 | 功能 | 有效控制信号 |
> |---|---|---|
> | C1 | MAR ← (PC) | PCout, MARin |
> | C2 | MDR ← M(MAR)，PC ← (PC) + 1 | MemR, MDRinE, PC+1 |
> | C3 | IR ← (MDR) | MDRout, IRin |
> | C4 | 指令译码 | 无 |

**分析**：要完成 (R0) + ((R1)) → (R1)：
1. 先用 R1 的内容作地址，读出主存中的操作数（寄存器间接寻址）
2. 与 R0 相加
3. 结果写回 R1 所指的主存单元（地址还在 MAR 中，不用再送）

**答案**：

| 时钟 | 功能 | 有效控制信号 |
|---|---|---|
| C5 | MAR ← (R1) | R1out, MARin |
| C6 | MDR ← M(MAR) | MemR, MDRinE |
| C7 | A ← (MDR) | MDRout, Ain |
| C8 | AC ← (A) + (R0) | R0out, Add, ACin |
| C9 | MDR ← (AC) | ACout, MDRin |
| C10 | M(MAR) ← (MDR) | MDRoutE, MemW |

🧒 **做这类题的诀窍**：
1. 先用“人话”写出要做的几件事
2. **每个节拍总线上只能有一个数据**（只能有一个 `xxout` 连到内总线）
3. ALU 的一个操作数必须先放到暂存寄存器（A 或 Y）
4. ALU 的结果先放到 AC（或 Z），下一拍再送走
5. 访存：地址先进 MAR，读用 MemR + MDRinE，写用 MDRoutE + MemW
6. 能不能合并？看是否用了同一条总线：C7 和 C8 都要用内总线，不能合并

⚠️ 常见错误：C8 写成“AC ← (MDR) + (R0)”一拍完成——不行，因为 MDR 和 R0 都要占用内总线。

> 5）图中控制信号由什么部件产生？图中哪些寄存器的输出信号会连到该部件的输入端？

**2）** 这是**单总线**结构，同一时刻内部总线上只能传送一个数据：
- ALU 有两个输入端，而总线一次只能提供一个操作数，所以要先把一个操作数送入 **Y** 暂存，另一个再通过总线送到 B 端
- ALU 是**组合逻辑**电路，没有存储功能，其输出随输入变化；运算时总线正被 B 端的操作数占用，结果不能同时送上总线，所以要先存入 **Z**，下一个节拍再由 Zout 送到总线

**3）**
- rs、rd 都是 **4 位** → 最多 **2⁴ = 16 个**通用寄存器
- rs、rd 是指令中的寄存器编号字段，来自 **IR（指令寄存器）**
- **rd 连接地址译码器**：写寄存器时，要用译码器根据编号**选中一个寄存器**，使它的写使能有效；**rs 连接多路选择器**：读寄存器时，用多路选择器从 16 个寄存器的输出中**选一个**送出

**4）** 控制信号序列：
```
① PCout, MARin          ; MAR ← (PC)
② Read                  ; 发出读命令，等待主存读出，数据经系统总线送入 MDR
③ MDRout, IRin          ; IR ← (MDR)
```
时钟周期数：① 1 个 + ② 5 个 + ③ 1 个 = **至少 7 个时钟周期**

**5）**
- 控制信号由**控制部件（控制器 CU）**产生
- 连到 CU 输入端的寄存器输出：**IR**（操作码等指令信息，图中“送 CU 等部件”）和 **FR**（标志信息，用于条件转移等）

## 四、控制器的两种实现方式（⭐⭐⭐）

控制器的核心任务：根据**当前指令的操作码**、**当前所处的节拍**、**状态标志**（如 ZF），产生**这一拍需要的控制信号**。

```
          操作码（来自 IR）──┐
          节拍（来自时序）───┼──► 控制器 ──► 控制信号（PCout, MARin, MemR, ...）
          状态（来自 PSW）───┘
```

### 📐 1. 硬布线控制器（组合逻辑控制器）
用**组合逻辑电路**（与门、或门……）直接产生控制信号。
- 每个控制信号写成一个逻辑表达式，例如：
  ```
  MARin = FE·T1 + IND·T1·(间接寻址) + EX·T1·(ADD + SUB + LOAD + ...) + ...
  ```
  （FE、IND、EX 是周期标志，T1 是节拍）
- 设计步骤：列出所有指令的微操作 → 安排到各节拍（**微操作节拍安排**）→ 列**操作时间表** → 写出每个控制信号的逻辑表达式 → 化简 → 画电路
- ✅ **速度快**（信号直接由电路产生）
- ❌ **设计复杂**，**难以修改和扩充**（改一条指令要重新设计电路）
- 适用于 **RISC**（指令简单、数量少）

#### 微操作节拍安排的原则（了解）
1. **先后顺序不能颠倒**的微操作必须按顺序安排
2. **互不冲突**（不占用同一部件、同一总线）的微操作尽量安排在**同一节拍**
3. 占用时间短的微操作尽量安排在同一节拍

### 📐 2. 微程序控制器（⭐⭐⭐）
**思想**：借鉴“**程序设计**”的方法——把每条机器指令的控制信号序列编成一段“**微程序**”，存放在 CPU 内部的只读存储器（**控制存储器 CM**）中。执行指令时，就依次读出微指令，**微指令中的各位就直接作为控制信号**。

🧒 **比喻：音乐盒**。音乐盒的滚筒上有许多凸点，滚筒每转一格，凸点拨动对应的音片发声。
- 滚筒上**每一排凸点** = 一条**微指令**（这一拍要发出哪些控制信号）
- **一首曲子** = 一段**微程序**（一条机器指令的全部控制信号序列）
- **滚筒** = **控制存储器**
想换一首曲子（修改指令）？只要换一个滚筒（改控存内容），不用重新设计整个机器。

### 📐 微程序的基本概念（⭐⭐⭐）
| 概念 | 含义 |
|---|---|
| **微命令** | 控制部件向执行部件发出的**控制信号**（如 PCout） |
| **微操作** | 执行部件接收微命令后进行的**操作**（如 PC 内容送总线）；微命令和微操作一一对应 |
| **相容微命令** | 可以**同时**出现的微命令 |
| **互斥微命令** | **不能同时**出现的微命令（如 ALU 的加和减、同一总线上的两个 out） |
| **微指令** | 若干微命令的集合，存放在控存的一个单元中。包括**操作控制字段**（发出哪些微命令）和**顺序控制字段**（下一条微指令的地址） |
| **微周期** | 执行一条微指令的时间，通常 = 一个时钟周期 |
| **微程序** | 一系列微指令的有序集合，**一条机器指令对应一个微程序** |
| **控制存储器（CM）** | 存放微程序，在 **CPU 内部**，用 **ROM** 实现 |
| **微地址寄存器（μAR / CMAR）** | 存放要读出的微指令地址 |
| **微指令寄存器（μIR / CMDR）** | 存放从控存读出的微指令 |

⚠️ **程序 vs 微程序**：
| | 程序 | 微程序 |
|---|---|---|
| 组成 | 指令 | 微指令 |
| 存放位置 | **主存**（RAM） | **控制存储器**（ROM，在 CPU 内） |
| 对应关系 | —— | **一条机器指令 ↔ 一个微程序** |
| 相关寄存器 | PC、IR | μAR（相当于 PC）、μIR（相当于 IR） |

### 📐 微程序控制器的工作过程
1. 执行**取指令公共微程序**（所有指令共用）：从主存取出机器指令送 IR
2. 由机器指令的**操作码**，经**微地址形成部件**，得到该指令对应微程序的**入口地址**，送 μAR
3. 从控存中逐条取出微指令，执行（每条微指令的操作控制字段直接发出微命令）
4. 该指令的微程序执行完，转回**取指令微程序**，取下一条机器指令

### 📐 控存中微程序的个数
- **取指周期**的微程序：所有指令**公用 1 个**
- **间址周期**：公用 1 个（如果有）
- **中断周期**：公用 1 个
- **执行周期**：**每条机器指令一个**
- 所以：若机器有 n 条指令，微程序数 **至少 n + 1 个**（n 个执行 + 1 个取指），考虑间址和中断则为 **n + 3 个**

## 五、微指令的编码方式（操作控制字段）（⭐⭐⭐）

### 📐 1. 直接编码（直接控制）方式
操作控制字段中**每一位代表一个微命令**，1 表示发出，0 表示不发出。
- ✅ 简单直观，速度快，并行性最好
- ❌ 微指令字长太长（有 n 个微命令就要 n 位），控存容量大

### 📐 2. 字段直接编码方式（⭐⭐⭐ 必考计算）
把微命令**分成若干字段**，**每个字段内的微命令互斥**，**不同字段的微命令相容**。每个字段单独**译码**，一个编码对应一个微命令。
- **每个字段要留出一个编码表示“不发出任何微命令”**（通常用全 0）
- 某字段有 **k 个**互斥微命令，需要 **⌈log₂(k + 1)⌉ 位**

✏️ **例**：某微程序控制器共有 **33 个微命令**，分成 5 个互斥组，各组的微命令个数分别为 **7、3、12、5、6**。采用字段直接编码，操作控制字段至少多少位？
| 组 | 微命令数 k | k + 1 | 位数 |
|---|---|---|---|
| 1 | 7 | 8 | 3 |
| 2 | 3 | 4 | 2 |
| 3 | 12 | 13 | 4 |
| 4 | 5 | 6 | 3 |
| 5 | 6 | 7 | 3 |
合计 **15 位**（直接编码需要 33 位）。

⚠️ **最常见的错误**：忘记“+1”。7 个微命令需要 log₂(7 + 1) = 3 位；8 个微命令需要 log₂(9) → **4 位**！

### 📐 3. 字段间接编码方式
一个字段的某些微命令还需要**另一个字段**的编码来共同解释。进一步缩短字长，但速度慢，很少用。

### 📐 微指令格式
| | 水平型微指令 | 垂直型微指令 |
|---|---|---|
| 特点 | 一条微指令能定义**多个并行**的微命令（直接/字段直接编码） | 一条微指令只能定义**一两个**微命令，类似机器指令，有“微操作码” |
| 字长 | 长 | 短 |
| 微程序长度 | **短**（条数少） | 长 |
| 速度 | **快** | 慢 |
| 编写 | 难 | 容易（像写程序） |

（混合型：在垂直型基础上增加一些不太复杂的并行操作。）

## 六、微指令的地址形成方式（顺序控制字段）（⭐⭐）

### 📐 1. 下址字段法（断定方式）
微指令中设一个**下址字段**，直接给出**下一条微指令的地址**。
- 下址字段位数 = ⌈log₂(控存中微指令总条数)⌉
- 🧒 像每页书的页脚写着“下一页请翻到第 X 页”

### 📐 2. 计数器法
下一条微指令地址 = 当前地址 + 1（像 PC + 1），遇到转移时才由转移字段给出地址。
- ✅ 下址字段短；❌ 需要额外的转移控制

### 📐 其他
- 由机器指令的**操作码**形成微程序入口地址（每条机器指令的第一条微指令）
- 根据**状态标志**（如 ZF）实现条件转移（微程序中的分支）

### ✏️ 例：求下址字段位数（经典题型）
某计算机采用微程序控制器，共有 **32 条**机器指令，公共的取指令微程序包含 **2 条**微指令，各指令对应的微程序平均由 **4 条**微指令组成，采用**断定法**（下址字段法）确定下条微指令地址，则微指令中下址字段的位数至少是多少？
- 微指令总条数 = 32 × 4 + 2 = **130** 条
- 2⁷ = 128 < 130 ≤ 256 = 2⁸ → 下址字段至少 **8 位**

### ✏️ 例：求控存容量
某微指令格式：操作控制字段 15 位（上例），判断测试字段 3 位，下址字段 8 位。控存共 130 条微指令。
- 微指令字长 = 15 + 3 + 8 = **26 位**
- 控存容量 = 2⁸ × 26 位（按地址空间）；实际使用 130 × 26 位

## 七、硬布线 vs 微程序（⭐⭐⭐）

| | 硬布线控制器 | 微程序控制器 |
|---|---|---|
| 实现 | 组合逻辑电路 | 微程序存在控存中 |
| 速度 | **快** | 慢（要读控存） |
| 规整性 | 繁琐、不规整 | 较规整 |
| 修改扩充 | **困难** | **容易**（改控存） |
| 应用 | **RISC**（ARM、MIPS） | **CISC**（x86 的复杂指令） |
| 性能 | 高 | 低 |

---

## ⚠️ 易错点

1. **ALU、MUX、译码器、加法器是组合逻辑（操作元件）**；**PC、IR、寄存器组、存储器是时序逻辑（状态元件）**
2. 数据通路**包含**异常检测电路（2021 年第 18 题）
3. 单总线：**一个节拍总线上只能有一个数据**；ALU 一个输入要先放暂存寄存器
4. 取指 C2：**MemR、MDRinE、PC+1** 可以同时进行
5. 字段直接编码：每字段位数 = ⌈log₂(**k + 1**)⌉，别忘了“+1”
6. **一条机器指令 ↔ 一个微程序**；取指微程序是公用的
7. 控存在 **CPU 内部**，用 **ROM**；主存用 RAM
8. 硬布线**快、难改**，用于 RISC；微程序**慢、易改**，用于 CISC
9. 水平型微指令：**字长长、微程序短、速度快**
10. 下址字段位数由**微指令总条数**决定

## 📋 本课小结

| 知识点 | 要点 |
|---|---|
| 数据通路 | 组合逻辑元件（操作）+ 时序逻辑元件（状态） |
| 单总线 | 每拍一个数据；ALU 需暂存 A/Y 和 AC/Z |
| 取指节拍 | PCout MARin → MemR MDRinE PC+1 → MDRout IRin |
| 硬布线 | 组合逻辑；快；难修改；RISC |
| 微程序 | 控存 ROM；一条指令一个微程序；慢；易修改；CISC |
| 字段直接编码 | 字段内互斥、字段间相容；每字段 ⌈log₂(k+1)⌉ 位 |
| 下址字段 | ⌈log₂(微指令总数)⌉ 位 |

## 🏋️ 课后练习

1. 下列部件中属于状态元件的是：(a) 通用寄存器组；(b) ALU；(c) 程序计数器；(d) 符号扩展单元；(e) 数据存储器
2. 在单总线结构中（ALU 一端接暂存寄存器 Y、另一端接总线，输出到 Z），写出指令 `SUB R1, R2`（(R1) − (R2) → R1）执行阶段的节拍和控制信号。
3. 某微程序控制器的微命令分为 4 个互斥组，分别含 4、8、15、2 个微命令，采用字段直接编码，操作控制字段至少几位？
4. 某机器有 60 条指令，每条指令的执行微程序平均 5 条微指令，取指微程序 3 条，间址微程序 2 条，中断微程序 3 条。采用下址字段法，下址字段至少几位？
5. 简述为什么 RISC 常用硬布线控制器，而 CISC 常用微程序控制器。

<details>
<summary>📖 答案</summary>

1. 状态元件：**(a)、(c)、(e)**
2. C1：Y ← (R1)，**R1out, Yin**；C2：Z ← (Y) − (R2)，**R2out, SUB, Zin**；C3：R1 ← (Z)，**Zout, R1in**
3. ⌈log₂5⌉ + ⌈log₂9⌉ + ⌈log₂16⌉ + ⌈log₂3⌉ = 3 + 4 + 4 + 2 = **13 位**
4. 总数 = 60 × 5 + 3 + 2 + 3 = 308；2⁸ = 256 < 308 ≤ 512 → **9 位**
5. RISC 指令少、格式规整、多数单周期完成，控制逻辑简单，用硬布线速度快、设计也不太复杂；CISC 指令多、复杂、执行步骤多，用硬布线设计极其复杂，用微程序则规整、易于设计和修改扩充
</details>
