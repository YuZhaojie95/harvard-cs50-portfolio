## 🚪 课前引入

假设你的电脑只有 **8 GB** 内存，但同时开着浏览器、微信、游戏……它们加起来要 **20 GB**。怎么办？

再比如，每个程序编译时都假设自己从地址 0 开始、独占整个内存。那两个程序同时运行，都想用地址 0x1000，岂不打架？

**虚拟存储器**解决这两个问题：
1. **给每个程序一个“假想的”大内存**（虚拟地址空间，如 4 GB），程序只管用虚拟地址
2. **只把正在用的部分放进真实的主存**，暂时不用的放在磁盘上
3. 由硬件（MMU）+ 操作系统负责把**虚拟地址翻译成真实的物理地址**

🧒 **比喻**：你住酒店，前台给你一张“1808 号房”的房卡（虚拟地址）。但实际上酒店可能把你安排在任何一间空房（物理地址），前台有一本**登记簿（页表）**记录“1808 号房的客人实际住在 305 室”。你只需要记住 1808，其余的由前台负责。

## 一、虚拟存储器的基本概念

### 📐 定义
- **虚拟地址（逻辑地址）**：程序（CPU 执行指令时）使用的地址
- **物理地址（实地址、主存地址）**：主存中真实的地址
- **虚拟存储器**：由**主存 + 辅存（磁盘）**构成，在**硬件和操作系统**的共同管理下，对应用程序呈现为一个**容量接近辅存、速度接近主存**的存储器

### 📐 主存—辅存层次 vs Cache—主存层次
| | Cache—主存 | 主存—辅存（虚拟存储器） |
|---|---|---|
| 目的 | 解决**速度**问题 | 解决**容量**问题（也实现了进程隔离） |
| 交换单位 | 块（几十字节） | 页（几 KB） |
| 管理者 | **全部由硬件**完成 | **硬件 + 操作系统**（缺页由 OS 处理） |
| 对谁透明 | 对所有程序员透明 | 对**应用程序员**透明，对**系统程序员不透明** |
| 缺失代价 | 几十~几百个时钟周期 | **几百万个时钟周期**（访问磁盘） |
| 映射方式 | 直接/全相联/组相联 | 页式通常是**全相联**（虚页可放在任何页框） |
| 写策略 | 全写或回写 | **只能回写**（写磁盘太慢了） |
| 缺失时 CPU | 等待 | **切换到其他进程** |

⚠️ 虚拟存储器“缺失”（缺页）的代价太大，所以要尽一切可能降低缺页率：**全相联映射**、**较大的页**、**近似 LRU 的替换算法**、**回写法**。

### 📐 三种虚拟存储器
1. **页式**：按固定大小的“页”划分（最常用，⭐⭐⭐）
2. **段式**：按程序的逻辑结构（代码段、数据段……）划分，大小不等
3. **段页式**：先分段，段内再分页

## 二、页式虚拟存储器（⭐⭐⭐）

### 📐 基本划分
- **虚拟地址空间**划分为大小相同的**虚页（页，page）**
- **主存空间**划分为同样大小的**实页（页框、页帧，page frame）**
- 页大小一般是 4KB（2¹²）

### 📐 地址划分
```
虚拟地址：|    虚页号 VPN    |  页内地址（页内偏移） |
物理地址：|  实页号（页框号） |  页内地址（不变！）   |
```
- **页内地址位数** = log₂(页大小)，如 4KB → 12 位
- **虚页号位数** = 虚拟地址位数 − 页内地址位数
- **页框号位数** = 物理地址位数 − 页内地址位数

🧒 关键：**页内地址在转换前后不变**，只需要把“虚页号”换成“实页号”。就像房间号 1808 换成 305，但你在房间里床的位置（页内偏移）是一样的。

### ✏️ 例
虚拟地址 32 位，物理地址 24 位，页大小 4KB：
- 页内地址 12 位
- 虚页号 32 − 12 = **20 位**（共 2²⁰ 个虚页）
- 页框号 24 − 12 = **12 位**（共 2¹² 个页框）

### 📐 页表（Page Table）
每个进程一张**页表**，**存放在主存中**，每个虚页对应一个**页表项（PTE）**：

| 字段 | 作用 |
|---|---|
| **有效位（存在位、装入位）** | 1 表示该页在主存中，0 表示不在（在磁盘上或未分配） |
| **页框号（实页号）** | 有效位 = 1 时，该页在主存中的位置 |
| （磁盘地址） | 有效位 = 0 时，该页在磁盘上的位置（有的系统单独存放） |
| **修改位（脏位）** | 该页调入后是否被修改过，替换时决定是否写回磁盘 |
| **使用位（访问位、引用位）** | 近期是否被访问过，供替换算法（如 CLOCK）使用 |
| **存取权限位** | 读/写/执行权限，用于**存储保护** |

- 页表的**起始地址**存放在 CPU 的**页表基址寄存器（PTBR）**中
- 页表项的**地址** = 页表起始地址 + 虚页号 × 页表项大小
- ⚠️ 页表**不需要存“虚页号”这一栏**！虚页号就是页表的**下标**（就像数组下标不需要存）

### 📐 地址转换过程（⭐⭐⭐）
```
          虚拟地址
    ┌──────────┬──────────┐
    │  虚页号   │  页内地址 │
    └────┬─────┴─────┬────┘
         │           │
 PTBR ──►+ 查页表     │
         ▼           │
   ┌──────────┐      │
   │有效位=1? │──否──► 缺页异常（由操作系统处理）
   └────┬─────┘      │
        │是           │
        ▼            ▼
    ┌──────────┬──────────┐
    │  页框号   │  页内地址 │   物理地址
    └──────────┴──────────┘
```
1. 从虚拟地址中取出**虚页号**
2. 用 PTBR + 虚页号 × PTE 大小，找到页表项
3. 检查**有效位**：
   - = 1：取出**页框号**，与页内地址拼接成**物理地址**
   - = 0：**缺页异常**，由操作系统把该页从磁盘调入主存（可能要替换某页），修改页表，然后**重新执行**引起缺页的那条指令
4. 同时检查**存取权限**，违反则产生**保护异常**

### ✏️ 真题精讲
📝 **真题（2022 年第 15 题）**：某计算机主存地址为 24 位，采用分页虚拟存储管理方式，虚拟地址空间大小为 4GB，页大小为 4KB，按字节编址。某进程的页表部分内容如下表所示。当 CPU 访问虚拟地址 **0008 2840H** 时，虚-实地址转换的结果是：

| 虚页号 | 实页号（页框号） | 存在位 |
|---|---|---|
| 82 | 024H | 0 |
| … | … | … |
| 129 | 180H | 1 |
| 130 | 018H | 1 |

A. 得到主存地址 02 4840H　B. 得到主存地址 18 0840H　C. 得到主存地址 01 8840H　D. 检测到缺页异常

1. 页大小 4KB → 页内地址 **12 位**（低 3 个十六进制位）
2. 虚拟地址 0008 2840H：页内地址 = **840H**，虚页号 = 00082H = **130**（十进制！）
3. 查表：虚页号 130 → 页框号 **018H**，存在位 = 1
4. 物理地址（24 位）= 018H 拼接 840H = **01 8840H** → 选 **C**

⚠️ **陷阱**：表中虚页号是**十进制**的 82、129、130，而 00082H 是十六进制！若把 82H 看成十进制 82，就会误选 D（缺页）。**00082H = 8 × 16 + 2 = 130**。

## 三、快表 TLB（⭐⭐⭐）

### 🧒 为什么需要 TLB
页表在主存中。每次访存，**先要访问主存查页表，再访问主存取数据**——访存次数翻倍，太慢了！

利用局部性：最近用过的页表项很可能马上还要用。于是在 CPU 里放一个小而快的“**页表项的 Cache**”，这就是 **TLB（Translation Lookaside Buffer，快表）**。
- 相应地，主存里的页表叫**慢表**

### 📐 TLB 的结构
- TLB 由 **SRAM** 实现（和 Cache 一样；2020 年第 15 题“TLB 和 Cache 都由 DRAM 组成”是错的）
- 每个 TLB 表项：**有效位 + 标记（Tag）+ 页框号** +（修改位、权限位、LRU 位等）
- 映射方式：通常是**全相联**或**组相联**
  - **全相联**：Tag = **整个虚页号**
  - **组相联**：虚页号再分成 **Tag | 组号**，和 Cache 地址划分完全一样的思路

```
全相联 TLB 下的虚拟地址：| 标记 Tag（= 虚页号） | 页内地址 |
组相联 TLB 下的虚拟地址：| 标记 Tag | TLB 组号 | 页内地址 |
                         |<---- 虚页号 ----->|
```

⚠️ TLB 的“组号”来自**虚页号的低位**，不是来自页内地址！
（Cache 的组号来自**物理地址**的中间位；TLB 的组号来自**虚拟地址中虚页号**的低位。别混淆。）

### 📐 带 TLB 的地址转换
1. 用虚页号（的 Tag 和组号）查 TLB
2. **TLB 命中** → 直接得到页框号，拼成物理地址（**不用访问主存查页表**）
3. **TLB 缺失** → 访问主存中的页表：
   - 页表项有效 → 取出页框号，形成物理地址，**同时把该页表项装入 TLB**（可能要替换）
   - 页表项无效 → **缺页异常**

### ✏️ 真题精讲（⭐⭐⭐）
📝 **真题（2021 年第 44 题，8 分）**：假设计算机 M 的主存地址为 24 位，按字节编址；采用分页存储管理方式，虚拟地址为 **30 位**，页大小为 **4KB**；TLB 采用 **2 路组相联**方式和 **LRU** 替换策略，共 **8 组**。请回答下列问题。
1）虚拟地址中哪几位表示虚页号？哪几位表示页内地址？
2）已知访问 TLB 时虚页号高位部分用作 TLB 标记，低位部分用作 TLB 组号，M 的虚拟地址中哪几位是 TLB 标记？哪几位是 TLB 组号？
3）假设 TLB 初始时为空，访问的虚页号依次为 10, 12, 16, 7, 26, 4, 12 和 20，在此过程中，哪一个虚页号对应的 TLB 表项被替换？说明理由。
4）若将 M 中的虚拟地址位数增加到 32 位，则 TLB 表项的位数增加几位？

**1）** 页大小 4KB = 2¹² → **页内地址 VA11~VA0**（12 位）；**虚页号 VA29~VA12**（18 位）

**2）** TLB 共 8 组 → 组号 3 位，取虚页号的**低 3 位**：**TLB 组号 VA14~VA12**；**TLB 标记 VA29~VA15**（15 位）

**3）** 组号 = 虚页号 mod 8：

| 虚页号 | 10 | 12 | 16 | 7 | 26 | 4 | 12 | 20 |
|---|---|---|---|---|---|---|---|---|
| 组号 | 2 | 4 | 0 | 7 | 2 | 4 | 4 | 4 |

- 第 2 组：10、26 → 2 路装得下
- 第 4 组：12（装入）→ 4（装入，组满）→ 12（**命中**，12 成为最近使用，4 成为最久未用）→ 20（缺失，组满，按 LRU **替换虚页号 4** 的表项）
- **答：虚页号 4 对应的 TLB 表项被替换。**

**4）** 虚拟地址增加 2 位 → 虚页号增加 2 位 → TLB 组数不变，所以 **TLB 标记增加 2 位**，TLB 表项**增加 2 位**。（页框号位数由物理地址决定，不变。）

## 四、完整的访存流程：TLB + 页表 + Cache（⭐⭐⭐）

CPU 发出一个虚拟地址，要取到数据，完整过程如下：

```
虚拟地址
   │
   ▼
查 TLB ──命中──────────────┐
   │缺失                   │
   ▼                       │
查主存中的页表              │
   │                       │
 有效？──否──► 缺页异常（OS 从磁盘调页，更新页表，重新执行指令）
   │是                     │
   ▼                       │
更新 TLB                    │
   │                       │
   └──────► 物理地址 ◄──────┘
               │
               ▼
          查 Cache ──命中──► 取得数据
               │缺失
               ▼
          访问主存，调块入 Cache，取得数据
```

### 📐 三者命中组合判断（⭐⭐）
| TLB | 页表（Page） | Cache | 是否可能 | 说明 |
|---|---|---|---|---|
| 命中 | 命中 | 命中 | ✅ | 最好的情况 |
| 命中 | 命中 | 缺失 | ✅ | |
| 缺失 | 命中 | 命中 | ✅ | TLB 缺失，查页表后得到物理地址，Cache 命中 |
| 缺失 | 命中 | 缺失 | ✅ | |
| 缺失 | 缺失 | 缺失 | ✅ | 缺页，调页后数据刚进主存，不在 Cache |
| 命中 | **缺失** | 任意 | ❌ | **TLB 中有，页表中一定有**（TLB 是页表的子集）|
| 任意 | **缺失** | **命中** | ❌ | **页不在主存，其数据不可能在 Cache 中**（Cache 是主存的子集）|

📝 **真题（2010 年真题）**：下列命中组合情况中，一次访存过程中**不可能发生**的是：
A. TLB 未命中，Cache 未命中，Page 未命中
B. TLB 未命中，Cache 命中，Page 命中
C. TLB 命中，Cache 未命中，Page 命中
D. TLB 命中，Cache 命中，Page 未命中
→ **D**（TLB 命中则 Page 一定命中；Page 未命中则 Cache 也不可能命中）

🧒 记住两个“包含关系”：**TLB ⊂ 页表**，**Cache ⊂ 主存**。

### 📐 各部件由谁处理缺失
| 缺失 | 处理者 |
|---|---|
| Cache 缺失 | **硬件** |
| TLB 缺失 | 可以是**硬件**（x86，硬件自动查页表），也可以是**软件**（某些 RISC，由 OS 的异常处理程序填 TLB） |
| 缺页 | **操作系统**（软件，缺页异常处理程序） |

📝 **2020 年第 15 题**：“TLB 和 Cache 的缺失处理都可以由硬件实现”——**正确**；“命中率都与程序局部性有关”——正确；“缺失后都需要去访问主存”——正确（TLB 缺失去主存查页表，Cache 缺失去主存取块）；“都由 DRAM 组成”——**错误**，选 **D**。

## 五、真题精讲：2025 年第 43 题（⭐⭐⭐ 完整讲解）

> 现有 C 语言程序 P 的部分代码如下，假定运行程序 P 的计算机 M 字长为 32 位，按字节编址，**数据 Cache 的数据区大小为 32KB，采用 8 路组相联映射方式**，主存块大小为 **64B**，Cache 命中时间为 **2 个时钟周期**，缺失损失为 **200 个时钟周期**；采用页式虚拟存储管理方式，**页大小为 4KB**，数组 d 的起始虚拟地址为 **0180 0020H**（VA31~VA0）。
> ```c
> int x, d[2048], i;
> ......
> for (i = 0; i < 2048; i++)
>     d[i] = d[i] / x;
> ......
> ```
> (1) 主存地址中 Cache 组号字段和块内地址字段分别占几位？虚拟地址中哪些位可作为 Cache 索引？（2 分）
> (2) d[100] 的虚拟地址为多少？d[100] 所在主存块对应的 Cache 组号是多少？（3 分）
> (3) 假设执行 for 语句时对应代码已在 Cache，变量 i 和 x 已装入寄存器，数组 d 已调入主存但不在 Cache，则 d[0] 在其所在主存块内的偏移量是多少（用十六进制）？for 语句执行过程中，访问数组 d 的 Cache 缺失率和数组元素的平均访问时长是多少？（缺失率百分比保留两位）（4 分）
> (4) 数组 d 分布在几个页中？若执行 for 语句时对应代码已经在主存，但数组 d 还未调入主存，则执行 for 语句过程中，访问数组 d 所引起的缺页次数是多少？（3 分）

**(1)**
- 块大小 64B → **块内地址 6 位**
- 行数 = 32KB / 64B = 512；组数 = 512 / 8 = 64 → **组号 6 位**
- 组号 + 块内地址 = 12 位，正好等于**页内地址**的位数（4KB → 12 位）
- 页内地址在虚实转换中**不变**，所以物理地址的第 11~6 位 = 虚拟地址的第 11~6 位 → **VA11~VA6 可作为 Cache 索引**（组号）

🧒 这就是 **VIPT（Virtually Indexed, Physically Tagged，虚拟索引、物理标记）**：用虚拟地址的低位直接去找 Cache 组，**同时**进行 TLB 地址转换；等转换出物理地址，再用物理地址的 Tag 去比较。**查 TLB 和查 Cache 并行进行**，节省时间。前提是“组号 + 块内地址”的位数 ≤ 页内地址位数。

**(2)**
- d[100] 的虚拟地址 = 0180 0020H + 100 × 4 = 0180 0020H + 190H = **0180 01B0H**
- 组号 = VA11~VA6：1B0H = 0001 1011 0000，第 11~6 位 = 000110 = **6** → **第 6 组**

**(3)**
- d[0] 地址 0180 0020H，块内偏移 = 低 6 位 = 10 0000 = **20H**（即 32）
- 数组 d 共 2048 × 4 = 8192B，从块内偏移 32 开始，占的块数：
  - 第 1 块只放了 32B（8 个元素），之后 8160B 占 127.5 块 → 共 **129 个块**
  - （算法：(20H + 8192 − 1) / 64 取整 + 1 = 8223 / 64 = 128 + 1 = 129）
- 每个元素访问 2 次（读 d[i]、写 d[i]），总访问 2048 × 2 = **4096 次**
- 每个块第一次读时缺失，其余访问都命中（写的时候块已在 Cache 中）；Cache 32KB > 8KB，不会发生替换
- **缺失率 = 129 / 4096 ≈ 3.15%**
- **平均访问时长** = 命中时间 + 缺失率 × 缺失损失 = 2 + 3.15% × 200 ≈ **8.30 个时钟周期**

**(4)**
- 数组虚拟地址范围：0180 0020H ~ 0180 0020H + 8191 = **0180 201FH**
- 页号：01800H、01801H、01802H → 分布在 **3 个页**中
- 数组 d 未调入主存，每个页第一次访问时缺页 → **缺页 3 次**

⚠️ **本题的“对齐陷阱”**：数组起始地址不是块对齐（偏移 20H），也不是页对齐，所以块数是 129 而不是 128，页数是 3 而不是 2。**一定要按地址范围来数！**

## 六、2023 年第 43 题第 1 问：数页数与缺页

📝 **真题（2023 年第 43 题第 1 问）**：（条件见第 10 课：页大小 4KB，int a[24][64]，起始虚拟地址 0042 2000H，执行前数组 a 不在内存，执行过程中不会发生页面置换）数组 a 分布在几个页面中？对于数组 a 的访问，会发生几次缺页异常？页故障地址各是什么？

- 数组大小 = 24 × 64 × 4 = 6144B = 6KB
- 地址范围：0042 2000H ~ 0042 2000H + 6143 = **0042 37FFH**
- 0042 2000H 恰好是页的起始（低 12 位为 0），第 1 页 0042 2000H ~ 0042 2FFFH（4KB），第 2 页 0042 3000H ~ 0042 37FFH（2KB）
- **分布在 2 个页面中**，按行访问，每页第一次访问时缺页 → **2 次缺页异常**
- **页故障地址**（引起缺页的虚拟地址）：**0042 2000H**（访问 a[0][0]）和 **0042 3000H**（访问 a[16][0]，因为 4096 / 256 = 16，第 16 行开始进入第 2 页）

## 七、段式虚拟存储器（⭐）

### 📐 思想
按程序的**逻辑结构**划分为若干**段**（代码段、数据段、堆栈段……），每段长度**不同**。
- 虚拟地址 = **段号 + 段内地址**
- **段表**：每段一个表项，包含**段起始地址（段基址）、段长、装入位、访问权限**等

### 📐 地址转换
1. 用段号查段表，得到段基址和段长
2. **检查段内地址是否 < 段长**，否则**越界异常**
3. 物理地址 = 段基址 **+** 段内地址（注意是**相加**，不是拼接）

### 📐 优缺点
- ✅ 段是逻辑上独立的，便于**共享和保护**、便于编译
- ❌ 段长不固定，主存中会产生**外部碎片**（外碎片），分配和回收麻烦

⚠️ 对比：页式是**拼接**（页框号 ∥ 页内地址），段式是**相加**（段基址 + 段内地址）。

---

## 八、段页式虚拟存储器（⭐）

- 程序先按逻辑**分段**，每段再**分页**；主存按页划分
- 虚拟地址 = **段号 + 段内页号 + 页内地址**
- 每个进程**一张段表**，每个段**一张页表**
- 地址转换：段号查段表 → 得到该段页表起址 → 段内页号查页表 → 得到页框号 → 拼接页内地址
- ✅ 兼具段式（逻辑、共享保护）和页式（无外碎片）优点
- ❌ 地址转换要**查两次表**，更慢

| | 页式 | 段式 | 段页式 |
|---|---|---|---|
| 划分依据 | 固定大小 | 逻辑结构 | 先逻辑分段，段内固定大小分页 |
| 虚拟地址 | 页号 + 页内地址 | 段号 + 段内地址 | 段号 + 段内页号 + 页内地址 |
| 物理地址形成 | 拼接 | 相加 | 拼接 |
| 碎片 | 内碎片（最后一页） | 外碎片 | 内碎片 |
| 共享保护 | 较难 | 方便 | 方便 |

## 九、Cache 用虚拟地址还是物理地址？（了解，但 2025 年考了）

| 方式 | 说明 |
|---|---|
| **PIPT**（物理索引、物理标记） | 先 TLB 转换，再用物理地址查 Cache。简单，但串行，慢 |
| **VIPT**（虚拟索引、物理标记） | 用虚拟地址中的**页内地址部分**做 Cache 索引，与 TLB **并行**。要求“组号 + 块内地址”位数 ≤ 页内地址位数 |
| VIVT（虚拟索引、虚拟标记） | 不需要转换，但存在“同义/别名”问题，进程切换要清 Cache |

🧒 **判断能否 VIPT**：Cache 每路大小（= 组数 × 块大小）≤ 页大小。
- 2025 年第 43 题：每路 = 64 组 × 64B = 4KB = 页大小 ✓
- 这也解释了为什么 L1 Cache 常常是“32KB、8 路”：32KB / 8 = 4KB = 页大小，恰好可以 VIPT

---

## ⚠️ 易错点

1. **页内地址在转换中不变**；物理地址 = 页框号 **拼接** 页内地址
2. 页表**不存虚页号**（虚页号是下标）
3. 页表在**主存**中，页表基址在 **PTBR** 寄存器中
4. TLB 是**页表的 Cache**，用 **SRAM**；TLB 组号取自**虚页号的低位**
5. TLB 命中则页一定在主存；页不在主存则数据一定不在 Cache
6. 缺页由**操作系统**处理；Cache 缺失由**硬件**处理
7. 虚拟存储器只能用**回写法**，通常**全相联**
8. 看清数字是**十进制还是十六进制**（2022 年第 15 题）
9. 数页数、块数时，要按**地址范围**数，注意起始地址是否对齐
10. 段式：段基址 **+** 段内地址，要做**越界检查**

| 知识点 | 要点 |
|---|---|
| 虚拟存储器 | 主存 + 辅存，硬件 + OS 管理，对应用程序员透明 |
| 页式地址 | 虚页号 \| 页内地址 → 页框号 \| 页内地址 |
| 页表项 | 有效位、页框号、修改位、使用位、权限位 |

| 访存流程 | TLB → 页表 → 物理地址 → Cache → 主存 |

| 段式 | 段基址 + 段内地址，越界检查，外碎片 |
| 段页式 | 段号 + 段内页号 + 页内地址，查两次表 |
| VIPT | 用页内地址部分做 Cache 索引，与 TLB 并行 |

## 🏋️ 课后练习

1. 虚拟地址 32 位，物理地址 30 位，页大小 8KB，页表项 4B。求：虚页号位数、页框号位数、页表最多占多少字节？
2. 某进程页表如下（页大小 1KB，十进制）：虚页 0 → 页框 5；虚页 1 → 页框 2；虚页 2 → 不在主存；虚页 3 → 页框 7。求虚拟地址（十进制）1500、3100、2500 对应的物理地址。
3. 某 TLB 采用 4 路组相联，共 16 组，虚拟地址 32 位，页大小 4KB，物理地址 28 位。求 TLB 标记位数、TLB 组号在虚拟地址的哪几位？每个 TLB 表项至少多少位（含有效位）？
4. 判断下列组合是否可能：(a) TLB 缺失、页命中、Cache 命中；(b) TLB 命中、页缺失、Cache 缺失；(c) TLB 缺失、页缺失、Cache 命中。
5. 某 Cache 32KB、4 路组相联、块大小 64B，页大小 4KB。能否用 VIPT 方式？为什么？
6. int 数组 b[3000] 起始虚拟地址 0010 0F00H，页大小 4KB。数组跨越几个页？顺序访问一遍、数组初始不在主存，缺页几次？

<details>
<summary>📖 答案</summary>

1. 页内地址 13 位；虚页号 32 − 13 = **19 位**；页框号 30 − 13 = **17 位**；页表最多 2¹⁹ 项 × 4B = **2MB**
2. 1500 = 1 × 1024 + 476 → 虚页 1 → 页框 2 → 2 × 1024 + 476 = **2524**；3100 = 3 × 1024 + 28 → 虚页 3 → 页框 7 → 7 × 1024 + 28 = **7196**；2500 = 2 × 1024 + 452 → 虚页 2 不在主存 → **缺页异常**
3. 虚页号 20 位（VA31~VA12）；16 组 → 组号 4 位 **VA15~VA12**；Tag = 20 − 4 = **16 位**（VA31~VA16）；页框号 28 − 12 = 16 位；表项至少 = 1（有效位）+ 16（Tag）+ 16（页框号）= **33 位**
4. (a) **可能**；(b) **不可能**（TLB 命中说明页一定在主存）；(c) **不可能**（页不在主存，数据不可能在 Cache）
5. 每路大小 = 32KB / 4 = 8KB > 4KB。组数 = 32KB / 64B / 4 = 128 组 → 组号 7 位 + 块内 6 位 = 13 位 > 页内地址 12 位，**不能直接 VIPT**（组号最高位落在虚页号里，虚实转换后可能改变）
6. 大小 12000B，范围 0010 0F00H ~ 0010 0F00H + 11999 = 0010 0F00H + 2EDFH = **0010 3DDFH**；页号 00100H ~ 00103H → **4 个页**，缺页 **4 次**
</details>
